<objective>
Prove the whole phase's spine in one end-to-end path: a `drive` invocation that passes the
opt-in gate, starts a journal, spawns a real child process, drains its event stream into that
journal, finishes the journal, and exits — and the same invocation against a project that never
opted in, refused before anything is spawned and leaving nothing on disk.

The slice touches every layer the phase will modify: the CLI surface (`src/cli.rs`), the
dispatch that must land **before** `tui::init()` (`src/main.rs`), the driver module root and run
body (`src/driver/`), the capability type (`src/executor/mod.rs`), the opt-in record
(`src/config.rs`), the typed refusals (`src/error.rs`) and the journal (`src/journal/`).

Purpose: this is the phase's architectural bet, and proving it on the first commit is what stops
a dead end being discovered after six layers are already committed. It is also the moment two
Phase-15/16 components stop being dead code — `src/journal/mod.rs:547-550` says in as many words
that *"nothing in this repository spawns a `ClaudeExecutor` yet; wiring a real one is Phase 17's"*.
Success criterion #2 ("reopening the TUI shows that run still live with its current step") has no
journal to read unless this plan lands, so every later plan in the phase is downstream of it.

Output: `src/driver/` with a module root and a run body, the `Drive` subcommand, the
`DriverOptIn` record, `DrivableProject::from_registry`, the renamed escape hatch, and the
mechanical guard that keeps the seam closed.

**Deliberately NOT in this plan, and why each is a field addition rather than an architectural
change later:** the `flock` guard (plan 17-02 adds one field to the run state), the dry-run branch
(plan 17-04 adds one arm to `drive()`), the SIGTERM handler (plan 17-06 adds one arm to the run
body's `select!`), and the detached spawn (plan 17-05 is a *caller* of this CLI surface, not a
change to it). None of them moves a layer boundary this plan establishes.
</objective>
