<objective>
Harden the opt-in record so the two ways it could silently become true are both closed, and prove
the second half of ROADMAP success criterion #4 — that a live run against one project touches no
other registered project.

Plan 17-01 introduced `DriverOptIn` and the gate. This plan does the parts that make the gate
trustworthy rather than merely present:

1. **The migration.** `#[serde(default)]` alone makes an old `config.json` load; it does not prove
   it. FEATURES:236 names silent enrollment as the single failure that is *"invisible until the
   agent has already committed"*, so the byte-for-byte load of a pre-Phase-17 config is a test, not
   an assumption (D-15).
2. **The single construction site.** A record that can be built anywhere is a record that can be
   built by accident. `registry::record_opt_in` becomes the only place outside tests where a
   `DriverOptIn` value comes into existence, and `auto_register_from_sessions` — the
   silent-enrollment hazard site — is mechanically fenced away from it (D-14).
3. **The counting seam.** `Preferences.driver_max_concurrent`, default 1, which Phase 20 inherits
   as a working cap rather than building one. Without it, "one driver per project" multiplied
   across N opted-in projects burns the *shared* 5h/7d quota N times over (D-18).
4. **Criterion #4's second half.** Register two projects, opt in only A, drive A against a fixture
   that records its own working directory, and assert B's whole tree is byte-identical afterwards
   and that the agent's cwd was never under B.

Output: config schema version 2 with a forward-compatible read path, `record_opt_in` /
`clear_opt_in`, `driver_max_concurrent`, and the isolation proof.
</objective>

**`src/config.rs`** — four changes, each with the reasoning in a doc comment.

(a) **Schema version.** Add `pub const CONFIG_SCHEMA_VERSION: u32 = 2;` with a doc stating what
version 2 means (a registry entry may carry a `driver_opt_in` record) and that version 1 configs
load unchanged. Change `Config::new()` to use the constant instead of the literal `1`. Leave
`version` **without** `#[serde(default)]`: a config lacking the field already fails to parse today,
that is the existing schema-version discipline D-15 points at, and relaxing it here would be an
unrelated behaviour change.

(b) **Forward-compatible read path.** Add `fn migrate(config: &mut Config)` and call it from
`load_config` immediately after the parse. Its rules, in this order:
- `version < CONFIG_SCHEMA_VERSION` → set `version = CONFIG_SCHEMA_VERSION`. Nothing else changes:
  every `driver_opt_in` is already `None` because `#[serde(default)]` produced it, and **that is
  the migration** — an old config has no opted-in project and must not acquire one by being read.
  Say exactly that in the doc, citing FEATURES:236.
- `version > CONFIG_SCHEMA_VERSION` → leave it alone and emit a `tracing::warn!` naming both
  numbers and nothing else. Do **not** downgrade the recorded version: the file was written by a
  newer binary and stamping it back would tell that binary its own migration had already run.
- Idempotent by construction: running `migrate` on an already-migrated config changes nothing. A
  test asserts this rather than the comment asserting it.
The write side is a **one-shot normalisation** in the existing `save_config`, which needs no code
change at all — because `migrate` already set `version` in memory, the next ordinary save stamps
the file. Note this in `migrate`'s doc as the deliberate shape: read-side fallback plus write-side
one-shot, the `queue_md.rs:189-230` structure, with **no** destructive rewrite of a file an older
binary might still be reading.

(c) **Unknown-field carriers.** Add `#[serde(flatten)] pub extra: serde_json::Map<String, serde_json::Value>`
to `RegisteredProject` and to `Preferences`. This is the same tolerance technique
`JournalRecord.rest` already uses at `src/journal/reader.rs:198-209`, applied to a file two binary
versions may share. Without it, a v1.6 binary loading a v2.1 config and saving it would silently
delete every field it did not know — a destructive rewrite by omission, which is precisely what
D-15 forbids. The doc must name that failure. Both fields need `#[serde(default)]` semantics, which
`Map` gets for free from `flatten`; confirm by test rather than by assumption.

(d) **`driver_max_concurrent`.** Add `#[serde(default = "default_driver_max_concurrent") ] pub driver_max_concurrent: usize`
to `Preferences` with `fn default_driver_max_concurrent() -> usize { 1 }`. **Remove `Default` from
`Preferences`'s derive list and hand-write the impl**, because a derived `Default` yields
`usize::default()`, which is `0`, which means "no run may ever start" — the one place D-18's
"almost free" costs more than a field (PATTERNS note 5). The doc states D-18's rationale: the
fleet dimension enters v2.0 as a **count**, never as a second run identity; the default is 1
because the 5h/7d Claude quota is shared across every surface the user has, so N concurrent driven
projects burn it N times over (PITFALLS:329); and Phase 20 inherits a working cap rather than
building one. Enforcement lands at the spawn seam in plan 17-05 — say so, so nobody looks for it
here.

**`src/registry.rs`** — the single construction site.

`pub fn record_opt_in(config: &mut Config, alias: &str) -> anyhow::Result<()>` — look the alias up,
`bail!` in the existing style when absent, compute the digest, and set
`driver_opt_in = Some(DriverOptIn { opted_in_at, claude_md_digest })`. `opted_in_at` is
`chrono::Utc::now().to_rfc3339_opts(chrono::SecondsFormat::Secs, true)`. Its doc must carry D-14's
central claim: **this is the only function outside tests that constructs a `DriverOptIn`**, which
is what makes a `Some(record)` in the config a proof of a deliberate user action rather than a bit
that could have been flipped anywhere. Note that it does **not** persist — the caller calls
`save_config`, consistently with every other function in this module.

`fn claude_md_digest(project_root: &Path) -> Option<String>` — read `<root>/CLAUDE.md`, return
`Some(crate::journal::argv_digest(&[contents]))`, `None` when the file is absent or unreadable.
Reusing `argv_digest` adds no hashing code and no dependency; its doc already states it is
FNV-1a-based and explicitly **not** a security control, which is exactly right here — this is
drift detection for Phase 21, not integrity. Say both facts in the doc, and say that Phase 17
records the digest and acts on **nothing**.

`pub fn clear_opt_in(config: &mut Config, alias: &str) -> anyhow::Result<()>` — set the field to
`None`. `pub fn is_opted_in(config: &Config, alias: &str) -> bool` — a cheap read for the UI in
plan 17-07.

## Trust Boundaries

| Boundary | Description |
