## The boundary, stated exactly

For a word `w` that has already passed the existing `!token.operator && token.literal` filter, every byte
index `i` with `w.as_bytes()[i] == b'/'` yields a candidate `&w[i..]`. Each candidate goes through the
**existing** `lexical_absolute_components` normaliser and the **existing** two comparisons — `word_is_within`
(component-wise PREFIX over the envelope directory) and `word_is_exactly` (EQUALITY against the guard's own
binary). **`i == 0` is today's rule, so the new candidate set CONTAINS the old one.**

**It is not a list of attachment characters, and that is forced rather than preferred.**

| Candidate boundary | Reaches | Misses |
|---|---|---|
| split at the FIRST `=` | `of=/p`, `--git-dir=/p` | `--opt=a=/p`; `-C/p`, `-t/p` (attached SHORT options, no `=`); `host:/p` |
| split at EVERY `=` | the above plus `--opt=a=/p` | the attached short options and the `:` |
| a LIST `= : , @` | most spellings | the next program's character — **and it is a PROGRAM-GRAMMAR ENUMERATION, D-08's defect one level over** |
| **`/`-anchored substrings** | **all of them, and every attachment character that exists, and none** | only what the existing conditions already exclude |

`dd`'s `of=` is not an option at all — it is that program's operand grammar. `tar -C/path` attaches with

that has to know every program's grammar, which is exactly what `resolve_program` never asks and what D-08
and `wrapper_names_the_fix_must_not_know_are_absent_from_the_production_logic` both forbid.**
