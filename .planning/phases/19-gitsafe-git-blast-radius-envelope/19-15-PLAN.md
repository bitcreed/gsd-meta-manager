## The rule, and why it is positional

`tokenize` marks a `{`, `}`, `(` or `)` operator token as a **word-splitting flush** when a word
was in progress immediately before it. That is true at every boundary inside `${X}push`,
`$(true)push`, `${C}NT` and `${C}`. It is false for `{ cmd; }` and `( cmd )`, because bash's own
grammar requires whitespace after `{` and an operator or newline before `}`, so no word is in
progress at either boundary — grouped commands keep today's segments exactly.

A segment whose **immediately preceding operator** is a word-splitting **CLOSER** (`}` or `)`) is a
fragment continuing the enclosing word after an expansion. Its first token is not a command
position: what the shell will put in front of it is unknowable. If such a segment resolves a
governed program, it is refused — which is step 5's existing wrapper-prefix rule applied where the
prefix was severed rather than merely expanded.

The **opener** is excluded on purpose. After `{` you are inside `${NAME}`, which is a variable name
and never a governed program; after `(` you are inside `$(cmd)`, which is a genuine command
position and must keep being classified. That exclusion is what keeps these running:

```
permitted: echo $(git rev-parse HEAD)              permitted: DIR=$(mktemp -d)
permitted: git log --format=%h $(git rev-parse HEAD)  permitted: RUN_ID=$(uuidgen)
permitted: ROOT=$(git rev-parse --show-toplevel)   permitted: CONFIG=$(cat cfg)
permitted: { git status; } and ( git status )      permitted: COMMAND=$(which git)
```

"Immediately preceding" is equally load-bearing: in `(git status)&&git fetch origin` the second
segment's immediately preceding operator is `&&`, not `)`.

## The formulation that was withdrawn, recorded so it is not repeated

An earlier draft keyed Rule B on a literal fragment being a substring of an `ENVELOPE_ENV_KEYS`
entry. It was withdrawn on two measurements:

- **Evadable.** Move the split point: `C=GIT_CONFIG_COU; env -u ${C}NT git fetch origin` leaves the
  two-character fragment `NT`, a one-character tail is easier still, and the bare
  `env -u ${C} git fetch origin` leaves no literal fragment at all.
- **Unshippable.** The commonest `$(`-carrying shape in ordinary shell is an uppercase assignment,
  and `ROOT`, `DIR`, `RUN`, `CONFIG` and `COMMAND` all sit inside envelope key names — including
  `GSD_MM_RUN_ID`, which `19-14` adds. Every one of those commands would be refused, on every Bash
  tool call.

The positional rule refuses both evasion spellings and permits all five assignments, with nothing
to floor and nothing to duck under. That paragraph goes in the code, because a later reader tempted
by the textual version needs to find the measurement rather than repeat it.
