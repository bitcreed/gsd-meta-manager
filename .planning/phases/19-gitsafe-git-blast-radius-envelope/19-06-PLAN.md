<objective>
Tell the truth about what this envelope does and does not guarantee, mechanically: probe the
remote's protection state read-only and record `protected | unprotected | unknown(reason)` (D-26),
and pin the honesty statement as a constant with a test in the same style as the existing dry-run
section constants (D-27).

Purpose: client-side hooks are defeatable in principle, so the honest posture is defence in depth
plus an explicit, pinned statement of what is and is not guaranteed. An overstated safety claim is
worse than a stated limitation, because it gets trusted — and the Replit incident this phase is
built on had exactly two failures, of which the second was reporting success over a deletion the
agent had performed. Pinning the text with a test is what stops a later refactor from softening it
by accident.

Output: `src/envelope/advisory.rs` with a read-only probe and the pinned constant, and a dry-run
preview that renders four sections in a fixed, test-asserted order.

Reversibility note: D-26 and D-27 are locked decisions in `19-CONTEXT.md`, and D-27 is a
`[USER-HARD-REQUIREMENT]`. Ratings are recorded on the tasks; no `checkpoint:decision` is inserted
for a door the developer has already walked through.

  <action>
Create `src/envelope/advisory.rs` and add `pub mod advisory;` to `src/envelope/mod.rs`.

  - `pub enum ProtectionState { Protected, Unprotected, Unknown { reason: String } }` with
    `pub fn as_str(&self)` yielding stable identifiers in the style of `JournalEvent::Diagnostic`'s
    `code`. Its doc states the invariant that carries the whole decision: `Unknown` is never
    rendered as `Protected`, and a probe failure is a statement about what we do not know, not a
    statement about risk.
  - `pub fn probe_protection(project_root: &Path, env: &EnvelopeEnv) -> ProtectionState`. It runs
    once, at run start, and never on the guard's per-tool-call path — that constraint belongs in
    the doc, because a network call on the agent's critical path is the reproduced hang this
    project already shipped a mitigation for.

Probe sequence, every step read-only:
  1. Resolve the remote URL with the established `git --no-optional-locks -C <root> …` shape,
     `.output()`, failure as `None`. Every git invocation the envelope makes outside the hook path
     carries `--no-optional-locks`, because a git read opportunistically writes the index otherwise.
  2. If the URL does not name a GitHub host, return `Unknown` with that as the reason. A non-GitHub
     remote is a thing we cannot probe, not a thing that is unprotected.
  3. Query the repository's rulesets for the default branch through the external GitHub client,
     falling back to the branch-protection endpoint when the first returns nothing usable. Both are
     `GET`s. Run the client under the envelope environment so it cannot read the user's own host
     configuration.
  4. A missing client binary, a network failure, a permission failure, or an unparseable response
     each yields `Unknown` carrying that specific reason.

**No write path exists.** There is deliberately no function in this module that issues a `POST`,
`PUT`, `PATCH` or `DELETE`. Applying protection needs an administration scope that the run
credential withholds by design, so the envelope detects and reports and never mutates. State this
in the module doc alongside the deferred alternative: a later milestone that wants to apply
protection needs a separate, explicitly consented credential, which is a product decision rather
than a code one.

Add `src/envelope/advisory.rs` to `SPAWN_ALLOWLIST` in `tests/spawn_seam_guard.rs` in this same
commit, with a one-line justification in the existing style ending "No agent."

Create `tests/envelope_advisory.rs` with fixtures that need no network:
  - a repository whose remote is a `file://` URL probes to `Unknown` with the non-GitHub reason;
  - a repository with no remote at all probes to `Unknown` with that reason;
  - `ProtectionState::Unknown` renders with its reason visible and does not render the protected
    wording — a behavior assertion over the rendered string.
  </action>

| probe → run journal and preview | A single claim text reaches two rendering surfaces |
