<objective>
Attach the envelope to the spawn seam and make every refusal observable from disk rather than from
prose: the tool denylist and the settings path on argv (D-06 layer 1, D-07), the envelope
environment in the one place the child's environment is built (D-09, D-16), envelope establishment
at the single `ExecutionOptions` construction site, a positioned refusal in the ordered chain, and
`JournalEvent::Parked`'s first emission (D-24, D-25).

Purpose: everything the previous six plans built is inert until it reaches the child. This is the
plan where the envelope stops being a module and starts being a boundary — and it is also where
the phase's carried-in constraints (D-28) are most easily broken, because it touches four of the
five files those constraints name.

Output: a driven run that cannot be started without an envelope, cannot reach the user's ambient
git identity, and leaves a park reason on disk when the envelope refuses.

Reversibility note: D-06, D-24, D-25 and D-28 are locked decisions in `19-CONTEXT.md`, and D-25 is
a `[USER-HARD-REQUIREMENT]`. Ratings are recorded on the tasks; no `checkpoint:decision` is
inserted.
</objective>

`advisory::probe_protection` **once** and append `advisory::envelope_notice(&state)` into the run

come from one producer.

Every one of those calls is synchronous file and process work on an `async fn` path. Wrap them in
`tokio::task::spawn_blocking` following the shape `src/driver/mod.rs`'s dry-run arm establishes —

deadlock this discipline prevents was observed, not theorised: a blocking advisory lock inside an
`async fn` defeated a timeout outright on a current-thread runtime.

rather than proceeding with a partial envelope. Handle `journal::run_paths`' `Option` at every new
call site rather than unwrapping — that signature is the whole of the path-traversal fix and it
exists to conscript the compiler into enumerating callers.

already explains why inherited agent variables are scrubbed; the envelope extends the identical

test can assert on them without spawning.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driver → driven child process | argv and environment are the only carriers of policy across the spawn |
| envelope establishment → run start | A partially-established envelope would leave a run running with some layers absent |
