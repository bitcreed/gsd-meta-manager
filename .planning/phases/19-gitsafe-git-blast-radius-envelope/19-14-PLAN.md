## What this plan is, and what it deliberately leaves red

measured rows. The two it cannot reach are the ones where the flush lands in a wrapper prefix

```
C=GIT_CONFIG; env -u ${C}_COUNT git fetch origin   ->  env -u $ | C | _COUNT git fetch origin
K=GIT_SSH;    env -u ${K}_COMMAND git fetch origin ->  env -u $ | K | _COMMAND git fetch origin
```

The last fragment resolves `git` behind a clean one-word prefix and its verb is the literal
`fetch`. No verb-slot rule can see it, because by then the shape is gone. **Those two rows are
written here, observed red here, and left red.** `19-15` closes them positionally, by recording
which boundaries severed a word — with `SEPARATORS` untouched there too.

Rule B would be a rule nobody had shown was needed. If this plan closed them, nobody could tell
which mechanism did it. Three rounds of this phase have been certified by corpora that could not
fail on their own class; separating the two rules is how this one avoids being the fourth.

## The design question, answered

**Option (a) — thread the expansion bit through to the classifiers' decision region — is chosen.
Option (b) — refuse any expansion-carrying token anywhere in a governed segment — is rejected.**

(b) is rejected on a cost, not on taste. It refuses `git commit -m "use ${HOME} here"` and
`gh pr create --title "fix $PATH handling"`, which are ordinary commands this project types and
which this round's scope names as must-keep-working. That is `T-19-75` widened from `rg` to every
commit: a control that fails into unusability gets switched off (AR-19-11).

(a) is implemented as a **decision region**, and the region is exactly **the words the matched arm
reads** — no wider, no narrower. Every index in it is reported by the scan the classifier itself
runs, so it cannot drift one slot from the words that decide:

- **git — the VERB**, at the absolute index `classify_git` slices to, plus, when that verb is
  `config`, the one operand `classify_config` tests with `is_hooks_path_key`. The tokens
  `scan_leading` WALKS are deliberately *not* in the region: `leading_git_option` consumes a `-c`
  option and its assignment token, so a region defined that way would refuse
  `git -c user.name="$NAME" commit -m x`. Those options are governed by the key-half check
  instead, which matches the only decision that scan makes.
- **forge — the first TWO non-flag subcommand words**, because `pr_command_label` matches on
  `["pr", "create", ..]` and `["mr", "create", ..]`. One word leaves
  `P=create; gh pr $P --title x` unmatched, uncounted and unparked. All of `subcommand_words` is
  wrong the other way: it pulls `--title`'s value in and refuses a title carrying a `$`.
- **forge, `api` arm — additionally** the `-X` / `--method` value in both spellings, and the
  tokens whose **flag-ness** the arm decides on. `gh_api_posts_a_pull_request` sets `implies_post`
  by whole-token membership in `GH_API_IMPLIES_POST` (`policy.rs:1845`), so an unreadable token
  yields `posts == false` and the pull request opens with no refusal and no ledger line. A
  decision word is therefore a token that **begins with an expansion marker** —
  `F=-f; gh api repos/o/r/pulls $F title=x` — **or begins with `-` and carries an expansion before
  its first `=`** — `F=f; gh api repos/o/r/pulls -$F title=x` and its `-${F}` spelling, the same
  hole one character to the left. The second clause is the same key-half readability test the
  `git -c` check applies, and it leaves `-f title="$T"` alone: `-f` has a readable key half, and
  `title="$T"` neither begins with `-` nor with a marker.

Everything to the right is an OPERAND and stays free. That boundary is the whole of (a)'s cost
containment, and it is pinned from both sides rather than asserted:

```
refused:  V=push; git $V --force origin main       permitted: git commit -m "use ${HOME} here"
refused:  git ${V}push --force origin main         permitted: git commit -m "$MSG"
refused:  P=pr; gh $P create --title x             permitted: gh pr create --title 'fix $PATH handling'
refused:  P=create; gh pr $P --title x             permitted: gh pr create --title "$MSG"
refused:  gh api /repos/o/r/$P -X POST -f title=x  permitted: gh api repos/o/r/pulls -f title="$T"
refused:  F=f; gh api repos/o/r/pulls -$F title=x  permitted: git -c user.name="$NAME" commit -m x
refused:  git -c $K commit -m x                    permitted: git config user.email "$EMAIL"
refused:  git config $K /tmp/x                     permitted: echo $(git rev-parse HEAD), cd "$HOME"
```
