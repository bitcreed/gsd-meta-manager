## The design question, answered

**Option (a) — thread the expansion bit through to the classifiers' decision region — is chosen.
Option (b) — refuse any expansion-carrying token anywhere in a governed segment — is rejected.**

(b) is rejected on a cost, not on taste. It refuses `git commit -m "use ${HOME} here"` and
`gh pr create --title "fix $PATH handling"`, which are ordinary commands this project types and
which this round's scope names as must-keep-working. That is `T-19-75` widened from `rg` to every
commit: a control that fails into unusability gets switched off, which is the failure mode
AR-19-11 exists to record.

(a) is implemented as a **decision region** rather than as one hard-coded index, and the region is
computed by the classifiers' OWN scanners:

- git: the tokens `scan_leading` walks — the leading `-c` / `--config-env` options — plus the verb
  it stops at, at absolute segment index `governed + 1 + scan_leading_index`;
- forge: the tokens the subcommand scan walks plus the first non-flag subcommand word
  `pr_command_label` reads its arm from.

Everything to the right of the verb is an OPERAND and stays free. That boundary is the whole of
(a)'s cost containment, and it is pinned from both sides rather than asserted:

```
refused:   V=push; git $V --force origin main        permitted: git commit -m "use ${HOME} here"
refused:   git ${V}push --force origin main          permitted: git commit -m "$MSG"
refused:   P=pr; gh $P create --title x              permitted: gh pr create --title 'fix $PATH handling'
refused:   gh `true`pr create --title x              permitted: gh pr create --title "fix $PATH handling"
refused:   git -c $K commit -m x                     permitted: git -c user.name="$NAME" commit -m x
                                                     permitted: echo $(git rev-parse HEAD), cd "$HOME"
```
