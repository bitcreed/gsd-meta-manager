## Why this is not a sixth enumeration

Rounds 1–3 enumerated the ways a shell ASSEMBLES a word and guarded each. Round 4 inverted: a decision
word must be provably LITERAL, evidenced positively while the word is consumed. Audit 5's verdict on
that inversion, in its own words:

> The inversion is genuine, and it is the first control in this phase that is not an enumeration of
> shell syntax. … Audit 5 enumerated bash's word expansions one at a time against the bit's trigger
> set and clause 2 and found **no gap in word ASSEMBLY**. … **And the class is still open, because
> word assembly was never the whole class.**

## The production, and the fail-closed residue that keeps it from being an enumeration

```
[ IO_NUMBER | {varname} ]  OPERATOR  WORD          both operator and target DELETED
OPERATOR ∈ { < > >> <> >| <& >& &> &>> << <<- <<< }
IO_NUMBER = a DIGITS-ONLY run since the start of the word, and nothing else
```

**The control is the invariant, not the list.** Any unquoted `<` or `>` the parser cannot resolve into
a complete (operator, target) pair makes the simple command **UNRESOLVABLE** and refuses it through
the same exhaustive post-filter clause 2 already uses — so a spelling nobody enumerated fails closed
rather than falling through as an ordinary word.

## Three shapes the parser must get right, each a different mechanism

```
git &>/tmp/o push --force origin main     bash: [push][--force][origin][main]   exit 0 TODAY
git push>/dev/null --force origin main    bash: [push][--force][origin][main]   exit 0 TODAY
git x2>/tmp/o push --force origin main    bash: [x2][push][--force][origin][main]  exit 0 TODAY — and it STAYS exit 0
```

1. **`&>` must be recognised BEFORE `&` reaches the separator arm.** `&` is in `SEPARATORS`, so today
   the guard splits ONE simple command into TWO and a parser running after that arm never sees it.
2. **An attached operator terminates the word before it** — the operator need not be its own word, and
   `push` survives as a word.
3. **The IO_NUMBER prefix is digits-only since the word start.** `x2` IS argv. A parser that deleted
   any word part before a `>` would delete a real argv word and displace every decision word LEFT.
   `git x2>/tmp/o push --force origin main` is this axis's `ls {git,svn}-repo` — permitted today,
   permitted after, and the row that tells a deletion MODEL apart from over-deletion.
