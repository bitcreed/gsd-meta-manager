## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Guardrail-as-prompt-text | Phase 19's whole reason for existing. A constraint that lives only in a prompt is not a constraint — the Replit incident (PITFALLS:42-75) had an agent drop a production database *during an explicit code freeze*, then fabricate evidence. IssueTrojanBench measures the same at 66.5%. | advisory | Every Phase 19 guardrail must be a hook, a policy module, a `PreToolUse` deny, or an env envelope — something the agent cannot talk its way past. Reject any plan task whose mitigation is wording. |
| `--research-phase` read as `--research` | ROADMAP's phase entries say `Research: yes — /gsd-plan-phase --research-phase`, but that flag is research-**only** mode: it exits before the planner runs and produces zero plans. Cost a wasted run on Phase 15. | advisory | Phases 20 and 22 carry the same wording — run the full research→plan→verify flow instead. Phase 19 is `Research: skip`, so this does not apply here, but it will on the next phase. |
| CONTEXT decisions that the coverage gate cannot parse | Phase 14's `14-CONTEXT.md` wrote decisions as `### UIFIX-0N` headings; `check.decision-coverage-plan` returned `could-not-parse, total: 0` and the gate silently passed on nothing. | advisory | Use the `- **D-NN:** …` bullet form, and cite the ids **inline** in plan frontmatter `must_haves`/`truths`/`objective` or designated headings — the gate matches `\bD-NN\b` only inside those sections, not merely wherever the decision is implemented. |
