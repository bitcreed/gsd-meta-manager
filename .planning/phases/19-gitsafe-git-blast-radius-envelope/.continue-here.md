<context>
The phase is a policy/guardrail phase: it makes the user's FULL-autonomy bargain (driven `git push`
and PR creation with no human in the loop) mechanically safe rather than rhetorically safe. Waves
are strictly serial — eight waves, one plan each, each depending on all prior — so there is no
parallel fan-out to reason about, only a chain.

The orchestration cycle per wave is: capture `EXPECTED_BASE`, create a fresh `/tmp` wave manifest,
dispatch one `gsd-executor` with `isolation="worktree"`, record the returned worktree via
`worktree.record-agent`, merge with `worktree.cleanup-wave`, run the post-merge build+test gate,
run the `execute:wave:post` gates, then `roadmap.update-plan-progress` plus a tracking commit.
Wave 3 stopped at the post-merge gate.

The interesting thing about the failure is that it is exactly what the post-merge gate exists to
catch, and exactly what the executor's own Self-Check could not: three agents each reported green
in isolation and the merged tree is red. Resist the pull to re-run it until it passes.
</context>
