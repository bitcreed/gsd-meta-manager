## The design question, ANSWERED — and the answer is not a list of characters

`lexical_absolute_components` reads a word and asks whether it starts with `/`. The obvious fix is to
split at the first `=` and test the tail. **That fix is one character short in exactly the way the current
one is.**

| Candidate boundary | Reaches | Misses |
|---|---|---|
| split at the FIRST `=` | `of=/p`, `--git-dir=/p` | `--opt=a=/p` (a second `=`); `-C/p`, `-t/p`, `-f/p` (attached SHORT options, no `=` at all); `host:/p` (a `:`) |
| split at EVERY `=` | the above plus `--opt=a=/p` | the attached short options and the `:` |
| a LIST of attachment characters `= : , @` | most spellings | whatever character the next program uses — **and it is a PROGRAM-GRAMMAR ENUMERATION, which is D-08's defect one level over** |
| **`/`-ANCHORED SUBSTRINGS of a LITERAL word** | **all of the above, and every attachment character that exists, and none** | only what the four existing conditions already exclude |

**The mandated boundary, stated exactly.** For a word `w` that passes the existing `Token.literal` filter,
every byte index `i` with `w.as_bytes()[i] == b'/'` yields a candidate `&w[i..]`. Each candidate goes
through the EXISTING `lexical_absolute_components` normaliser and the EXISTING two comparisons —
`word_is_within` (component-wise PREFIX over the envelope directory) and `word_is_exactly` (EQUALITY
against the guard's own binary). **`i == 0` is today's rule, so the new candidate set CONTAINS the old one
and no refusal that exists today can be lost.**

**So the three answers the round owes:**

1. **Which characters can attach a path?** **All of them, and the rule never asks.** It reads the word's
   text and finds absolute paths in it; what precedes a `/` is not a question the predicate is capable of
   asking. That is what stops the boundary being one character short a thirteenth time.
2. **Can a path appear after more than one?** **Yes, and it is reached** — `--opt=a=/p`, `-o=x:/p`,
   `a=b=c=/p` all yield the same candidate.
3. **What does an ordinary command containing `=` and a slash cost?** **Nothing, and the reason is
   structural rather than lucky.** The cost is bounded by the PATH SET, not by the split: a candidate is
   refused only if it prefixes a directory of at least three components rooted at `<root>/<alias>`, or
   equals a full binary path. `word_is_within` returns early on `word.len() < dir.len()`, so a short
   suffix cannot match a deep directory at all.

```
--author=A <a@b.c>                 no `/` in the word              -> no candidate
--format=%H                        no `/`                          -> no candidate
sed s/x/y/                         [x, y], [y], []                 -> shorter than any envelope dir
https://github.com/o/r             [github.com, o, r], [o, r], [r] -> wrong first component
git push origin HEAD:refs/heads/gsd-auto/alpha/w
                                   [heads, gsd-auto, alpha, w], …  -> wrong first component
git --git-dir=/tmp/g status        [tmp, g]                        -> not under <root>/<alias>
FOO=/tmp/x cmd                     [tmp, x]                        -> not protected: PERMITTED
```

**And the ONE real over-refusal, stated rather than discovered.** A RELATIVE word that textually contains
the carrier path — `./tmp/x/alpha/pr-ledger.ndjson` when the envelope directory is `/tmp/x/alpha` — is
refused although the shell reaches a different file. It fails CLOSED, it is bounded to a word naming this
run's own directory, and it is MEASURED and RECORDED here at its verdict rather than left to be met. It is
the same family as the already-disclosed cost that `cat <ledger>` is refused.
