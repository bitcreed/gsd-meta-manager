# Phase 37 — UI Design Contract

> Visual and interaction contract for the Owner inbox screen, the three owner actions (run, acknowledge,
> copy) and their popups, status copy, help overlay rows and README. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.

**Medium.** Rust ratatui 0.30 terminal UI, not a web UI. Pixels become terminal cells, fonts become
`Modifier`s and glyphs, hex colors become the ANSI colors the codebase already uses. "Owner" means the
human running the projects.

**Provenance tags.** Unmarked statements are locked by `37-CONTEXT.md` (D-01..D-23), by the approved
`36-UI-SPEC.md`, or are verified facts about the existing code (file:line cited). `(inferred)` marks a
choice this spec made that CONTEXT left open, with its source. `(inferred; CONTEXT discretion)` marks a
choice CONTEXT explicitly delegated (column widths and breakpoints, the `o` mechanism, module split).
This run was unattended: no question was asked, every open point was decided from CONTEXT, the report
(`.planning/research/OWNER-INBOX-UX.md` section 3.3/3.4 mockups) and the code.

**Scope.** `InboxScreen` (header, sections, rows, expansion, folds, footer, empty/loading states), the
acknowledge confirm popup, the status-line copy of `v` `A` `y` `o`, the Owner-block key bindings of D-21
(no layout change), help overlay rows, README section. **Not in scope and frozen:** the Phase 36 dashboard
`You` cell, the `You:` summary line, the Owner block layout/footer (36 human UAT is pending on it; the
only change there is that four formerly swallowed keys now act), `❢`/`needs_human` (D1), per-item pass/fail
entry, a native acknowledge writer, todo triage UI, notifications.

## Spacing Scale

Units are terminal cells (columns) and rows; there is no pixel scale and no 4-multiple rule applies. Width
is always `Line::width()`, never `len()`. "Width W" is the outer terminal area width passed to `render`.

### Screen geometry (D-02)

The screen is borderless and fills the whole area (the mockup is borderless; a border would cost 2
columns at 80x24).

| Row | Height | Content |
|-----|--------|---------|
| Header | 1 | `Owner inbox ── …` left, lane keys right |
| Spacer | 1 | blank (always, as in the mockup) |
| Body | `H - 5` with the fold line, `H - 4` without | Section titles, group rows, expansion lines, rows of open folds. Scrolls |
| Rule | 1 | full-width DIM `─` run. Always drawn; carries the scroll hint at its right end (inferred; the mockup's two-cell `──` becomes a full rule so the pinned region reads as separate) |
| Fold line | 0 or 1 | pinned; omitted when no fold has content (D-19 carried) |
| Footer | 1 | key hints, replaced by the status message while one is live |

Vertical layout: `[Length(1) header][Length(1) spacer][Min(0) body][Length(1) rule][Length(1) fold line (0 when none)][Length(1) footer]`.
At `H < 7` the spacer is dropped, then the fold line (inferred; never panic, `Layout` already clamps).
Horizontal: one cell left margin for section titles, the header and the fold line (column 0 of a group row
is the cursor, see grid); no right margin.

### Row grid (D-04; breakpoints inferred; CONTEXT discretion)

One group row, left to right. Columns are separated by 2 spaces unless noted. Widths are computed per frame
over **every current-scope row of every lane plus the rows of any open fold**, not over the active filter, so
pressing `1`-`4`/`a` or expanding a group never reflows the columns (inferred).

| # | Column | Width (cells) | Content | Rows that have it |
|---|--------|---------------|---------|-------------------|
| 0 | Cursor | 1 | `>` on the cursor row, else a space | all |
| 1 | Marker | 1 | `▸` collapsed, `▾` expanded | all |
| 2 | Space | 1 | | all |
| 3 | Alias | clamp(longest, 8, 18) | `shown(alias)` | all |
| 4 | Phase cell | clamp(longest, 5, 18) | optional Magenta `ws <name> ` prefix, then `ph 24`, `debug`, `handoff`, `checkpoint`. Same `phase_cell` truncation as 36 (the ws name gives way first, the phase number last) | all |
| 5 | Name | flex, natural = longest, cap 32, floor 8 | TEST/DECIDE/FIX: group name (session name for debug); BLOCKED: the tally (`2 device · 1 third party`) which spills over the columns to its right | all |
| 6 | Checks | 9, right-aligned | `6 checks`, `1 check` | TEST and FIX groups with counted checks; blank otherwise; never on BLOCKED |
| 7 | Phrase | clamp(longest, 12, 32); 0 when no visible-set row has one | see Copywriting | DECIDE and FIX always; TEST only in the "phase stays open" section (`+ fix 2`, `+ unblock 1`) and for bookkeeping-only groups (`all checks passed, run {command} to finalize`, which spills over the age and command columns like the Owner block, ladder `all checks passed`) |
| 8 | Age | 11 | `2 d`, `203 d stale` (`stale` Yellow) | all that carry `age_days`; BLOCKED blank |
| 9 | Command | remaining, truncated, floor 12 | `/gsd-plan-phase 16 --gaps` | **FIX rows only** (D-04; TEST and DECIDE are run with `v`, their command shows in the expansion and the status line) |

The phrase ceiling is 32, not 36's 30 (inferred): the widest standard phrases are
`paused · 1 human action pending` (31) and `1 open question in 07-CONTEXT.md` (32), and the mockup shows
the first whole.

**Narrowing order** (D-04 "command dropped before the name is truncated", 36 D-17 order):

1. The Command column is shown only when it fits **without squeezing any other column** (natural widths of
   columns 0-8 plus 2 plus the command's natural width, capped at 44). Otherwise dropped.
2. The Age column is shown iff `W >= 80`.
3. If the rest still exceeds `W`: Phrase shrinks toward 12, then Phase cell toward 5, then Alias toward 8.
4. Name truncates (`…`) last, floor 8.
5. Below that every row is cut with `fit_cells`/`fit_spans` at `W`; no panic at any area size, including
   0x0 and 1x1.

`Alias` truncates only at step 3 (fixture aliases are 9 cells or fewer so the 80-column snapshot truncates
phrases, not aliases).

Worked widths for the fixture (below): natural widths `3 + 9 + 2 + 7 + 2 + 18 + 2 + 9 + 2 + 32 + 2 + 11 = 99`
cells; Command natural 25, so it shows from `W >= 126`.

| W | Age | Command | Phrase | Name | Result |
|---|-----|---------|--------|------|--------|
| 140 | yes | yes (25) | 32 | 18 | everything whole |
| 120 | yes | no (99 + 2 + 25 = 126 > 120) | 32 | 18 | everything whole except FIX commands |
| 100 | yes | no | 32 | 18 | everything whole (99 <= 100); no `…` anywhere (SC2 legibility) |
| 80 | yes | no | 13 | 18 | phrases cut to 13 cells (`paused · 1 h…`), name whole |
| 79 | no | no | 13 -> shrinks as needed | 18 | age gone; then phrase to 12 |

First rung that fits `W`; two leading spaces:

| # | Copy | Width |
|---|------|-------|
| 1 | `[j/k]move  [Enter]expand  [g]o to project  [v]run command  [o]pen file  [A]cknowledge  [y]copy checklist  [Esc]back  [?]help` | 126 |

### Scroll rules (D-06, D-10)

- Whole-row viewport; the cursor row is always in view. When the cursor is the first row of a section, the
  section title row scrolls into view with it (inferred).
- `PgUp`/`PgDn` move by the body height minus 1 (inferred); `Home`/`End` jump to the first/last stop.
- Hint when body rows are clipped: DIM ` {first}-{last} of {total}` at the right end of the rule row (rows
  of the body, 1-based, titles and expansion lines included). None when nothing is clipped.

## Typography

No sizes exist; roles are `Modifier`s and glyph classes. Modifiers used: `BOLD`, `DIM`, `REVERSED` (new
here, one use, justified below). Colors used: `Cyan`, `Yellow`, `Magenta`. No `ITALIC`, no `UNDERLINED`.

| Role | Style | Used for |
|------|-------|----------|
| Body | default fg, no modifier | alias, phase text, group name, checks, phrase, item lines, header numbers, fold text |
| Label / emphasis | `Modifier::BOLD` | `Owner inbox`, section titles (`TEST — closes a phase`, `DECIDE`, `FIX — code needed`), the `[key]` tokens in header and footer, popup field labels |
| Muted | `Modifier::DIM` (`muted_style()`) | age, expansion detail/gap/`file`/`run` lines, `… N more`, rule, column heads (`checks`, `age`), scroll hint, `· {M} loading`, the BLOCKED section title and rows, whole Acknowledged rows, the Triage fold, empty-state hint text, the argv line in the popup |
| Cursor | `Color::Cyan` + `BOLD` over the whole row (fg replaced, DIM removed) | the one cursor row (always present while any stop exists; no focus levels on this screen) |
| Active lane key | `Modifier::REVERSED` on the one `[n]Name` token | only when the filter is not the default (D-03 "defaults are silent") |

Why `REVERSED` here (inferred): the active lane key is the same "which choice is active" cue as the tab
bar's active tab and the popup's focused button (`confirm_popup.rs` `REVERSED | BOLD`). 36 forbade it for the
Owner block because nothing there was a choice among peers. It is not used on any row.

Glyphs (one source each, none new to the registry):

| Glyph | Code point | Source | Used for |
|-------|-----------|--------|----------|
| `▸` / `▾` | U+25B8 / U+25BE | `glyphs::TRIANGLE_RIGHT_SMALL` / `TRIANGLE_DOWN_SMALL` | group row marker and fold marker, collapsed / expanded |
| `──` / `─` | U+2500 | STRUCTURAL range | header `Owner inbox ──`, the rule row |
| `—` | U+2014 | TYPOGRAPHY set | section titles `TEST — closes a phase` (locked by D-02; East-Asian-Ambiguous but never inside a table cell, so it cannot shift columns) |
| `·` | U+00B7 | TYPOGRAPHY set via the existing `OWNER_SEP` | header clause separator, phrase separators (`paused · 1 human action pending`) |
| `…` | U+2026 | TYPOGRAPHY set | truncation, `… N more` |
| `←` `→` | | TYPOGRAPHY set | footer `[←/→]fold` |

Ambiguous-width risk (carried from 36, not re-opened): `·` in the header and in the Phrase column is
East-Asian-Ambiguous. The phrase column is the last text column before Age, so an ambiguous-wide terminal
shifts only Age and Command, never the checks column; recorded for UAT item 1.

## Color

Ground rule from the report and 36: **quiet.** Meaning is always in the text, never in color alone. Every
color below is an existing color on an existing role.

| Role | Value (ANSI) | Existing site | Usage in this phase |
|------|--------------|---------------|---------------------|
| Dominant (default text) | `Color::Reset` | n/a | everything not listed below |
| Secondary (muted) | `Modifier::DIM` | `driver.rs:120` | see Typography "Muted" |
| Accent: cursor | `Color::Cyan` + `BOLD` | Owner block cursor row (36), Phases list `detail.rs:7568-7573` | ONLY the cursor row |
| Accent: warn | `Color::Yellow` | 36 `stale` | ONLY the word `stale` in an Age cell (not on the cursor row, where Cyan wins; the word is still there) |
| Accent: workstream cue | `Color::Magenta` | 36 `ws` prefix | ONLY the `ws <name> ` prefix (not on the cursor row) |
| Accent: confirm | `Color::Yellow` | `driver_launch.rs:1085` launch confirm | ONLY the A popup border, title and focused button |
| Destructive / error | `Color::Red` | | **not used** by any inbox element. A failed acknowledge, a refusal, a launch failure are default-color status text (a refusal is not a hard stop, and Red stays reserved for them as in 36) |
| Green | | | **not used** (36's `closes phase` Green is a row phrase that the inbox replaces with the section title) |

Accent reserved for (explicit list):
1. The cursor row: Cyan + BOLD.
2. `stale` on a non-cursor Age cell: Yellow.
3. The `ws <name> ` prefix on a non-cursor workstream row: Magenta.
4. The `A` confirm popup frame: Yellow (via `render_confirm_popup`'s `accent`).
5. The active lane key in the header: `REVERSED` (a modifier, not a color).

Nothing else takes a color. Color-independent meaning check: every state has a word (`stale`, section
titles, `>` cursor mark, `▸`/`▾`, the `[2]Decide` bracketed key); removing all color and `REVERSED` leaves
every distinction intact except the active-lane highlight, which is also announced in the empty state copy
and by which sections are listed. When the screen sits under the popup, `dim_background` dims everything
(existing).

| Line | Copy | Shown when |

### Folds (D-02, D-09, D-19)

### Selection identity and live refresh (D-10)

The screen reads `ctx.owner_digests` (the 36 D-02 map; the planner's name) on every render and parses,
stats and spawns nothing on the render path (`async_blocking_guard`). Selection is the identity (alias, scope,
workstream, phase or slug, kind, file) plus the sub-cursor fold; expansion state is a set of identities. When
a `ProjectStateLoaded` makes a group vanish (a UAT flipped to `pass`, or an acknowledged file), the row
disappears on the next frame, and selection falls to the next row, else the previous, else the fold line, else
none. A vanished expanded group is dropped from the set. The cursor and scroll clamp after every refresh; an
empty stop list is valid and never panics. Digests arrive per project, so rows may appear one project at a
time while loading (the header shows ` · {M} loading`).

### Acknowledge flow (D-14..D-16)

1. `A` validates. Refusals are status lines, no popup.
2. Popup, default No. `y`/Enter-on-Yes confirm, `n`/Esc/Enter-on-No cancel (no message).
3. On Yes: re-resolve the group by identity (gone: `Group is no longer listed...`), mark the file busy,
   status `Acknowledging {file} via gsd-core...`, spawn the bounded child (10 s budget, cwd project path).
4. The result `Action` sets the status line (done / failed / timed out) and clears busy. The row disappears
   by itself on the next watcher refresh (D-10); there is no manual reload.

Because messages expire after 3 s, a failure copy cut to one line is all the owner sees on screen; the full
capped output is in the tracing log `~/.local/share/gsd-meta-manager/gsd-meta-manager.log`. This is a known
limitation of the single status channel (inferred risk; a longer-lived result line is out of scope).

### Owner block keys (D-21; layout unchanged)

group row through the same shared action functions: same refusals, same popup, same status copy. The block's
