# Phase 36 — UI Design Contract

> Visual and interaction contract for the Owner inbox dashboard and detail surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Medium.** This is a Rust ratatui 0.30 terminal UI, not a web UI. Every web-template section is
translated: pixels become terminal cells, fonts become `Modifier`s and glyphs, hex colors become the
ANSI colors the codebase already uses. "Owner" means the human running the projects (the user).

**Provenance tags.** Unmarked statements are locked by `36-CONTEXT.md` (D-01..D-23) or are verified
facts about the existing code (file:line cited). `(inferred)` marks a choice this spec made that
CONTEXT left open, with its source. `(inferred; CONTEXT discretion)` marks a choice CONTEXT
explicitly delegated.

**Scope.** Dashboard `You` column, `You:` summary line, `has owner work` sort rank, `/y [lane]`
filter, detail Phases-tab Owner block, help overlay rows, README section. Not in scope: the inbox
screen, `v`/`o`/`A`/`y` actions, any change to the `❢` badge or `needs_human` (D1).

## Spacing Scale

Units are terminal cells (columns) and rows. There is no pixel scale. Display width is always
measured with `Line::width()`, never `len()`.

### Dashboard width tiers (OWN-16, D-05)

`terminal_width` is the outer area width (borders included), as in `dashboard_columns`
(`normal.rs:439`). Tiers `80..99`, `60..79`, `<60` are byte-identical to today.

| Outer width | Header cells | Constraints | Notes |
|-------------|--------------|-------------|-------|
| `>= 100` (NEW) | `Alias, Phase, Status, You, Progress, Backlog` | `Percentage(20)`, `Percentage(26)`, `Min(13)`, `Length(21)`, `Percentage(12)`, `Percentage(9)` | `YOU_COLUMN_CELLS = 21` as one named constant. The Status column index stays 2 (`DASHBOARD_STATUS_COLUMN`) |
| `80..99` | `Alias, Phase, Status, Progress, Backlog` | unchanged (25/30/Min 13/15/15) | no `You` column, no summary line |
| `60..79` | `Alias, Phase, Status, Progress` | unchanged | |
| `< 60` | `Alias, Phase, Status` | unchanged | |

Resolved column widths for the `>= 100` tier, measured with the same layout `status_column_cells`
runs (ratatui 0.30.2 `Layout::horizontal`, `Flex::Start`, spacing 1, inner width = outer − 2 border −
2 highlight symbol). Verified by probe 2026-11-14; the planner re-asserts them in a unit test:

| Outer | Alias | Phase | Status | You | Progress | Backlog |
|-------|-------|-------|--------|-----|----------|---------|
| 100 | 18 | 19 | 13 | 21 | 11 | 9 |
| 120 | 23 | 30 | 13 | 21 | 14 | 10 |
| 140 | 27 | 36 | 18 | 21 | 17 | 12 |
| 160 | 31 | 41 | 25 | 21 | 19 | 14 |
| 200 | 39 | 51 | 39 | 21 | 23 | 18 |

Why these numbers (verified against existing tests, not a free choice):
- The Status column must be exactly 13 at width 120 (and 100). `the_agent_summary_is_a_whole_ladder_form_at_every_width` asserts the form `w2/11 13run` at 80 and 120, and the next-wider form is 14 cells. Wider Status at 120 would break an existing test.
- Status must be at least 22 at width 200: `the_fixer_estimate_is_a_whole_ladder_form_at_80_120_and_200` expects the 22-cell `3 fixers ∙ ~5/48 fixed` there. Probe: 39.
- `status_column_cells_matches_the_rendered_status_column` iterates widths 50, 60, 80, 100, 120, 160, 200 and must stay green.
- Progress is 11 cells at width 100 (same as today's 80 tier, where `13/18 phases` already clips by one cell). Accepted (inferred; CONTEXT discretion, D-05). Phase is 19 cells at width 100, so a 20+ cell phase label clips at exactly 100 columns; UAT item 2 looks at this.

If the planner prefers another vector, it must keep: Status `Min(13)` floor, Status = 13 at widths 100 and 120, Status ≥ 22 at 200, `You` = 21 fixed.

### `You` cell (D-05..D-09)

- Fixed 21 cells. Widest normal forms: `decide 99 · fix 99 ph` (21), `decide 99 · test 99` (19), `test 99 → closes 99` (19).
- One line only. Workstream continuation lines of a project row leave the `You` cell blank (the counts already include every scope, D-22 carried).
- Fit rule: ladder, first whole form whose `Line::width() <= cells` wins (the `agent_summary_line` pattern). Ladder order: (1) lanes + ` → closes M` + ` (+N old)`, (2) lanes + ` → closes M`, (3) lanes without `→ closes`, (4) `fit_cells(lanes, cells)` with `…`. Lanes always win space over ` (+N old)` (D-08). Never clip a number mid-digit.
- Left-aligned, no padding, no leading space.

### Summary line `You:` (OWN-17, D-10)

- One row, full terminal width, no border, column 0 (same left edge as the existing footer's left text).
- Shown only when outer width `>= 100` **and** area height `>= 12` (inferred: keeps at least 8 inner table rows at the existing 12-row test height; below it the layout is the old one).
- Vertical layout at `>= 100` and height `>= 12`: `[Min(0) table block][Length(1) You line][Length(1) footer]`. Otherwise unchanged `[Min(0)][Length(1)]`.
- Left text and right `[i] inbox` share the row; minimum 2 cells between them. Right part is `Length(9)` (`[i] inbox`) right-aligned.
- Left text fit ladder (first that fits `width − 9 − 2`): (1) full, (2) without `K of N projects`, (3) without `(C close)`, (4) without ` in P phases`, (5) `fit_cells` with `…`. (inferred; same pattern as the Status cell ladder)

### Owner block geometry (OWN-19, D-15..D-19)

Block width `W` = the Phases tab content width (`area.width` of `render_pipeline_tab`). The block is
borderless: a header rule line, a body, and one pinned fold line. It is drawn above the existing
40/60 split, which receives the remaining area unchanged.

| Region | Rows | Notes |
|--------|------|-------|
| Header | 1 | `Owner ── …` (see Copywriting). Always the first row of the block; never scrolls |
| Body | 0..n | Group rows, their expanded item lines, then the rows of any open fold. Scrolls inside the block |
| Fold line | 0 or 1 | Pinned as the last row of the block when at least one fold has content. Open folds put their rows at the end of the body, above the fold line |

- Height = `1 + body_rows_shown + (1 if fold line)`.
- Cap: `max(4, floor(tab_height * 40 / 100))` rows (D-15 "about 40%"). Body scrolls when longer; the cursor row is always in view; the viewport changes by whole rows.
- Hidden entirely (zero rows, not focusable) when `tab_height < 12` (inferred: the 40/60 split needs the rows; the existing Phases tab keeps today's rendering).
- Zero rows when the project has no digest, or the digest has no current group **and** no fold has content (D-15). Existing Phases-tab tests build contexts with no digest, so they stay byte-identical (SC3 spirit).
- Overflow hint: when body rows are clipped, the header's right edge shows DIM ` {first}-{last} of {total}` (rows, 1-based, body rows only). No hint when nothing is clipped. (inferred; no up-arrow glyph exists in the registry)
- Rendered in the early-return branches of `render_pipeline_tab` too: if the project has owner rows but no phases (`No phases found`), the block still draws above that message (inferred: a project with only a debug session or handoff still has owner work). With no `ProjectState` at all there is no digest, so nothing draws.

### Owner block row grid (D-17; breakpoints inferred; CONTEXT discretion)

One group row, left to right. Columns are separated by 2 spaces unless noted. Variable widths are
computed per frame from the visible rows, then clamped.

| # | Column | Width (cells) | Content | Drops at |
|---|--------|---------------|---------|----------|
| 0 | Gutter | 2 | `> ` on the cursor row while the block has focus, else two spaces | never |
| 1 | Lane tag | 7 + 1 space | `TEST   `, `DECIDE `, `FIX    `, `BLOCKED` | never |
| 2 | Phase cell | clamp(longest, 5, 18) | `ph 24`, `debug`, `handoff`, optional `ws <name> ` prefix | never (truncate with `…`) |
| 3 | Name | flex, min 12 | `phase_name` (or the tally for BLOCKED) | never (truncated first) |
| 4 | Checks | 9, right-aligned | `6 checks`, `1 check`; blank for BLOCKED and bookkeeping-only | never |
| 5 | Status phrase | clamp(longest, 12, 30) | see Copywriting | never (truncated before the name goes under 12) |
| 6 | Age | 11 | `2 d`, `29 d stale` | `W < 80` |
| 7 | Command | rest, truncated | `/gsd-verify-work 24` | `W < 100` |

So: `W >= 100` shows every column, `80 <= W < 100` drops the command, `W < 80` also drops the age
(D-17 order: command, then age, before the name is truncated). BLOCKED rows show only columns 0-3
(the name cell carries the tally, as in the report mockup).

Indent of expanded content: item lines start at column 4 (2 past the gutter); detail lines at column 7;
the file line at column 4.

Header-line ladder at width `W`: (1) full, (2) each `(ph …)` list capped at 6 numbers followed by ` …`, (3) `(ph …)` lists dropped (counts only), (4) `not built` clause dropped, (5) `fit_cells` with `…`.

Fold-line ladder: (1) `▸ Old debt (N): <summary>   ▸ Acknowledged (N files)   ▸ Todos N (oldest D d)`, (2) drop `: <summary>`, (3) `▸ Old debt (N)   ▸ Acknowledged (N)   ▸ Todos N`, (4) `fit_cells`. Folds are separated by 3 spaces.

Exceptions to the "terminal cell" arithmetic: none. Every value above is an integer count of cells or rows.

## Typography

No sizes exist; the roles are `Modifier`s and glyph classes. Exactly three modifiers are used (`BOLD`, `DIM`, `UNDERLINED`), plus one foreground color (`Color::Cyan`) on the block cursor row; no
`ITALIC` and no `REVERSED` anywhere in this phase (REVERSED stays the tab bar's active-tab cue).

| Role | Style | Used for |
|------|-------|----------|
| Body | default foreground, no modifier | cell lane text, summary clauses, row names, item names, header body text |
| Label / emphasis | `Modifier::BOLD` | table header cells (existing, `normal.rs:652`), `You:` prefix, `Owner` in the block header, lane tags (`TEST`, `DECIDE`, `FIX`, `BLOCKED` except BLOCKED rows, which are DIM), `[i]` key token |
| Muted | `Modifier::DIM` on the default foreground (`muted_style()`), no fg color | the clean `·`, `(+N old)`, rule glyphs `──`, age, expanded detail lines (`expected:`, `why:`, `reason:`, `blocked by:`, `gap:`, `file`), whole BLOCKED rows, whole Acknowledged rows, the Todos fold, the overflow hint, `Loading...` |
| Selection | `Modifier::BOLD | UNDERLINED` on the dashboard row (existing `row_highlight_style`, `normal.rs:657`); `BOLD` + `Color::Cyan` on the block's cursor row (the Phases list idiom, `detail.rs:7568-7573`) | selected dashboard row; Owner block cursor row |

Glyphs (one source each; none new to the registry):

| Glyph | Code point | Source | Used for |
|-------|-----------|--------|----------|
| `·` | U+00B7 | TYPOGRAPHY set (`glyphs.rs:321`) | clause separator ` · `, the clean-project cell, `You: ·` (locked by D-07, D-08, D-10) |
| `→` | U+2192 | TYPOGRAPHY set | ` → closes M` (locked by D-07) |
| `…` | U+2026 | TYPOGRAPHY set | truncation (`fit_cells`), `… N more` |
| `—` | U+2014 | TYPOGRAPHY set | not used in new copy |
| `──` | U+2500 | STRUCTURAL range | the `Owner ──` header rule (existing idiom `driver.rs` `── name ───`) |
| `▸` / `▾` | U+25B8 / U+25BE | `glyphs::TRIANGLE_RIGHT_SMALL` / `TRIANGLE_DOWN_SMALL` | fold collapsed / expanded; group row collapsed / expanded marker (see below) |

Ambiguous-width risk, recorded not hidden: U+00B7 and U+2192 are East-Asian-Ambiguous. The registry
rule (`glyphs.rs:1-30`) and quick 261111-ixj moved the Status cell's separator off U+00B7 for exactly
this reason (a table cell must not hold an Ambiguous char, or an ambiguous-wide terminal shifts every
later column). CONTEXT locks `·` and `→` in the `You` cell, so this spec keeps them, and:
(a) builds the separator from ONE constant (`OWNER_SEP`) so a swap to U+2219 `∙` (`glyphs::BULLET_OPERATOR`, one cell, Neutral) is a one-line change; (b) measures with `Line::width()`; (c) makes this the first thing human UAT item 2 looks at (Progress/Backlog alignment). `→` has no registered Narrow replacement.

Group row markers (inferred; D-18): group rows carry no fold marker. The gutter is `> ` (cursor) or two spaces, and the lane tag leads, as in the report mockup. An expanded group is recognizable by the item lines directly beneath it. Only the three folds on the fold line use `▸` / `▾`.

## Color

Ground rule from the report (§3) and D-07: **quiet.** The owner cell and summary never use Red or
Yellow, and meaning is always in the text, never in color alone. Everything below is an existing
color applied to an existing role; no new color is introduced.

| Role | Value (ANSI) | Existing site | Usage in this phase |
|------|--------------|---------------|---------------------|
| Dominant (default text) | terminal default fg (`Color::Reset`) | n/a | every `You` cell, summary clause, row name, item name, header body |
| Secondary (muted) | `Modifier::DIM` on default fg | `driver.rs:102-121` | see Typography "Muted" |
| Accent: active/good | `Color::Green` | `category_color` Active, `normal.rs:65`; summary `active`, `normal.rs:1372` | ONLY the phrase `closes phase` in an Owner block TEST row |
| Accent: warn | `Color::Yellow` | `category_color` Idle `normal.rs:66`; `agent_summary_line` stalled `normal.rs:525` | ONLY the word `stale` in an Owner block age cell |
| Accent: cursor | `Color::Cyan` + BOLD | Phases list highlight `detail.rs:7568-7573`; sort indicator `normal.rs:1390` | ONLY the Owner block cursor row (while the block has focus) |
| Accent: workstream cue | `Color::Magenta` | `detail.rs:7554`, `normal.rs:604` | ONLY the `ws <name> ` prefix on a workstream group row |
| Destructive / error | `Color::Red` | `category_color` Blocked `normal.rs:67` | **not used** by any new element (D-07: never red/yellow in the cell; Red marks hard stops and `❢`) |

Accent reserved for (explicit list):
1. `closes phase` text on an Owner block TEST row: Green.
2. `stale` text on an Owner block age cell: Yellow.
3. The Owner block cursor row while `focus == Owner`: Cyan + BOLD.
4. The `ws <name> ` prefix on workstream group rows: Magenta.

Nothing else in this phase takes a color. In particular:
- **The `You` cell is `Color::Reset` explicitly**, set on every span (inferred, source D-07 "plain default-color text"). A `Row` carries `fg(row_color)` (`normal.rs:1221-1224`); the Progress and Backlog cells inherit it. A bare `Span::raw` in the `You` cell would inherit Green/Yellow/Red/DarkGray from the row (a red `missing` project, a yellow idle project) and break the quiet rule. The explicit Reset prevents that. The dim `·` and `(+N old)` are `Reset` + DIM.
- The `❢` badge, `needs_human`, `/h` and AttentionFirst rank 0 are untouched (D1).
- The summary line takes no color. `You:` is BOLD, `[i]` is BOLD, the rest default. The idle form `You: ·` is entirely DIM (D-10 "dim").
- When the tab bar has focus the whole content area is overlaid with `Color::DarkGray` fg (`detail.rs:6289-6293`); the Owner block inherits that like every other tab content. No special case.

Color-independent meaning check: every state has a word (`closes phase`, `stale`, `awaiting your confirmation`, lane tags, `old`). Removing all color leaves every distinction intact.

## Copywriting Contract

All strings are exact. US spelling. No singular "they" anywhere (README snippet refers to "you").
Project-authored fragments are shown here as `{braces}`; each goes through `shown()` and `fit_cells`.

### Dashboard `You` cell (D-06, D-07, D-08, D-09)

Lane order is fixed `decide`, `test`, `fix`; at most two lanes; `blocked` never appears; with three
lanes non-zero, `fix` is dropped.

| Element | Copy |
|---------|------|
| Column header | `You` |
| decide lane | `decide {N}` (N = `decide`) |
| test lane | `test {N}` (N = `test`); when `test` is the only lane shown and `closeable_phases` M > 0, append ` → closes {M}` |
| fix lane | `fix {N} ph` with N = `fix_phases` when `fix_debug` is 0; else `fix {N}` with N = `fix_phases + fix_debug` |
| Separator | ` · ` (one `OWNER_SEP` constant) |
| Old debt suffix | ` (+{N} old)`, DIM, N = `archived.test + archived.fix + archived.decide` (blocked excluded); shown only when the whole form still fits |
| Clean project | `·` (DIM). Includes blocked-only and archived-only-without-suffix cases; archived-only with N > 0 reads `· (+{N} old)` |
| No digest yet | empty cell (never `·`; absent data must not read as clean, D-09) |
| Unreadable files | already counted as Test work by the reader, so they appear as `test N` |

Worked rows, all 21 cells wide at widths 100, 120, 140 (see Snapshot-test expectations for the fixture):

| State | Cell |
|-------|------|
| test only, closeable | `test 10 → closes 4` |
| test only, nothing closeable | `test 4` |
| two lanes | `decide 1 · fix 2 ph`, `test 6 · fix 4 ph` |
| three lanes non-zero | `decide 2 · test 5` (fix dropped) |
| debug-only fix | `fix 2` |
| phases + debug fix | `fix 2` (1 phase + 1 debug) |
| lane + old debt | `decide 1 (+2 old)` |
| clean | `·` |
| archived only | `· (+3 old)` |
| blocked only | `·` |
| no digest | (blank) |

Known consequence of D-07 (recorded, not changed): a project with `decide` or `fix` work next to
closeable Test work shows no `→ closes M`, because the arrow only appears when `test` is the only
lane shown.

### Summary line (D-10, D-11)

Form: `You: test {T} in {P} phases ({C} close) · decide {D} · fix {F} phases · {K} of {N} projects` and, right-aligned, `[i] inbox`.

| Element | Copy |
|---------|------|
| Prefix | `You: ` (`You:` BOLD) |
| test clause | `test {T}` + ` in {P} phase(s)` when P > 0 + ` ({C} close)` when C > 0; omitted when T = 0. `1 phase`, `N phases` |
| decide clause | `decide {D}`; omitted when D = 0 |
| fix clause | `fix {F} phases` (`fix 1 phase`) when no visible project has `fix_debug`, else `fix {F}` (inferred; same rule as the cell, applied to the fleet) |
| projects clause | `{K} of {N} projects` (`{K} of 1 project` when N = 1). Always present when any clause above is |
| Separator | ` · ` |
| Pending digests | with M visible rows still missing a digest and any clause present: DIM ` · {M} loading` appended (inferred, source D-09 fail-safe) |
| Only pending | with every visible row missing a digest: `You: ` + DIM `Loading...` (same wording as `driver::DRY_RUN_LOADING`, inferred) |
| No owner work | `You: ·`, whole text DIM (D-10) |
| Right part | `[i]` BOLD + ` inbox` |

Definitions (D-11): T = Σ `test`, C = Σ `closeable_phases`, D = Σ `decide`, F = Σ per-project D-07 fix number, P = distinct (scope, phase) pairs with current Test groups, K = visible rows with `has owner work`, N = visible rows. "Visible" = `ctx.filtered_aliases` (current filter and sort). One shared function builds every per-project number; the cell and the summary both call it. The two-lane cap never hides a lane from the totals.

## Interaction Contract

### Dashboard keys (conflict check against `NormalScreen::handle_key`, `normal.rs:686-850`)

Bound today: `q j k a c d s M Enter b / G ? Tab`, `Up`, `Down`. Search mode (`/`) is handled
separately.

| Key | Action | Conflict |
|-----|--------|----------|
| `i` | sets the status message `Inbox screen not built yet: run gsd-meta-manager inbox in a terminal`; pushes no screen (D-12) | none: `i` is free on the dashboard |
| `s` | unchanged toggle; AttentionFirst now uses four ranks | none |
| `/` + `y` forms | see Filter grammar | none: `/y` is free next to `/n /p /s /h` |

No new key is bound in the dashboard search mode. `y` as a bare dashboard key is NOT bound
(reserved for Phase 37's copy).

### Sort (OWN-18, D-13)

`attention_rank(needs_human, driven_and_live, has_owner_work)` returns 0 needs a human, 1 has owner
work, 2 driven and live, 3 everything else. `has owner work = decide + test + fix_phases + fix_debug > 0` for the current milestone (blocked and archived excluded; same predicate that makes the cell non-`·`).
Alphabetical stays default; stable sort and alias-pinned selection unchanged. A project with no
digest ranks as no owner work. The owner-work rank does not depend on the experimental flag
(unlike rank 2). A digest-only change re-sorts and re-filters (D-02).

### Filter grammar (OWN-18, D-14)

Extends `app::parse_filter` suffixes (longest match first; case-sensitive like today):

| Typed (`filter_text`) | Meaning | `FilterColumn` |
|-----------------------|---------|----------------|
| `{term}/y` | term matches any column AND row has owner work | `OwnerWork(None)` |
| `{term}/y test` or `{term}/yt` | AND `test > 0` | `OwnerWork(Some(Test))` |
| `{term}/y decide` or `{term}/yd` | AND `decide > 0` | `OwnerWork(Some(Decide))` |
| `{term}/y fix` or `{term}/yf` | AND `fix_phases + fix_debug > 0` | `OwnerWork(Some(Fix))` |
| `{term}/y {other word}` | falls through to a plain `All` term (no error), like unknown suffixes today | `All` |

The short forms `/yt /yd /yf` are included (inferred; CONTEXT discretion): while typing `/y test` the
filter is a plain `All` term at `/y ` and `/y t…`, which empties the list until the word completes;
the one-letter forms avoid that flicker. `blocked` is not a lane here (D-14). `/h` is unchanged.
On screen the prompt supplies its own `/`, so the all-rows forms read `//y`, `//y test`, `//yt`.
A project without a digest never matches an `OwnerWork` filter.

### Detail: Owner block focus (OWN-19, D-18, D-20)

New focus level `DetailFocus::Owner` (one enum value, never a view-cache flag, as `Pane` and
`ScopeStrip` are; resets to `Content` on any tab but Phases, as `Pane` does,
`detail.rs:3939-3943`). Handler contract is the `handle_waves_pane_key` shape: `Some(action)`
consumes the key, `None` falls through.

**Existing collision, resolved.** Today `↑`/`k` on the first phase row sends focus to the tab bar
(`content_at_first_row`, `detail.rs:4263-4270`; documented in README). D-20's default entry takes that
key. Resolution (inferred; source D-20 "planner confirms … picks another unused key"): the vertical
order on screen is tab bar, Owner block, phase list, so the focus order follows it. `↑`/`k` from the
first phase row enters the block's **last** row; `↑`/`k` from the block's first row goes to the tab
bar (the existing level-up). The cost: for a project whose block is showing, reaching the tab bar
from the first phase takes one press per block stop plus one (`Esc` then `Esc` is the shortcut: the
first returns to the phase list, the second goes to the tab bar). Nothing changes when the block has
zero rows. No alternative key is needed, so none is bound.

| Key (focus = Owner) | Action |
|---------------------|--------|
| `j` / `↓` | next cursor stop; past the last stop returns focus to the phase list (selection unchanged, `pipeline_selected` stays 0) |
| `k` / `↑` | previous stop; from the first stop focus goes to the tab bar |
| `Enter` / `Space` | toggle the selected group's item lines, or toggle the selected fold; never launches anything |
| `←` / `→` | on the fold line: move between folds; elsewhere: swallowed |
| `Esc` | return to the phase list (`Content`). A second `Esc` is the existing step to the tab bar |
| `g` / `G` | first / last stop |
| `PgUp` / `PgDn` | page the cursor by the visible body height |
| `e`, `o`, `v`, `A`, `y` | swallowed no-ops (Phase 37 owns `v o A y`; `e` must not fall through to Content's enqueue) |
| `q` | leaves the detail view (every level) |
| `?`, `Tab`, digits, `D`, `[`, `]` | fall through (`None`); digits, `D`, `[`, `]` also reset focus to `Content`, as the Waves pane does |

Cursor stops are: every body group row (and, when a fold is open, its rows), then the fold line.
Item lines, sub-headers, the Todos fold and the overflow hint are never stops. The fold line is one
stop with a sub-cursor over its selectable folds (`←`/`→`; Todos skipped). While focus is not `Owner`
no cursor is drawn (gutter blank), but expansion state is kept.

**Expansion state** (D-18): per project, in memory only, in `ProjectViewCache` beside
`pipeline_selected`: expanded-group set, open-folds set, cursor stop, scroll offset. A group's
identity is `(lane, kind, scope label, workstream, phase, file)` so an expansion survives a digest
refresh; a vanished group is dropped; the cursor clamps (D-04's watcher refresh must never panic or
leave the cursor out of range). Switching tabs or projects keeps it; restarting resets it.

**Mouse** (inferred; may be deferred without failing this contract): a click inside the block
focuses it and selects the clicked stop; the wheel sends `Down`/`Up` with focus (the Waves pane
rule, `detail.rs:6370-6395`); a double click replays `Enter`. Whatever is built, a click in the
block's rectangle must never select a phase row: the phase list's click region is recorded from the
rect below the block, so it follows the layout automatically.

**Width/focus interplay:** below `ROADMAP_SIDE_BY_SIDE_MIN_COLS` (100) a focused Waves pane takes the whole tab
(`detail.rs:7498-7522`). Focus cannot be `Pane` and `Owner` at once; entering the Waves pane from
the phase list is unchanged and the block is not drawn while that full-tab pane is up.

### Data flow the UI may rely on (D-01..D-04)

The render path reads `ctx.owner_digests: HashMap<String, OwnerDigest>` only (name is the planner's
choice). It never parses, stats or spawns on the render path (`async_blocking_guard`). Rows render
first; the `You` cell and block appear when `Action::ProjectStateLoaded` delivers the digest. The
dashboard recomputes per frame from the map; no timer-driven refresh.
