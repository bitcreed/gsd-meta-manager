Add key handlers in `DetailScreen::handle_key()` that are active only when `current_view == DetailSubView::Queue`. All mutations follow the pattern: load queue -> mutate -> save_queue -> reload project state -> update cache.

Helper: Create a private function `queue_mutate_and_save(alias: &str, ctx: &mut AppContext, mutate: impl FnOnce(&mut Vec<QueuedAction>)) -> Result<(), String>` that:
1. Gets the planning_dir from `ctx.config.projects.get(alias)`
2. Calls `queue_md::load_queue(&planning_dir)`
3. Calls `mutate(&mut actions)`
4. Calls `queue_md::save_queue(&planning_dir, &actions)` — map error to string
5. Reloads project state: `state_reader::parse_project_state(&planning_dir)` and inserts into `ctx.project_states`
6. Returns Ok(())

Key bindings (all guarded by `current_view == DetailSubView::Queue`):

**'a' key — Add (per D-02):**
- Same logic as existing 'e' key on other tabs: clear input_buffer, set suggestion_index = 0, push `EnqueueScreen::new(alias)`. The EnqueueScreen already handles save and state reload.

**'d' or 'x' key — Delete with confirmation (per D-04):**
- Get the selected item text from `ctx.project_states.get(&self.alias).queued_actions[cache.queue_selected]`.
- Push a new `QueueDeleteConfirmScreen` (see Task 2) with `alias`, `selected_index`, and the item text for display.

**Enter or Space key — Mark done / remove (per D-07):**
- Call `queue_mutate_and_save` with a closure that calls `actions.remove(selected_index)` (bounds-checked).
- Clamp `cache.queue_selected` to new length.
- Set status message: `"Done: {command}"`.

**Shift+J (KeyCode::Char('J') — uppercase due to shift) — Move item down (per D-05):**
- If `queue_selected < len - 1`: call `queue_mutate_and_save` with `actions.swap(selected, selected + 1)`. Increment `cache.queue_selected`.

**Shift+K (KeyCode::Char('K') — uppercase) — Move item up (per D-05):**
- If `queue_selected > 0`: call `queue_mutate_and_save` with `actions.swap(selected, selected - 1)`. Decrement `cache.queue_selected`.

**'e' key — Edit (per D-03, using EnqueueScreen pre-filled approach from deferred note):**
- When on Queue tab: get selected item command text, put it in `ctx.input_buffer`, set `ctx.suggestion_index = 0`.
- Call `queue_mutate_and_save` to remove the item at the selected index first (so adding back creates the replacement).
- Push `EnqueueScreen::new(alias)`. The user edits the pre-filled text and presses Enter to re-add.
- Note: If user cancels (Esc), the item is already removed. This is acceptable — document in status message: "Editing: {command} (Esc cancels and removes)".

IMPORTANT: The existing 'e' key handler (line ~396) currently opens EnqueueScreen for ALL tabs. Refactor it: when `current_view == DetailSubView::Queue`, use the edit behavior above. Otherwise, keep existing behavior (generic enqueue with suggestions or backlog pre-fill).
