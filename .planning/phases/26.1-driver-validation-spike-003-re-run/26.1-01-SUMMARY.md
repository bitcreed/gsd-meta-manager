## Inferred decisions (audit)

1. **`NEW counts` lists rounds, not observations.** The plan says both "count after each observation" and `NEW counts=[1, 2]` for three observations. The required exact line wins: the list holds the count of each round the rule opens; coalesced observations are reported separately as `NEW coalesced=1`.
2. **Out-of-order writes.** `GapCounter` compares `abs(ts - previous)` and slides the anchor with `max(prev, ts)`, so a scan that visits two VERIFICATION files of one phase out of mtime order cannot move the window backwards or fail open. The plan's boundary cases (strict `< 45.0`) are unchanged for in-order writes.
3. **Coalescing needs an existing round.** A write is coalesced only when `per_phase >= 1`; a hand-crafted state with a `last_write` but no count counts as `new` (never silently dropped).
4. **Fork docstring and blank lines.** The fork-notes docstring lines carry literal `# s003:H1 begin/end` marker lines inside the module docstring, and H4/H3/H5 helper hunks include their trailing blank lines, so the "every difference is inside a hunk" check can stay strict (no whitespace exemption).
5. **Helper functions for H3/H4.** The plan describes inline blocks; they are implemented as module-level `add_stop_guard()` and `classify_run_exit()` inside marked hunks (call sites are marked too) so the selftest can drive the exact code the launcher runs. `classify_run_exit` calls `exitclass.classify_exit` with the plan's argument order.
6. **Extra fidelity assertions.** Besides the diff-in-hunks check, the selftest asserts the S2 text of `seed_config`, `host_access_token`, `mentions_phase`, `run_dir_of`, `cmd_init`, `Launch.__init__/gate/trip`, the `STRIP_ENV` tuple, the token check, the env + bwrap command block and the trip predicate is present verbatim in the fork.
7. **Stop-guard counter is not reset** when a later dispatch reports (kept to the plan's "at most `GUARD_LIMIT = 3` blocks per run" property, T-26.1-03); a second stall in the same run would not be guarded.
8. **Single commit for the `tdd="true"` task.** Task 2's tests are the in-module `selftest`s (they live in the same files as the code), so RED/GREEN separate commits were not made; the plan's action says "commit the five files". `TDD_MODE` was not passed.
9. **Guard fails open on any exception** (`except Exception` in the hook entry) and on a missing `--run-dir`, in addition to the plan's listed conditions.
10. **Skeleton value filter.** Skeleton string values must match `^[A-Za-z0-9._:-]{1,80}$` and contain none of `sk-ant|oat01|accessToken|refreshToken|eyJ`, else they are dropped (belt and braces over the key allowlist).
