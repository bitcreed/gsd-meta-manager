## Inferred decisions (audit)

1. **Campaign count includes Haiku (carried from the plan).** SPENT_ALL 7.8080 vs the original rubric's real-launch figure 7.7787; the stricter total costs $0.03 of headroom.
2. **Prompt v0.4 combines brief, config and guard (carried from the plan).** Which single lever matters cannot be told from the runs; the hypothesis under test (divergence logic in rule 5) is untouched.
3. **Partially priced result directories.** A `launcher-result-*.json` without a numeric cost (killed launch) is charged the directory's `MAX_BUDGET_USD` and flagged `ESTIMATED`, alongside any priced results in the same directory. Plan text covers only the "neither" case.
4. **Unmeasurable spend fails closed with exit 8.** If `campaign_budget.py` exits 2 (unreadable results, an empty results dir with no run-env), run.sh refuses with exit 8 rather than launching on an unknown total. An empty results directory therefore blocks launches until removed.
5. **Phase 26 labels are never relaunched into.** `RELAUNCH=1` with label `l7`, `smoke1`, `smoke2`, `run1`, `run1b` or `run2` exits 2 (the prohibition on touching committed Phase 26 evidence, made mechanical).
6. **`RESULTS_LABEL` set but empty is a bad label (exit 2)**, using `${RESULTS_LABEL-$MODE}` (no colon) so only an unset variable defaults to the mode name.
7. **Relaunch run-env.** `RELAUNCH=1` does not rewrite run-env.txt, so it appends `RELAUNCH_STARTED_UTC` and `RELAUNCH_CAMPAIGN_SPENT_USD`; the `WATCHER_ALIVE*` keys are appended again on each launch (later value wins for a last-key reader).
8. **Stand-in re-reads the last gap line in a loop** (0.5 s polls) until `window + 5` s have passed since it, rather than reading it once, so a gap line logged during the wait pushes the write later. The wait is measured from the LOG line's second-truncated UTC time; since the line is written after the file mtime, the write is at least window + 4 s after the mtime. With no gap line yet the stand-in does not wait.
9. **Selftest is not coupled to the committed results.** The 7.8080 / 7.7787 figures are checked by the plan's verify command, not by `campaign_budget.py selftest`, which would otherwise start failing as soon as 26.1 results are added.
10. **v0.4 Run-2 comment span.** The `make_variant.py` comment span now covers the v0.3 and v0.4 comment lines together and replaces them with one `v0.4-run2` note; the v0.3 rule-5 narrative is dropped from the Run-2 file because rule 5 is removed there.
11. **Loop step 4 fallback** "if it cannot, follow Startup step 3" points the driver at the existing Reconcile procedure (park on ambiguity), per the plan's wording.
