## Summary

The new tooling is carefully built and self-tested: `gapcount` has a single shared round definition, and
`launcher_s003` has a hunk-fidelity self-check against pinned spike 002. There are no critical defects.
The weaknesses are places where two components that must agree use different definitions: the launcher and
drift.py disagree on what a quoted status is, and a denied dispatch closes an unreported one. There are also
gaps in the "fail-closed" spend gate and one stop-guard design hole. These are the kinds of defect that could
silently skew the verdict of the Run 2 re-run, which is why they are warnings and not info.

## Warnings

### WR-01: `outstanding_item` lets a denied dispatch close an earlier, genuinely unreported one

**File:** `tools/exitclass.py:57-74` (consumed by `tools/stop_guard.py:94` and `tools/launcher_s003.py:200`)
**Issue:** `driverctl log dispatched` is written by the driver BEFORE its Agent call, and the PreToolUse hook
logs `RUN | dispatch-denied` after it. A denied attempt therefore leaves a `dispatched` line followed by a
`dispatch-denied`. `last_dispatch[item]` keeps only the newest `dispatched` line. Take `I-01 dispatched` (worker
running, unreported), then `I-01 dispatched` (a retry or duplicate), then `RUN | dispatch-denied`. The newest line
is closed by the denial, so `outstanding_item` returns None. The first worker is still unreported, which is
the Run 1b shape. Consequences: the Stop guard allows the stop (`no-outstanding`) and `classify_exit` labels the
exit `crashed` instead of `stalled`. The same happens when the denied attempt is for another item, because
`dispatch-denied` is item-agnostic and closes every earlier open dispatch. This is the scenario the guard
exists to catch (driver re-dispatching instead of using SendMessage), and the cap makes it likelier.
**Fix:** Track dispatches as a per-item stack/count and let a denial cancel only the dispatch it immediately follows
(the nearest preceding `dispatched` line with no event between), not the item's earlier open dispatches:
```python
open_by_item = {}                      # item -> list of event indices still open
for n, (_, item, ev, kv) in enumerate(events or []):
    if item != "RUN" and ev == "dispatched":
        open_by_item.setdefault(item, []).append(n)
    elif ev == "dispatch-denied" and prev_was_dispatched(n):   # cancels only the immediately preceding dispatch
        ...
    elif ev in ("report", "recovered") or (ev == "status" and kv.get("state") in DONE_STATES):
        open_by_item.get(item, []).clear()
```
Add a self-test for the sequence dispatched, dispatched, dispatch-denied, which must remain outstanding.

### WR-02: Stop-guard block budget is a single global counter that is never reset and survives relaunch

**File:** `tools/stop_guard.py:44, 100-105`
**Issue:** `stop-guard.count` is one integer for the whole run. It lives in the per-run CLAUDE_CONFIG_DIR, which
persists across relaunches. Once three blocks have been spent, for any item at any time, the guard is permanently
off (`allow reason=limit`). It is not reset when the stall resolves, when the item reports, or per item or per
launch. In a multi-item or multi-launch run, an early stall that the driver resolves by SendMessage uses up
attempts, so a later Run 1b-style stall is no longer guarded. The `limit` result is also indistinguishable from
a genuine "gave up" in the evidence (L8-1 only checks for a `block` line).
**Fix:** Key the counter by item and reset it when the condition clears.
```python
# store {"item": "I-01", "n": 2}; reset when item changes or when outstanding_item(events) is None
```
Keep the hard cap per (item, dispatch line index), and log `reset` decisions.

### WR-03: drift.py accepts a quoted `status:` value, but the launcher gap counter and cap do not

**File:** `tools/drift.py:217` vs `tools/launcher_s003.py:137, 157` (unchanged from spike 002)
**Issue:** IN-05 widened drift.py's `_STATUS_RE` to `status:\s*["']?(...)` and added a selftest asserting that
`status: "gaps_found"` is read as `gaps_found`. The enforcing path, `FM_STATUS = ^status:\s*([A-Za-z_]+)` in the
launcher (pinned byte-identical to spike 002, outside any s003 hunk), does not accept quotes. A verifier that
quotes the value is then snapshotted as `gaps_found` by drift.py, so A8, A9 and A10 score it as a round. The
launcher never counts it, so the gate and the kill cap (the thing Run 2 exists to test) never fire. The
two sides of the experiment disagree about what a round is, which is the very D-01 class of bug this phase fixes.
**Fix:** Move the status match into `gapcount.py` (one definition) and use it from drift.py, the launcher fork
(inside a new marked hunk H2) and acceptance.py. At minimum, revert drift.py to the unquoted regex so both
sides agree, or make the launcher fork's H2 hunk include a quote-tolerant `FM_STATUS`.

### WR-04: `campaign_budget` prefers a possibly stale `stage-cost.txt` over measured launcher results

**File:** `tools/campaign_budget.py:122-131`
**Issue:** Rule 2 returns the last `TOTAL ... total=` of `stage-cost.txt` and never looks at
`launcher-result-*.json`. `run.sh` supports `RELAUNCH=1` into an existing label and copies each new launch's
`launcher-result-N.json` into the same results dir. If `stage-cost.txt` was produced after launch 1, a later
relaunch's spend (up to its `MAX_BUDGET_USD`) is invisible to the ceiling gate. The gate is documented as
"fail closed", but this path under-counts silently.
**Fix:** Take the maximum of the two measurements, or charge launcher results newer than the stage-cost file:
```python
st = stage_total(...)
lc_sum = priced + unpriced * budget()
cost = max(st, lc_sum) if st is not None and lc else (st if st is not None else lc_sum)
```

### WR-05: In-script auth relaunch loop bypasses the campaign ceiling gate

**File:** `experiment/run.sh:244-263` (gate at `:98-105`)
**Issue:** `campaign_budget.py` is evaluated once, before the first launch, with `--next $BUDGET`. The `while :`
loop can launch the launcher up to two more times (RELAUNCHES < 2) with the same `--max-budget-usd`, with no
re-check. The header and the campaign_budget docstring both claim "before every launch (any mode, any
relaunch)". Worst case the ceiling is exceeded by 2x BUDGET (about $30 for run1/run2).
**Fix:** Re-run the gate before each `continue`, or reserve `(1 + max relaunches) * BUDGET` in the first check:
```bash
python3 -I "$S3/tools/campaign_budget.py" --ceiling "$CEIL" --next "$BUDGET" >/dev/null || exit 8   # before RELAUNCHES++
```
(`campaign_budget` can only see the finished launch's cost once it has been copied to `$RES`; copy the interim
launcher-result into `$RES` first.)

### WR-06: Cleanup trap's unit glob can stop a different concurrent run

**File:** `experiment/run.sh:162`
**Issue:** `systemctl --user stop "gsdmm-$RUN_ID-*.scope"` is a prefix glob. Labels may contain `-`, so
RUN_ID `s003-r261-run2` also matches `gsdmm-s003-r261-run2-retry-<epoch>.scope`. Ending one run kills another
run that is in flight in parallel (parallel runs are the project's stated default).
**Fix:** Match the exact timestamp shape: the unit is `gsdmm-<run_id>-<digits>.scope`, so stop only units that
match `gsdmm-$RUN_ID-[0-9]*.scope` and whose remainder after the run id is purely numeric. Better, have the
launcher write its unit name to `$RES`/`$STATE_DIR` and stop exactly that.

### WR-07: `scan_gaps` reads the file before it stats it (digest and mtime can belong to different writes)

**File:** `tools/launcher_s003.py:150, 163-166`
**Issue:** The digest comes from `f.read()` and the mtime from a later `os.stat`. If the verifier's `sed -i`
lands between the two (the exact 6.5 s re-write pattern, or a quicker one), the old content's digest is paired with
the new write's mtime. The next scan then sees the new digest at the same mtime, which is no more than 45 s
away, so it is counted `coalesced`. The pairing is wrong but harmless in that instance. In the other order a
genuine new write can be classified `new` using the earlier write's time. The window rule is only as exact as its
mtime sample.
**Fix:** `os.stat` first, read next, then stat again, and skip the file this tick if the mtime changed:
```python
st1 = os.stat(p); raw = open(p, "rb").read(); st2 = os.stat(p)
if st1.st_mtime_ns != st2.st_mtime_ns: continue   # retry on the next 2 s tick
```
(Keep this inside the H2 hunk to preserve fork fidelity.)

### WR-08: Stand-in timestamp is taken after the stand-in write, so its snapshot can be scored as organic

**File:** `experiment/run.sh:217-218`, `experiment/acceptance.py:152-156`
**Issue:** `Ctx.snapshots` labels a snapshot `standin` if `snapshot.utc >= standin.log timestamp`. `standin_loop`
runs `gap-writer.sh` first and calls `date -u` only afterward when appending to `standin.log`. With a 0.4 s poll
interval and 1 s resolution, a snapshot of the stand-in write that straddles a second boundary has
`utc = T` and the log line `T+1`, so the comparison fails. The stand-in snapshot then counts as an organic
`gaps_found` for A8, A10 and A9, and the next real snapshot (if any) is mislabeled stand-in. Probability is low
per run but it directly corrupts the pre-registered scoring.
**Fix:** Record the stand-in time BEFORE the write and compare against that:
```bash
ts="$(date -u +%FT%TZ)"; bash "$S2/experiment/cap-tests/gap-writer.sh" "$PROJECT" 1 0 >/dev/null
echo "$ts trigger=$trig wrote gaps_found via gap-writer.sh" >> "$SCRATCH_ROOT/standin.log"
```

### WR-09: A reused SCRATCH_ROOT silently has its `project/` deleted; the basename guard only checks the name

**File:** `experiment/setup-scratch.sh:16-18`, `experiment/run.sh:124, 185`
**Issue:** The "refuse unless basename is `project`" guard (WR-09) protects against typos, not against deleting a
previous run's scratch repo: `SCRATCH_ROOT` is an env override and run.sh only checks that its parent is not a
git work tree. Pointing it at an earlier run's root runs `rm -rf <root>/project` on that run's scratch project
(its git history and verification state). The run.sh header says "nothing is ever wiped".
**Fix:** In run.sh, before `setup-scratch.sh`, refuse when `"$PROJECT"` already exists and `RELAUNCH` is not 1:
```bash
[ ! -e "$PROJECT" ] || { echo "run.sh: $PROJECT already exists; choose a new SCRATCH_ROOT" >&2; exit 2; }
```

## Info

### IN-01: Stop-guard counter and hook wiring live in a directory the sandboxed driver can write

**File:** `tools/launcher_s003.py:179-190`, `tools/stop_guard.py:100`
**Issue:** `CLAUDE_CONFIG_DIR` is bind-mounted read-write. The model can edit `settings.json` (drop the guard) or
write `stop-guard.count` (`_bump` accepts negative numbers, so `-999` makes the guard block indefinitely).
This matches spike 002's existing trust boundary for the driverctl hook, but the launcher header says it
"owns everything the model must not be trusted with". Document it, or clamp `n = max(n, 0)` in `_bump`.

### IN-02: `gapcount.replay` raises on a malformed LOG timestamp instead of returning exit 2

**File:** `tools/gapcount.py:127`
**Issue:** `epoch(utc)` can raise `ValueError` (the writes-fixture path at line 140 is guarded; the LOG path is
not), giving a traceback and exit 1, contradicting "Exit codes: 2 no data or bad input".
**Fix:** Wrap in `try/except ValueError: return 2, ["gapcount: ERROR bad timestamp in LOG.md"]`.

### IN-03: `make_variant.py` reads and writes with the locale's default encoding

**File:** `tools/make_variant.py:93-96, 112`
**Issue:** `open(path)` has no `encoding=`. The committed variants are byte-compared in `--check` (run.sh gate 1);
a non-UTF-8 locale or a non-ASCII character in MASTER-PROMPT.md would raise or yield false drift.
**Fix:** `open(path, encoding="utf-8")` in both places.

### IN-04: Check A2 passes vacuously when the item parks with no gap observed

**File:** `experiment/acceptance.py:202-203`
**Issue:** When `count_event(3)` and `count_event(4)` are both absent, A2 returns PASS with
"parked at gaps_found count=0 (before the third)". An item that parks for an unrelated reason (e.g. a worker
failure) before any verification passes the gap-cap check. Report NOT-REACHED when `max(gap_counts) == 0`.

### IN-05: Unguarded first poll in the feed watcher

**File:** `tools/drift.py:323`
**Issue:** `cmd_watch` calls `w.poll()` directly, whereas the loop uses `poll_safe` (WR-07). An exception in
the first poll kills the watcher; run.sh would still see it alive during its 1 s check if the failure is late.
Use `w.poll_safe()`.
