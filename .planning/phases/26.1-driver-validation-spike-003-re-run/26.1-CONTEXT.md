<decisions>
## Implementation Decisions

### Gap-round signal
- **D-01:** Fix the divergence / gap-round signal so that a single verifier re-write cannot inflate
  the gap count or trip the gap-round cap. Run 1 failure mode: one verifier re-write logged 3 gaps
  across 2 verifier runs, so the driver parked on the gap-round cap instead of divergence and round 2
  never ran. Count gap rounds per verifier run (one round per verifier run that returns
  `gaps_found`), deduplicating repeat writes inside one run — the exact mechanism is chosen from what
  the Phase 26 artifacts (LOG.md, driverctl, launcher counters, transcripts) support.
- **D-02:** The fix must be proven offline against the recorded Phase 26 Run 1 evidence (a scripted
  replay / fixture) before any paid Opus run.

### Headless driver liveness
- **D-03:** Keep the headless driver alive until its dispatched worker reports, so a premature
  end-of-turn is not treated as a crash (Run 1b failure mode: the driver dispatched one worker, ended
  its turn, and the launcher recorded a crash). Acceptable alternatives: make the launcher
  distinguish "driver ended its turn with a worker outstanding" from a crash and resume/relaunch
  accordingly. Proven offline against the Run 1b shape before any paid run.

### Acceptance tooling (security + review)
- **D-04:** Close T-26-11: `acceptance.py` must not report `RESULT PASS` when every check is
  UNDETERMINED (empty or missing results dir). That case must yield INCONCLUSIVE (or FAIL) with a
  non-zero exit, pinned by a selftest assertion on the RESULT line and return code.
- **D-05:** Address the 26-REVIEW.md advisory warnings (WR-01..WR-10) where cheap; disposition the
  rest explicitly (fixed / deferred with reason) in 26-REVIEW-DISPOSITION.md or a 26.1 equivalent.
  WR-06 (`SEED VALID` emitted while A10 UNDETERMINED) is in the same vacuous-green class as T-26-11
  and should be fixed with it. `[inferred — audit]` priority: WR-06, WR-08, WR-01, WR-09 first.

### Re-run
- **D-06:** Re-run Opus Run 1 under the revised instruments to prove VALID-01 (gap rounds 1 and 2
  observed, park `needs-human` no later than the third `gaps_found`, rule recorded by driverctl in
  LOG.md). Run 2 (prompt divergence rule disabled; launcher cap trips deny L+1 / kill L+2) runs only
  if the pre-registered rubric allows after Run 1 succeeds, to prove VALID-02.
- **D-07:** `[inferred — audit]` Spend cap for 26.1: **$52.19**, the unspent remainder of spike 003's
  original $60 ceiling after Phase 26's measured $7.81. Total spike-003 spend (26 + 26.1) stays within
  the original rubric's $60. The rubric's retry and skip rules carry over; any rubric revision is
  committed (pre-registered) before the first paid run.
- **D-08:** Zero duplicate planner/executor runs (VALID-03) is re-checked on every 26.1 run as a
  regression guard.

### Gating and verdict
- **D-09:** 26.1 records a revised spike-003 verdict (GO / ADJUST / NO-GO / INCONCLUSIVE) in the
  spike README and MANIFEST, and the go / adjust / no-go for Phases 27-31 in STATE.md. Phases 27-31
  stay blocked unless the verdict is GO or ADJUST.

- Plan split and wave layout (tooling fixes can run in parallel; paid runs strictly after them).
