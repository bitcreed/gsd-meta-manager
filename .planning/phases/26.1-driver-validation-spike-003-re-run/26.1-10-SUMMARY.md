### r261-seed2 (first launch) and the diagnosis

- Cause (one sentence): the scratch repo sits on `main`, which gsd-core's commit guard (`git.base-branch --is-protected`) refuses, so the Sonnet executor halted before any change, reported `blocked`, and the Haiku driver parked on `needs-human`; no verifier ever spawned, so the gate result says nothing about the feed trigger.
- Evidence: `LOG.md` (executor report `NEEDS_HUMAN: allow commits on main or a feature branch`), `drift.log` (only the `start` line, no advance, no snapshot), `dup-report.txt` (`gsd-verifier` absent, `DUP=0`), `extract-spawns` (planner and executor only).
- In the earlier Opus `r261-run2` the executor chose a `gsd/phase-01-slugify` branch on its own; the Haiku run did not. The halt is nondeterministic executor behavior at a harness hazard, not a feed defect.

### The one seed fix (commit 73cf71c)

`run.sh` `allow_main_commits`: for the verifier-trigger modes (seed2 and run2), after `setup-scratch.sh` it sets `git.allow_default_branch_commits: true` in the scratch `.planning/config.json` and folds that into the scratch commit with `git commit --amend` (scratch repo only), so the tree is clean and the scratch history keeps its shape. `drift.py`, the feed tables, the nine house-rule classes, the scratch text, `acceptance.py` and every rubric block are untouched; the verifier-spawn trigger still advances the feed after the executor ends and before the verifier reads. `run.sh selftest`, the drift, launcher_s003 and acceptance selftests and `make_variant.py --check` pass; all three rubric-checks print RUBRIC-UNCHANGED.
