<objective>
Give the human two places to type: a message into a running agent, and a command plus a goal into a
new run.

Purpose: **OBS-03 is unreachable while the goal is always empty.** `App::start_driver_run` already
threads `goal: Option<&str>` and passes `None` because *"there is no screen to type one into — that
is Phase 18's"*, and `Action::DriverStartRequested.command` is filled today from the single constant
`driver_confirm::DEFAULT_DRIVE_COMMAND`, whose own doc says *"Phase 18's command picker is what
makes the field carry more than one value."* Both seams are reserved and empty; this plan fills them.
`RunRecord.goal` and `ObservedRun.goal` already exist and `run.json` is the one committed artifact,
so nothing below the UI needs new plumbing.

The injection screen is `enqueue.rs` (120 lines) with three deliberate changes: different footer
copy, no Tab suggestions (`suggest_next_commands` suggests GSD commands and a steering message is
free prose — offering irrelevant completions would be worse than offering none), and **the Enter arm
dispatches an `Action` instead of writing to disk inline**, which is what `enqueue.rs` does and what
D-06 / D-28 forbid here.

Output: two new screens and a confirmation that names what it will actually run.
</objective>

## Scope Fence (18-CONTEXT `<domain>`, operative half restated)

Out of scope, each with a named later owner: `decide()`, multi-command sequences and run bounds →
**Phase 20**; a Phase 18 run executes exactly one GSD command per `drive` invocation, so the picker
chooses **one** command and the screen must not imply a sequence. Git blast-radius enforcement →
**Phase 19**. **LLM goal decomposition and prompt-injection hardening → Phase 21**; this phase stores
the human's goal string verbatim and interprets nothing. `ExecutionTarget::Container` → Phase 22.
The `control.sock` fast path → a later milestone; file inbox only. **`tmux send-keys` is a named
anti-feature** — driver keystrokes and human keystrokes interleave on a shared pane and corrupt each
other, there is no delivery confirmation, and it breaks mid-prompt; tmux stays attach/watch-only and
the existing `terminal_switch.rs` path is untouched by this phase (D-01). **`tui-textarea` or any
richer text input → declined outright** (D-22). No interrupt affordance → Phase 20. The 5
pre-existing `--all-targets` clippy lints must not grow and are not this phase's to shrink.
