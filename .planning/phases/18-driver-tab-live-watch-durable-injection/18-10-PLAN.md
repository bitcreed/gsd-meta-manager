<objective>
Show the run: its output, its injected messages in four honest states, and — for a run that has
already ended — the same view over a journal that has stopped growing.

Purpose: this is the plan where "watch its output" and "queued → delivered → acted-on, never a bare
sent" become real. Three failure modes are named in advance and each is a trap this plan must walk
past rather than into. **A three-state UI with three labels over two real states**, with delivered and
acted-on both set from the same event — the tell is that no code reads the replay marker; 18-02
closed that on the driver side and this plan must not re-open it on the render side. **A delivery
badge that lights instantly** — the real dequeue ack was measured at fifty-five seconds, so the
progression must read correctly across a minute-long gap, which is exactly why it is a filling shape
and not a spinner. And **a Driver tab that promises live output for an adopted run** — physically
impossible, because once the TUI exits the child's stdout pipe is gone.

The fourth trap is mechanical: the clamp-ordering invariant is repeated in four source comments and
guarded by an existing test block because it was a shipped bug. The output pane is a new place for
exactly the same defect.

Output: the output pane with its follow bit, the four-state injection widget, the evidence-derived
terminal-state table, the adopted-run notice, and the Driver tab's key routing.
</objective>

Make the message states a pure function of what is on disk.

`derive_injection_states(inbox, records)` takes the inbox lines and the run's journal records and
returns, per message, its state and the timestamp of its last transition. The rule is a set
intersection and nothing more: an id present in `inbox.jsonl` and in no journal record is **queued**;
present in an `interjected` record is **delivered**; present in an `interjection_acted_on` record is
**acted-on**; present in an `interjection_missed` record is **missed**. Later states win over earlier
ones. **Nothing is held in memory that a restart would lose** — that is precisely what makes STEER-03
hold across a TUI restart with no extra persistence, and it belongs in the function's doc.

The function is pure so it can be tested exhaustively without a terminal or a process; copy the
register of `driver/mod.rs:129-135`.

`injection_rows(entry)` renders **always two rows, at every width**: row one is the Cyan+BOLD
injection marker, the state glyph, the exact state label and the queue timestamp; row two is a
four-cell-indented, sanitised, verbatim copy of the message text. The delivered state adds an elapsed
counter to row one; the missed state adds a third row carrying the pinned gloss. Always two rows means
no width branch, a perfectly aligned state column, and no right-alignment arithmetic that could clip
in the narrowest pane.

**The four labels are exact and the vocabulary is a safety property.** The word for a write to the
agent's stdin is delivered and nothing else; the word for the dequeue echo is acted-on. The word
"sent" is forbidden, and so are "received", "read" and "acknowledged", because the ack arrives
roughly fifty-five seconds after the write and any word implying receipt is a lie about the protocol.
Write that into the module's doc so the next reader cannot soften it by accident. The filling-shape
progression is the whole design: **no spinner, no animation, no implied imminence** — a spinner idiom
here is actively dishonest and must be rejected at review.

A run with **no** injected messages renders no injection rows at all — not an empty queued
placeholder.

exec exit — which is the four-source derivation Phase 15 already computes. The doc on this function
