<objective>
Make the dashboard answer two questions at a glance — *is something driving this repo?* and *which
of these is waiting on me?* — without adding a screen, a column, or a second source of truth.

Purpose: OBS-02 and OBS-07 are both dashboard-shaped, and both are one predicate away from working
because 18-04 already built `needs_human` and `attention_rank`. The design constraint that matters is
`alias_badge`'s existing contract (`normal.rs:62-79`): it returns `Option<(&'static str, Color)>`
with a documented priority, and **at most one badge ever renders**, which is what keeps the Alias
column aligned. Both mechanisms are deliberate — the `Option` return is how "at most one" is
enforced, and the `&'static str` return type is how "never derived from file content" is enforced, so
no HANDOFF body can leak onto a dashboard row. Widen the type, keep both mechanisms.

The one thing that will look done and is not: a **parked badge wired to `JournalEvent::Parked`**.
Nothing emits that until Phase 20, so the badge would never light, and no test would catch it because
the test would emit the event by hand. 18-04's evidence predicate is what makes the badge honest.

Output: two new badge ranks, the `s` sort toggle and its indicator, and the needs-human filter's
dashboard half.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project state files (HANDOFF, queue) → dashboard row | File content decides whether a badge lights; it must never decide what the badge *says*. |
| filter text → alias list | User-typed text; no path or command is derived from it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-32 | Tampering | badge glyph derived from file content | high | mitigate | `AliasBadge.glyph` is `&'static str` and every value is a `\u{…}` constant; the type is the mechanism, asserted by a grep criterion. No HANDOFF body can reach a dashboard row. |
| T-18-33 | Spoofing | a badge that misrepresents whether an agent is driving the repo | high | mitigate | Rank 1 is driven-**and**-live via `ObservedRun::is_live()`, which reads the tri-state `Liveness`; `LivenessUnknown` is never collapsed into dead (CR-05). |
| T-18-34 | Denial of service | badge/sort computation on every frame for a large fleet | low | accept | Both are pure functions over already-loaded state with no I/O; the fleet size this tool targets makes the cost immaterial. Recorded rather than measured. |
| T-18-35 | Information disclosure | filter text echoed into a log or a path | low | mitigate | The filter is compared in memory only; no new log line and no path is derived from it. |
| T-18-36 | Tampering | package-manager installs | low | accept | Zero Cargo dependencies added; no package-legitimacy surface exists. |

ASVS level 1; blocking threshold `high`. T-18-32 and T-18-33 are the `high` rows and both are
`mitigate` with a structural, grep-checkable guarantee plus tests.
</threat_model>
