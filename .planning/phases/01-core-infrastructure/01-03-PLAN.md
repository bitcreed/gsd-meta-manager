2. Create `src/event.rs` — Async EventBus using tokio mpsc (per D-09):
```rust
use crate::action::Action;
use tokio::sync::mpsc;
use crossterm::event::{Event, KeyCode, KeyModifiers, KeyEvent, EventStream};
use futures::StreamExt;
use std::time::Duration;

pub struct EventBus {
    pub rx: mpsc::UnboundedReceiver<Action>,
    pub tx: mpsc::UnboundedSender<Action>,
}

impl EventBus {
    pub fn new() -> Self {
        let (tx, rx) = mpsc::unbounded_channel();
        Self { tx, rx }
    }

    pub fn spawn_crossterm_reader(&self) {
        let tx = self.tx.clone();
        tokio::spawn(async move {
            let mut reader = EventStream::new();
            while let Some(Ok(event)) = reader.next().await {
                if let Some(action) = map_event_to_action(event) {
                    if tx.send(action).is_err() { break; }
                }
            }
        });
    }

    pub fn spawn_tick(&self, interval_ms: u64) {
        let tx = self.tx.clone();
        tokio::spawn(async move {
            let mut interval = tokio::time::interval(Duration::from_millis(interval_ms));
            loop {
                interval.tick().await;
                if tx.send(Action::Tick).is_err() { break; }
            }
        });
    }
}
```

`map_event_to_action` maps crossterm events to Action variants. The mapping depends on current `InputMode` — but since the event reader doesn't know app state, map raw keys and let `App::update` interpret them based on mode. Map:
- `KeyCode::Char('q')` with no modifiers -> `Action::Quit` (but only when not in input mode — handle in app.rs)
- `KeyCode::Char('j')` or `KeyCode::Down` -> `Action::MoveDown`
- `KeyCode::Char('k')` or `KeyCode::Up` -> `Action::MoveUp`
- `KeyCode::Char('a')` -> `Action::KeyInput('a')`
- `KeyCode::Char('d')` -> `Action::KeyInput('d')`
- `KeyCode::Char(c)` -> `Action::KeyInput(c)`
- `KeyCode::Enter` -> `Action::KeyInput('\n')` (special marker)
- `KeyCode::Esc` -> `Action::CancelInput`
- `KeyCode::Backspace` -> `Action::Backspace`
- `Ctrl+C` -> `Action::Quit`

Actually, simpler approach: send ALL key events as raw data and let App::update handle mode-specific interpretation. Define a `RawKeyEvent` action or just use `KeyInput` broadly. The key insight: the event reader should be dumb, the App should be smart.

Revised approach — add `Action::RawKey(KeyEvent)` to `action.rs` so the event reader just forwards crossterm KeyEvents. Then `App::update` matches on `(self.input_mode, key)` to decide the right action. This avoids the event reader needing app state knowledge.

```rust
use crate::config::{Config, load_config, save_config};

    pub error_message: Option<String>,
    pub needs_redraw: bool,
}
```

`App::new(config_path)`: Load config, create default state, set `needs_redraw = true`.

`App::load_project_states(&mut self)`: For each project in `self.config.projects`, call `state_reader::parse_project_state(&project.path.join(".planning"))` and store in `self.project_states`. This runs synchronously at startup for simplicity in Phase 1 (Pitfall 4 notes concern with 10+ projects; acceptable for Phase 1 stub).

`App::update(&mut self, action: Action)`: Match on action. For `RawKey(key_event)`, match on `(self.input_mode, key_code)`:

**Normal mode:**
- `'q'` -> set should_quit = true
- `'j'` or Down -> select next row (wrap at end)
- `'k'` or Up -> select prev row (wrap at start)
- `'a'` -> set input_mode = AddAlias, clear input_buffer
- `'d'` -> if a project is selected, set input_mode = DeleteConfirm { alias of selected }
- Ctrl+C -> set should_quit = true

**AddAlias mode:**
- printable char -> append to input_buffer
- Backspace -> pop from input_buffer
- Enter -> if input_buffer non-empty, transition to AddPath { alias: input_buffer.clone() }, clear input_buffer
- Esc -> back to Normal, clear input_buffer, clear error_message

**AddPath mode:**
- printable char -> append to input_buffer
- Backspace -> pop from input_buffer
- Enter -> attempt add_project with alias and PathBuf::from(&input_buffer). On success: save_config, reload project state for new project, set status_message "Added \"{alias}\"", back to Normal. On error: set error_message from the anyhow error string.
- Esc -> back to Normal, clear buffers

**DeleteConfirm mode:**
- `'y'` -> remove_project, save_config, remove from project_states, set status_message "Removed \"{alias}\"", back to Normal, adjust table selection
- `'n'` or Esc -> back to Normal

Set `needs_redraw = true` on every state change.

Status messages expire after 3 seconds (checked in Tick handler: if status_message age > 3s, clear it and set needs_redraw).
