<objective>
**Round 9, wave 2. The `.planning/` layer, closed by the same carrier — so the five sites
verification pass 9 found by reading become a compile error, and the fixture hole that hid
them becomes a fixture.**

Verification pass 9 went looking for the cause of an intermittent probe failure and instead
found what the probe's disclosed coverage hole actually contains: five sites in
`src/ui/screens/detail.rs` that draw `.planning/`-derived names raw into terminal cells. The
disclosure was honest. The hole is populated. And — with the corrected per-widget measurement
from 21-23 — three of those five sites are `ListItem`s, which **preserve** every member of the
invisible class rather than dropping it.

**This plan does not fix five sites.** It retypes the eight carriers those sites read, and then
resolves whatever the compiler names. The measured expectation is that the compiler names MORE
than five; the SUMMARY records the difference, because that difference is the entire argument
for doing it this way rather than the way rounds 1 through 8 did it.

| Carrier | Fields | Source of the bytes | Render sites pass 9 could see |
|---|---|---|---|
| `state_reader::backlog::BacklogItem` | `dir_name`, `number`, `description`, `content` | `.planning/BACKLOG.md` and its directory names | `detail.rs:2882` |
| `session_detector::ClaudeSession` | `session_id` | a `claude` process's cmdline | `detail.rs:3349` |
| `ProjectViewCache` | `archive_milestones`, `archive_file_name`, `browser_file_name` | `.planning/archive/` directory names | `detail.rs:3416` |
| `archive::ArchiveFile` | `name` | `.planning/archive/` file names | `detail.rs:3438` |
| `archive::PhaseArchive` | `name`, `display_name` | `.planning/archive/` phase directory names | `detail.rs:3444` |
| `browser::BrowserEntry` | `name` | `.planning/` directory listing | none pass 9 named — the Browse tab's cache is empty in the fixture |

**The second half of the plan is the fixture hole, and it is the durable half.** The reason
these five sites were green at HEAD is that `probe_ctx` calls
`ctx.view_cache.entry(identity).or_default()` and leaves every one of those caches empty, so
five of the eleven `DetailScreen` tabs render their *empty* branch under probe. Populating them
is what stops the next raw site in those tabs from being invisible for another nine rounds.

**And the one place the rule inverts, stated rather than smuggled.** `ctx.status_message`
(WR-03) is built by six `format!`s in `src/app.rs` that interleave authored text with a
registry key. There is no field to retype: the trust boundary runs through the middle of a
format string. So this one is escaped at the RENDER site, the comment there says that this is
a deliberate inversion of the escape-at-the-producer rule and why, and `NormalScreen`'s
disposition row finally names the footer it has never mentioned. Round 8 fixed
`delete_confirm.rs:161`'s sibling correctly and left these three because nothing pointed at
them; the fixture state added here is what points at them from now on.

**What this plan does NOT cover, carried forward from 21-23's table so it is not lost:**
`state_reader::ProjectState` (5 fields, 135 mentions, a `HashMap` key and a router input),
`roadmap_md::RoadmapPhase` (4 fields, reached through `ProjectState`),
`queue_md::QueuedAction` (1 field, compared against `SAFE_COMMAND_ALPHABET`),
`AppContext::filtered_aliases`/`selected_alias` (93 mentions, D-21-4's measured 25-error
cascade) and `config_json::GsdConfig` (the Defaults tab). Those five stay bounded by the census
and the probe alone — a sampling control — and after this plan that sampling is materially
better, because the tabs that read them now render their populated branch. That is an
improvement in the bound, not a closure of it, and the limits block must say so in those words.
</objective>
