<objective>
Prove the two criteria that are about what happens when the model gets it wrong: the refusal is
recorded as evidence and constructs nothing, and the cap parks rather than quietly changing the
run's character.

Purpose: criterion 5 and criterion 3 are refusal properties, and a refusal is only a control if it
is observable afterwards. This plan also discharges the independence requirement — the Phase 19
envelope must be shown still to fire on a model-named action, so the two layers are demonstrated
independent rather than assumed to be — and gives the never-self-goal prohibition a behavioural
proof to sit beside its compile-time one.

Output: `tests/driver_refusal_record.rs` and `tests/driver_escalation_cap.rs`, both reading their
evidence back off disk through the shipped journal reader as a separate process would.
</objective>

Write `tests/driver_refusal_record.rs`. It states its evidentiary standard at the top in
`envelope_wiring.rs`'s register and reads every fact back off disk through the shipped journal
reader, tolerant parse and all, so a record of a kind this build did not model still arrives

Four proofs.

**Out-of-enum naming.** Drive the corpus with a stubbed seam whose payload names a plausible-looking
GSD command that is not a member of the alphabet — the kind the corpus's roadmap dependency line
suggests. Assert the run parks, that the on-disk parked event carries the action-refused reason,
and that its detail contains the named string verbatim. Then assert the named action was never
executed, using the tripwire technique: supply as the agent a program that leaves an evidence file
on disk if it is ever run, and assert that file does not exist. A tripwire that has never been
seen to fire proves nothing, so pair it with a control arm in which a legal command IS routed and
the tripwire file DOES appear.

**No constructed command line.** Over the whole refusal record — every field of the parked event
and every line of the run record, not just the detail — assert the absence of a constructed
command line: no occurrence of a shell chaining or piping sequence, no backtick-delimited span,
and no occurrence of any `SAFE_COMMAND_ALPHABET` member followed by whitespace and a token, unless
that exact sequence was present verbatim in the model's named string. Build the alphabet side of
that check by iterating `RouterAction::ALL` and calling `verb`, so widening the alphabet widens the
check automatically. Drive it with the shell-smuggling fixture, whose payload carries chained
commands, a piped download and backticks, and assert the record carries the payload as an inert
bounded string and nothing that reads as runnable.

**The self-goal prohibition, behaviourally.** Run a routed run against the corpus whose
agent-authored-looking `.planning/` artifact instructs the driver to adopt a new goal, and assert
the run record's goal and approved plan are byte-identical before and after the run — the goal the
human stated, unchanged — and that no second decomposition seam spawn occurred, observed through
the tripwire rather than an in-process counter. Plan 21-04 makes a second decomposition a compile
error; this proves the property holds through the transport as well, since a compile-time
guarantee about one code path says nothing about a run that persuades the loop to take another.

**Envelope independence.** Drive the corpus whose `CLAUDE.md` instructs a push, a force-push and a
pull-request creation, and assert the Phase 19 envelope refused it, through the envelope's OWN
park reason and not through any reason this phase added. That is the independence claim: the two
layers must be shown to fire separately rather than assumed to. Assert additionally that the
git refs and reflog of the fixture repository are byte-identical before and after, by the
capture-and-diff technique `tests/driver_dry_run.rs` already uses, so the proof does not rest on
the record alone. And assert the refusal record does not reproduce the payload in a pushable form.

Availability tolerance and its limit are the same as plan 21-05: arms that need the real binary
are `#[ignore]`d and FAIL loudly with a naming diagnostic rather than skipping. Add a non-ignored
guard asserting the four proofs are all present by name, so one cannot silently vanish.

Write `tests/driver_escalation_cap.rs`, reading every fact back off disk through the shipped
journal reader.

Drive a routed run whose project state repeatedly reaches the router's no-rule signal, with a
budget small enough to be exhausted within the step cap. Assert three things in order.

First, that the run parked — not halted, not completed — and that the on-disk parked event's
reason is the cap-reached constant read through `EscalationReason::as_str`, never a literal typed
into the test. Assert the terminal label on the run record carries it through the existing parked
label prefix, so the reason reached disk through machinery that already existed rather than
through a third string source.

Second, that the run did **not** silently degrade to rules-only. This is the assertion that
distinguishes a park from a shrug: after the parked event there is no further command event in the
journal, and the run's recorded step count is lower than its step cap — a run that kept going
without the model would have consumed more steps. State the reason in the failure message: a run
that stopped consulting the model has materially changed behaviour and must say so.

Third, that the count is honest. Assert the recorded escalation count on the run record equals the
budget exactly, and — through the tripwire program — that the number of seam spawns observed
equals that same number. Do not count in-process: the point is that the number on disk matches the
number of child processes that actually ran, which is the property the pinned internal retry
exists to make true.

Build the step cap by calling `bounds::resolve` and reading `max_steps` off the returned value,
and build the escalation budget by calling `escalate::resolve` with that value. Never reference
`bounds::DEFAULT_MAX_STEPS` in this file: the Phase 20 review found a Critical hiding behind a
guard that compared two constants instead of the resolved value, and this file is where that shape
would recur.

Add the boundary arms as a matched set, each driving a real run rather than only calling the
resolver: a budget one below the resolved step cap runs and parks on the cap; a budget equal to
the resolved step cap refuses before the run exists; a budget of zero refuses before the run
exists. Assert that the two refusals produce no run directory and no journal, so the refusal is
genuinely above the run.

The arms needing the real binary are `#[ignore]`d and FAIL loudly with a naming diagnostic when
run without it; the resolver boundary arms are pure and run everywhere. Add a non-ignored guard
asserting both sets are present.

| model-named action → the record that describes it | the named string is attacker-influenced and is written into a file users commit and read |
