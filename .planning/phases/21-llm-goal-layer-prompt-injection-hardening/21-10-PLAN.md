<objective>
Close the two Warning-level defects `21-VERIFICATION.md` recorded in its
anti-patterns table but deliberately did **not** elevate to blocking gaps. They
are planned here rather than deferred because both are confirmed live, both are
cheap, and both undermine an affordance this phase shipped.

- **WR-02** (`src/driver/run.rs:1005`, `:1126`, `:2808`): `set_escalations_used`
  is called at `:3285` immediately before the normal-path `finish`. Three other
  production paths call `finish` without it — `shutdown_on_terminate`,
  `shutdown_during_startup`, and the spawn-failure arm. A goal-driven run always
  spends one consultation before any of them can fire, because the decomposition
  happens above `execute_run`, so those runs write `escalation_cap: Some(n)` and
  `escalations_used: null`. The field's own doc (`src/journal/mod.rs:1250-1265`)
  says the value is recorded unconditionally precisely so a reader can tell it
  apart from "a build that predates the counter" — the ambiguity these three
  paths reintroduce, on the runs a reader most wants to audit.
- **WR-04** (`src/ui/screens/driver_confirm.rs:519-524`): when a withdrawal
  succeeds in memory but `save_config` fails, the revert calls
  `registry::record_opt_in`. That is not a restore — it is the *only* constructor
  of a `DriverOptIn`, and it stamps a fresh `opted_in_at` and a fresh
  `current_prompt_inputs` snapshot. A project whose `CLAUDE.md` was rewritten
  under a `git pull`, and which would have been refused at the spawn gate with
  `OptInError::PromptInputsDrifted`, comes back with the new bytes already
  approved — and the next successful save persists it.

Purpose: WR-02 is an auditability hole on exactly the killed and failed-to-spawn
runs an operator investigates; WR-04 launders the drift the SHA-256 disclosure
digests were added in plan 21-03 to catch. Neither blocks re-verification of
criterion 1, so this plan is last — but neither is dropped.

Output: one stamped terminal-write helper with a guard that keeps it single, a
revert that restores rather than mints, and a regression test for each.
</objective>
