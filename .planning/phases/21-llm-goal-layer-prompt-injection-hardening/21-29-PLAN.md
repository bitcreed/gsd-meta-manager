<objective>
**Round 10, wave 1. A claim the tree does not satisfy is a claim, not a control.**

`src/text.rs` declares `render_for_terminal` **the ONE composition of the two classes,
resolved once so that no consumer re-decides which halves apply**. `detail.rs`'s `shown()`
was moved to it in round 9 with an explicit argument — a `.planning/` file can carry a raw
`ESC` just as easily as a `U+202E`, so that file no longer decides which halves apply, it
inherits the resolution. `main.rs`'s CLI echoes and `LegacyRegistryKey`'s display were moved
for the same stated reason.

**`normal.rs` draws the same `ProjectState` fields and the same registry key, and still calls
`display_identity` alone.** So does every `ctx.input_buffer` echo, every `ctx.error_message`
echo, and the roadmap widget. The one-composition claim is not true of this tree.

**What this plan is careful NOT to claim.** ratatui 0.30 filters `char::is_control` graphemes
in both `Span::styled_graphemes` and `Buffer::set_stringn`, so the control class does not
reach a terminal cell today through any widget family. That is exactly why the reviewer rated
this a WARNING and not a BLOCKER, and prohibition 2 forbids dressing it up as a live leak.
What this plan closes is **a false claim** and **a residual that rests on dependency
behaviour asserted nowhere in this tree and that does not travel** — `ctx.error_message` and
`ctx.status_message` are also produced by non-TUI paths, where no ratatui filter exists.

And the claim stops being a sentence: a census in `src/ui/mod.rs` asserts it, with exactly
two exemptions named with their reasons, and a non-ban control arm so the next author cannot
satisfy it with a rename.

**Two more controls that would lie if they were ever asked a harder question.**

*WR-07:* `parse_backlog_items` sorts `.planning/` directory names on
`partial_cmp(..).unwrap_or(Equal)` over an `f64`. A not-a-number suffix parses successfully,
the comparator stops being transitive, and the Backlog tab's order becomes silently wrong.
The reviewer called this a panic; **verification pass 10 built a standalone program on this
toolchain and measured that it is not** — `slice::sort_by` produces a wrong order without
complaint. Prohibition 3 requires this plan to fix the real defect and record the refutation
rather than inherit the stronger claim.

*WR-08:* `the_debug_route_of_every_alias_carrying_variant_uses_this_projects_own_notation`
builds its expected value by concatenating the escaped form of *every* invisible character in
the fixture. It works because every member of `LOOK_ALIKE_PAIRS` happens to carry exactly
one. Add a two-character fixture — which this phase's own arguments make likely — and the
test goes red for a **correct** implementation. That is a latent trap on a control this phase
depends on, in a fixture list this phase keeps extending.

**What this plan does NOT touch, stated so the wave stays parallel.** `detail.rs` and
`text.rs` are **21-27**'s. `driver.rs`, `driver_confirm.rs`, `src/ui/screens/mod.rs` and
`render_escape_guard.rs` are **21-28**'s. Note the fence between `src/ui/mod.rs` — this
plan's file — and `src/ui/screens/mod.rs`, which is not: they are different files.
</objective>
