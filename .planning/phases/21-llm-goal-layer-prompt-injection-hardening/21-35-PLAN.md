<objective>
**Round 12. One gap. The build emits an argv it can no longer read.**

Verification pass 12 scored 90/91 must-haves and recorded `gaps_remaining: []`. **The verifier was
wrong.** The independent code review found one real defect and the orchestrator re-confirmed it by
reading the source:

- **Producer** — `src/ui/screens/detail.rs:713` emits the **fused** form,
  `format!("{RESUME_OPTION_FUSED_PREFIX}{}", …)` with the prefix declared at `detail.rs:585`. One
  argv element.
- **Consumer** — `src/session_detector.rs:159-169` scans `args.windows(2)` for a standalone
  `--resume` and takes the next element. The **split** two-element form. The fused single element
  never equals that byte literal, so it never matches.
- **Confirmed:** the fused prefix appears at `detail.rs:585`, `:713` and three times in `detail.rs`'s
  own tests (`:7660`, `:7805`, `:7808`) — and **nowhere else in `src/`**. There is no
  `starts_with` on the fused prefix anywhere in the crate.

**The effect is a silent capability deletion in the exact feature this phase spent eleven rounds
hardening.** A session the TUI itself resumes cannot have its id read back out of
`/proc/<pid>/cmdline`. It becomes undetectable in the Sessions tab and therefore un-resumable. No
error, no log — just a row that stops being actionable. The resume loop that worked at `2c13fcf`
(resume a session, see it, resume it again) is broken.

**The fix goes on the consumer, and only there (D-21-66).** Round 11 *measured* the alternative at
`claude` 2.1.248: a `--` end-of-options separator closes the injection and DELETES the resume —
probe D (`claude --resume -- <valid-uuid>`) returns byte-identical output to probe C
(`claude --resume -- --version`), both the `requires a valid session ID` error. Fusion has neither
cost. So the producer is right and stays. The consumer learns the fused form **in addition to** the
split form, because a human typing `claude --resume <id>` by hand still produces the split one and
dropping it would re-break detection for every session not started by this TUI.

**And the lesson is half the deliverable.** The doc comment above `read_session_id` argues, under
`# No control is added in this file, deliberately`, that the property that matters is a property of
the SINK and that a second assertion here would let the class be counted as closed twice. **That is
correct about the *security* property and is precisely what hid the *functional* coupling.** Fusing
at the producer changed the wire format the consumer parses; every control lived on one side or the
other; **no control spanned both**. So a build that had silently lost its resume detection passed
the whole gate green.

This round therefore does three things, not one:

1. Teaches the consumer both wire forms, with the pass-through, the trim check and the `Untrusted`
   wrap all intact (D-21-67).
2. Adds the control that spans producer and consumer together — a **round trip**: what
   `resume_terminal_argv` emits is NUL-joined into the `/proc` encoding and driven through the real
   parser, over the shared 28-fixture hostile corpus, in **both** wire forms. **Observed RED against
   the pre-fix parser first** (D-21-68, D-21-69).
3. Corrects the falsified reasoning **in place, at the sentence**, quoting it verbatim and leaving it
   standing (D-21-70), and writes the phase-21 `ui.safety-gate` rationale down durably so it stops
   being re-derived ad hoc every round (D-21-71).

**This is a deliberately SMALL round.** One plan, one wave. No new mechanism, no new census, no
generalisation to sibling argv builders. The code change is small and well-defined; the round-trip
control and the doc correction are the substance.

Requirements addressed: **DRIVE-01** (a resumed run must remain findable for the goal to be pursued
across commands), **DRIVE-03** and **DRIVE-04** (the detector's parse boundaries), **SAFE-07** (the
untrusted-id boundary and its wrap), **SAFE-08** (the fused argv that keeps a hostile id from
becoming an option — preserved, not weakened).
