<objective>
Make TRANS-02 a testable correctness claim rather than an assertion: derive a run's outcome
from the terminal envelope, the exit code, the disk fingerprint and git — and prove it stays
correct when those sources disagree (D-10, D-11, D-26, D-29, D-32).

Purpose: ROADMAP success criterion 2 says the outcome must be correct "even when the agent's
own prose summary says otherwise". Disagreement between sources is only observable in a
matrix, which is why D-26 asks for a test per distinguishable combination rather than a happy
path. Two of the terminal states this phase can actually reach were not in the original
decision list at all, and the phase spike proved the terminal envelope is a TURN boundary —
an executor that reads the first one truncates every steered run while reporting success.

Output: `src/executor/outcome.rs` carrying the full derivation matrix and the disk/git delta,
plus the two git helpers it needs, added beside the existing ones.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| terminal envelope → user-visible verdict | Fields written by the agent's runtime become the tool's statement about what happened |
| agent prose → verdict | The model-authored summary string is present in the envelope and must never reach any derivation branch |
| git and filesystem → delta | The project's own state is read to corroborate or contradict the envelope |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-20 | Spoofing | the agent's prose summary being trusted as the verdict | high | mitigate | D-10: the derivation reads only the structured fields, the exit code, and the disk/git delta. The primary result field is carried for display and no derivation branch reads it; a test proves a success envelope with no disk change is a no-op rather than a success. |
| T-15-21 | Repudiation | a steered run truncated at the first terminal envelope and reported as succeeded | high | mitigate | D-29: envelopes are collected per turn and the run-level outcome derives from the LAST one; fixture 05 pins this with a test asserting exactly one run outcome from two envelopes. |
| T-15-22 | Tampering | a panicking accessor on an absent envelope field aborting the derivation | medium | mitigate | The primary result field is optional and error envelopes omit it; the non-test region carries no panicking accessor and the criterion asserts that mechanically. |
| T-15-23 | Information disclosure | the notional cost figure being presented as a real charge | low | mitigate | Under subscription auth this figure prices work that is not billed per call; it is carried as data with a doc comment saying so, and the prohibition above forbids presenting it as what the run cost. |
| T-15-24 | Denial of service | shelling out to git in a non-repository project | low | mitigate | Both new helpers return an option and never propagate an error for a project that is not a git repository, following the existing file's failure posture; a test covers the non-repository case. |
</threat_model>
