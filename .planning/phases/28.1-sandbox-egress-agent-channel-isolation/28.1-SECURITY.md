# Phase 28.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| sandboxed driver -> egress unix socket | every byte is attacker-controlled; the driver can bypass the bridge and write raw HTTP | HTTP requests (untrusted) |
| egress server -> api.anthropic.com | the real token crosses here; only fully judged requests may | run token (secret), inference bodies |
| egress server -> allowlisted CONNECT hosts | DNS answers are untrusted (rebinding) | TLS tunnels, resolved addresses |
| in-sandbox bridge -> egress socket | untrusted convenience; holds no policy and no secret | relayed bytes |
| sandboxed driver -> its own settings tiers | the driver can start a nested claude with any config dir, settings file or setting source | settings / hooks |
| host /etc/claude-code -> per-run managed file | administrator policy must survive into the sandbox | managed policy |
| driver-written checkout -> host git run by the push step | config, hooks, attributes, pointers are attacker-controlled | git config / filters |
| driver-written project files -> operator's later unsandboxed tools | `.git`, `.claude`, `.envrc`, `.vscode`, `.mcp.json` | executable config |
| launcher -> state.json / DIRECTION frontmatter | posture words launcher-chosen; planted paths driver-chosen | frontmatter text |
| operator config -> egress allowlist | hand-written config decides CONNECT reach | host names |
| driver-written run files -> TUI | frontmatter values are driver-influenced text | untrusted display text |
| run artifacts -> outside coordinator | DIRECTION.md and `.planning/` read by agents outside the sandbox | plan text (steering) |
| sandboxed driver -> operator `$HOME` / toolchain caches | everything not allowlisted must be invisible; caches compiled from later | credentials, crates |
| host settings -> per-run settings | user hooks are programs the driver triggers | hook commands |
| sandbox -> host network namespace / filesystem sockets | fresh netns with only `lo`; `/run`, `$XDG_RUNTIME_DIR`, `/tmp` tmpfs | sockets |
| host env -> driver env | routing variables scrubbed, launcher sets applied after | env vars |
| sandboxed process -> host kernel | same uid; the sandbox is not a VM | syscalls |
