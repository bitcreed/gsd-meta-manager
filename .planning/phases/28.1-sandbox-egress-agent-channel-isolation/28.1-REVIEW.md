## Warnings

### WR-04: A `bin/` or `versions/` parent grants the whole grandparent, whatever that directory is

**File:** `src/launcher/home.rs:195-202` (`install_root`), `:245-248` (the exe bind), `:88-99` (`REFUSED_ROOT_REL`)
**Issue:** _Persists, narrowed. 870a027 fixed the parent fallback._ The rule is now "the parent is named `bin` or `versions`, so bind the grandparent unless it is on a fixed refusal list". The check is on directory names only; nothing shows that the grandparent belongs to one product. Anything under `$HOME` whose child is called `bin` is bound whole and read-only:
- `/home/u/work/bin/tool` binds `/home/u/work`.
- `/home/u/Downloads/bin/tool` binds `/home/u/Downloads`.
- `/home/u/projects/bin/tool` binds `/home/u/projects`.
- `~/go/bin/x` binds all of `~/go`, including `src/` and `pkg/mod`.

`REFUSED_ROOT_REL` blocks only `.local`, `.local/share`, `.local/bin`, `.config`, `.cache` and `bin`. Sibling content (other repositories with `.env` files, installers, notes) becomes readable in the sandbox. This is the exposure WR-04 described, now narrower but still reachable from the user's own layout.
**Fix:** Require the grandparent to be a dedicated tool root. For example, accept it only when it lies at least two levels under `$HOME`, or sits under a known tool prefix (`.nvm/versions`, `.local/share/<tool>`, `.cargo`, `.rustup`, `.bun`, `.volta`, `.deno`, `.sdkman`, `.asdf`). Otherwise bind just the file. Add a golden test for `/home/u/work/bin/tool` expecting `ro /home/u/work/bin/tool` and no `ro /home/u/work`.

### WR-11: The tunnel idle limit is applied per direction, so a long one-way transfer is cut

**File:** `src/launcher/egress/mod.rs:827-830` (`tokio::try_join!` of two `pump`s), `:848-850` (the idle timeout inside `pump`); the doc claim at `:82-84` and `:789-791`
**Issue:** _New (introduced by the WR-02 fix f5bab13)._ `TUNNEL_IDLE` is documented as "no byte in either direction" for 5 minutes. The code gives each direction its own `timeout(idle, from.read())`. A direction that stays silent for 300 s returns `Err(TimedOut)`, and `try_join!` then drops the other direction mid-transfer.

Consequences for allowlisted hosts (D-07):
- A download whose request is sent once and then streams for more than 5 minutes (slow link or large artifact) is cut, because the client-to-upstream pump sees no byte.
- A large upload where the server answers only at the end is cut, because the upstream-to-client pump sees no byte.

The previous `copy_bidirectional` had no such limit. The tests do not catch it: `a_silent_tunnel_ends_at_its_idle_limit` has no traffic in either direction, and `a_busy_tunnel_still_ends_at_its_lifetime` ends at the lifetime limit before the idle limit could matter.

I reproduced it with a scratch crate at `/tmp/claude-1000/-home-blk-projects-rust-gsd-meta-manager/30911796-0f3c-4659-8e08-ce10f00ad0d8/scratchpad/tun`. The same `pump` and `try_join!` shape was used, with a 200 ms idle limit and the upstream streaming for 1 s while the client stayed silent. The output was `Err(TimedOut "idle")` and `download cut`.
**Fix:** Make idleness a property of the tunnel, not of a direction. Share a last-activity timestamp, for example an `Arc<AtomicU64>` of elapsed milliseconds that both pumps update on every read or write. Run one supervisor that fires when `now - last_activity > idle`. Each `pump` then waits on `read` without its own timer. Add a test that streams upstream-to-client for longer than `idle` while the client sends nothing, and expects success.

### WR-12: A truncation the baseline also had makes the guard's coverage depend on a cutoff that moves between snapshots

**File:** `src/launcher/push/planted.rs:949-957` (`ScanIncomplete` downgrade), `:267-278` (`list_dir_bounded`), `:862-876` (`entry_change` for `*/.git`)
**Issue:** _New (follow-on to the WR-08 fix 2d5ab57)._ The docs and the new test assume that "a truncated snapshot is a function of the tree". That holds for one tree. The guard compares two different trees (baseline and now). The cut-off point of a name-ordered, budgeted pre-order walk moves whenever the number of entries visited before it changes.

Trace, with limit 10 and a root holding `a/` (5 files), `b/` (5 files) and `z/.git`:
- Baseline: root takes 3 and `a` takes 5, so 8 are used. `b` has 5 entries against a room of 2, so the walk is truncated and `z/.git` is never recorded.
- After the agent deletes 4 files in `a/`: root takes 3, `a` takes 1, `b` takes 5, `z` takes 1. This records `z/.git` and `z/.git/config`.
- `diff` then reports `z/.git` as `Created`. `entry_change` turns that into `NestedGit` or `WorktreePointer`, both git-relevant, so the push is refused for a repository that was already there.

The same drift hides real plants. Anything the driver puts after the cutoff is unseen, and `scan-incomplete` does not block. 2d5ab57 documents the second half as accepted.

The first half is not documented, and it defeats the point of WR-08 in the one situation it targets: a baseline-truncated checkout. A routine clean-up (`rm -rf dist`) produces phantom blocking findings, while additions go unnoticed. The code does not make the downgrade safe by keeping the nested-`.git` entries out of the comparison when both sides are truncated.
**Fix:** Pick one of these.
- Record the baseline's cutoff, for example the last visited path, in `Snapshot`. When both sides are truncated, compare nested-git and pointer entries only up to that cutoff, and report entries beyond it as `ScanIncomplete`.
- Or stop truncating by budget: skip git-ignored and `SKIP_DIR_NAMES`-like directories (the review's original suggestion), and keep a per-subtree budget.
- At least, state the drift in `docs/DRIVER-SANDBOX.md`, next to the "undetected plant" sentence.

### IN-07: The case-variant refusal covers four positions; the content-block policy reads are still exact-case

**File:** `src/launcher/egress/policy.rs:206-221` (the new checks), `:264-284` (`remote_source`), `:395-401` (doc comment on `judge_body`)
**Issue:** _Persists, narrowed. 84a4053 closes `Tools`, `MCP_SERVERS`, `Container` and `tools[].Type`._ `remote_source` reads `source`, `source.type` and the nested block `type` (`url`, `file`, `mcp_tool_use`, `mcp_tool_result`, `container_upload`) with exact-case lookups. A case-folding decoder would read `{"type":"image","Source":{"Type":"url",...}}` as a URL-sourced block, and the policy would forward it. The fix note acknowledges this ("Positions the walk reads deeper remain exact-case only"). The `judge_body` doc comment says "elsewhere a name's case is data", which hides the fact that the policy reads those names too.
**Fix:** Run `is_case_variant(key, &["source", "type"])` on every object inside `remote_source`. PascalCase `input_schema` and `tool_use.input` keys do not collide, because only the two names are checked. Or reword the doc comment to list the unchecked positions. Update `28.1-SECURITY.md` T-28.1-41 either way.

### IN-08: `PLANTED <n>` counts the non-blocking `scan-incomplete` line

**File:** `src/launcher/run.rs:996-1013` (`record_planted` stores every finding), `src/ui/screens/driver_run.rs:1162-1168` and `:1119-1133` (`planted_count`)
**Issue:** `record_planted` writes `render_bounded(&found)` into the run's `planted` list, including `scan-incomplete .`. The header then shows a Yellow BOLD `PLANTED 1` on every large repository for the whole run, although nothing was planted and the push is not blocked. That recreates the alert fatigue WR-08 set out to remove, and it trains the operator to ignore the `PLANTED` group.
**Fix:** Count only git-relevant lines in the header, or render `ScanIncomplete` as its own muted token such as `scan incomplete`. Add a test with `planted = ["scan-incomplete ."]`.

### IN-09: The `.git/worktrees` listing is outside the entry budget the module advertises

**File:** `src/launcher/push/planted.rs:395-407` (`record_root_git`); the claim at `:53-62`
**Issue:** The new doc comment on `MAX_WALK_ENTRIES` says a flood directory "cannot make the push step hold more than `MAX_WALK_ENTRIES + 1` listing entries". `record_root_git` iterates `read_dir(.git/worktrees)` with no bound and runs three `entry_of` reads per child. The directory sits inside the project's read-write bind, so the driver can fill it. The effect is a stalled or memory-heavy push step; no secret is exposed.
**Fix:** Route it through `list_dir_bounded` with the shared `Budget`, and mark the snapshot truncated when it is over budget. Or narrow the doc claim to the two walks.

### IN-10: A comment in `handle` says an unparsable head is "not logged"; the code logs it

**File:** `src/launcher/egress/mod.rs:454-466`
**Issue:** The comment says a connection that never produced a complete head is "answered where there is anyone to answer, and not logged". For `Timeout`, `HeadTooLarge`, `BodyTooLarge` and `Malformed`, `ctx.deny` calls `log.record(...)` (`:330-340`) before replying. Only `Closed` and `Io` skip the log. The behaviour is the better one, because the refusal share relies on these lines. The comment misleads whoever audits the log.
**Fix:** Reword to "a connection that closes before a head, or fails at the I/O level, is not logged; every other failed head is logged as `refused`".

### IN-11: Rotation lets 16 MiB of allowed traffic evict earlier refusal evidence

**File:** `src/launcher/egress/log.rs:69-74`, `:172-195`, `:243-248`
**Issue:** _Residual of WR-10, acknowledged in 28.1-REVIEW-FIX.md._ The refusal share stops junk refusals from pushing out carried-out requests. The reverse still works: a driver that issues enough allowed requests rotates the file twice. An allowlisted `CONNECT` to a public host costs about 100 bytes of log, so roughly 170,000 of them fill both files. That erases the earlier `denied:` lines, such as probes of metadata addresses or IP literals. The marker line does not say how many records fell out. The `EgressStats` counters keep totals but no hosts.
**Fix:** On rotation, carry a one-line summary of the file being discarded into the new file. For example, count `denied` lines by class and list the distinct refused `CONNECT` hosts, capped. Or keep a small append-only `egress.refusals.log` with its own cap for refusals only.
