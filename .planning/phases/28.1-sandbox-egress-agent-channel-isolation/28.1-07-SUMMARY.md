# Phase 28.1 Plan 07: Wire the egress server and bridge into `driver launch` Summary

**Every bwrap-scope launch now starts a launcher-side EgressServer that alone holds the run token, runs the driver as `bridge -- claude` on a dummy token with the operator's `driver.egress` allowlist enforced by the CONNECT proxy, and records `auth`, `egress_allow` and `inference_requests`; proved by a real launch (200 / 403 / 200 / 0 / 403) on this host.**

## Performance

- **Duration:** about 22 min (2026-10-24T23:01:25Z to 23:24Z, plus this summary)
- **Tasks:** 3 (tracer, TDD, auto), 4 code commits
- **Files:** 1 created, 11 modified

## Accomplishments

- `supervise` binds the egress socket (`bind_run_socket`, run lock held, stale socket replaced), builds `TokenProvider::Static` (stored) or `TokenProvider::Host` (host login, re-read per request), starts `EgressServer` and holds it in `EgressGuard`; `finish()` stops it after the driver is reaped and returns the `EgressStats`, `Drop` stops it and unlinks the socket on every other path.
- Env: both postures get `CLAUDE_CONFIG_DIR`, `DRIVERCTL_SOCK`, `DRIVER_LOCK_HELD`, `PATH` and `common_env_sets()`; bwrap adds `egress_env_sets(3128)` (dummy token), degraded adds the real token.
- `LaunchOptions.egress_allow` resolved by `driver launch` (exit 1 with `projects.<alias>.driver.egress: ...` before anything is written) and by the TUI (status-line refusal, nothing launched); `launch_options_for` gained the argument.
- `launch_posture(ctx)` records `auth` and (bwrap only) `egress_allow` right after `begin_launch`; `record_inference_requests` adds each launch's forwarded count to the stored total; one stderr warning when the launcher's env sets `HTTPS_PROXY`/`https_proxy`.
- Live evidence, `launcher_live_egress::a_real_launch_reaches_the_api_only_through_the_proxy` (real systemd-run and bwrap, only `claude` faked, `rust` + `github-read` presets, host login token):
