# Phase 28.1: Sandbox Egress & Agent-Channel Isolation - Context

**Gathered:** 2026-10-24
**Status:** Ready for planning
**Mode:** unattended (operator unavailable; equivalent to `--auto`). Every decision not taken verbatim from
ROADMAP / AUDIT-FINDINGS / Phase 28 CONTEXT is tagged `[inferred — audit]`. Factual questions were settled
by live experiments on this Linux host (bwrap 0.11.1, claude 2.1.310, kernel 7.0, Ubuntu with
`apparmor_restrict_unprivileged_userns=1`); the prototypes are committed under `evidence/`, and the
"Evidence" section below summarises the results. Total probe spend: about $0.07.

**Operator goal (governs every trade-off):** the sandboxed driver must not be able to reach any agent
or service outside the sandbox that has more capability than it has.

<domain>
## Phase Boundary

Harden the Phase 28 bwrap sandbox (`src/launcher/sandbox.rs` `bwrap_argv`, the per-run config dir, the
gate's settings and the push step) so a confined driver has no outward channel:
- network egress only through launcher-owned proxies outside the sandbox;
- the run token never enters the sandbox;
- `$HOME` exposed by allowlist;
- planted files that the operator later executes are blocked or flagged;
- agent-to-agent tools denied by a policy that a nested `claude` cannot shed;
- regression tests for the channels that are already closed;
- degraded mode lists which protections it lacks.

Every AUDIT-FINDINGS item (A1-A5, B1-B5) plus the new channels found during this discussion (B6 below)
must end up closed with a test, verified as closed, or documented as accepted residual risk.

Out of scope:
- macOS functional sandbox: degraded only, as before;
- the Phase 30 launch-form layout beyond showing the absent-protections list (28.1 supplies the data
  and the one-line rendering);
- the Phase 31 threat-id closures. Phase 31 closes them, pointing at 28.1 mechanisms.
</domain>

### Network egress (SC1, LNCH-09)
- **D-02:** bwrap gains `--unshare-net --unshare-ipc --unshare-uts --hostname <fixed>`.
  - Verified working unprivileged on this host despite the AppArmor userns restriction.
  - Inside, only `lo` exists.
  - 127.0.0.1:8787 (claudear), LAN 192.168.x, 1.1.1.1, the docker bridge nets and `@/tmp/.X11-unix/X0`
    are all unreachable (refused or unreachable); all are reachable today.
  - SysV shm segments go from 1 to 0.
- **D-03 (new channel B6):** `--tmpfs /run` is added after `--ro-bind / /`, and before the
  `$XDG_RUNTIME_DIR` tmpfs and the driverctl socket re-bind.
  - Evidence: with `--unshare-net` alone, `/run/docker.sock` still works from inside. The user is in
    the docker group, and `GET /info` returned 200. That is root-equivalent and beats every other
    control (`docker run --network host -v /:/host`).
  - Also reachable: the system D-Bus, snapd, `/run/ssh-unix-local/socket` (mode 666), systemd
    varlink, cups, avahi and pcscd.
  - `/var/run` is a symlink to `/run`, so the tmpfs covers both. claude ran normally with it.
  - A live test asserts that `find / -xdev -type s` inside lists only the driverctl socket and the
    egress bridge. `[inferred — audit]` for the exact assertion form.
  - Abstract sockets are handled by D-02.
  - Not copied from sandbox-runtime: its seccomp blanket AF_UNIX ban, because it would break the
    driverctl hook shim. Filesystem hiding is precise here because `/`, `/run`, `/tmp`, `$HOME` and the
    runtime dir are all covered.
- **D-04: Inference goes through a token-injecting reverse proxy; the run token never enters the
  sandbox.** `[inferred — audit]`
  - The launcher serves a plain-HTTP reverse proxy for `api.anthropic.com` on a unix socket.
  - Inside, `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` and `CLAUDE_CODE_OAUTH_TOKEN` is a fixed dummy
    (`sk-ant-oat01-DUMMY…`).
  - The proxy drops inbound `authorization` / `x-api-key` headers, injects the real token, and forwards
    over TLS.
  - Why: the token probe showed `CLAUDE_CODE_OAUTH_TOKEN` is readable inside via
    `/proc/<claude pid>/environ` (same uid, same pid namespace). The driver could lift it and `curl` the
    account APIs, which beats every client-side gate and deny rule.
  - Measured: `claude -p` works on the dummy (`POST /v1/messages?beta=true → 200`); no refresh attempt;
    no platform.claude.com traffic.
  - Supersedes Phase 28 D-19's "token passed in the environment" for bwrap-scope runs. Degraded runs
    keep the env token and record its absence as a missing protection (D-27).
  - **Reversibility:** costly. The auth path, env contract and acceptance harness all change.
- **D-05: Path allowlist plus body check on the reverse proxy.** `[inferred — audit]`
  - Only `POST /v1/messages` and `/v1/messages/count_tokens` (any query string) are forwarded; anything
    else gets a fast 403.
  - Measured: with the full-scope host token injected and no filter, `GET /v1/code/sessions` returned
    200. With the filter, `/v1/code/sessions`, `/v1/code/triggers`, `/v1/mcp_servers` and
    `/v1/environments/bridge` all returned 403.
  - The proxy also parses the JSON body and refuses a request that carries an `mcp_servers` field or a
    server-side tool other than `web_search`, such as `web_fetch` or code execution. Without that check,
    a `/v1/messages` call could ask Anthropic's servers to reach out. This check is UNVERIFIED in live
    traffic; research must confirm the field and tool-type names against the current API and the
    traffic claude actually sends.
  - Supports Content-Length and chunked bodies.
  - The log records method, path, status and request count only, never headers, under the run's data
    dir.
- **D-06: CONNECT proxy for everything else, deny by default.**
  - The launcher serves an HTTP CONNECT proxy. Port 443 only. Every request is logged.
  - Allows only hosts from the run's egress allowlist.
  - Applies a resolved-address guard: an allowlisted name that resolves to a loopback, link-local or
    private address is refused (sandbox-runtime prior art, DNS rebinding).
  - CONNECT to `api.anthropic.com` is DENIED, so all inference goes through D-04/D-05. Measured: once
    `skipWebFetchPreflight` is set, nothing needs a direct CONNECT to it. The only remaining attempts
    (the WebFetch preflight and RemoteTrigger org lookups) are exactly what must be blocked.
  - Inside: `HTTPS_PROXY` / `https_proxy` / `HTTP_PROXY` / `http_proxy` point at the bridge, and
    `NO_PROXY=127.0.0.1,localhost`.
  - Claude Code has no SOCKS support; HTTP CONNECT is the only option (docs).
- **D-07: Package and git hosts come from an operator-configurable allowlist, default empty. Offline
  vendoring is deferred.** `[inferred — audit]`
  - Named presets the operator opts into per project:
    - `rust`: `index.crates.io`, `static.crates.io`, `crates.io`;
    - `github-read`: `github.com`, `codeload.github.com`, `objects.githubusercontent.com`;
    - `npm`: `registry.npmjs.org`;
    - `python`: `pypi.org`, `files.pythonhosted.org`;
    - plus free-form extra hosts.
  - Stored in gsd-mm's config per project (exact key is the planner's call, under the existing
    `driver.*` table).
  - The active list is recorded on the run as an additive frontmatter key (`egress_allow: [...]`) and
    shown with the posture.
  - Rationale:
    - The driven project can be any GSD project, so vendoring is per-ecosystem work and breaks new
      dependencies mid-run.
    - A fixed broad allowlist adds ingress and exfil surface for runs that don't need it.
    - None of these hosts gives more capability without credentials: anonymous gist/API writes fail,
      and D-10/D-12 keep credentials out.
  - Residual: allowlisted hosts are prompt-injection ingress and a low-bandwidth exfil path. That goes
    in the residual-risk doc (D-26).
- **D-08: In-sandbox bridge is a hidden `gsd-meta-manager bridge <listen-port> <unix-sock>`
  subcommand.**
  - Started inside bwrap before claude (a small wrapper as the bwrap command, or the bridge
    double-forks and execs claude; planner's call).
  - No socat dependency (socat is not installed here, and sandbox-runtime needs it) and no python.
  - One TCP listener can serve both proxies, or two ports, one per proxy; planner's call.
  - The binary is already ro-bound via the `current_exe()` bind (D-11).
- **D-09: The proxies run in-process in the launcher on tokio, one pair per run.**
  - Sockets live under `$XDG_RUNTIME_DIR` with short names (`gsdmm-egress-<hash8>.sock`), because
    `sun_path` is limited to 108 bytes and the prototype hit `AF_UNIX path too long` from a deep path.
  - Re-bound into the runtime-dir tmpfs like the driverctl socket.
  - The launcher already owns the run's lifetime (Phase 28 D-04), so no new daemon is needed.
- **D-09a: Environment additions inside:**
  - `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1`, `DISABLE_AUTOUPDATER=1`,
    `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `ENABLE_CLAUDEAI_MCP_SERVERS=false`;
  - strip `TMUX` and `TMUX_PANE` (claude tried `/tmp/tmux-1000/default` because `TMUX` leaked);
  - per-run `settings.json` gets `"skipWebFetchPreflight": true` and `"disableClaudeAiConnectors": true`.
  - Measured: with these set, a headless run contacts only `api.anthropic.com`, and `example.com` is
    refused by the proxy.

### Auth posture (SC4, LNCH-12)
- **D-10: Setup-token preferred; host-token fallback kept but recorded.** `[inferred — audit]`
  - Evidence:
    - The bundle's setup-token flow calls
      `startOAuthFlow({inferenceOnly:true, expiresIn:31536000})` and requests only `user:inference`.
    - The host login token carries `user:file_upload user:inference user:mcp_servers user:plugins
      user:profile user:sessions:claude_code`.
    - This host has no stored setup-token, so every launch today uses the full-scope host token.
  - With D-04/D-05 the token never enters the sandbox, and only `/v1/messages` reaches the API, so
    even the host token is path-confined.
  - The fallback stays (Phase 28 D-22/D-23) but is recorded as posture `auth: host-token` vs
    `setup-token` (additive key) and shown in the TUI. The Driver tab tells the operator to run
    `driver auth setup` to shrink the server-side scope.
  - Refusing the fallback outright was rejected. It would make every launch on this host fail today,
    and D-04/D-05 already contain it.
- **D-11: SC4 probe.**
  - A committed probe (opt-in live test plus script) runs from inside the sandbox with the stored token.
  - It deliberately bypasses the proxy filter: a direct `curl` with the token on the host side of a test
    harness, and a forged `CLAUDE_CODE_OAUTH_SCOPES` to defeat client gates. Read-only requests:
    - `GET /v1/mcp_servers?limit=1`;
    - `GET /v1/code/triggers`;
    - `GET /v1/code/sessions`;
    - the Remote Control eligibility/profile check.
  - It records the status codes.
  - Positive control: the host token, already measured 200 for sessions and connector listing.
  - **Human prerequisite:** minting a setup-token needs browser OAuth (`driver auth setup`). It is the
    only part of this phase an agent cannot do. If no stored token exists at verify time, the probe
    records `NOT-RUN: no setup-token` and SC4's "settled by evidence" rests on:
    - the static bundle evidence above;
    - the measured fact that D-05 refuses those paths regardless of token scope.
  - Flag that as the single human UAT item.

### Agent-to-agent tools and the nested-claude gap (SC4, SC5, LNCH-12/13)
- **D-12: Gate policy moves into a managed-settings file bound at `/etc/claude-code/`.**
  - Why: a nested `claude` with a different `CLAUDE_CONFIG_DIR` fired no gate hooks, and with
    `--settings <file>` it fired only that file's hooks.
  - Measured mechanism: `--overlay-src /etc --tmp-overlay /etc` then
    `--ro-bind <per-run managed dir> /etc/claude-code`.
  - Managed PreToolUse hooks then fired under every bypass tried:
    - `--setting-sources user|project`;
    - a foreign `CLAUDE_CONFIG_DIR`;
    - `disableAllHooks:true` in user settings or `--settings`;
    - `CLAUDE_CODE_MANAGED_SETTINGS_PATH` pointed elsewhere;
    - `--bare` with an `apiKeyHelper` (only SessionStart is skipped under `--bare`).
  - What moves out of the per-run `settings.json` into the managed file:
    - the gate's PreToolUse / PostToolUse / Stop entries (moved, never duplicated, so nothing is
      double-counted);
    - the deny rules (D-13).
  - The driverctl socket path is baked into the hook command line, so unsetting `DRIVERCTL_SOCK` can't
    escape. `onFailure: block` stays.
  - If the host has its own `/etc/claude-code/*`, its contents are merged into the per-run file, never
    hidden. The admin's policy stays in force.
  - **Reversibility:** costly. Gate wiring, golden tests and the acceptance harness move.
    `[inferred — audit]`
- **D-13: Deny rules** in the managed file's `permissions.deny`:
  - `Cron*`, `RemoteTrigger`, `SendMessage`, `ListAgents`, `ScheduleWakeup`, `DesignSync`,
    `mcp__claude_ai_*`.
  - Verified live under `--permission-mode bypassPermissions`:
    - deny rules hold;
    - the trailing `*` wildcard matches all three Cron tools;
    - `mcp__claude_ai_*` removes every connector tool;
    - a forced call returns "No such tool available".
  - `DesignSync` is denied on the inferred grounds that it is a cloud design feature with unanalysed
    reach `[inferred — audit]`.
  - `Workflow`, `Task`, `Agent` and `Monitor` stay allowed: they stay inside the cage and are counted
    by the gate.
  - Defence in depth on top of D-04/D-05, which are the real control.
- **D-14: A5 closes as follows:**
  - Hook-counted caps now see nested claudes (D-12).
  - Residual: raw API calls via the proxy with no tool use are invisible to hooks. They are bounded by:
    - the monitor's active-seconds cap;
    - `RuntimeMaxSec`;
    - `MemoryMax=6G` / `TasksMax=1024`;
    - the reverse proxy's request log.
  - The proxy counts `/v1/messages` requests per run and records the total on the run (additive key) so
    the operator can see out-of-hook usage. A request-count cap is NOT added. That would be new scope;
    see Deferred.
- **D-15: bwrap version floor.**
  - `--overlay-src` / `--tmp-overlay` need bwrap ≥ 0.10, and overlayfs in a user namespace needs kernel
    support (present here). Ubuntu 24.04 ships an older bwrap (UNVERIFIED version).
  - The launcher feature-detects (`bwrap --version` plus a dry probe).
  - When overlay is unavailable, the run proceeds and records `managed-settings` and `registry-overlay`
    as absent protections (D-27). The gate hooks stay in the per-run `settings.json` as in Phase 28, and
    the cargo registry is bound ro.
  - Research checks whether `--tmpfs /etc` plus per-entry ro re-binds is a viable fallback for old bwrap
    and adopts it if cheap.
  - CI is unaffected: argv builders are pure, live tests are opt-in.

### `$HOME` allowlist (SC2, LNCH-10)
- **D-16:** `--tmpfs $HOME`, then ro re-binds, all **before** the project, run-dir, config-dir and
  socket binds (the project lives under `$HOME`). Verified live:
  - `claude`, `node`, `cargo`/`rustc`, `rtk`, `gsd-meta-manager`, `git commit` and an offline cargo
    build all work;
  - all 16 GSD/rtk hook scripts work;
  - `gsd-tools` works;
  - a real `claude -p` runs with every hook succeeding.

  The allowlist, derived at launch (paths resolved from the running host, not hardcoded to this user):

  | Entry | Mode |
  |---|---|
  | realpath of `claude` and its install dir (`~/.local/share/claude`) | ro |
  | install root of `node`'s realpath (nvm etc.) | ro |
  | `$CARGO_HOME/{bin,env,config.toml}` and `$RUSTUP_HOME` (not all of `~/.cargo`, so `credentials.toml` is out by construction) | ro |
  | `$CARGO_HOME/{registry,git}` | `--tmp-overlay` (D-15); ro fallback; never rw, because a planted crate would be compiled later on the host |
  | `~/.claude/{agents,commands,skills,gsd-core,get-shit-done,hooks,scripts}` | ro |
  | `~/.claude/.gsd-profile`, `~/.gsd`, `~/.gsd-capabilities.json` | ro |
  | `~/.config/rtk` | ro |
  | realpath dir of `current_exe()` (gsd-meta-manager, for the driverctl shim and the bridge) | ro |
  | `~/.cache`, `~/.local/share/rtk` | per-run tmpfs |

  - `~/.claude/scripts` must also be added to `LINK_FROM_HOST`. `gsd-tools` crashed without
    `fix-slash-commands.cjs`; this is a latent Phase 28 bug.
  - Today's denylist misses `.boto`, `.pgpass`, `.password-store`, `.codex`, `.railway`,
    `.appstoreconnect`, `.electrum`, `.claudear` and several `~/.config/*` token stores. All are
    readable now and absent under the allowlist.
  - `[inferred — audit]` for the exact derivation rules.
- **D-17: Per-run gitconfig.**
  - The launcher writes a minimal per-run gitconfig and ro-binds it at `~/.gitconfig`:
    - `user.name` / `user.email` read from the host via `git config --get`;
    - `init.defaultBranch`.
  - Host `~/.config/git` is NOT bound.
  - Keeps out aliases, includes, `credential.helper` and other config-executed programs. Consistent
    with the Phase 19 T-19-118 lesson. `[inferred — audit]`
- **D-18: Symlinks out of the allowlist are not followed.**
  - Example: `~/.claude/skills/reap-worktrees` points into `~/projects/...`; bwrap never follows
    symlinks inside a bound dir, so it dangles inside.
  - Accepted loss, logged once at launch as a list of dangling entries.
  - Auto-binding symlink targets was rejected: it would widen the allowlist with whatever the user
    symlinked. `[inferred — audit]`
- **D-19: `settings_transform` drops hooks that are not GSD or rtk hooks.**
  - Today it copies the claudear hooks through. Under the allowlist they fail on every event, and they
    are a channel to the operator's phone bridge.
  - Keep only hooks whose command resolves inside the allowlist and matches the existing GSD/rtk keep
    rule.
- **D-20: Masks.**
  - `TMPFS_MASK_DIRS` is dropped from the argv. It is kept as a test invariant: no allowlist entry may
    overlap one.
  - `NULL_MASK_FILES` stays as a second layer for credential files that can sit inside an allowlisted
    dir (`.cargo/credentials*`, `.config/git/credentials`, the run-token file).
  - Phase 28 SC3 stays true; the mechanism under it changes, as AUDIT §D says.

### Planted-file guard (SC3, LNCH-11)
- **D-21: Per-path choice** (from bwrap and git experiments):

  | Path | Inside the sandbox | After the run |
  |---|---|---|
  | `.git/config`, `.git/hooks/` | ro-bind (when present) with `.git` itself self-bound so it cannot be renamed | hash + flag |
  | `.claude/settings.json`, `.claude/settings.local.json`, `.claude/{hooks,agents,commands}/` | ro-bind if present, with `.claude` self-bound | hash + flag (for paths that were absent) |
  | `.claude/skills/`, `CLAUDE.md` | rw (GSD writes them: `sketch-wrap-up`, quick tasks, `generate-claude-md`) | hash + flag |
  | `.claude/` as a whole | rw (harness worktrees live in `.claude/worktrees/`) | — |
  | `.envrc`, `.vscode/tasks.json`, `.mcp.json`, `.gitattributes`, `.git/info/attributes` | rw | hash + flag |
  | `.git/worktrees/*/{commondir,gitdir}`, worktree `.git` files, any new nested `.git` | rw (a ro-bind cannot close this class) | detect + flag |

  Evidence that drove each row:
  - **Parent rename:** a ro-bound file resists write, rename, unlink and replace (EBUSY). Its parent
    directory can still be renamed: `mv .git .gitx` succeeded with `.git/config` ro-bound. Hence the
    ancestor self-binds.
  - **Missing paths:** placeholders for missing paths leave 0-byte junk on the host, and
    `--ro-bind-try` silently skips. Hence detect-only for absent paths.
  - **Git with `.git/config` ro-bound** (strace + sha):
    - `commit`, `branch`, `checkout -b`, `worktree add`/`remove`, `merge`, `gc` and `fetch` never
      write it;
    - `branch -D` warns and exits 0;
    - `branch -m` exits 128 after renaming.
  - **Confirmed bypasses:**
    - rewriting a worktree's `commondir` to an attacker config with `core.fsmonitor` ran on a host
      `git status`;
    - a new nested `sub/.git/config` did the same.

  `[inferred — audit]` for the table as a whole.
- **D-22: Detection.**
  - Before launch, the launcher snapshots the hashes of every row above (plus a listing of `.git` dirs
    and files and worktree pointers).
  - After every launch it re-scans:
    - hash diffs;
    - new or changed nested `.git` and worktree pointers outside the known worktrees;
    - every git config found, grepped for `fsmonitor|hooksPath|sshCommand|pager|editor|alias|filter\.|textconv|credential|include`.
  - Findings are recorded on the run (additive frontmatter key `planted: [...]`, plus LOG lines) and
    shown on the Driver tab in the warning style.
  - Files are never reverted automatically, in line with the non-intrusive constraint.
- **D-23: The push step refuses on git-relevant planted findings.**
  - The Phase 28 push runs git on the host, in the project. A planted `core.fsmonitor`, hook, filter or
    worktree pointer would execute there.
  - The push therefore:
    - runs detection first;
    - parks with a typed reason when any finding touches git config, hooks, attributes or worktree
      pointers;
    - additionally hardens its own git invocations with `-c core.fsmonitor=false` (plus the existing
      `core.hooksPath=/dev/null`), and the other config-exec keys where git allows overriding them.
  - The operator clears the park explicitly (re-run `driver push` with an ack flag after inspecting).
  - `[inferred — audit]` for the ack mechanism's shape.

### Regression tests (SC5, LNCH-13)
- **D-24:** Following the Phase 28 D-20 pattern:
  - pure argv and settings goldens run everywhere (CI included);
  - live probes are opt-in (`#[ignore]`, skip-with-reason when bwrap or a user systemd is absent) and
    run on this host with captured evidence.
  - Live probes cover:
    - A1/A2: `$XDG_RUNTIME_DIR/cc-socks/*`, session bus, Wayland, ssh/gpg agent sockets absent;
    - A3: `~/.claude/daemon/dispatch` and similar unwritable (EROFS);
    - A4: push mirror `core.hooksPath=/dev/null`, plus the new fsmonitor override;
    - A5: a nested `claude` in a foreign config dir still hits the managed gate hook, live and cheap on
      Haiku;
    - B1/B3/B6: 127.0.0.1 and LAN listeners, abstract X11 socket, `/run/docker.sock`, and the
      "only expected sockets" sweep;
    - D-05: account-API paths get 403;
    - D-06: a non-allowlisted host and a private-address resolve are refused;
    - D-16: a planted `~/.claudear/env` lookalike is unreadable;
    - D-21/D-22: planted `.git/config`, nested `.git` and commondir are flagged and push is refused.
  - Spend cap for all live probes in this phase: $2. The Haiku runs measured here cost cents.
    `[inferred — audit]`

### Degraded posture (SC7, LNCH-15)
- **D-26/D-27: The absent-protections list.**
  - New additive frontmatter key `protections_absent: [...]` (Phase 27 schema-v1 additive rule,
    `#[serde(default)]`), recorded at launch. Vocabulary:
    `net-isolation`, `egress-proxy`, `token-injection`, `home-allowlist`, `run-tmpfs`,
    `planted-file-ro`, `managed-settings`, `registry-overlay`.
  - Degraded/unsandboxed runs list all the bwrap-dependent ones. Post-run planted-file detection and
    the push refusal still run in degraded mode, because they are host-side.
  - A bwrap-scope run on an old bwrap lists only `managed-settings` and `registry-overlay`.
  - Shown on the Driver tab's posture line, in the launch form's sandbox line, and in the degraded-host
    second confirm (the Phase 30 surfaces; 28.1 owns the change per the Phase 30 ROADMAP note).
