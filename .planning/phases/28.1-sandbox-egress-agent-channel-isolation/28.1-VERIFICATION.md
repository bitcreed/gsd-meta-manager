### Open review warnings: do they break a success criterion?

All three are `open` in `28.1-REVIEW-DISPOSITION.md`. No TBD/FIXME/XXX markers exist in the covered source files. I judged each against the criteria text `[inferred — cleanup 2026-10-28]`.

- **WR-04** (`home.rs:195-202`, `:245-248`): binds the grandparent when a tool binary sits under `bin/` or `versions/`. Not a gap. SC2 requires an unlisted credential file in `$HOME` (the `~/.claudear/env` lookalike, a symlink to a project env file) to be unreadable; the live probe proves both are. The exposure needs a tool binary of the operator's own (claude, git, gsd-meta-manager) installed at `<dir>/bin/<tool>` under `$HOME`, and `root_refused` (`home.rs:170-181`) already rejects any root that is, contains or touches a credential mask dir, `~/.cargo`, `.local`, `.config`, `.cache` and `bin`. Tests `a_shared_directory_is_never_an_install_root`, `an_exe_in_a_shared_bin_directory_binds_only_the_file` and `an_exe_outside_a_bin_layout_binds_only_the_file` pin the narrowed behaviour. It is read-only over-exposure of sibling files in an unusual layout; the reviewer's fix (tool-prefix allowlist) would tighten it.
- **WR-11** (`egress/mod.rs:827-830`, `:848-850`): the 5-minute tunnel idle limit is applied per direction. Not a gap for the criteria: it fails closed (a long one-way transfer on an allowlisted host is cut), it opens no channel, and the CONNECT allowlist is empty by default (per-project opt-in), so SC1's "legitimate fetches still work" holds for transfers under 5 minutes of one-way silence. The 5-minute limit and 1-hour lifetime are documented in `docs/DRIVER-SANDBOX.md:189`, but the per-direction behaviour is not what the doc says ("no byte in either direction"). Availability bug to fix in a follow-up.
- **WR-12** (`planted.rs:949-957`, `:862-876`): applies only to checkouts over 1,000,000 directory entries (`MAX_WALK_ENTRIES`, `planted.rs:63`) where the baseline was already truncated. The detection half is accepted and documented (`DRIVER-SANDBOX.md` "A plant in the unvisited part of such a checkout is not detected"). The undocumented half is a false positive (the push parks and needs `--ack-planted`) that never lets a plant through silently on its own. SC3's primary protection, the ro binds of `.git/config`, hooks, `.claude/` and the other listed paths, does not depend on the scan. Non-blocking; the doc should state the drift.
