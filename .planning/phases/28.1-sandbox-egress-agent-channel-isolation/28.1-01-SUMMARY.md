# Phase 28.1 Plan 01: Egress Server Library Summary

**Launcher-side egress library: a unix-socket inference reverse proxy that injects the run token per request after a path allowlist, server-side-reach body check and re-framing, plus a deny-by-default CONNECT proxy with a resolved-address guard, all decided by pure table-tested policy and testable in CI against a plain-TCP stub of api.anthropic.com.**

## Performance

- **Duration:** 35 min
- **Started:** 2026-10-24T20:27:10Z
- **Completed:** 2026-10-24T21:02Z
- **Tasks:** 3 (1 tracer, 2 TDD)
- **Files modified:** 9 (6 created, 3 modified); about 3,700 added lines, 41 unit tests plus 21 integration tests (one opt-in live)

## Accomplishments

- `EgressServer::start(UnixListener, EgressSpec) -> EgressHandle` serves one socket on a `gsdmm-egress` thread (current-thread tokio, the `install_signal_handlers` shape), with a 64-connection semaphore (65th gets a 503), a 64 KiB / 30 s head bound, a 32 MiB / 120 s body bound, and `stop()` that cuts open connections and returns the counters.
- Inference path (D-04, D-05): `classify_target` admits only origin-form `POST /v1/messages[/count_tokens]`; `framing_verdict` and `judge_body` refuse anything the proxy cannot fully read; `request_bytes` re-serialises with its own `Host`, `Authorization: Bearer`, `Content-Length` and `Connection: close`; the inbound `authorization`, `x-api-key`, `cookie`, hop-by-hop and `proxy-*` headers are dropped.
- CONNECT path (D-06): `connect_verdict` (names only, 443 only, never the inference host, IP-literal-like hosts refused), then ONE `lookup_host`, every address `ip_denied` flags dropped (IPv4-mapped, NAT64, 6to4 and IPv4-compatible forms judged as their IPv4), the vetted address dialled, `tunnel()` pumping the leftover first.
- `egress.log` (0600): `ts|kind|subject|path|status|verdict`, sanitised, written before the client sees the answer.
- `TokenProvider::Host` re-reads the credentials file per forwarded request through `spawn_blocking` and keeps the last good token.
- The real TLS leg is proven once against the real host (401 for a bogus token) in an opt-in test.

## Known Limitations (carried forward, not defects)

- `inference_body_verdict`'s recursive walk refuses ANY nested object with `source.type` of `url` or `file`, including one inside a model-generated `tool_use.input`. That is a possible false-positive 403 on a legitimate request (RESEARCH accepted this fail-closed trade).
- An allowed `CONNECT` tunnel has no idle timeout; a hung tunnel holds one of the 64 slots until the peer or the handle closes it.
- `host_access_token` refuses a file token with under 5 minutes left (`MIN_TOKEN_LIFETIME`), so in that window the proxy keeps sending the previous, older token until the host's own `claude` refreshes the file.
- `socket_path_for` yields `egress-<hash8>.sock`, 19 characters, which can be a few characters longer than driverctl's `<run-id>-<hash8>.sock`; 28.1-07 binds it and must run the `sun_path` length check (`bind_run_socket` does).
- A client-typed `CONNECT` authority (including an IP literal) is logged as typed; only a RESOLVED address is withheld.
