# Phase 28.1 Plan 05: In-Sandbox Bridge Summary

**Hidden `gsd-meta-manager bridge --port --sock -- <cmd>` subcommand: binds 127.0.0.1 first, relays every TCP connection to the launcher's egress unix socket, runs the driver as its child and returns its exit code (shell-style 126/127/128+signal, 70 for an unbindable port), writing nothing to stdout, proven in CI against a real in-process EgressServer.**

## Performance

- **Duration:** ~20 min
- **Completed:** 2026-10-24T22:25Z
- **Tasks:** 2 (1 tracer, 1 TDD)
- **Files modified:** 6 (2 created, 4 modified); about 600 added lines

## Accomplishments

- `bridge::run(port, sock, command) -> i32`: binds `127.0.0.1:<port>` BEFORE anything else (exit 70 and one stderr line on failure, child never started), starts a named accept thread, then runs the driver through `process::spawn_bridged_child` and returns its exit code.
- Per connection: `UnixStream::connect(sock)`; a failure drops only that TCP stream. Otherwise two std threads `io::copy` each direction and `shutdown(Write)` the destination on EOF.
- `spawn_bridged_child` joins `process.rs` as the sixth shape (environment and stdio inherited, no `env_clear`, no `process_group`); `tests/spawn_seam_guard.rs` passes unchanged.
- Hidden `Commands::Bridge` (`#[arg(last = true)]`), not cfg-gated, dispatched in `main` before `init_tracing` with a never-reached arm in `async_main`; two cli unit tests pin its parse and its usage error.
- `tests/launcher_bridge.rs` helpers: a plain-TCP stub upstream, a short-path `EgressServer` rig, a `Bridge` guard that leads its own process group and kills the group on drop, bounded waits (5 s).
