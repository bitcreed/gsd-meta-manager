## Top 3 Priority Fixes

1. **Row 4 overflows and clips by position, not by importance** (`src/ui/screens/driver_run.rs:1051-1099`, `clip_line` at `:1621`) — With every key recorded the row is about 140 cells (SUMMARY). The detail pane is `Constraint::Min(DRIVER_DETAIL_MIN_CELLS)` beside a 40% list (`driver.rs:728-729`), so on a 120-column terminal it is roughly 72 cells. `clip_line` drops from the right, so `auth ... run driver auth setup`, `prompt`, `egress` and `api` vanish first. A degraded run is worse: `UNSANDBOXED missing: bwrap, systemd-run` followed by all eight `absent:` words (about 120 cells) pushes `auth` and the prompt version out entirely. Fix: split the 28.1 posture onto its own row, or wrap it, or order it so the compact items (`PLANTED n`, `auth x`) come before the long `absent:` list. For a degraded run, collapse the list to `absent: all 8` when it equals the whole vocabulary. Add tests at width 80 and 100, since all three posture tests use width 200 only (`driver_run.rs` tests around L4950-4990).
2. **The new words are unexplained and the remedies are not shown** (`driver_run.rs:1103`, `driver_launch.rs` confirm prompt) — The operator sees `net-isolation, egress-proxy, token-injection, ...` with no gloss and no pointer to `docs/DRIVER-SANDBOX.md`, which holds the only table that explains them. `PLANTED 4` gives no hint of `driver push --ack-planted`, the action it blocks. `AUTH_SETUP_HINT = "run driver auth setup"` omits the binary name (`gsd-meta-manager driver auth setup`), and the second confirm repeats eight bare words. Fix: add one short clause to the confirm (`See docs/DRIVER-SANDBOX.md`) and show `push blocked: --ack-planted` where PLANTED is drawn (for example in the detail pane or footer when `planted` is non-empty). Spell out the full command in the hint.
3. **Row 4 reads as one run-on sentence** (`driver_run.rs:1125-1147`) — The output is `sandbox bwrap PLANTED 4 absent: registry-overlay auth host-token run driver auth setup  ·  prompt ...`. Only the original sandbox/prompt boundary uses `HEADER_SEP`. The `host-token` hint is a command sentence glued to a value, so `host-token run driver auth setup` parses as one phrase. Fix: put `HEADER_SEP` between `PLANTED`, `absent:`, and `auth`. Wrap the hint as `auth host-token (run: driver auth setup)`. Use singular/plural for `egress 1 host`. Optionally split `PLANTED` out of the sandbox group so the main sandbox word is not visually fused to a security alert.

Further items (below the top 3): the Yellow severity collapse (Color); the `host-token` posture is rendered in plain text although it is the weaker posture (Typography); no pane-width regression test for the confirm popup with the longer prompt beyond the 120x40 draw in `launcher_launch_the_unsandboxed_confirmation_lists_every_absent_protection`.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- Good: honest, plain-spoken warnings. `Unsandboxed, the run would lack: ...` (`driver_launch.rs`, unavailable-sandbox block, Yellow) and `Absent protections:` in the confirm prompt state the loss before the operator commits. This meets the LNCH-15 prohibition ("MUST NOT hide or soften").
- Gap: the eight vocabulary words (`net-isolation`, `egress-proxy`, `token-injection`, `home-allowlist`, `run-tmpfs`, `planted-file-ro`, `managed-settings`, `registry-overlay`) are internal identifiers shown verbatim. The consequence of each (for example "the token is readable from `/proc/<pid>/environ`") exists only in `docs/DRIVER-SANDBOX.md`. The TUI never mentions that file.
- Gap: `AUTH_SETUP_HINT = "run driver auth setup"` (`driver_run.rs:1103`) is not a copy-pasteable command, and it is not delimited from the value before it (`driver_run.rs:1143-1145`). Elsewhere in the codebase the same instruction is phrased `rerun driver auth setup` (`src/launcher/outcome.rs:223`), so the wording is inconsistent too.
- Gap: `format!("egress {} hosts", hosts.len())` (`driver_run.rs:1092`) renders `egress 1 hosts` and `egress 0 hosts`. `api 0` has no unit.
- Gap: the confirm prompt now carries both `Missing: bwrap, ...` (causes) and `Absent protections: <eight words>` (effects) in one very long sentence ending in `[y/n]`. The docs explain the cause/effect split; the prompt does not.
- Docs copy (`docs/DRIVER-SANDBOX.md`) is clear and leads with "not a complete isolation boundary"; the 11 residual-risk entries match the plan. Out of scope for the TUI pillars but a strength.
- Resolved assumption `[inferred — audit]`: SUMMARY flagged the `+N more` overflow shape as assumed. `src/launcher/push/planted.rs:959-967` writes exactly `+{n} more` as the last line, so `planted_count` (`driver_run.rs:1107-1119`) matches the real writer.

### Pillar 2: Visuals (3/4)

- Good: focal ordering within the new group is correct: `PLANTED` (bold) comes first, so it is the last thing `clip_line` would cut within the group. `UNSANDBOXED` keeps its existing BOLD Yellow treatment.
- Good: no new header row, so the 30-03 height tiers are untouched; `posture_row_is_unchanged_without_the_28_1_keys` pins backwards compatibility.
- Gap: row 4 now holds up to nine distinct facts (sandbox, missing, planted, absent, auth, hint, prompt, egress, api) on one clipped line. There is no truncation marker priority and, apart from `fit_cells`' `…`, no sign of how much was lost. The important security facts compete with low-value ones (`api n`, `egress n hosts`) for the same cells, and the low-value ones sit last, where clipping already hides them, which is acceptable, but the mid-row `auth` posture is hidden on degraded runs (Top fix 1).
- Gap: the second line of the launch form for an unsandboxed host is three Yellow/Red lines (`Sandbox unavailable...`, `A sandboxed launch is refused...`, `Unsandboxed, the run would lack: ...`, `[U] launch UNSANDBOXED instead`). The list of eight words then sits between the refusal and the action, which makes the `[U]` option slightly harder to find. This is minor.
- Positive: the render path wraps the long confirm prompt through the existing `wrapped_rows`/`render_confirm_popup` sizing (plan 30-06), and the 30-06 sizing tests stayed green per SUMMARY.

### Pillar 3: Color (3/4)

- Good: no hardcoded RGB or hex colors in the diff. Only `Color::Yellow` through `Style::default().fg(...)`, the same warning color as the existing `UNSANDBOXED`, `custom:` prompt and `[U]` text.
- Gap: Yellow now marks four different severities on the same row: degraded sandbox, a planted-file alert, a missing optional protection (`registry-overlay` on an older bwrap), and a mere hint (`run driver auth setup`). `PLANTED n` is the one finding that indicates probable tampering by the agent; it differs from the others only by BOLD. No Red tier exists in the new code (Red is used on the same screen for refusal text). `[inferred — audit]` whether the 28.1 CONTEXT D-22 "warning style" deliberately excludes Red; the plan prohibition says only "the warning style", so this is a WARNING, not a defect against the contract.
- Gap: the `auth` word is plain default color while its hint is Yellow, so the colour draws the eye to the remedy rather than to the weaker posture itself.
- Counts from the diff: Yellow spans in new code: 4 (`PLANTED`, `absent:`, hint on row 4; `absent:` and `Unsandboxed, the run would lack` on the launch form); Red: 0; hardcoded colors: 0.

### Pillar 4: Typography (3/4)

- Emphasis vocabulary stays at two modifiers: BOLD on `PLANTED` and the existing `UNSANDBOXED`; labels use the existing `label_style()` and absent values `muted_style()`. No new weights or modifiers were introduced.
- Gap: `host-token` is the weaker auth posture (broader server-side scope per the docs) but is drawn identically to `setup-token`; only the trailing hint differs. No emphasis helps a reader scanning the row.
- Gap: `PLANTED 4` is BOLD+Yellow but the number carries no extra weight, and for a `+N more` overflow the displayed count (`4`) cannot be distinguished from a count of fully listed findings.
- Safety: all driver-influenced text goes through `shown_capped` / `shown` (`driver_run.rs:1136, 1142`; `driver_launch.rs` `joined_shown`). Not a typography issue per se but it removes the usual control-character risk to rendering.

### Pillar 5: Spacing (2/4)

- Gap: separators are inconsistent on one row. The existing sandbox/prompt groups use `HEADER_SEP` (`"  ·  "`), while `push_posture_28_1` appends `" PLANTED n"`, `" absent: ..."`, `" auth ..."` and `" run driver auth setup"` with one leading space each. The SUMMARY's own after-example shows the result: `sandbox bwrap PLANTED 4 absent: registry-overlay auth host-token run driver auth setup  ·  prompt ...`. Four distinct facts are visually one group.
- Gap: width budget is not designed. With all keys the row is about 140 cells (SUMMARY, width 200); the detail pane is `Constraint::Min(DRIVER_DETAIL_MIN_CELLS)` next to a `Percentage(40)` list (`driver.rs:728-731`). No width-dependent layout exists for this row, and the three new posture tests all call `header_row_4(&fm, 200)`; a narrow-width golden would have exposed the clipping.
- Good: `clip_line` guarantees the row never wraps or overflows the pane; the launch-form lines use the existing wrap helpers (`wrapped_rows`) rather than fixed row counts.
- Good: no arbitrary numeric constants were added; the row stays inside the existing tier layout.

### Pillar 6: Experience Design (3/4)

- Good, state coverage: the preflight has four tested states (full host, bwrap without overlay, missing bwrap, claude refusal path unchanged), a tested "key absent → unchanged row" case, an empty-list case (`protections_absent = Some(vec![])` renders nothing), and a `setup-token` no-hint case. This is the strongest pillar.
- Good, safety of hostile input: the render-escape guard gained fixtures for `auth`, `protections_absent`, `egress_allow` and `planted` plus an "absent protection" launch-form state (deviation 2 in SUMMARY). Dispatch of the second confirm still requires an explicit `y`.
- Good: the confirm lists the missing protections before the operator commits, the central UX requirement of D-27 / LNCH-15.
- Gap: no actionability for `PLANTED`. The TUI flags the run but nowhere in the diff shows that `driver push` will be refused or how to clear it (`--ack-planted`); the remedy is in the docs only.
- Gap: no way in the TUI to see the clipped part of row 4 (full `absent:` list, `auth`, `egress`, `api`) when the pane is narrow. `[inferred — audit]` no expanded view was added in this plan; I did not search other plans for one.
- Gap: `unsandboxed_absent` is always all eight words, regardless of what probes found, so the unavailable-sandbox line and the confirm repeat the same fixed list every time. That is informationally correct but gives the operator a wall of eight identifiers on every degraded launch.
- Process note: Task 2 (tdd) was committed as one commit with no RED history (SUMMARY deviation 1); behaviour impact none.
- Registry audit: `components.json` absent; skipped (not a web/shadcn project).
