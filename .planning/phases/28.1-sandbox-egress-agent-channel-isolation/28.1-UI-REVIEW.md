### Residual clipping (why F1 is PARTIAL, not FIXED)

Widths below are computed from the asserted strings (label `  sandbox ` = 10 cells, `HEADER_SEP` = 5 cells), `[inferred — audit]` that the detail pane is about 60% of the terminal (`Percentage(40)` list, `Min(DRIVER_DETAIL_MIN_CELLS = 39)`, `driver.rs:717-731`), so about 72 cells at 120 columns and about 48 at 80 columns.

1. **Bwrap run, `host-token`:** through `auth host-token` the row is about 78 cells; the remedy ` (run: gsd-meta-manager driver auth setup)` (42 cells) ends it at about 120. So at the 72-cell pane the `auth` word itself is cut (`auth host…`), and the copy-pasteable remedy only appears on panes of 121+ cells (a terminal of roughly 200 columns). The remedy fix is real in the code and in the width-200 test, but invisible on a normal-width layout. The narrow test deliberately asserts `auth` only at width 100 (28.1-13 summary key-decision).
2. **Degraded run with all three probes missing** (`bwrap, systemd-run, user-systemd` — a state `host.rs:216-225` produces and `host.rs:468` tests): the sandbox group is about 62 cells, so `absent: all 8` ends at about 80. At a 72-cell pane the `absent:` text is truncated to roughly `abse…`. The narrow test only uses two missing items (`degraded_fm`, `:5058`).
3. **80-column terminal (pane about 48):** a bwrap run keeps `PLANTED 4` (ends at about 29) but `absent: registry-overlay` is truncated; a degraded run's `absent:` group is gone entirely (the sandbox group alone is 49). Widths under 72 are not tested.
4. The order PLANTED, absent, auth is a documented `[inferred — audit]` decision, fine; but severity-by-position still decides what survives, and `missing:` (a cause, DarkGray) is placed ahead of `absent:` (the effect LNCH-15 names), so a long `missing:` list costs the effect list cells.

None of these is a BLOCKER: the degraded `UNSANDBOXED` word, the PLANTED count and, at 100+ cells, the absent summary all survive. They are the reason row 4 is not 4/4 on Visuals or Spacing.

## Top 3 Priority Fixes

1. **Show the remedies and the vocabulary inside the TUI (F2, F2a, F8; WARNING)** — The operator sees `PLANTED 4`, `absent: all 8` and eight bare identifiers but learns nothing in-app about what they cost or what to do; `driver push` is blocked by planted files and the only route to clear it is `--ack-planted`, documented only in `docs/DRIVER-SANDBOX.md:139`. Fix: add one clause to `UnsandboxedConfirmScreen::prompt` (`driver_launch.rs:1150`) such as `See docs/DRIVER-SANDBOX.md`; show `push needs --ack-planted` where `PLANTED` is drawn when `planted` is non-empty (detail pane body or footer, not row 4, so it cannot be clipped away); name the eight words once on the Driver tab when `absent: all 8` is shown (for example in the detail pane).
2. **Stop the weaker-auth remedy and the degraded effect list from clipping at normal widths (F1 residual; WARNING)** — On a 120-column terminal the `host-token` hint never appears and a three-missing degraded run can lose `absent:`. Fix: either move the hint out of row 4 into the detail body (shorten row 4 to `auth host-token ⚠`), or shorten it to `(driver auth setup)`; shorten `missing:` to a count (`missing 3`) when `absent:` follows, since the effect list is the SC7 datum; add tests at width 48 and 60 and for the three-item `missing:` list (`degraded_fm` with `user-systemd`).
3. **Give PLANTED a severity tier and make `host-token` visible as the weaker posture (F4, F5; WARNING)** — PLANTED (probable tampering), a missing optional protection and a mere hint all share Yellow; the weaker posture is plain text while the hint is Yellow. Fix: render `PLANTED n` in `Color::Red` + BOLD (the screen already uses Red for refusals, `driver_launch.rs:834-850`) and style `host-token` itself with `warn`. Record the choice against the 28.1 D-22 "warning style" wording first (`[inferred — audit]`: the contract is ambiguous on Red).

Minor recommendations (below the top 3): unify `rerun driver auth setup` (`src/launcher/outcome.rs:223, 431`) with the new copy-pasteable form; give `api N` a unit or label (`api 12 req`); distinguish `PLANTED 4+` when the count includes a `+N more` overflow; add a clip test that asserts no row ends in a bare `HEADER_SEP`.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- Fixed: the auth hint is now a command that can be pasted (`driver_run.rs:1104`), `egress 1 host` reads correctly (`:1092`), and the groups are no longer a run-on (`:1144-1166`). Plan 28.1-13 tests assert all three.
- Gap (WARNING, unchanged): the eight vocabulary words are shown verbatim and unglossed in the launch form (`driver_launch.rs:857`, `:872`) and the confirm (`:1150`). Their meanings live only in `docs/DRIVER-SANDBOX.md:42-66`, which no TUI string mentions (grep of `src/ui` for `DRIVER-SANDBOX` is empty). The README link (`README.md:425`) is good but is not where the operator is when the confirm appears.
- Gap (WARNING): `absent: all 8` is shorter but more opaque than the list it replaces.
- Gap (minor): `api {n}` has no unit (`:1097`); `rerun driver auth setup` (`outcome.rs:223`) and `run: gsd-meta-manager driver auth setup` (`driver_run.rs:1104`) are two phrasings for one remedy.
- Gap: the confirm is still one long sentence (`Launch X on "Y" WITHOUT a sandbox? ... Missing: ... Absent protections: ... [y/n]`), cause and effect in one run (`driver_launch.rs:1150`).
- Strength: honest warnings (`Unsandboxed, the run would lack:`, `A sandboxed launch is refused on this host.`), and `docs/DRIVER-SANDBOX.md` leads with "not a complete isolation boundary" (`:8`).

### Pillar 2: Visuals (3/4)

- Fixed: row 4 follows importance order: sandbox word, PLANTED (BOLD Yellow), absent (Yellow), auth, then prompt, egress, api (`driver_run.rs:1073-1098`). Clipping now eats the low-value tail first, which is the right way round.
- Fixed: a degraded run shows one 13-cell `absent: all 8` instead of about 120 cells (28.1-13 before/after table, asserted by tests).
- Gap (WARNING): the row is still one clipped line, with no marker of how much was lost beyond `fit_cells`' ellipsis, and the `auth` and remedy groups (about 78 and 120 cells in) clip at pane widths of 72 and below (computed; see Residual clipping).
- Gap (minor, unchanged): in the launch form the list of eight sits between the refusal and the `[U]` action (`driver_launch.rs:855-866`).
- Not 4/4 because the focal security facts still depend on pane width, and the two-column layout offers no alternative surface for them.

### Pillar 3: Color (3/4)

- No hardcoded RGB/hex in `driver_run.rs:1141-1170` or the `driver_launch.rs` sandbox block. New-code spans: Yellow 3 on row 4 (PLANTED, `absent:`, hint) plus 2 on the launch form; Red 0 in new row-4 code.
- Gap (WARNING, unchanged, F4): one hue for four severities. Plan 28.1-13 did not touch it and its prohibition list (`28.1-13-PLAN.md`) does not ask for it, so this stands as an open quality gap, not a contract violation. `[inferred — audit]` D-22 "warning style" does not exclude Red.
- Gap: the weaker posture `host-token` is plain default-colored while only its hint is Yellow (`:1165-1167`).

### Pillar 4: Typography (3/4)

- Two modifiers only (BOLD on PLANTED and UNSANDBOXED, existing `label_style()`/`muted_style()`); no new weight. `posture_row_shows_absent_planted_auth_egress_and_api` asserts PLANTED is BOLD and `absent:` is not (`:4987-4992`).
- Gap (unchanged): `host-token` carries no emphasis (F5).
- Gap (unchanged, minor): `PLANTED 4` cannot show that the count includes a `+N more` overflow (F6).
- All driver-influenced text goes through `shown_capped` (`:1064, 1156, 1165`) and `joined_shown`; the escape guard fixtures still pass (19 pass).

### Pillar 5: Spacing (3/4)

- Fixed: every group starts with `HEADER_SEP` (`:1144, 1160, 1164`); empty or absent groups add neither text nor separator (test `:5039-5051`). The previous bare-space glue and the `host-token run driver ...` run-on are gone.
- Fixed: the width budget is now designed and tested at 72, 80, 100 and 200 (`:5065-5083`). The final two-row fixture covers a degraded run with planted findings at 100.
- Gap (WARNING): widths below 72 (the detail pane at an 80-column terminal is about 48 cells, computed) and a three-item `missing:` list are untested, and both lose the `absent:` text per "Residual clipping".
- Gap (minor): a clip landing on a separator can leave a trailing `  ·  ` (computed).
- Good: `clip_line` still guarantees no wrap/overflow; no arbitrary numeric constants added; no new header row, so the 30-03 height tiers are untouched.

### Pillar 6: Experience Design (3/4)

- State coverage is still the strongest area and has grown: bwrap full/old host, degraded all-eight, whole-vocabulary vs seven/repeated/unknown, singular host, empty lists, key absent (byte-identical pre-28.1 row), PLANTED forgery attempts. All pass.
- Good: LNCH-15's central requirement (the degraded run shows what it lacks) now holds at pane widths of 72 to 100 for the two-missing fixture, and the confirm lists every absent protection before the operator commits (`driver_launch.rs:1150`; the confirm still requires an explicit `y`).
- Gap (WARNING, unchanged): no actionability for `PLANTED` (F2a) and no TUI route to the clipped tail (F7).
- Gap: the weaker-auth remedy only appears on very wide panes (Residual clipping 1); the operator on a normal terminal sees `auth host…` or `auth host-token` with no way to act.
- Gap (process, informational): plan 28.1-14 is a verify-only gate with no UI change; the ledger lists WR-02, WR-05, WR-06, WR-08 and IN-03..IN-06 as still `open`, none of which I assessed as UI findings (not read for this audit).
- Registry audit: `components.json` absent; skipped (not a web/shadcn project).
