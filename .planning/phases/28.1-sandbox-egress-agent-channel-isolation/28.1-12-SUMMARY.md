# Phase 28.1 Plan 12: Release cross-target check restored, shared-bin bind, BOM-tolerant config scan Summary

**The rustls/ring TLS crates move to a Linux-only target table and the unix-only `home.rs` tests are cfg-gated, so the exact `release.yml` `cross-target-check` commands exit 0 for `x86_64-pc-windows-gnu` and `x86_64-apple-darwin` (CR-01); a binary in `~/.local/bin` or `~/bin` now binds as a single file (WR-04) and a leading BOM no longer hides `core.fsmonitor` from the push gate (WR-07).**

## Accomplishments

- `Cargo.toml`: `rustls`, `tokio-rustls`, `webpki-roots` (feature lists verbatim) live in `[target.'cfg(target_os = "linux")'.dependencies]`; `httparse` stays unconditional. The comment records why: only the Linux bwrap posture starts the egress server, and `ring`'s C build cannot target macOS (`TargetConditionals.h` missing) or windows-gnu (no mingw) from the ubuntu runner. `Cargo.lock` is unchanged.
- `upstream.rs`: the `Arc`/`TlsConnector` imports, `Connector.tls`, the TLS `new` and `dial`, and the ring test are `cfg(target_os = "linux")`. A `cfg(not(target_os = "linux"))` `new`/`dial` pair serves `Upstream::Plain` and returns `ErrorKind::Unsupported` for `Upstream::Tls` (a shared `tls_unsupported()` helper). The `Upstream` enum is identical everywhere, so `run.rs` compiles unchanged.
- `home.rs`: `host_tests` (`cfg(all(test, any(linux, macos)))`) holds the four tests that use `symlink`, `HostFacts::from_host` or `HomeSetup::for_host`, bodies unchanged; the ungated `tests` module lost its `fs`/`symlink` imports.
- WR-04: `REFUSED_ROOT_REL` gains `.local/bin` and `bin`. Tool roots are unaffected (a `bin` parent already maps to its grandparent, `~/.local` was already refused, `$HOME` is never a root).
- WR-07: `parse_config` strips one leading U+FEFF before the line loop, as git does.
