## Spacing Scale

Terminal-cell spacing (rows and columns, not pixels). All values in character cells.

| Token | Value | Usage |
|-------|-------|-------|
| cell-gap | 1 col | Inline spacing between spans (e.g., breadcrumb separators) |
| indent | 2 col | Left padding for content within bordered blocks |
| section-break | 1 row | Blank line between logical content groups |
| tab-bar-height | 3 rows | Tab bar area (Constraint::Length(3)) — matches existing |
| footer-height | 1 row | Footer hint bar (Constraint::Length(1)) — matches existing |
| content-area | Min(0) | Remaining space for archive content — matches existing |

Exceptions: Breadcrumb header takes 1 row from content area (rendered as first line inside content block).

## Typography

Terminal text styling via ratatui `Style` and `Modifier`. No pixel font sizes.

| Role | Style | Modifier | Color | Usage |
|------|-------|----------|-------|-------|
| Body | default | none | default (terminal fg) | Artifact file list items, plain markdown text |
| Label | default | BOLD | default | Breadcrumb segments, field labels ("Path:", "Status:") |
| Heading | default | BOLD | Cyan | Tab highlight, milestone names in list, `#` markdown headers |
| Muted | default | DIM | DarkGray | Loading states, empty states, secondary info, `###` headers underline hint |

### Markdown Rendering Styles (file viewer)

| Markdown Element | Style | Details |
|------------------|-------|---------|
| `# H1` | Bold + Cyan fg | Top-level header |
| `## H2` | Bold + default fg | Section header |
| `### H3` | Bold + DIM modifier | Subsection header |
| `**bold**` | Bold modifier | Inline emphasis |
| `` `code` `` (inline) | default fg on default bg | Rendered as-is (no background in terminal) |
| Triple-backtick code block | DarkGray fg | Entire block rendered in DarkGray to distinguish from prose |
| `- ` list items | default | Preserved as-is (already has bullet prefix in source) |
| Plain text | default | No modifications |

## Color

Follows established codebase palette. All colors are ratatui `Color` enum values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | default (terminal bg) | Background, content area, text surfaces |
| Secondary (30%) | DarkGray | Muted text, loading indicators, code blocks, metadata, completed-status items |
| Accent (10%) | Cyan | Active tab highlight, selected list item, breadcrumb current level, `#` headers, milestone version labels |
| Destructive | Red | Not used in this phase (archive is read-only) |

Accent reserved for:
- Active tab label in tab bar (Bold + Cyan)
- Selected list item highlight (`highlight_style`: Cyan + Bold)
- Breadcrumb current-level segment
- `# H1` markdown headers in file viewer
- Milestone version label in milestone list (e.g., "v1.0")

Additional semantic colors (established, reused):
- **Green**: Completed phase badges in phase list
- **Yellow**: In-progress phase badges, scroll position indicator
- **DarkGray**: Code blocks in markdown viewer, "Loading..." text, empty state text

## Interaction Contract

### Navigation States

| State | View | Keys |
|-------|------|------|
| Archive root | List of milestones | Up/Down/j/k to navigate, Enter to drill in |
| Milestone selected | List of phases | Up/Down/j/k to navigate, Enter to drill in, Esc to go back |
| Phase selected | List of artifact files | Up/Down/j/k to navigate, Enter to view file, Esc to go back |
| File viewing | Scrollable markdown content | Up/Down/j/k to scroll, Esc to go back to artifact list |

### Keyboard Bindings

| Key | Context | Action |
|-----|---------|--------|
| Enter | Any list level | Drill into selected item |
| Esc | Milestone list (root) | Return to normal detail tab behavior (no drill-up) |
| Esc | Phase/artifact/file view | Return to parent level |
| Up / k | Any level | Move selection up / scroll up |
| Down / j | Any level | Move selection down / scroll down |
| Left / Right | Tab bar focused | Switch tabs (existing behavior) |
| 8 | Any detail view | Jump to Archive tab (if number-key tab switching exists) |

### State Transitions

```
[Tab Bar] --select Archive--> [Milestone List]
[Milestone List] --Enter--> [Phase List]
[Phase List] --Enter--> [Artifact List]
[Artifact List] --Enter--> [File Viewer]
[File Viewer] --Esc--> [Artifact List]
[Artifact List] --Esc--> [Phase List]
[Phase List] --Esc--> [Milestone List]
```

## Tab Bar Overflow Resolution

Current 7 tabs at 80 columns: `1:Phases|2:Roadmap|3:Backlog|4:Git|5:Pipeline|6:Queue|7:Sessions`

Measured character width: ~73 characters (including dividers). Adding `|8:Archive` = ~83 characters.

**Resolution**: Abbreviate tab labels to fit 80 columns.

| Current Label | New Label | Savings |
|---------------|-----------|---------|
| `1:Phases` | `1:Phases` | 0 |
| `2:Roadmap` | `2:Roadmap` | 0 |
| `3:Backlog` | `3:Backlog` | 0 |
| `4:Git` | `4:Git` | 0 |
| `5:Pipeline` | `5:Pipe` | 4 |
| `6:Queue` | `6:Queue` | 0 |
| `7:Sessions` | `7:Sess` | 4 |
| (new) | `8:Archive` | -- |

New total: ~75 characters. Fits within 80 columns.

Alternative (Claude's discretion): If abbreviation feels too aggressive, use full labels and accept minor truncation on 80-col terminals. Wider terminals (120+) display all labels fully. The executor should implement the abbreviation approach as the safer default.

## Async Loading Contract

| Trigger | Action | UI During Load | UI After Load |
|---------|--------|----------------|---------------|
| First visit to Archive tab | Scan `.planning/milestones/` for `v*-ROADMAP.md` files | "Loading..." (DarkGray) | Milestone list |
| Drill into milestone | Parse ROADMAP.md for phase list, scan phase directories | "Loading..." (DarkGray) | Phase list |
| Drill into phase | List files in phase directory | "Loading..." (DarkGray) | Artifact file list |
| Select artifact file | Read file content, apply markdown styling | "Loading..." (DarkGray) | Styled file content |

Cache: `HashMap<String, MilestoneArchive>` in `AppContext`. Never invalidated (archived milestones are immutable). Cached across tab switches.

Loading pattern: `tokio::spawn_blocking` for file I/O, results delivered via existing `mpsc` channel. Same pattern as `session_detector.rs`.
