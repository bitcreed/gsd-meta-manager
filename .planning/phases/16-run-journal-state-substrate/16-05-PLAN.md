<objective>
Make "free watching" actually free.

`parse_project_state` reads STATE.md, ROADMAP.md, QUEUE.md, HANDOFF, every phase directory's
disk inference and every workstream, and shells out to git for last-activity
(`src/state_reader/mod.rs:102-240`). The 500 ms dedup at `src/app.rs:325-331` caps that at **two
full re-parses per second, indefinitely** — roughly 28 800 of them across a four-hour run. That
is not an optimisation target; it is the difference between a usable TUI and an unusable one
during exactly the workflow this milestone exists to enable.

This plan forks the `FileChanged` arm on a pure classification (D-11, D-12), routes driver
journal appends to a byte-offset tail whose cost is proportional to bytes appended rather than to
project size (D-15), and proves the result by **counting** the re-parse dispatches (D-17) — with
the control arm that stops the test passing against a handler that simply dropped file events.

Purpose: also to fix a correctness bug that classification *introduces*. The watcher's dedup is
per-root today, so the first path for a project in a debounce batch wins and every later path for
that root is silently dropped. Once journal appends start arriving, a single 200 ms batch can
carry a journal append **and** a STATE.md write — and if the journal append is first, the state
write is swallowed and the project never re-parses. D-10 is explicit that this is a correctness
fix and must land in the same change.

Output: the OBS-06 route end to end, plus the sibling state it needs. This phase ships **no UI**
(D-36); the tail exists to keep state cheap, not to display it. Every rendered driver surface is
Phase 18's.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
