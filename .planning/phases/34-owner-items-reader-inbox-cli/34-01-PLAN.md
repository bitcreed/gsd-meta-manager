[inferred] schema decisions (RESEARCH "Inbox JSON schema: what §3.5 leaves open", all resolved here; they are part of D-19's costly contract and every later plan uses them unchanged):
1. `projects[].target` exists (string or null), as in `status`.
2. A group is one (file, lane) pair: one UAT can yield a test, a fix and a blocked group.
3. R3 merged gaps live in `items[].gaps` (array of `{name, result, reason}`); every group has `counts {checks, failed, gaps, unreadable}`: checks = listed items, failed = items whose result is issue, failed or partial, gaps = merged plus standalone gap items, unreadable = unparsed blocks (UAT) or 1 for a file that could not be read or classified.
4. Unreadable checks produce a `fix` group (created with `items: []` when the file has no fix items) with `command: null`; such a file is never clean.
5. `scope` is `current` or `archived`; `archived_milestone` carries the root-run archive label (`v1.5`, `ws-x`, `<ws>/v0.1`) or null.
6. `bookkeeping_only` and `acknowledged` are booleans on every group.
7. Deferred items appear only as `lane: "deferred"` groups under `--include deferred`; `--lane` accepts test, decide, fix, blocked only.
8. D-8 hidden noise is counted in `hidden.noise` and `summary.noise`.
9. `projects[].todos` is always present (`[{file, title}]`, empty unless `--include todos`); `hidden.todos` is the pending count from `oneoff::todos::list_pending` (0 when that call errors).
10. `test` is a string or null; `id` is `<file basename>#<test>` for numbered rows and verification entries, `#g<k>` for gap entries, `#v<k>` for unnumbered verification entries, `#d<k>` for deferred entries (k is 1-based within the file and origin); a repeated id in one file gets `~2`, `~3` in file order.
11. `phase_name` is the roadmap phase name when the phase is in the scope's roadmap, else the phase-dir slug after the token.
12. `summary.archived.{test,blocked,fix}` are item counts; `summary.deferred`, `summary.superseded`, `summary.acknowledged_files` and `summary.noise` total every scope.
13. Error entries carry `error {kind, message}` with the `status` kinds `unresolved`, `folder_missing`, `no_planning`, plus `milestone: null`, `groups: []`, zeroed `hidden`, `todos: []`.
14. `milestone` is `{version}` (STATE.md `milestone`, escaped, null when blank); `closes_after` is added by Phase 35 (D-19).
15. `command` is built only from a phase token matching `^\d+[A-Za-z]?(\.\d+)*$` (the roadmap number when the phase is in the roadmap, else the dir token) and a workstream dir name matching `^[A-Za-z0-9._-]+$`; anything else gives null. Archived groups carry `command: null`.
16. `summary.projects` counts every entry, error entries included. `--lane` and `--include` filter listed groups only; `summary` and `hidden` always report the full counts (D-20).
