4. **src/ui/screens/detail.rs** — Add j/k navigation for Sessions tab in handle_key:
   ```rust
   DetailSubView::Sessions => {
       // Filter active_sessions by project path
       let session_count = ctx.config.projects.get(&self.alias)
           .map(|proj| ctx.active_sessions.iter().filter(|s| s.working_dir == proj.path).count())
           .unwrap_or(0);
       let cache = ctx.view_cache.entry(self.alias.clone()).or_default();
       if session_count > 0 {
           let max = session_count.saturating_sub(1);
           cache.sessions_selected = (cache.sessions_selected + 1).min(max); // for j
           // (for k: cache.sessions_selected = cache.sessions_selected.saturating_sub(1))
       }
       ctx.needs_redraw = true;
   }
   ```

5. **src/ui/screens/detail.rs** — Add Enter key handler for Sessions tab (per D-10, resume selected session):
   In the Enter key match arm, add a `DetailSubView::Sessions` branch that:
   - Gets the selected session from filtered list using `cache.sessions_selected`
   - If session has a session_id, spawn a terminal: try `$TERMINAL` env var, fall back to "kitty", "alacritty", "gnome-terminal", "xterm" (per D-11)
   - Command: `$TERMINAL -e claude --resume {session_id}` with cwd set to session's working_dir
   - Use `std::process::Command::new(terminal).args(&["-e", "claude", "--resume", &sid]).current_dir(&session.working_dir).spawn()`
   - If no session_id (new session), resume is not possible — show status "No session ID to resume"
   - Show status message "Resumed session {short_id}" or error

6. **src/ui/screens/detail.rs** — Add 'n' key handler for launching new session (per D-09):
   In handle_key, when current_view is `DetailSubView::Sessions` and key is `KeyCode::Char('n')`:
   - Get project path from `ctx.config.projects.get(&self.alias)`
   - Detect terminal: try `std::env::var("TERMINAL")`, fall back to trying ["kitty", "alacritty", "gnome-terminal", "xterm"] by checking `which` via `std::process::Command` (per D-11)
   - Spawn: `Command::new(terminal).args(&["-e", "claude"]).current_dir(&project_path).spawn()`
   - Return `ScreenAction::SetStatusMessage("Launched new Claude session".into())`
   - On error: return `ScreenAction::SetStatusMessage(format!("Failed to launch: {}", e))`

7. **src/ui/screens/detail.rs** — Add Sessions tab rendering in the `render` method's tab content match:
   Add a `DetailSubView::Sessions` arm that:
   - Filters `ctx.active_sessions` to sessions where `working_dir` matches the current project's path
   - If empty: render a centered `Paragraph` saying "No active Claude sessions" with hint "[n] Launch new session"
   - If non-empty: render a `List` widget (same pattern as git/backlog tabs) with items showing:
     - Per D-06: `"PID {pid} | Session: {session_id_truncated_to_8} | Started: {formatted_time}"`
     - If session_id is None, show "new session" instead of truncated ID
     - For start_time, compute elapsed from boot time: read `/proc/uptime` to get system uptime, subtract (uptime_ticks - start_time) / clock_ticks_per_sec to get seconds since start. Or simpler: just show the raw PID and session_id, with "active" status. Use a helper function.
   - Use `ListState` with `sessions_selected` from cache for highlight
   - Footer hint line: "[j/k] Navigate  [Enter] Resume  [n] New session"
