# Phase 30 — UI Design Contract

> Visual and interaction contract for the rebuilt Driver tab (launcher runs first), the selected-run
> view, the steering inputs, the new-run / launch / relaunch flows, the LOG.md tail, the collapsed
> legacy section and the dashboard markers. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Binding sources of truth, in precedence order:**

1. `30-CONTEXT.md`: every `D-NN` is binding. Where this document names a `D-NN`, that decision is the
   authority and this document only renders it.
2. `18-UI-SPEC.md`: the medium rules, colour vocabulary, never-colour-alone rule, clamp ordering,
   untrusted-input boundary and honest-vocabulary rules. **This contract extends it and repeals only
   what is listed under `## What Phase 30 repeals`.**
3. The shipped code cited inline (`src/ui/screens/driver.rs`, `detail.rs`, `normal.rs`,
   `driver_confirm.rs`, `confirm_popup.rs`, `help.rs`, `src/main.rs`). Patterns are reused, not
   re-invented.

`[inferred — audit]`. The operator was unavailable; nothing here was confirmed by a human.

## THE MEDIUM

Unchanged from `18-UI-SPEC.md` §THE MEDIUM. This is a terminal UI: no CSS, px, hex, font stack,
hover or animation. Colour = the 16 ANSI named colours (`ratatui::style::Color`). Hierarchy =
`Modifier::{BOLD, DIM}` + colour + indentation + section rules. Spacing = integer cells (columns) and
rows. Breakpoints = width tiers in columns and height tiers in rows, **measured from the `Rect` the
render function receives, never from the terminal size**. Mouse: the shipped click/wheel regions
(quick 260926-kes) are kept; everything is keyboard-operable.

## Spacing Scale

Whole terminal cells and rows. The quantum is 1 cell (18-UI-SPEC precedent); there is no base-4 rule in
this medium.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 1 cell | glyph → word gap; posture cell; gap between cap value and bar |
| sm | 2 cells | left indent inside every section; column gap between fields; the `"> "` highlight / cursor symbol; footer hint separator |
| md | 4 cells | continuation indent for LOG.md detail lines (the indented worker-report lines); the second row of the answer input |
| label column | 10 cells | header rows: 2-cell indent + 7-cell label (`reason`, `control`, `sandbox`, `at`, `last`) + 1 gap; values start at column 10 |
| section rule | 1 row | `── name ───…` (U+2500), DarkGray, padded to the pane width |

Exceptions: none. Every measurement in this document is an integer cell or row.

## Typography

There is no type scale. One monospace grid; the roles below are the modifier + colour vocabulary from
`18-UI-SPEC.md` §Typography, reused unchanged. Exactly two weights exist: regular (`Style::default()`) and
`BOLD`.

| Role | Style | Usage in this phase |
|------|-------|---------------------|
| Body | `Style::default()` | Values, item titles, run ids, LOG lines, connection lines |
| Label | `fg(DarkGray)` | Header labels, section rules, LOG timestamps, `(pending)`, `missing:` lists, the legacy collapsed line |
| Muted | `fg(DarkGray)` + `DIM` | Empty-state rows (`(none recorded)`, `No events logged yet.`), the ring-overflow notice, `no limit` |
| Emphasis | `BOLD` | Footer key spans (`[c]`), input prompt words (`Answer I-03> `), `crashed`, `stale`, `MISMATCH`, `UNSANDBOXED` |
| Selection | `fg(Cyan)` + `BOLD` | Selected run row, item cursor row, launch-form field cursor (all with the `"> "` symbol) |
| State | `fg(<state colour>)` | Status glyph + word, item glyph + word, cap rows at or over the limit |

**No `Wrap`** in any scrolling pane (18-UI-SPEC rule; breaks the scroll clamp). Long values are
ellipsised with `…` by `char` count. `Modifier::REVERSED` gains **no new use**: it stays only on the
focused tab-bar label and the focused confirm-popup button, where it already ships
(`detail.rs:673`, `confirm_popup.rs:167`).

## Height tiers (D-10, D-29)

`H` = the tab area height passed to `render_driver_tab` (the detail screen gives it `rows − 4`). The detail
pane's title takes one row, so detail inner height = `H − 1`.

| Tier | Condition | Detail sections, top to bottom (rows) | Terminal rows at the detail screen |
|---|---|---|---|
| FULL | `H >= 21` (inner `>= 20`) | header 6 · items (rule + 1..8 item rows + 1 cursor-item row) · caps 5 (rule + 3 caps + audit) · connected (rule + 1..3) · log (rule + `>= 3`) | `>= 25` |
| MEDIUM | `12 <= H <= 20` (inner 11..19) | header 2 · caps 3 (no rule; each row is self-labelled) · items (rule + 1..8 item rows) · log (rule + `>= 3`) | 16 to 24 (80x24 lands here) |
| SUMMARY | `1 <= H <= 11` | **No sections.** One summary row per run, across the full width (both panes give way), windowed to keep the selection visible | `<= 15` |
| none | `H == 0` | nothing drawn | n/a |

**Minimum allocations, checked:** FULL `6 + 3 + 5 + 2 + 4 = 20`; MEDIUM `2 + 3 + 2 + 4 = 11`.
**Spare rows go, in order,** to item rows (up to `min(n, ITEMS_MAX_ROWS)`), then (FULL only) connection rows
(up to `min(c, CONNECTED_MAX_ROWS)`), then all remaining rows to the log.

**The no-orphan rule (D-29), REQUIRED:** a section rule or header is drawn only together with at least one
content row under it. A section that cannot get its minimum is dropped by the tier, never squeezed. The
check is a `TestBackend` sweep over `H` = 1..=40 at `W` = 40, 60, 80, 120, for a fixture run with items,
caps and connections, asserting that no rendered row is a rule with an empty or rule row directly beneath it
and that the bottom row of the area is never a rule.

**Legacy detail obeys the same rule** (D-29, the folded WR-05 todo): when a legacy row is selected, the
shipped tiers apply except that `8 ..= 13` rows draw **header (2) + output** and drop the pipeline row and
the steps section together. `>= 14` and `< 8` are unchanged. `[inferred — audit]`.

### Heartbeat (D-08)

- Heartbeat = `last_heartbeat` of the `connected[]` entry with `role: driver`, else the newest
  `last_heartbeat` in `connected[]` `[inferred — audit]`. None → `heartbeat (none recorded)` muted.
- Age = `now − heartbeat`, recomputed on the existing UI tick with **no file I/O per tick**. Format `m:ss`
  under an hour, `h:mm:ss` under a day, `{d}d {h}h` beyond. A future timestamp (clock skew) renders `0:00`.
- **Stale** = age `> heartbeat_stale_after_s` (from the file, never a TUI constant) **and** the run is live.
  FULL renders `heartbeat 3:10 ago stale (after 2:00)`: `stale` Yellow + BOLD, the threshold DarkGray. A stale
  live run is never called crashed.
- A run that is not live shows the age DarkGray with no stale judgement.

### Caps section (D-07)

```
── caps ──────────────────────────────
  dispatches    7/10  ███████░░░
  minutes      47/60  ████████░░
  gap rounds    2/2   ██████████  phase 30
  audit   logged 7  ·  observed 7  ·  denied 0
```

- Bar: `█` U+2588 filled, `░` U+2591 empty, `filled = min(10, floor(used × 10 / limit))`.
- Minutes: `wall_clock_min` rounded down to whole minutes for display.
- `used >= limit`: the whole row Yellow, value BOLD. No limit → value `{used}/–` and the bar replaced by
  `no limit` muted.
- Gap rounds: ` phase {phase}` DarkGray after the bar, when present.
- **Audit row:** `logged != observed` → the whole row Red, followed by ` MISMATCH` Red + BOLD (D-07).
  `denied > 0` → the denied value Yellow. In MEDIUM the audit row is not drawn; the audit lives in the
  status tokens.

### Connected section (D-09; FULL only)

One row per `connected[]` entry: `role (padded to 9) · state (padded to 12) · model · pid {pid} · hb {age} ·
{scope_unit} · {session_id first 8}`. Absent fields omitted; `…`-ellipsised at the pane edge; every field
through `shown_capped`. Zero entries → `(none recorded)` muted. More than `CONNECTED_MAX_ROWS` →

### LOG.md tail (D-23)

```
── log ──────────────────────────── [following] ──
  14:02:11 I-03 dispatched step=execute dispatch=2/4
      status: done
  14:09:40 RUN end reason=pause
```

- Rule with the right-aligned indicator, reusing `output_header_line` (`driver.rs:1685`):
  `[following]` Green, `[scrolled +N]` Yellow (`+999` cap), and **`[not live]` DarkGray** when the run's
  derived status is not live `[inferred — audit]`. Never `paused` for a scroll state.
- Only event lines are shown: the template preamble (through the first `-->`) is skipped on the first read
  `[inferred — audit]`.
- An event header (`- {ISO-8601 UTC} | …`) renders its stamp as local `HH:MM:SS` DarkGray, then the rest of
  the line sanitised. Any other line: indented `md` (4 cells), DarkGray. **No colour is ever chosen from LOG
  content** (event names included): the driver's words are content only (Replit rule, 30-CONTEXT
  §Specifics). `[inferred — audit]` for the structural styling.

## Steering flows (DTAB-03, SC3)

Every write goes through `driver::direction::write_body` on `spawn_blocking` → `Action` (D-14, D-25).
**The key handler never touches the filesystem.** On non-Linux the keys `c`, `a`, `u`, `e` and `s` are
absent from the footer, inert, and the footer carries the read-only suffix (D-14).

### Control chooser (`c`; D-15)

A pushed footer-input screen (the `enqueue.rs` idiom; body = `render_main_only`):

```
  control (now: run)>  [r]un  [p]ause  [s]top    [Esc] cancel
```

`control (now: …)>` BOLD; key spans BOLD; the rest DarkGray.

| Key | Effect |
|---|---|
| `r` / `p` | Write at once; pop; status message (copy below) |
| `s` | Push the polite-stop confirmation (below); `y` writes, `n`/`Esc` returns to the tab |
| the current value | No write; status `control is already {word} in DIRECTION.md. Nothing was written.` |
| `Esc` | Pop |

### Answer (`a`; D-15, D-16)

```
  Answer I-03> use $XDG_RUNTIME_DIR_   [Enter] write  [Esc] cancel
      I-03 is parked by gap-rounds: an answer alone will not resume it. Raise its budget with [e] or relaunch with higher caps with [R].
```

- Row 1: `Answer {id}> ` BOLD, buffer, `_` caret, hints DarkGray. No movable cursor, no `tui-textarea` (the
  18-UI-SPEC D-22 rule).
- Row 2 (OQ-R1, D-16): shown **only** when the item's park rule is not `needs-human`. Yellow, `md` indent.
- At `DIRECTION_ANSWER_MAX_CHARS` further characters are ignored and the hint reads `[Enter] write (500 max)`.
- `Enter` on an empty buffer: no-op, the screen stays open (an empty answer lifts nothing).
- `Enter` on a non-empty buffer: control characters and newlines are rejected by the transform (they cannot be
  typed, but can arrive by paste) → the error copy, buffer kept, screen open. Otherwise write `answer:` +
  `hold: false`, pop, status message.

### Un-hold (`u`)

Writes `hold: false` at once (reversible by editing), then shows a status message. No confirmation
`[inferred — audit]`.

### Edit in `$EDITOR` (`e`; D-17)

1. Read the body, write it to `<run dir>/.DIRECTION.md.edit` (the name must not share the
   `.DIRECTION.md.fm.` prefix; it is the edit temp the watcher ignores, D-24) `[inferred — audit]` for the
   name.
2. `ScreenAction::SuspendAndEdit(temp, None)`, the shipped handoff (`main.rs:834`). Editor resolution stays
   the shipped `$VISUAL` → `$EDITOR` → `vi`. **D-17's parenthetical reads `$EDITOR` first; this spec keeps
   the one shipped order so the app has a single resolution rule** `[inferred — audit]`.
3. On return, a post-editor hook for the edit temp (beside `refresh_after_editor`) dispatches the apply on
   `spawn_blocking`:

| Outcome | UI |
|---|---|
| editor exited non-zero | Nothing written; temp kept; status message `[inferred — audit]` |
| text unchanged | Nothing written; temp removed; status message |
| live body no longer equals the base | **Nothing written.** Conflict chooser (below) |
| edited body fails `body_sane` | Nothing written (`write_body` refuses it); conflict-chooser keys with the insane-body copy |
| `driver check` problems | Confirm popup "Apply this edit?" (Yellow accent) listing findings; `y` applies, `n` opens the chooser |
| clean | Applied; temp removed; status message |

Conflict / not-applied chooser (footer screen, the control-chooser idiom):

```
  Not applied: DIRECTION.md changed while you were editing.  [r]e-open yours  [d]iscard yours  [Esc] keep it at .DIRECTION.md.edit
```

`r` re-opens the kept text with the **current** live body as the new base (saving it replaces the other
change; the popup row says so). `d` deletes the temp. `Esc` keeps it on disk. `[inferred — audit]` for the
key set.
