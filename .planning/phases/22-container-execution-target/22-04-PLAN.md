<objective>
Turn a selected target into a verified one, record what the run actually got, and make stopping a
containerized session from the TUI reach the container.

This plan implements D-22-06 (the container is stopped through the API and its identity is
recorded on the run), D-22-16 (the journal's target string stops being a derived-trait rendering),
and the recording half of D-22-14 as corrected by RESEARCH **C-1** (the run records the egress
posture it obtained). It lands the second and third promotions recorded in `22-01-PLAN.md`'s
`<assumption_delta_decision>`, and the contract test that stops the singular assumption returning.

Purpose: `run.json` and `journal.jsonl` are durable, are tailed by the TUI and are read back by
`driver::reconcile` for runs that already exist on disk. A derived-trait rendering that yields a
bare variant name today would start writing a structured debug dump the moment the variant gains
fields — a durable on-disk value derived from a derived trait, which is the one thing this
repository's conventions say a durable format must never be.

Output: one total label function, a reader that accepts both spellings, two new run-record fields
with the scope word their own census demands, the pre-flight wired in before anything is created,
and the TUI's stop reaching the container.
</objective>

- **I-19 — D-22-16's `one-way` rating is superseded by a DESIGN CHANGE, not by a re-rating, and
  the task is therefore rated `costly` and carries no decision checkpoint.** The rating was
  `one-way` because `journal.jsonl` is durable, is tailed, and is read back by
  `driver::reconcile`, so changing the rendered value would make old runs read wrong or require a
  migration. **Reader tolerance for both spellings removes exactly that property**: no record on
  disk reads wrong and no migration exists. The reversibility doctrine's own preference is to
  remove the irreversibility rather than gate it, and that is what this plan does. The mechanism is
  a committed test, not a comment. **This is the most audit-worthy inference in the phase** —
  if a reviewer disagrees that tolerance discharges the one-way property, the remedy is a
  `checkpoint:decision` in front of Task 2, and nothing else in the plan moves.
- **I-20 — `container_id` stores the container NAME, which is the run id.** The container is
  created under the run id, so no lookup and no third write to `run.json` are needed. The field is
  still named for what it identifies rather than for what it happens to equal today, because a
  runtime with a narrower name grammar would need a prefix (assumption A8).
- **I-21 — `egress` is recorded as a rendered string, not a typed enum, on the durable record.**
  `run.json` carries no version discriminator, so the durable side takes the same tolerance posture
  every other field takes; `EgressPosture` stays the typed value in memory and renders through one
  producer. The two spellings recorded are the enforced form naming its mechanism and the
  unrestricted form naming its backend.
- **I-22 — a pre-flight refusal aborts the run.** It never falls back to the host. This is the
  phase's first prohibition made mechanical, and it is the reason the refusal carries a remedy.
</inferred_decisions>
