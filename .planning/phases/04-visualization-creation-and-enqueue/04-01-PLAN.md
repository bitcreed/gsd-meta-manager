1. Create `src/ui/roadmap_widget.rs` with a custom ratatui Widget (per D-02, D-03, D-04):

```rust
use ratatui::buffer::Buffer;

use ratatui::style::{Color, Modifier, Style};
use ratatui::widgets::Widget;
use crate::state_reader::roadmap_md::RoadmapPhase;
```

Define `RoadmapWidget<'a>` struct with fields:
- `phases: &'a [RoadmapPhase]`
- `current_phase_num: u32` (derived from completed_phases + 1)
- `scroll_offset: u16`

Implement `Widget` trait for `RoadmapWidget`:
- Each phase renders as a 3-line box (top border, content, bottom border) using Unicode box-drawing chars
- Between boxes: 2-line connector (`│` centered + `▼` centered), except after last phase
- Phase content line format: `│ {icon} P{num}: {name_truncated}  {completed}/{total} │`
- Status icons: `+` complete, `*` in-progress, `o` pending (matching existing detail_view convention)
- Current phase uses bold box chars (`┏━┓┗━┛┃`) and Color::Yellow with BOLD modifier (per D-04)
- Completed phases: Color::DarkGray text
- Pending phases: default text color
- Current phase has `▶` marker prepended to the line outside the box-left boundary
- Box width: min(area.width - 4, 40) to leave room for the `▶` marker and margins
- Boxes are horizontally centered in the given area
- Scroll support: skip `scroll_offset * phase_block_height` lines from the top
- Stop rendering when y exceeds area.height (per Pitfall 1 from research)
- Name truncation: truncate phase name to fit within box width minus overhead (icon + number + plan count takes ~15 chars)

2. Add `pub mod roadmap_widget;` to `src/ui/mod.rs`.
