<objective>
Close the two gaps in the `4: Git` tab of the project detail screen: the row drops the
`Co-authored-by` trailer (which in this repo is the model that did the work), and Enter
shows only `git diff-tree --stat`, never the commit message — the half that carries the
reasoning.

Purpose: make "who wrote this and what does it say" readable without leaving the TUI.
Output: co-author column on each log row; an Enter pane whose top half is the full,
scrollable commit message and whose bottom half is the existing file list.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party repo -> TUI cell | `git log` / `git show` output from a repository this user merely watches is attacker-controlled text drawn into a terminal. |
| selected hash -> argv | The commit hash becomes an argv element of `git show` / `git diff-tree`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-vr1-01 | Spoofing | commit body + co-author trailer rendered in `render_git_tab` | high | mitigate | Both carriers are `crate::text::Untrusted`, which implements no `Display`/`AsRef<str>`/`Into<Cow<str>>`, so the raw spelling is a compile error; every render site goes through `.shown()`. This is the CVE-2021-42574 Trojan Source class the tab already carries (T-21-23-01). |
| T-vr1-02 | Tampering | field splitting in `parse_git_log_line` | medium | mitigate | The trailer field is placed BEFORE `%s` so a crafted `\x1f` in a subject cannot shift hash/date/author; a crafted `\x1f` inside a trailer value can only truncate the co-author column and corrupt the subject, both of which render escaped (QD-11). |
| T-vr1-03 | Tampering | multi-line body collapsing | low | mitigate | Newlines are split at the producer before wrapping, so a body cannot smuggle a fake row into the pane by embedding a line break (QD-08). |
| T-vr1-04 | Information disclosure | stale detail rendered under the wrong commit title | medium | mitigate | `GitCommitDetailLoaded` carries the hash it was asked for and is applied only when it matches the selected entry (QD-07). |
| T-vr1-05 | Injection | hash passed to `git show` | low | accept | The hash is an argv element, not a shell fragment, and comes from this build's own `git log` output for the selected row — the same posture `load_diff_stat` already takes at `detail.rs:2020-2024`. |
| T-vr1-SC | Tampering | package installs | n/a | accept | No new dependency is added; `Cargo.toml` is untouched. |
</threat_model>
