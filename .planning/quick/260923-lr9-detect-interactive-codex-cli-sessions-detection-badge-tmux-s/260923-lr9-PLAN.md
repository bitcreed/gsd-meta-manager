The human is unavailable. These are planner decisions made from the brief and artifacts, recorded for audit.
- [INFERRED 1] depends_on 260923-lr8: both items edit src/session_detector.rs. lr8 rewrites the
  `ClaudeSession.tty` field doc (lines 23-25). This item must NOT touch that doc. Put the new `kind` field
  directly after `pid` so the two hunks are not adjacent.
- [INFERRED 2] Session id = the lexicographically lowest stem among OPEN `thread-writer-locks/*.lock` fds
  (brief heuristic). For lowercase canonical UUIDv7 strings, lexicographic order is creation order, so the
  main thread beats the later guardian-review thread.
- [INFERRED 3] A lock stem counts only if it is a lowercase canonical UUID: 36 bytes, hyphens at byte
  offsets 8/13/18/23, every other byte in `[0-9a-f]`. The version nibble is not checked. Anything else is
  ignored, so a hostile or odd path gives `session_id: None` (under-detection, silent) and never a
  fabricated id. This does NOT contradict the declined validator on the Claude path (D-21-48). That
  validator was declined because claude resumes by title, so a shape rule would delete resumable
  sessions. A Codex id feeds no parser (resume is disabled), and the shape check exists only so the
  ordering in INFERRED 2 means something.
- [INFERRED 4] The lock directory is matched by its parent-dir NAME `thread-writer-locks`, not anchored
  to `~/.codex`. This supports `$CODEX_HOME` and matches the portability constraint.
- [INFERRED 5] A process counts as interactive only if all three hold. (a) argv[0] basename is exactly
  `codex`. (b) No argv element after argv[0] and before the first `--` equals one of {exec, e, app-server,
  exec-server, mcp, mcp-server}. The element can appear anywhere before `--`, not only at argv[1], so
  `codex -m gpt-5 exec ...` is excluded too. (c) fd/0 is a terminal device (`pts/*` or `tty*` after
  read_tty's `/dev/` strip). `e` is exec's visible clap alias per the codex-rs CLI definition; it was not
  probed at 0.155.1. The tty rule applies to Codex only; the Claude path is unchanged.
- [INFERRED 6] A Codex row with no id renders `unknown`, not Claude's `new session`, because Codex
  cannot be resumed or "new" from here.
- [INFERRED 7] Agent-neutral wording is "Claude or Codex". Resume refusal text:
  "Resume is not supported for Codex sessions — press Tab to switch to it".
- [INFERRED 8] The fd scan is capped at 4096 entries per process (CODEX_FD_SCAN_LIMIT). A process
  holding more gets its id from the first 4096 entries only (under-detection). This bounds the
  per-poll work a hostile process named `codex` can cause.
- Residual, recorded, not addressed: an npm-wrapper Codex install whose native binary's comm is not
  exactly `codex` is invisible to `pgrep -x codex` (under-detection, silent). The macOS /proc limitation
  is documented by sibling 260923-lra.
