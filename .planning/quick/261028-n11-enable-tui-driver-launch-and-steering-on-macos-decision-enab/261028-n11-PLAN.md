<objective>
Enable TUI driver launch, steering and stop on macOS. This is the user's 2026-10-28 decision that resolves Phase 28 review
WR-05 ("macOS enablement is half applied"). Phases 28 and 29 already moved the launcher, the run store, `serve` and
`direction.rs` to `any(linux, macos)`. The CLI `driver launch --unsandboxed` and `driver stop` were proven on Darwin in
28-UAT test 2. Only the TUI still gates on Linux, through `can_steer()` (src/ui/screens/driver_steer.rs:43-45) and
`#[cfg]` arms in src/app.rs and the driver screens. Two Linux assumptions also leak into code that compiles on macOS:
`host_name()` reads a `/proc` file, and the CR-01 umask test reads `/proc/self/status`.

Purpose: a macOS user can start, relaunch (including the `[U]` unsandboxed second confirmation), steer and stop a run from the
Driver tab, as on Linux, and a macOS test run is green.

Output: widened TUI gates and copy (Task 1, the tracer), the portable host name, the Linux-gated umask test and the
widened tests (Task 2), then cross-target and Darwin evidence plus the WR-05 and todo bookkeeping (Task 3).

**Sizing (planner probe, HEAD 5a5175c): quick task, not a backlog item.** In a throwaway worktree the planner applied
exactly the widening in Tasks 1 and 2. Production: 19 sites in app.rs, 3 in driver_launch.rs, 1 in driver_run.rs and 1 in
driver_steer.rs. Tests: 60 in app.rs, 12 in detail.rs, 8 in driver_launch.rs, 23 in driver/steer.rs and 1 in
driver_frontmatter.rs. The FIFO tests stayed Linux-only. With that tree, `cargo clippy --locked --all-targets -- -D warnings`
exited 0 for x86_64-apple-darwin, aarch64-apple-darwin and x86_64-pc-windows-gnu. No Linux-only primitive sits under the TUI
path. The only one the compiler flagged was `rustix::fs::mknodat` in the FIFO test helper, which stays Linux-only. The probe
worktree was removed afterwards.
