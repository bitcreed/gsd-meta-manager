<objective>
Ship the core slice of one-off sandboxed task dispatch (CONTEXT.md "Core slice"). Behind GSDMM_EXPERIMENTAL_FEATURES, the user picks a pending todo or types a task on the Driver tab and presses `q` (/gsd-quick) or `f` (/gsd-fast). ONE sandboxed headless `claude -p` session runs it in a private clone, reports through a strict `taskctl report` CLI, and returns a result shown in the TUI. The result links to the quick task's SUMMARY.md and offers merge, push and discard.

Purpose: act on any GSD project's backlog from the TUI without a driver run, DIRECTION.md or a terminal. The launcher's sandbox posture is kept, and the user's checkout is untouched until they land the work.

Output: `src/oneoff/` (runtime seam, report, prompt, todos, store, launch, land); `taskctl report` (hidden) and `task run|status|stop|land` CLIs; small, behaviour-preserving launcher seams (one-off bwrap profile, gate-free config seeding, store-free push core); a Driver-tab TUI (picker, confirm, status line, result popup); help rows; CONFIGURATION.md and README corrections; five follow-up todos for the deferred items.

Task shape: the orchestrator mandates three tasks split along the slice's items (core + report CLI / launch + land CLI / TUI + help + docs). Each task commits on its own with a green `cargo build` and its own tests. Task 1 is the tracer of the riskiest contract, the agent -> host report path (real binary -> validator -> atomic file -> host re-validated read -> final result). Task 2's fake-shim e2e is the end-to-end tracer of the whole CLI path.

Planner inferred decisions (the human is unavailable; carry each into SUMMARY tagged [inferred — audit]):
- I-1 The clone is `git clone --no-hardlinks`. A hardlinked object file shares its inode with the project's `.git/objects`, and the same uid can chmod and rewrite it from inside the sandbox.
- I-2 Run id `oneoff-YYYYMMDD-HHMMSS` (UTC; `-2`, `-3`... on a collision), checked with `driverctl::serve::valid_run_id` plus the `oneoff-` prefix.
- I-3 A `--todo` must exist as a regular file in the clone (i.e. be committed); otherwise the run fails before the agent starts, with "commit the todo first".
- I-4 A git-relevant planted finding in the clone (`launcher::push::planted`) refuses both merge and push. There is no `--ack-planted` for one-offs; discard is the way out.
- I-5 SUMMARY rule: a changed path matching `^\.planning/quick/(?P<dir>[A-Za-z0-9][A-Za-z0-9._-]*)/(?P<id>[A-Za-z0-9][A-Za-z0-9._-]*)-SUMMARY\.md$` where `dir` starts with `id + "-"`. This covers both `261103-em6-slug/261103-em6-SUMMARY.md` and the irregular `261006-badge-.../261006-SUMMARY.md` in this repo. Added (`A`) beats modified; ties go to the last in byte order.
- I-6 Synthesized result per outcome: finished -> `partial` ("The agent finished without reporting; check the commits"); over_budget / timed_out / stopped / failed -> `failed`; rate_limited -> `blocked`. Every headline is cut to fit the 120-char rule.
- I-7 The validator also rejects invisible-formatting characters (`text::carries_invisible_formatting`), not only control characters.
- I-8 The egress CONNECT allowlist is the project's `driver.egress` allowlist (`RegisteredProject::driver_egress_allowlist`), as `driver launch` resolves it.
- I-9 Only the tip of `refs/heads/gsd-oneoff/<run-id>` is recorded and landed. If the clone's HEAD resolves to another commit, run.json records a warning.
- I-10 The merge confirmation (TUI ask and CLI output) lists changed paths under `.claude/`, `.github/`, `.husky/`, and the files `.gitattributes`, `.gitmodules`, `.envrc`, as "sensitive". It warns and does not block.
- I-11 No pull request is opened after a one-off push.
- I-12 `task` is a visible subcommand (like `driver`); `taskctl` is hidden (like `driverctl`). Neither is flag-gated: the flag is a discovery gate (CONFIGURATION.md already says so for `driver`).
- I-13 The dashboard running badge is deferred. It needs a per-project oneoff-root scan on the dashboard tick, which is not cheap (CONTEXT "Deferred").
- I-14 One `OneoffScreen` with internal modes, so the render-escape guard needs one adjudication and one fixture.
- I-15 "Raw" stream = the stream-json lines exactly as emitted, with the existing SAFE-04 credential redaction of `spawn_launch_child`'s pump. No reformatting.
- I-16 Scope unit `gsdmm-oneoff-<run-id>-<hash8>`; `RuntimeMaxSec = ceil(cap_minutes * 60) + 300` (the launcher's `RUNTIME_MAX_GRACE_S`).
- I-17 `--mode` defaults to `quick`. The wall clock starts at the agent spawn, not at the clone.
- I-18 The `T` popup and `task status` show the agent's report and the host's facts (outcome, commit count, SUMMARY present) side by side, labelled "agent-reported" vs "host".
