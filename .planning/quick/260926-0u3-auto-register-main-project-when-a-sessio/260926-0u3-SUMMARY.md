# Quick 260926-0u3: Auto-register the main project when a session cwd is inside a linked worktree Summary

A live session whose cwd is a git linked worktree (or any subdirectory of one) now auto-registers
the worktree's MAIN worktree, exactly once however many worktree sessions are live, via a new
private `registry::discovery_root` resolver (structural `linked_worktree_main` first, then the
outermost `.claude/worktrees/agent-*` prefix). The worktree path itself is still never registered,
and manual `add` still refuses it.

## What changed

- **`src/agents/worktrees.rs`**: `claude_agent_worktree_prefix(path)` returns the components before
  the outermost `.claude`/`worktrees`/`agent-*` window. `has_claude_agent_worktree_segment` now
  delegates to it, so the triple is spelled in one place.
- **`src/registry.rs`**:
  - `discovery_root(cwd, registered)` resolves in this order: linked worktree -> main;
    agent-shaped path -> prefix, but only when the prefix is not itself a linked worktree;
    under a registered project's `.claude/worktrees/` -> skip; otherwise the cwd.
  - `auto_register_from_sessions`: an exact-registered fast path, then `discovery_root`, then
    `.planning/` on the ROOT, then canonical dedupe (`registered` + `seen_this_pass`) on the root.
    A resolved root passes a worktree gate again. The alias comes from the root and `add_project`
    stays the backstop. The two old x0v inline skip blocks were removed, since their logic now
    lives in the resolver and the root gate. The doc comment was rewritten.
  - Test-only: `worktree_fixture::add_fake_worktree`. `fake_linked_worktree` delegates to it with
    an identical layout. New `worktree_session_discovery_tests` module (7 tests), placed above
    `mod tests`.
- **`tests/registry_worktree_guard.rs`**: the x0v test
  `auto_discovery_skips_a_linked_worktree_even_when_the_main_is_unregistered` was REPLACED by
  `auto_discovery_registers_the_main_when_a_session_sits_in_its_linked_worktree`. Four new real-git
  tests were added (13 real worktrees, registered main no-op, main without `.planning/`, real
  subdirectory). Every test asserts that no worktree was registered.
- **README.md** (feature bullet and setup step 4) and **docs/GETTING-STARTED.md** (first launch)
  now state the new rule. The phrase "main worktree is auto-registered" appears 2 times in
  README.md and once in GETTING-STARTED.md.
- Untouched, as UD-5 requires (verified with `git diff`): `add_project`, `add_project_unchecked`,
  `refuse_linked_worktree`, `LinkedWorktreeRefusal`, `prune_worktree_entries`,
  `load_config_pruning_worktrees`, `src/main.rs`, `src/app.rs`, `src/ui/`.

## Supersession

UD-1..UD-6 are user decisions. For **auto-discovery**, they supersede 260925-x0v's inferred
decision 3: "a linked worktree is never auto-registered even when its main worktree is
unregistered". **Manual add (CLI `add`, TUI Add, create-project) is unchanged**: it still refuses
a linked worktree with `LinkedWorktreeRefusal` naming the main. The x0v PLAN and SUMMARY were not
edited.

## Inferred decisions (audit later)

1. [inferred, per brief] UD-3 applies only when the derived prefix is NOT itself a linked worktree.
   Such a prefix registers nothing and is not resolved a second level. Pinned by
   `a_heuristic_prefix_that_is_a_linked_worktree_registers_nothing`.
2. [inferred] The path heuristic keys on the x0v shape: an `.claude`/`worktrees`/`agent-*`
   triple, or a path under a registered project's `.claude/worktrees/`. The second case stays a
   plain skip. A non-agent name under an unregistered, non-git project keeps x0v behaviour.
3. [inferred] With nested triples, the OUTERMOST one wins
   (`/p/.claude/worktrees/agent-a/.claude/worktrees/agent-b` gives `/p`).
4. [inferred] A plain subdirectory of a MAIN worktree (e.g. `ttbook/src`) is not walked up.
5. [inferred] A cwd exactly equal to a registered canonical path short-circuits before any
   classification, which keeps the ~5s poll cheap.
6. [inferred] Resolution and skip logs stay at `tracing::debug!`.
7. [inferred, executor] An EMPTY heuristic prefix is skipped with a debug log rather than falling
   through to step 4. This can only happen for a relative cwd that failed to canonicalize. Falling
   through would have registered the agent-shaped cwd itself, which x0v skipped. The plan's text
   only said "if the prefix is non-empty" and left the empty case implicit.
