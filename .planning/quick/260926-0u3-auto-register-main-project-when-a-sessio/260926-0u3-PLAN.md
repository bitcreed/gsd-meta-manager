# Quick 260926-0u3: Auto-register the main project when a session cwd is inside a linked worktree

<objective>
When a live Claude/Codex session runs inside a git linked worktree (the common case being 13 GSD executor
sessions at `~/projects/python/ttbook/.claude/worktrees/agent-*`), auto-discovery must register the
worktree's MAIN project — once — instead of silently skipping it. The worktree itself must still never
be registered. Resolution uses the existing `registry::linked_worktree_main` from quick 260925-x0v, plus
the `.claude/worktrees` path heuristic when structural resolution finds nothing.

Purpose: 260925-x0v made auto-discovery skip every linked-worktree cwd, "even when its main worktree is
unregistered" — an [inferred] choice (x0v SUMMARY decision 3, `src/registry.rs` comment at the
linked-worktree skip in `auto_register_from_sessions`). The user has now decided otherwise. So a project
whose only live sessions are executor worktrees never appeared on the dashboard. This plan
implements the user decision and supersedes that [inferred] choice for auto-discovery only.

User decisions (locked, from the brief):
- UD-1: a session cwd inside a linked worktree resolves to the main worktree via `linked_worktree_main`, and
  the main is auto-registered iff (a) it has `.planning/`, (b) it is not already registered (canonical
  path compare), (c) it passes every usual auto-register rule.
- UD-2: a cwd that is a SUBDIRECTORY of a worktree resolves the same way.
- UD-3: when structural resolution fails but the x0v `.claude/worktrees` heuristic matches, the main is the
  prefix before `/.claude/worktrees/`, under the same checks.
- UD-4: the alias comes from the main project's directory name; dedupe must hold across many concurrent
  worktree sessions (13 sessions -> exactly one registration, no `ttbook-2`).
- UD-5: manual CLI/TUI add behaviour is unchanged (refuse + name main path).
- UD-6: the worktree path itself is never registered.

Inferred decisions (human unavailable — audit later):
- [inferred, per brief] UD-3 applies only when the derived prefix is itself NOT a linked worktree
  (`linked_worktree_main(prefix)` is None). A prefix that is a linked worktree registers nothing; it is
  not resolved a second level to its own main.
- [inferred] The path heuristic keys on exactly the shape x0v's discovery skip used: a
  `.claude`/`worktrees`/`agent-*` component triple anywhere in the cwd, or a cwd under an
  already-registered project's `.claude/worktrees/`. The second case resolves to a registered project and
  is therefore a no-op, so it stays a plain skip. A non-agent name under an UNregistered project with no
  git linkage keeps x0v's behaviour. A real git worktree at any name is handled by structural resolution
  anyway.
- [inferred] When the cwd has nested triples, the heuristic uses the OUTERMOST one (for example
  `/p/.claude/worktrees/agent-a/.claude/worktrees/agent-b` gives `/p`), because a worktree created from
  inside a worktree still belongs to the outer repository.
- [inferred] A plain subdirectory of a MAIN worktree (for example `ttbook/src`) keeps today's behaviour and is
  not walked up. The brief widens resolution for worktrees only.
- [inferred] A session cwd exactly equal to a registered project's canonical path short-circuits before any
  classification. This keeps the ~5s poll as cheap as today and never reaches the git fallback for a
  registered repo.
- [inferred] Resolution and skip logs stay at `tracing::debug!`, like x0v's skip, because the poll runs every ~5s.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session cwd -> registry | Session working directories come from /proc and Codex state and can point anywhere, including cloned or hostile repositories |
| repository gitfile/commondir -> resolved main | A worktree's `.git` gitfile and admin `commondir` decide WHICH directory discovery registers as the main |
