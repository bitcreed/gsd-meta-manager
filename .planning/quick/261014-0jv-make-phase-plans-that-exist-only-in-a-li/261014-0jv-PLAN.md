Make phase plans that exist only in a linked git worktree browsable in the TUI. ## Inferred decisions (for audit)

The human was unavailable. Each decision below was inferred from code and planning artifacts, and is marked `[inferred]` where the executor cites it.

- **ID-1 [inferred] Resolve in the agents scan, not in `parse_project_state`.** The task said "wherever plan_waves/disk_status are computed off the render thread". The same `infer_disk_status` still computes the inference, but it is invoked from `agents::scan_project_with_probe` (spawn_blocking, ~5 s poll). Reasons:
  - (a) That scan already holds the project's `CoreScan`, so it adds no extra `git worktree list`.
  - (b) A worktree edit never fires the main-tree `.planning/` watcher that drives `parse_project_state`, so only the poll keeps the plans fresh.
  - (c) `ProjectState` / `phase_disk_statuses` feed the driver router, the DRIVE-05 gates and the dashboard frontier. Keeping worktree plans out of them makes the feature strictly display-only, and the router can never act on unmerged worktree content.
  - (d) The sibling detectors `unmerged` and `worktree_phases` already live there.
- **ID-2 [inferred] Live updates come from the existing ~5 s agents poll. No notify watcher on worktree dirs.** The comment at `src/app.rs` ~1258 (D-B04) forbids per-worktree watchers. Two consequences:
  - The first paint after launch waits for the first agents scan, about 5 s.
  - `infer_disk_status` re-reads the winning holders' PLAN/SUMMARY files on every poll. The cost is bounded: only phases main lacks plans for, and only one holder per phase. It is accepted, with no mtime memo.
- **ID-3 [inferred] "Main has plans" works on two levels.**
  - In the scan, names-only: main's `phases/<id>-*` dir holds `PLAN.md` or `*-PLAN.md`, or the key appears under `milestones/*-phases/`. Archived means main holds it.
  - In the UI: main's inference must have `plan_count == 0` before a worktree is browsed. A main dir whose only plans are superseded therefore shows nothing from the worktree. This is a rare edge, accepted.
- **ID-4 [inferred] Winner rule.**
  - Newest `*-PLAN.md` mtime in the candidate phase dir; an unreadable mtime ranks oldest.
  - Tie → smallest worktree path.
  - A winner with `plan_count == 0` falls through to the next holder.
  - "Mention it" is read as: show ` +N more` in the pane title. The rule is also documented on `detect`.
- **ID-5 [inferred] Plan states inside a worktree-sourced pane use the worktree's own inference.** A plan summarized in the worktree reads Done, and the title's "plans in worktree …" marker carries the not-in-main fact. The alternative was to render every such plan as ◐ Unmerged; it was rejected as less browsable. The stage ladder and head lines above the pane stay main's truth, unchanged.
- **ID-6 [inferred] Live agent states are not followed in worktree-sourced phases (follow-up).** `AgentView.waves` is still derived from MAIN's inference, so a Running agent in a worktree-sourced phase reads Queued/Planned in the pane. Extending `waves::derive` would change the dashboard executor ladder, which is out of scope.
- **ID-7 [inferred] Roadmap marker included, because it is cheap and consistent.** `roadmap_model_for` already receives the `AgentView`. The badge reuses the ghost-node `@<short_ref>` form. A main ROADMAP plan checklist still wins the counts. The unmerged post-pass treats worktree-sourced counts as 0 done in main; otherwise `d + k` would double count.
- **ID-8 [inferred] Label and branch.**
  - The label is the holder path's last component (`lanes-15`).
  - The branch is git's short name (`gsd/phase-15`). A detached holder drops the parenthesised branch.
  - Both are `Untrusted` and reach a cell only through `shown()`.
- **ID-9 [inferred] `src/registry.rs` is not touched.** `agents::worktrees::scan_worktrees` is the existing read-only enumerator.
- **ID-10 [inferred] View gate.** A scan holding only worktree plans now gets an `AgentView`. Its `summary_forms` are empty, so the dashboard cell is byte-identical.
  - Observed but NOT fixed (follow-up): `worktree_phases` alone still does not open a view, so ghost nodes need another trigger.
- **ID-11 [inferred] `Eq` is added to `PlanTokens`, `PlanMeta` and `DiskInference`.** `ProjectAgents` and `AgentView` derive `Eq` and now hold a `DiskInference`. None of the three types has a float field.
- **ID-12 [inferred] First content-reading detector in `src/agents/`.** `worktree_plans` is the first agents detector that reads file content rather than names: plan titles, waves and tokens need it. The reads go only through `disk_status::infer_disk_status`, and only for winners. The D-B01/D-B03 guard forbids writes, `/proc` and spawns, not reads, so it stays satisfied.
