<objective>
Stop `./scripts/pre-tag-check.sh --container` growing Docker storage without bound. Its cache volume `gsdmm-pretag-target` measured 51.6 GB today, and it reached 115 GB at the last release before ~92 GB was pruned by hand. The fix bounds the cache volumes with a size cap that is checked before every run, stops `debug/incremental` growth, prunes this script's own dangling images, and adds a `--clean` escape hatch. All of it is scoped strictly to resources the script owns, and it must work on docker and podman.

Purpose: the release process (CLAUDE.md step 3) runs this script for every tag. Each time rustc or Cargo.lock changes, it leaves another generation of stale test binaries in the target volume (168 stale `gsd_meta_manager-<hash>` binaries measured), and nothing ever reclaims them.

Output: a modified scripts/pre-tag-check.sh, a one-paragraph addition to CLAUDE.md step 3, and live before/after size evidence in the SUMMARY.

Decided design from the orchestrator. It is encoded below and must not be re-litigated:
- (1) an ownership label;
- (2) a size cap folded into the privileged chown container;
- (3) `CARGO_INCREMENTAL=0`;
- (4) a label-scoped dangling-image prune;
- (5) `--clean` and `PRE_TAG_CONTAINER_CLEAN`;
- (6) docker and podman support;
- (7) docs.

The human is unavailable. Inferred decisions carry the marker `[INFERRED — audit]`, and Task 3 lists them again for the SUMMARY.
