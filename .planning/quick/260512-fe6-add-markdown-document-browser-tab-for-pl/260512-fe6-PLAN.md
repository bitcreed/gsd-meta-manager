# Quick Task 260512-fe6 — `.planning/` Markdown Browser Tab

## Goal

A new detail-view tab (`0:Docs`) that lets the user crawl a project's `.planning/` tree as a drill-down file browser with rendered markdown preview. The tab opens at the project's **active phase directory** by default; quick-jump keys let the user pop up to `.planning/` root or move to sibling phases.

## User Decisions (from /gsd-quick discussion)

| Decision | Choice |
|---|---|
| Entry point | New tab in detail view |
| Initial dir | Active phase, with quick-jump keys |
| Nav model | Drill-down list → view (Archive-style) |
| File filter | `.md` files + directories only |

## Design — Mirrors the Archive Tab Pattern

The Archive tab already implements the same primitives (list → list → fileview, `archive::render_markdown_lines` for styled rendering, list-state + scroll-offset cache). The Docs tab reuses `render_markdown_lines` and `line_number_lines`, but tracks its own state because the data shape (a generic recursive directory walk) is different from the archive's milestone/phase/file fixed hierarchy.

## Tasks

### Task 1 — `src/browser.rs` module

New file. Contains:

- `BrowserDepth` enum: `List` (showing a directory listing) | `View` (viewing a markdown file).
- `BrowserEntry { name: String, path: PathBuf, is_dir: bool }`.
- `list_dir(dir: &Path) -> Vec<BrowserEntry>`:
  - Returns entries sorted: directories first (alphabetic), then `.md` files (alphabetic).
  - Skips dotfiles (entries starting with `.`) except keep `.planning` itself navigable from above.
  - Filters to: `is_dir() == true` OR file name ends with `.md` (case-insensitive).
  - Silently returns empty vec on read errors.
- `resolve_active_phase_dir(planning_dir: &Path, state: &ProjectState) -> PathBuf`:
  - If `completed_phases >= total_phases && total_phases > 0` → return `planning_dir` (milestone complete, no active phase).
  - Else compute `phase_num = completed_phases + 1`, find the matching `RoadmapPhase` by `number`, and pass that number to `state_reader::disk_status::find_phase_dir`. Fall back to `planning_dir` if not found.
- `read_md_file(path: &Path) -> String`:
  - `std::fs::read_to_string(path).unwrap_or_else(|e| format!("Could not read file: {}\n\nError: {}", path.display(), e))`.

Unit tests cover:
- `list_dir` sorts dirs first, then `.md` files; hides non-`.md` files.
- `list_dir` hides dotfiles other than `.planning` itself.
- `list_dir` returns empty on missing directory.
- `resolve_active_phase_dir` returns the planning root when milestone is complete.
- `resolve_active_phase_dir` returns the matching phase dir when not complete (uses a tempdir with `phases/01-foo/`).

### Task 2 — Wire `Browse` into `DetailSubView` and `ProjectViewCache`

**Files:**
- `src/app.rs`: add `Browse` variant to `DetailSubView`.
- `src/ui/screens/mod.rs`: add browser state to `ProjectViewCache`:
  - `browser_depth: browser::BrowserDepth` (default `List`)
  - `browser_current_dir: Option<PathBuf>` (None = uninitialized; set on first activation)
  - `browser_entries: Vec<browser::BrowserEntry>`
  - `browser_selected: usize`
  - `browser_scroll_offset: u16`
  - `browser_file_content: Option<String>`
  - `browser_file_name: Option<String>`
- `src/lib.rs`: declare `pub mod browser;`.

### Task 3 — Detail screen: tab title, render, input

**File:** `src/ui/screens/detail.rs`

- `TAB_TITLES`: extend from `[&str; 9]` to `[&str; 10]`, append `"0:Docs"`.
- `tab_index` / `sub_view_from_index`: add the `Browse` ↔ `9` mapping (10th slot).
- Add `KeyCode::Char('0') => switch_to_tab(.., 9, ..)`.
- Extend `switch_to_tab`: when switching to `Browse`, lazy-init the browser if `browser_current_dir.is_none()` — resolve the active phase dir from the project's state, set `current_dir`, populate `entries` via `browser::list_dir`.
- Render branch in the detail render loop:
  - `List` mode: show breadcrumb line (`Docs > <rel path from .planning/>`) plus a `List` of entries with `[DIR]` prefix on directories. Reuse the same highlight style as the archive tab.
  - `View` mode: split into gutter (line numbers via `archive::line_number_lines`) + main pane (`archive::render_markdown_lines`) with scroll offset, just like Archive's `FileView` does.
- Key handlers (only fire when `current_view == DetailSubView::Browse`):
  - `j`/`k` / `Down`/`Up`: move selection (List) or scroll (View).
  - `Enter`: descend into dir or open `.md` file (load content into `browser_file_content`, switch to `View`).
  - `Backspace` / `h` / `Left`:
    - In `View`: drop back to `List` (keep `current_dir`).
    - In `List`: if `current_dir` is a strict descendant of the project's `.planning/`, go up to parent (re-`list_dir`, reset selection).
  - `g`: jump to project's `.planning/` root.
  - `p`: jump back to the active phase dir (the original entry point).
  - `PageUp`/`PageDown`: existing PAGE_SCROLL_LINES behavior, applied to either selection or scroll.
- Tab `[Left]`/`[Right]` already cycle by index — no changes needed beyond `TAB_TITLES.len()` math, which adapts automatically.
- The `9-tab detail view` line in `README.md` updates to mention the new tab as well — but that's a docs concern handled in the SUMMARY commit, not a separate task.

## Out of Scope

- Editing markdown files in-place (Backlog tab already shells out to `$EDITOR` if needed).
- Non-`.md` file rendering (decision: `.md` + dirs only).
- Fuzzy-search across `.planning/` (could be a follow-up).
- A separate "Files" filter for symlinks, very large files, etc. — defer until a real case appears.
