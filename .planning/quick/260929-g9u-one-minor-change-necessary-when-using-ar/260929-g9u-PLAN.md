## Inferred decisions (for audit)

The human was unavailable. Each decision below was inferred from the code and planning artifacts.

- **I-1: Focus model.** A new `DetailFocus::ScopeStrip` level, modelled on `DetailFocus::Pane` (quick 260926-2l4): a level that is valid on one tab only and resets to `Content` elsewhere.
  - The Docs and Sessions strips have NO focus level of their own. They belong to `Content`, where `←`/`→` switch sub-tabs. So there is no strip-focus model to copy, and the Pane level is the codebase's precedent for adding one.
  - It is not a view-cache flag, per the enum doc's rule against a second flag that must agree with the first.
  - Folding Config into `sub_tab_pair` was rejected. It would make `←`/`→` on the rows switch scope, and it would not "land on" the strip as the user asked.
- **I-2: Arrows on the strip are directional and clamped.** `←` selects Project and `→` selects Global. They do not toggle or wrap, which mirrors `step_sub_tab`. They go through `set_config_scope` and set the same status message as `g` and click.
- **I-3: Ways onto the strip.**
  - From the tab bar on Config, the whole descend set lands on the strip: `↓`, `j`, `Enter` and `Space` (1t1 I-3).
  - From the rows, `↑`/`k` on the first visible row climbs onto it.
  - A digit, `7` included, still jumps into the rows. This is 1t1 D-04: a digit is an explicit jump into content.
- **I-4: Leaving the strip.**
  - `↓`/`j`/`Enter`/`Space` go to the rows with no other change. `Enter` never opens an editor from the strip.
  - `↑`/`k`/`Esc` go to the tab bar.
  - `Esc` on the strip does not clear a confirmed filter.
- **I-5: Unchanged row behaviour.**
  - `Esc` from the Config rows still goes straight to the tab bar, not via the strip, so two `Esc` presses still leave (1t1 D-01).
  - `←`/`→` on the rows still switch tabs.
  - `[`/`]` never switch scope.
  - This supersedes t3s I-5 at the strip level only, per the user's "needs arrow-keys support".
- **I-6: Other keys on the strip.**
  - `g`/`d` switch scope and keep the strip focused, because they toggle the very thing that is focused.
  - `?`, `Tab`, `q` and `M` act as they do at every level.
  - Every other key drops focus to the rows and runs there. This is the tab bar's 1t1 I-2 rule, so `/`, `x`, `r`, digits and `PgUp`/`PgDn` never cost an extra keypress.
- **I-7: The focus cue.**
