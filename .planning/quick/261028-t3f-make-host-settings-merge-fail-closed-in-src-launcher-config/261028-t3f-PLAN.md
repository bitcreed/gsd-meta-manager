<objective>
Make the host managed-settings merge in `managed_settings` (src/launcher/config_dir.rs:583-616) fail closed. If the host's `hooks` or `permissions` value is not a JSON object (a string, an array, null, a number or a bool), it must never replace the launcher's gate hooks or its `DENY_TOOLS` deny list. Pin this with tests for every non-object shape, in both postures. Correct the doc claims that say every host value is merged. Record the finding as fixed in both phase disposition files that list it: 28-REVIEW WR-08 and 29-REVIEW WR-02, which are the same defect.

Purpose: on a bwrap launch the managed tier carries the whole gate (28.1 D-12/D-13), and the per-run settings.json then holds no driverctl entry. Today a host file such as `{"hooks": []}` passes `read_host_managed`, because it is a JSON object. It reaches the catch-all arm, and the run starts with no dispatch gate, no stop guard and no deny list anywhere. Whether Claude Code would refuse such a file is a claim about another program. IN-03 already refused that dependency one level down. This change refuses it one level up as well.

Output: one fix arm plus three tests (one end-to-end seed test and two shape tables), three corrected doc claims, and two disposition rows set to fixed with the commit sha.
