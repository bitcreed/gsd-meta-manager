<objective>
This builds on quick 261103-f5y. A one-off run gets a live viewer, operator message injection into the running agent, and a notional spend meter with rate-limit status. If it fits, it also gets a launcher-enforced soft cap that can be adjusted live, and `task attach`. All of it is experimental and TUI-first, behind the same GSDMM_EXPERIMENTAL_FEATURES gating as the one-off itself.

Purpose: today the `T` popup shows only "running Nm". The operator cannot see what the agent is doing, correct it mid-run, or see what it is spending.

Output:
- The agent is switched to stream-json stdin. The prompt becomes its first message, and the launcher ends the session at the end of the turn.
- A host-only inbox plus `injections.jsonl`.
- A runtime-neutral stream module: classifier output type, tail, renderer, estimator.
- `task send`. Task 3 adds `task budget` and `task attach`.
- A full-screen viewer screen with a meter and a composer.
- Help rows, CONFIGURATION.md and follow-up todos.

Task shape. The orchestrator wants the core slice first.
- Task 1 is the tracer of the riskiest contract, the path from the operator to the agent's stdin: `task send` -> inbox -> daemon -> stdin pipe through systemd-run/bwrap -> agent -> replay -> `stream.jsonl` -> lifecycle closes stdin -> session ends. It runs end to end on the fake harness.
- Task 2 builds the TUI viewer, the meter, help and docs, and closes the starting todo.
- Task 3 holds the ship-if-fits items: soft-cap enforcement and `task attach`. The executor MAY defer either one, or both, to a todo when the budget runs out (CONTEXT "Core slice vs deferred"). Task 3's todo step is never skipped.

Planner inferred decisions. The human is unavailable; carry each one into the SUMMARY tagged [inferred — audit].
- I-1 `classify(line)` returns `Vec<StreamEvent>`, not one event: one stream line can carry several content blocks plus a `usage`. Thinking blocks are not rendered.
- I-2 A replay is `type:"user"` + `isReplay:true` + no `parent_tool_use_id`, with text content (a string or text blocks). Replays are matched to writes by COUNT, in order, never by text: the SAFE-04 pump may redact the replayed text.
- I-3 Stdin is written by a dedicated writer thread (`ChildInput`) fed by a channel. A full pipe (a 120 KiB prompt is bigger than the 64 KiB pipe buffer) can then never block the wait loop or the wall clock. A write error (EPIPE) marks the input closed, and later sends are refused.
- I-4 The daemon follows its own `stream.jsonl` with the same `StreamTail` the viewer uses. `pump_redacted` and the driver's capture are not touched.
- I-5 Each injection record also carries `id` (the inbox file stem), so `task send` and `task budget` can wait (`--wait-secs`, default 10) and report `delivered`, or `refused: <reason>`, for their own request.
- I-6 At most 200 injections per run (`MAX_INJECTIONS`); later ones are refused. Inbox files still pending when the session ends are drained and recorded as refused, "the session ended".
- I-7 The viewer is its own screen, `OneoffViewerScreen`, which App pushes on `Action::OneoffViewerOpen`. Its tail loop stops on a cancel flag (`Arc<AtomicBool>`) that the screen sets in `Drop`, and also by itself once the run is finished and the stream drained.
- I-8 The price table holds notional USD per MTok, first-party list prices from the claude-api skill's model table (cached 2026-10-06). Cache write is 1.25 × input; cache read is as listed where listed, else 0.1 × input. The longest model-id prefix wins, then the family substring, else $5/$25. Haiku 5.5's >100K tier is ignored.
- I-9 `result.total_cost_usd` is taken as the session's cumulative cost. The per-message-id usage map resets at every result.
- I-10 The viewer also follows `injections.jsonl` and shows a refused injection as one `! refused <kind>: <reason>` line, so a refusal is visible where the operator typed.
- I-11 The wrap-up is sent at most once per run. A second crossing, after a raise, restarts the grace without a second message.
- I-12 A test-only grace override, `GSDMM_ONEOFF_SOFT_CAP_GRACE_SECS` (integer 1..=600), is read once at session start. It is documented in the env table as "tests only". The sandboxed agent cannot set the daemon's environment.
- I-13 The meter's `soft` segment and the `b` key ship WITH the enforcement in Task 3, so a deferral leaves no dead key or misleading `soft off`.
- I-14 The viewer bounds each event at `DRIVER_OUTPUT_RECORD_MAX_LINES` (64) lines and each line at `DRIVER_OUTPUT_LINE_CELLS` (512) chars. The CLI `task attach` uses the same renderer.
