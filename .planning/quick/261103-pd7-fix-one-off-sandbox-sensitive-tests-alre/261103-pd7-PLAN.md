**Item 4, land.lock churn: root cause found.**
- `driver::lock::acquire_at` opens the lock path with `create(true)` (src/driver/lock.rs:259-260). Releasing a lock means dropping the `RunLock` (src/driver/lock.rs:126-136, no Drop), which closes the fd but never unlinks the file. Probes never create it: `probe_at` opens read-only and returns `Absent` on NotFound (src/driver/lock.rs:437-440). `landing_in_progress` (src/oneoff/land.rs:100-105) and `lock_is_free` (src/oneoff/recycle.rs:675-677) are probes.
- Every `take_land_lock` (src/oneoff/land.rs:108-121) therefore creates `land.lock`. Only two places unlink it, and only on success: `slim_run` when the outcome is `Slimmed` (src/oneoff/recycle.rs:339-342), and `recover_dead` after a `Slimmed` slim (src/oneoff/recycle.rs:868).
- These takers leave the file behind:
  - `tidy_finished` (src/oneoff/recycle.rs:750). It runs on EVERY scan (`task list`, `task run`, TUI start) for every finished run that is not slimmed, which includes an already-slimmed landed run, since `leftover_slim_note` returns None for it at recycle.rs:586-588. This is the churn source.
  - `merge_locked` (src/oneoff/land.rs:748), on every exit including refusals.
  - `slim_run` on Kept or Skipped (recycle.rs:331-343).
  - `recover_dead` on its early returns (recycle.rs:805-813).
  - `age_out` when a record is no longer clean (recycle.rs:988-1002).
  - the resume start (src/oneoff/resume.rs:261).
- Measured in the user's data dir. Both run dirs of project hash `f4c69b74` hold a `land.lock` whose holder record is `pgid 3124208, started_at 2026-11-04T00:12:42Z`. One scan process re-created both. Run `…000607` had been landed and slimmed at 00:08:00, and slim_run had unlinked its lock then. The 00:12:42 lock can only have come from `tidy_finished`.

**Item 3, stale preservation message: the verdict is NOT stored.**

Nothing persists it: `task_cli::recycle` prints it (src/task_cli.rs:652-660), and the TUI only logs it with `tracing::warn!` (src/app.rs:3367-3373).
