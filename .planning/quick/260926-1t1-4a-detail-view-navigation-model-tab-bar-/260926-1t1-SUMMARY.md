# Quick 260926-1t1: 4a detail-view navigation model (tab bar / content) Summary

The detail view now has a tab-bar focus level above each tab's content. `Enter` at the tab bar descends and does nothing else, so it can no longer resume a session by accident. `Esc` steps up one level and `q` leaves. The arrows switch sub-tabs inside Sessions and Docs, and each tab re-opens the sub-tab you last used there. Focus is shown by text as well as colour: the active tab is bracketed, and the open pane has a `▸`. The footer, help popup, README and GETTING-STARTED all describe the same model.

## Final key map

**At the TAB BAR** (reached by `↑` on a content's first row, by `Esc` from content, or by `←`/`→` on a tab without sub-tabs):

| Key | Effect |
|-----|--------|
| `←` / `→` | Previous / next tab, clamped at the visible count (flag off: Docs is last). Focus stays on the tab bar. Lands on the tab's remembered sub-tab |
| `↓` / `j` / `Enter` / `Space` | Descend into content with no other state change (Sessions Enter never resumes from here) |
| `↑` / `k` | No-op |
| `Esc` / `q` | Pop to the dashboard |
| `?`, `Tab` | Act as today, and focus stays on the tab bar |
| any other key (digits, `D`, `[`, `]`, `m`, `e`, `x`, `n`, `/`, `g`, PgUp/PgDn, …) | Moves focus to content, then runs exactly as in content |

Footer: `  [←/→]tabs  [↓/Enter]open  [1-8/D]jump  [Esc]back  [?]help` (flag off: `[1-8]jump`). It is shown on every tab, the Driver tab included.

**In CONTENT** (where every opening lands, and where every digit lands):

| Key | Effect |
|-----|--------|
| `1`-`8`, `Shift+D` | Jump to that tab's content, onto its last-used sub-tab |
| `←` / `→` | Open Backlog pane: `←` closes it, `→` does nothing. Sessions/Agents and Files/Milestones: previous / next sub-tab, clamped, focus stays in content. Any other tab: switch tab (clamped) and land on the tab bar |
| `[` / `]` | Sessions / Docs: previous / next sub-tab, clamped. Roadmap list: same-wave walk, unchanged. Other tabs: no-op |
| `m` | Sessions / Docs sub-tab toggle. It still works as an alias but is not shown in the footer or the strip |
| `↑` / `k` | On the first row (`content_at_first_row`): go to the tab bar. Otherwise the tab's own move, unchanged |
| `Esc` | Pops one inner level first, as before: Archive depth, Backlog pane, Git commit pane, Browse file or dir, Config dropdown, confirmed Config filter. With nothing left to pop, it goes to the tab bar |
| `q` | Pop to the dashboard, without popping inner levels |
| `Tab` | Switch the terminal to this project's session (unchanged) |
| everything else | Unchanged per tab (Sessions `Enter` still resumes) |

Content footer:

- It starts `  [↑]tab bar  `, then the arrow token: `[←/→]Sessions|Agents`, `[←/→]Files|Milestones` or `[←/→]tabs`.
- Then `  [1-8/D]jump  [j/k]move  `, then the tab's own hints, ending with `[?]help`.
- No footer shows `[m]`.
- The Backlog pane footer reads `[Enter/Esc/←]close`.
- The Driver footer is unchanged ([inferred I-13]).

The Config text-edit and filter intercepts still run before all of the above (T-1t1-02).

## Inferred decisions (for audit)

The planner's decisions, all implemented as written:

- **[inferred I-1]** `←`/`→` on a tab without sub-tabs switch tab and land on the tab bar, even at the clamped end.
- **[inferred I-2]** The tab bar handles only `←` `→` `↓` `j` `Enter` `Space` `↑` `k` `Esc` `q`. `?` and `Tab` leave focus where it is. Every other key moves focus to content and then runs.
- **[inferred I-3]** `Space` at the tab bar descends like `Enter`.
- **[inferred I-4]** `q` leaves from any level without popping inner levels; the inner state stays in the view cache.
- **[inferred I-5]** `k` behaves like `↑`. `content_at_first_row` is exhaustive:
  - the scroll views count scrolled-to-top as the first row;
  - an open Backlog pane or Config dropdown never counts;
  - on Git, `↑` at row 0 leaves the commit pane as it is.
- **[inferred I-6]** The active tab is bracketed at every level, with the widget's pads set to empty so the width is unchanged.
- **[inferred I-7]** The dim at the tab bar is one `set_style(content_area, DarkGray)` after the content render.
- **[inferred I-8]** The `▸` and cyan border mark a focused pane only (the Backlog pane in 4a).
- **[inferred I-9]** Backlog pane: `←` closes it, `→` does nothing, `↑` never leaves it.
- **[inferred I-10]** `backlog_expanded` stays the single source of truth for the pane; there is no second focus flag.
- **[inferred I-11]** The sub-tab memory is per project, in memory only, and written by every arrival, including the Roadmap shipped-row jump and `opened_on`.
- **[inferred I-12]** The strip hint reads `←/→ switch` and is dimmed at the tab bar.
- **[inferred I-13]** The Driver footer is unchanged.
- **[inferred I-14]** The content footer keeps the digit token, now `[1-8/D]jump` / `[1-8]jump`.
- **[inferred I-15]** `[`/`]` on a tab without sub-tabs (other than the Roadmap list) do nothing.

- **[inferred I-17]** Both render paths reset and refill `DetailRegions` every frame.

## Deviations from Plan

The plan was followed, with these small structural choices:

1. **[Rule 3 - structure] Digit arms merged.** The eight literal `'1'`..`'8'` arms became one `KeyCode::Char(digit @ '1'..='8')` arm, which sets focus to Content and then switches. The behaviour is identical; the merge makes the "digits land in content" line exist once.
2. **[Plan option taken] Strip-row helpers.** The free functions `docs_sub_tab_row` and `sessions_sub_tab_row` were replaced by one `DetailScreen::sub_tab_row(frame, area, strip)` method, which also records the strip rect. The plan allowed "let their method callers record". `docs_sub_tab_strip` and `sessions_sub_tab_strip` are unchanged apart from the gutter and the hint.
3. **[Test fixture] `two_sessions_fixture` pre-creates the view-cache entry.** The new tests can then read `sessions_selected` directly; opening from the dashboard never guarantees a cache entry.

There were no auth gates and no architectural (Rule 4) decisions. Every task went RED, then GREEN; some of the Task 1 behaviour tests pin already-correct behaviour and passed at RED.
