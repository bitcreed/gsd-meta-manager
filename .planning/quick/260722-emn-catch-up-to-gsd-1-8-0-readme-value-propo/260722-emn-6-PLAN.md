<objective>
Adopt the ADR-2207 status vocabulary, read the new STATE.md frontmatter keys, prefer the
ROADMAP `## Progress` table for counts, detect async external jobs, and enrich
`ProjectState` — all the mod.rs-owning data-layer changes in one plan.

Purpose: GSD 1.8.0 distinguishes phase-level completion (`All phases complete`, an
INTERMEDIATE state — the milestone is not done) from milestone termination (`<version>
milestone complete` / `Awaiting next milestone`). It also writes `current_phase`,
`current_phase_name`, `current_plan` frontmatter and `.planning/async-jobs/*.json`
manifests (a phase waiting on an external job is legitimately blocked, not stuck). This
plan makes the dashboard reflect all of that.

Output: `state_md.rs` (frontmatter keys + ADR-2207 helpers), `app.rs` (status/phase
classification), `mod.rs` (`parse_project_state` rework + new `ProjectState` fields).

Scope guard: this is the wave-2 plan that OWNS `mod.rs`; plan 8 (workstreams) edits
mod.rs later in wave 3. `app.rs` is included here because that is where the status
keyword matching (`classify_status`, `format_phase_display`) actually lives — no other
plan touches it. Consumes plan 3's `roadmap_progress` (C→F1) and plan 5's
`project_last_activity` (E→F1), both already merged from wave 1.
</objective>
