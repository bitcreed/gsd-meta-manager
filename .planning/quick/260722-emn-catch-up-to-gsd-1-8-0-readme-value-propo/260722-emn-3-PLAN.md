<objective>
Extend ROADMAP.md parsing to the heading forms and progress conventions GSD 1.8.0
projects now use: additional phase heading shapes, strikethrough/backlog exclusion,
and an authoritative `## Progress` table parser.

Purpose: `parse_roadmap_phases` currently only recognizes `- [ ] **Phase N: Title** - desc`
checklist items with numeric IDs. Real 1.8.0 roadmaps use `###` headings, parenthetical
cluster tags, project-code/milestone-prefixed IDs, `<details>`-wrapped checklists,
strikethrough retirement, backlog sentinels, and a `## Progress` table that is the
canonical source of phase/plan counts. Missing these skews every project's phase list
and progress.

Output: Updated `src/state_reader/roadmap_md.rs` — broader phase recognition, retired/
backlog filtering, and a new `RoadmapProgress` struct + `roadmap_progress` parser,
with inline tests.

Scope guard: touch ONLY `src/state_reader/roadmap_md.rs`. Do NOT add fields to the
`RoadmapPhase` struct — `change_tracker.rs` (out of scope for this plan) builds
`RoadmapPhase` with a full struct literal and would fail to compile. Encode retirement/
backlog by FILTERING those phases out of the returned Vec, and put new progress data in
a separate `RoadmapProgress` struct. The "prefer the Progress table over STATE.md
frontmatter" wiring belongs to plan 6 (mod.rs) — this plan only exposes the parser.
</objective>

  <name>Task 1: Recognize additional phase heading forms</name>
  <files>src/state_reader/roadmap_md.rs</files>
  <behavior>
    - `### Phase 4: Visualization` (markdown heading, no checkbox) is parsed as a phase (number "4", name "Visualization"); with no checkbox its `completed` defaults to false.
    - `- [ ] **Phase 26 (Cluster B): Title** - desc` parses number "26", name "Title" (the parenthetical tag is not part of the number or name), description "desc".
    - Project-code / milestone-prefixed IDs parse: `- [ ] **Phase M-2: Title** - desc` → number "M-2"; `- [ ] **Phase AB-29: Title** - desc` → number "AB-29".
    - Phase/plan lines inside a `<details>...</details>` block (with a `<summary>` line) are still parsed; the `<details>`/`</details>`/`<summary>` wrapper lines are transparent.
    - All existing forms (numeric `**Phase N: Title**`, decimal `[0-9.]+`) still parse as before.
  </behavior>
  <action>
    Broaden the phase token: replace the `([0-9.]+)` capture with a phase-ID capture that
    accepts digits, dots, and an optional leading letter-code with hyphen — e.g. a pattern
    like `([A-Za-z]+-)?[0-9][0-9.]*` OR a bare `[A-Za-z]{1,3}-[0-9.]+` alternative — so
    `4`, `0.3`, `M-2`, `AB-29` all match while the trailing `: ` boundary is preserved.
    Allow an OPTIONAL non-capturing parenthetical/tag segment between the number and the
    colon (e.g. ` (Cluster B)`) and strip it from name/number. Add a SECOND recognizer for
    `###`-style headings: match lines like `^\s*#{2,4}\s+Phase <id>:\s+<title>` (no
    checkbox, no `**`), producing a `RoadmapPhase` with `completed: false` and empty
    description; its plan counts still come from the following plan-checklist scan.
    Make the parse loop treat `<details>`, `</details>`, and `<summary>...</summary>`
    lines as transparent (skip without breaking the plan-item scan) so phases and plans
    nested in a `<details>` block are counted. Keep the plan-item regex (`plan_re`) and
    per-phase plan counting intact. Add inline tests for each behavior bullet.
  </action>

  <name>Task 2: Exclude strikethrough (retired) and backlog-sentinel phases</name>
  <files>src/state_reader/roadmap_md.rs</files>
  <behavior>
    - A strikethrough phase, e.g. `- [ ] ~~**Phase 7: Old idea**~~ - desc` or `~~Phase 7: Old idea~~`, is RETIRED: it does not appear in the returned Vec and does not contribute to any count.
    - `Phase 0` (a backlog sentinel) is excluded from the returned Vec.
    - `Phase 999`, `Phase 999.1`, `Phase 999.x` (backlog sentinels) are excluded from the returned Vec.
    - Ordinary phases (1, 2, 0.3, 14, M-2, ...) are unaffected.
  </behavior>
  <action>
    Detect strikethrough by testing whether the matched phase line (or the phase-title
    span) is wrapped in `~~...~~`; if so, skip pushing that phase (retired → excluded from
    counts). Detect backlog sentinels by phase number: skip when the number equals `0` or
    when it is `999` or starts with `999.` (covers `999`, `999.1`, `999.x`). Apply both
    filters at the point where a parsed phase would be pushed so retired/backlog phases
    never enter the returned Vec. Add inline tests: a strikethrough phase is absent; a
    `Phase 0` line is absent; `Phase 999` / `Phase 999.2` are absent; a normal roadmap of
    3 real phases is unchanged.
  </action>

  </done>
