<objective>
Add a workstreams data layer: detect `.planning/workstreams/<ws>/` directories, parse
each as its own project state by reusing the existing readers, mark the active one, and
expose the list on `ProjectState`.

Purpose: GSD 1.8.0 supports parallel workstreams — each `.planning/workstreams/<ws>/`
holds its own `ROADMAP.md`, `STATE.md`, `phases/`, and `milestones/`, with the active
workstream tracked by `.planning/active-workstream`. The dashboard currently sees only
the flat top-level `.planning/`, so multi-workstream projects appear frozen.

Output: new `src/state_reader/workstreams.rs` and a `workstreams` field on
`ProjectState`, populated in `parse_project_state`, with tests.

Scope guard: this plan runs in wave 3 and OWNS the mod.rs edits for this wave (plan 7,
also wave 3, touches only queue_md.rs — disjoint). Both branch from post-wave-2, so
plan 6's `ProjectState` fields are already present. Do not touch any UI file (surfacing
workstreams in the UI is plan 9).
</objective>
