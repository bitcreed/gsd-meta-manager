<objective>
Make `suggest_next_commands` shell out to GSD's `smart-entry` when a resolvable
`gsd-tools` is available for the project, falling back to the existing keyword heuristic
otherwise — without changing its signature or touching any UI file.

Purpose: GSD 1.8.0 centralized "what should I run next?" in `gsd-tools smart-entry`,
which understands situations the meta-manager's keyword heuristic cannot (idle-stranded,
external-job-waiting, milestone boundaries) and always returns exactly one recommended
`/gsd:*` action. Deferring to it keeps the TUI's suggestions correct as GSD evolves.

Output: `src/state_reader/queue_md.rs` — `smart-entry` resolution + shell-out + JSON
parsing, with the keyword heuristic preserved as fallback, and inline tests.

Scope guard: touch ONLY `src/state_reader/queue_md.rs`. Read `state.project_root` (added
by plan 6, already merged from wave 2) so the public `suggest_next_commands(state)`
signature is UNCHANGED — the UI call sites in `detail.rs`/`enqueue.rs` need no edits.
Do not touch mod.rs or any UI file.
</objective>
