<objective>
Bring `disk_status.rs` phase-artifact scanning up to GSD 1.8.0 semantics: correct
PLAN/SUMMARY counting (exclusions + matched-summary rule + superseded plans),
robust phase-token/dir matching for non-2-digit conventions, and detection of four
new artifact types.

Purpose: The disk inference drives per-phase status badges and the Pipeline
drill-down across every registered project. GSD 1.8.0 introduced FIX/GAPCLOSURE
summaries, PLAN-REVIEW artifacts, `status: superseded` plans, decimal/prefixed phase
directory names, and new artifact files. Miscounting any of these corrupts the
status shown for a project.

Output: Updated `src/state_reader/disk_status.rs` with new `DiskInference` fields,
a shared phase-matching helper, and inline tests.

Scope guard: touch ONLY `src/state_reader/disk_status.rs`. `DiskInference` is stored
in `ProjectState` via `#[derive(Default)]`, so adding fields here needs NO change to
`mod.rs` (plan 6/8 own mod.rs). Do not edit any other file.

<task type="auto" tdd="true">
  <name>Task 1: Correct PLAN/SUMMARY counting — exclusions, superseded, matched-summary rule</name>
  <files>src/state_reader/disk_status.rs</files>
  <behavior>
    - A `*-FIX-*-SUMMARY.md` file (e.g. `05-01-FIX-01-SUMMARY.md`) is NOT counted in summary_count.
    - A `*-GAPCLOSURE-SUMMARY.md` file is NOT counted in summary_count.
    - A `*-PLAN-REVIEW.md` file is NOT counted in plan_count (and does not set has_plans).
    - A `NN-MM-PLAN.md` whose YAML frontmatter contains `status: superseded` is excluded from plan_count and its matching summary is excluded too.
    - A `NN-MM-SUMMARY.md` counts only if a non-superseded `NN-MM-PLAN.md` (same ID) exists in the dir (matched-summary rule); standalone `SUMMARY.md` counts only if `PLAN.md` exists.
    - Existing behavior for ordinary numbered + standalone plans/summaries is preserved (existing tests still pass).
  </behavior>
  <action>
    Rework the scan in `infer_disk_status` into two passes over the directory entries.
    Pass 1 collects plan IDs: for each file matching `PLAN.md` or `*-PLAN.md` but NOT
    `*-PLAN-CHECK.md` and NOT `*-PLAN-REVIEW.md`, derive its plan ID (the filename with
    the `-PLAN.md`/`PLAN.md` suffix removed; standalone `PLAN.md` → empty-string ID),
    read the file via `std::fs::read_to_string(entry.path())`, and skip it if its YAML
    frontmatter `status:` value is `superseded` (parse only the leading `---`…`---`
    block; a cheap line scan for a `status:` key equal to `superseded` is sufficient —
    do not pull in a YAML dep). Record surviving plan IDs in a set and count them as
    plan_count. Pass 2 counts summaries: for each file matching `SUMMARY.md` or
    `*-SUMMARY.md`, skip it if the name matches `*-FIX-*-SUMMARY.md` or ends with
    `-GAPCLOSURE-SUMMARY.md`; otherwise derive its summary ID (strip the
    `-SUMMARY.md`/`SUMMARY.md` suffix) and count it only if that ID is in the surviving
    plan-ID set. Keep the artifact-flag `continue` guards (UI-REVIEW, EVAL-REVIEW,
    REVIEW, specs, PATTERNS, PLAN-CHECK, VALIDATION, SECURITY, UAT) ahead of the
    PLAN/SUMMARY matching exactly as today so prefixed names are not double-counted.
    Add an explicit skip for `*-PLAN-REVIEW.md` in the guard region (mirroring the
    existing PLAN-CHECK guard) for clarity. Status derivation
    (`summary_count >= plan_count && plan_count > 0` → Complete, etc.) is unchanged.
    Add inline tests covering: FIX summary excluded, GAPCLOSURE summary excluded,
    PLAN-REVIEW not counted as a plan, a superseded plan removed from the denominator
    (and its summary not counted), an unmatched summary (summary with no plan) not
    counted, and a normal 2-plan/2-summary dir still Complete.
  </action>
  <verify>
    <automated>cargo test --lib disk_status 2>&amp;1 | tail -20</automated>
  </verify>
  <done>
    All new counting tests pass and all pre-existing disk_status tests still pass.
    FIX/GAPCLOSURE summaries, PLAN-REVIEW plans, and superseded plans no longer affect
    counts; summaries count only when matched to a surviving plan.
  </done>

<task type="auto" tdd="true">
  <name>Task 2: Robust phase-token/dir matching helper</name>
  <files>src/state_reader/disk_status.rs</files>
  <behavior>
    - `phase_dir_matches("14-2026-foo", "14")` is true (year-prefixed multi-segment dir).
    - `phase_dir_matches("0.3-slug", "0.3")` is true (decimal ID).
    - `phase_dir_matches("M1-2-slug", "M1-2")` is true (milestone-prefixed).
    - `phase_dir_matches("AB-29-slug", "AB-29")` is true (project-code prefix).
    - `phase_dir_matches("3-foo", "3")` and `phase_dir_matches("03-foo", "3")` are both true (pad-insensitive).
    - `phase_dir_matches("14-foo", "1")` is FALSE (a bare number must not match a longer number — the `-` separator guards this).
    - `phase_dir_matches("1.2-foo", "1")` is FALSE (decimal boundary).
  </behavior>
  <action>
    Add `fn phase_dir_matches(dir_name: &str, phase_number: &str) -> bool`. Build a
    candidate list from `phase_number`: always include the raw string; if it is
    entirely ASCII digits, also include the zero-padded-to-2-digits form and the
    leading-zeros-stripped form. For each candidate C return true when
    `dir_name == C` OR `dir_name.starts_with(&format!("{C}-"))`. The trailing `-` in
    the prefix form is the boundary guard that prevents `1` matching `14-…` or
    `1.2-…`. Replace the three ad-hoc `padded`/`prefix` `starts_with` sites — in
    `find_phase_dir` (phases/ scan and milestones/ scan) and in `infer_phase_status`
    (milestones/ archived scan) — with calls to `phase_dir_matches`. Delete the local
    zero-pad `if phase_number.len() == 1` blocks now that the helper handles padding.
    Add inline tests for every behavior bullet above, plus a `find_phase_dir` test
    against a `14-2026-foo` directory and a `0.3-foo` directory.
  </action>
  <verify>
    <automated>cargo test --lib disk_status 2>&amp;1 | tail -20</automated>
  </verify>
  <done>
    `phase_dir_matches` covers decimal, milestone-prefixed, project-code, multi-digit,
    and year-prefixed directory names, rejects bare-number-vs-longer-number collisions,
    and all three matching call sites use it. Existing `find_phase_dir`/archived tests
    still pass.
  </done>
</task>
