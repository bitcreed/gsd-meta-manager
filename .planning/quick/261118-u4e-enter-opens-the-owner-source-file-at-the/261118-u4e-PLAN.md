<objective>
Owner's words: "When I press enter on a FIX (or anything else that has a file) it shows the
file but then I should be able to select it and open it by pressing enter — ideally also bring
me to the right place."

Make the check lines and the `file PATH` line of an expanded group selectable, in the inbox
screen and in the Phases-tab Owner block, and let Enter on them open the existing read-only
viewer (the one `o` uses — never the editor) scrolled to the right line, with that line marked.

Purpose: one keypress from "I see the failing check" to "I am reading it in its file".
Output: locator + viewer jump (owner_actions.rs, owner_file_view.rs), sub-stop model
(owner_block.rs), both hosts wired (inbox.rs, detail.rs), help/README updated.

## Inferred decisions (record each as INFERRED in the SUMMARY)

- I-1: In an expanded group, every drawn check line and every `file PATH` line is a j/k
  sub-stop, in drawn order, in both hosts. The `… N more` line and the inbox `run …` line are
  not stops. Merged inbox rows draw `file PATH` before each part's checks, so their file stop
  precedes those checks; every other row draws its file line(s) after the checks.
- I-2: Enter on a check line opens the viewer at that check. Enter on a file line opens that
  file at the group's place: its first listed check (in a FIX group that is the first
  failure/gap entry), else the phase heading, else the top.
- I-3: Enter on a group row keeps expand/collapse; Space always toggles (so a sub-row can still
  collapse its group); the fold line is unchanged.
- I-4: `o`, `v`, `A`, `y`, `g`, `x` on a sub-row keep acting on the parent row (phase 39 D-04
  kept): `o` still opens the row's file at the top, `x` on a file line is the phase-level
  settle exactly as on the row.
- I-5: Target line in the viewer: `glyphs::POINTER_RIGHT` plus a space in a 2-cell gutter, and
  REVERSED+BOLD on the target's rows; scrolled so the target sits 2 rows below the top. No
  target found means today's viewer: top, no gutter.
- I-6: The `o` refusal on a multi-file row now points at the selectable file lines instead of
  `g` (the 38-UI-REVIEW fix 8 premise, "expansion lines are not cursor stops", stops being true).
- I-7: Positions are found by text search at key time in the text the viewer shows. No parser
  change: the owner-items readers are gsd-core oracle ports and carry no line numbers, and
  `owner_audit_conformance` must not move.
- I-8: Footer hints stay as they are (golden-tested rungs); help and README document Enter on
  sub-rows.
</objective>
