<objective>
Make the dashboard `/` filter find a project by its parallel workstreams' text. A query such as
`voice`, `v0.14` or `push-to-talk` must keep sentriq in the list, because those words name its
v0.14 workstream's milestone, its directory and the phase that workstream is working on. Today the
filter searches only the project alias, the root status and the root phase label. This closes the
"`/` filter does not search workstream text" entry in the `unresolved:` list of
`.planning/debug/resolved/workstreams-not-surfaced.md`.

Purpose: since 0fd27fa the dashboard draws every workstream on its own line
(`ws v0.14 P26: Push-to-Talk Voice`). A filter that cannot find a word the user can see on screen
is a broken filter.
Output: one predicate in `src/ui/screens/mod.rs`, wired into `recompute_filtered_aliases`, with
regression tests that use the sentriq-shaped fixture.

Inferred decisions (human unavailable; each is marked for later audit):
- [INFERRED — audit] D-A, the haystack per workstream. It covers the workstream's directory name
  (`ws.name`), its STATE.md milestone id (`ws.state.milestone`), its STATE.md milestone name
  (`ws.state.milestone_name`, raw via `as_raw_for_logic_only()`, which is a logic-only match and
  never rendered), and the exact dashboard line `crate::app::format_workstream_display(ws, now)`.
  That line carries the marker, the milestone label, and the focus phase as `P<n>: <name>`. Only
  the focus phase counts, not every phase on the workstream's roadmap. The item says "focus phase",
  and the dashboard draws only that phase, so the filter matches what is visible plus the two
  identifying names the item lists.
- [INFERRED — audit] D-B, which filter forms see it. `/term` (All) and the term half of `/term/h`
  (NeedsHuman) include workstream text. So does `/term/p` (Phase), because the workstream lines are
  drawn inside the dashboard's Phase cell. `/term/n` (alias) and `/term/s` (root status) are
  unchanged: workstream status text is only a line tint, and the dashboard aggregate status belongs
  to sibling item 261023-05j.
- [INFERRED — audit] D-C. The filter checks every workstream in `state.workstreams`, including any
  past the dashboard's 4-line `ws +N more` cap, because the item says "any workstream".
- [INFERRED — audit] D-D. Each `recompute_filtered_aliases` call takes one `chrono::Utc::now()`
  reading, the same way the dashboard render takes one per frame. The filter re-evaluates on every
  `/` keystroke and every state refresh, exactly when the drawn line can change.
- [INFERRED — audit] D-E. The change touches one file (`src/ui/screens/mod.rs`, code and tests), to
  keep this item off `normal.rs` / `app.rs`, which 261023-05j edits. The tests therefore drive
  `recompute_filtered_aliases` directly. That is the function each `/` keystroke calls
  (`normal.rs:992-993` pushes the char, then calls it), so this is the production path minus key
  decoding. The help overlay rows (`/term` "Search all columns", `/term/p` "Search phase only") stay
  accurate as written, so `help.rs` is not touched.
- [INFERRED — audit] D-F. No test pins which phase a LAPSED claim falls back to. Sibling item
  261023-05m changes that rule (`focus_phase_number`). The tests pin only the invariant "the filter
  matches the drawn line at instant t", which holds under either rule.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo `.planning/workstreams/**` → filter predicate | Workstream directory names, STATE.md `milestone` / `milestone_name` and ROADMAP phase names are third-party text from a registered project's repository. They are compared against the user's typed filter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05k-01 | Tampering / Information disclosure | `workstream_text_matches` | low | mitigate | Third-party text is used only for a lowercase substring test and is never rendered by this change. `milestone_name` is read through `Untrusted::as_raw_for_logic_only()`, the crate's greppable logic-only accessor. All rendering stays on the existing escaped paths (`render_for_terminal` in normal.rs), which are untouched. |
| T-05k-02 | Denial of service | `recompute_filtered_aliases` per keystroke | low | accept | The cost is linear in workstreams × text length. `format_workstream_display` makes one small allocation per workstream per alias per keystroke. The workstream count is bounded by subdirectories of `.planning/workstreams/`, which `load_workstreams` already enumerates on every refresh. |
| T-05k-03 | Spoofing (misleading match) | filter haystack | low | accept | The filter can match on the milestone name or directory name, which the dashboard does not draw (D-A), so a row can appear without the matched word visible. This is intended by the item ("workstream dir name") and recorded as an inferred decision. |
| T-05k-SC | Tampering | cargo dependencies | low | accept | No dependency is added or changed. `chrono` and `tempfile` are already in the crate, so there is no package-legitimacy surface. |
</threat_model>
