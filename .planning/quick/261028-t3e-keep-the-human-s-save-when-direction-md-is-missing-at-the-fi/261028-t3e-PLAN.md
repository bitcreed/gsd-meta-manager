<objective>
Close the second half of the Phase 30 WR-10 defect: the exchange back in `run_loop` hits the same `ENOENT` that quick 261028-n0z fixed one step later in `give_back_newest`. It is filed twice, as 30-REVIEW WR-12 and 31-REVIEW WR-03.

Today, if a human save raced the splice and DIRECTION.md is absent when the tool exchanges back, `run_loop` returns `Err("could not exchange back; a displaced file was left at ...")`. Absence comes from an unlink-then-create save, a `git checkout` or a `git stash`. The human's save then exists only at `.DIRECTION.md.fm.<pid>.<n>`, and the next `sweep_stale_temps` deletes it after 60 s. `regen` in `driverctl/store.rs` turns the error into a silent `GaveUp`. While DIRECTION.md is missing, any `control: pause|stop` the human wrote is invisible to the dispatch gate as well.

The fix:
- Restore the save by a no-replace rename.
- If a file was created in between, exchange with it, so the newest save still wins.
- Retry the splice on the restored file.
- Put this exchange-or-restore step in one helper that both sites call.

Hold one constraint while doing it: a crashed run must still never dispatch on a missing DIRECTION.md. 28 WR-04 stays deferred for exactly that reason, and this item does not touch `blocking_recovery`. A guard test pins that behaviour.

Purpose: a human's DIRECTION.md save must never be lost (D-12, module fact 3 of direction.rs), and the D-17 recovery gate stays fail-closed.

Output:
- The helper plus two race-hook unit tests in src/driver/direction.rs.
- One guard test in tests/driverctl_store.rs.
- Two disposition rows marked fixed.

Unattended run: the human is unavailable. The decisions below are not dictated by the reviews, so each is marked `[inferred — cleanup 2026-10-28]` here, in the code comment where it lands, and in the SUMMARY.
- **I-1. After a restore, `run_loop` retries.** It `continue`s the attempt loop instead of returning `Ok(SpliceOutcome::GaveUp)` as 30-REVIEW's sketch does. After the restore the directory is in the same state the existing "our own stale file: drop it and try again" branch leaves: the human's file at DIRECTION.md and no temp. Retrying builds the tool block onto the human's save. 31-REVIEW WR-03 counts "the splice is lost" as part of the defect. If the attempts run out, the loop still ends in its existing `Ok(SpliceOutcome::GaveUp)`.
- **I-2. The helper handles EEXIST itself.** It loops internally, bounded by the existing `GIVE_BACK_ROUNDS`, rather than returning a third state for each caller to loop on. This follows 31-REVIEW's "continuing on EXIST". For `give_back_newest` the behaviour is the same (EEXIST still means exchange again with the newly created file). The difference is that `Point::BeforeGiveBack` fires once per outer round instead of once per EEXIST retry. Every racing test acts only at the FIRST firing of a point, so none is affected.
- **I-3. `blocking_recovery` is not edited, and 28-REVIEW-DISPOSITION is not edited.** WR-04 stays deferred. The guard test only pins the fail-closed half that WR-04's deferral relies on.
