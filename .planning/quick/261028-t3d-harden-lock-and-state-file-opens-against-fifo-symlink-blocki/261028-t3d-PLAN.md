<objective>
Close the read-side and run-start halves of the run-directory open hardening that quick 261028-n0z (30 WR-08) began in `acquire_at`. Every open of a lock file and of `state.json` must refuse a planted FIFO without blocking and refuse a symlink without following it.

- **27 WR-03:** `driverctl serve` and `driver launch` create `DIRECTION.lock` with a bare create-open, and `RunStore::open` reads `state.json` unguarded. A FIFO at either name hangs the start while the run lock is held. A symlink makes the create write through to the link target.
- **27 WR-04 / 30 WR-11 / 31 WR-01** (one defect, reported three times, plus the pending todo `2026-10-28-lock-probe-and-holder-read-open-by-path.md`, which names the same two functions): `probe_at` and `read_holder_at` open `launcher.lock` by name. A FIFO there parks the TUI's marker-scan `spawn_blocking` worker, `driver stop` and the launcher reap. A symlink makes the liveness answer come from a file the project does not own.

The fix is one shared open helper in `src/driver/lock.rs`, used by all four lock-file entry points, plus `read_run_file_capped` for `state.json`. Each fix comes with tests that fail at HEAD. Afterwards the four findings are recorded as fixed and the todo is closed.

Purpose: a run directory is writable by `--unsandboxed` runs and by a cloned repository (git stores symlinks). Status display, `driver stop` and a run start must therefore never hang on a name in it, and never read through one (30-SECURITY T-30-04 / T-30-24 class).

Output: guarded opens in src/driver/lock.rs, src/driverctl/serve.rs, src/driverctl/store.rs, src/launcher/run.rs and src/launcher/stop.rs. 18 new tests: 9 in lock.rs, 3 in store.rs, 1 in run.rs, 1 in stop.rs, 1 in driver_frontmatter.rs and 3 end-to-end in tests/driverctl_serve.rs. Four fixed disposition rows, one closed todo, and one new pending todo.
