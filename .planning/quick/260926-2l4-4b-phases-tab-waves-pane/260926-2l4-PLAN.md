**Inferred decisions (the human is unavailable; each is marked for audit):**

- **[inferred I-1] State vocabulary.** It follows the scope's words and maps one-to-one onto `PlanState`: Done→`done ✓`, Running→`running ▶`, Queued→`queued ·`, Stalled→`stalled !`, Finished→`leftover ◐`. The scope's "leftover" replaces the report's "unmerged": the work is complete in a worktree and not merged. A sixth pane-only state, `planned ○`, is used for a not-done plan of a phase that is not the active one (report §4.2, §4.4). Every glyph must have `Span::width() == 1` and a distinct shape, and a test pins this.
- **[inferred I-2] Which grouping the pane uses.** Frontmatter `wave:` stays the authority, as in Phase 25's D-A10. This keeps the pane's current wave identical to the Agents model's. The cached `waves_manifest` supplies the grouping ONLY when no plan carries a `wave:` number. This reverses today's manifest-first order, which could disagree with the agents model's current wave. With no frontmatter waves and no manifest, the pane is the flat `Plans (no wave metadata)` list.
- **[inferred I-3] The plan title.** It is the leading-frontmatter `title:` scalar when present. Otherwise it is the first non-empty text after the `<objective>` tag, cut at the first `: ` or `. ` sentence boundary, trimmed, and capped at 160 chars. Otherwise it is None, and the row shows the id alone. H1 headings are NOT used: 0 of 130 PLAN.md files in this repo carry one outside a code fence. `objective_line` is the 1-based line of the `<objective>` tag, matching `editor_args`' convention (app.rs ~507).
- **[inferred I-4] Default expansion.**
  - Completed phase: every wave collapsed, and all of them merged into one row.
  - Executing phase: finished waves collapsed (consecutive ones merged); the current wave AND the next numbered wave expanded (report §4.2); later waves as header rows only. The `w?` bucket is expanded while it holds a not-done plan.
  - Not-started phase: every wave expanded.
  - Enter/Space on a header or merged row flips that wave's default. The flips are stored per phase in `ProjectViewCache.waves_toggles`, in memory only, the `roadmap_fold_toggles` pattern.
- **[inferred I-5] Pane keys.**
  - `j`/`↓` and `k`/`↑` move the cursor, clamped. `↑` never leaves the pane (report §3.2).
  - `PgDn`/`PgUp` page by the last rendered row count. `g`/`G` go to the first/last row.
  - `Enter`/`Space`: on a header or merged row, toggle it. On a plan row, jump to its agent when one is attributed; otherwise set a status message.
  - `e`: edit the plan under the cursor. On a header row it sets a status message. With no plans at all, `e` falls through to the tab's generic enqueue.
  - `←`/`Esc` go back to the list. `q` pops. `→` is a no-op.
  - `?` and `Tab` are focus-neutral.
  - Digits, `D`, `[` and `]` first move focus to Content, then run as in content (4a's I-2 rule).
  - Every other key is consumed as a no-op, so nothing acts on the phase list while the pane holds the keyboard.
- **[inferred I-6] The cursor.** It is a stable identity, `WavesCursor::{Wave(Option<u32>), Plan(String)}`, never an index. A merged row answers to any wave in its range. If the target disappears (for example after a refresh or collapse), the cursor falls to the first row at or after it.
- **[inferred I-7] Where focus lands.** On entering the pane, the cursor lands on the first not-done plan of the current wave, else on the first row. Moving the phase selection with j/k on the list clears `waves_cursor`, but toggles persist per phase. The Roadmap's Enter-to-Phases jump still lands at Content (unchanged).
- **[inferred I-8] Row tiering.** It is decided by what fits, not by fixed widths. The full row is `cursor(2) indent glyph word(8) id title tokens`. Below full width the WORD drops first, then the tokens. The title shrinks with `…` down to nothing. The glyph and id never drop. At 80 cols this means an unfocused pane (60% of 80) shows glyph+id+title, and the focused full-width pane has room for the word.
- **[inferred I-9] Titles and notes.**
  - Pane title: ` Waves {n} · plans {d}/{t} done · est {E} act {A} `, dropping est/act first when it does not fit.
  - Not started: ` Waves {n} · {t} plans · not started `.
  - Flat list: ` Plans (no wave metadata) · {d}/{t} done `.
  - When the phase is the state's active phase, some plans are done and some not, and no agent view covers it, the title gains ` · no live agents`. The report's "last activity 2h" is omitted, because no cached timestamp exists without I/O.
- **[inferred I-10] Cross-jump edge cases.**
  - Enter on an agent's child line uses its parent row's plan.
  - Enter on a worktree-less agent or an unattributed row sets the authored status message `This agent is not attributed to a plan`.
  - A plan whose phase is not in `state.phases` sets `Plan {label} is not a phase in this project`, where label = `PlanRef::label()`, authored digits only.
  - From the pane, the preferred agent is a running (Live/Idle) row attributed to the plan, else the first attributed row of any liveness.
- **[inferred I-11] The Agents strip format.**
  - Finished waves are `wN✓`, with consecutive ones merged as `w1–w8✓`.
  - The current wave is `▸wN` followed by ` {count} {word}` for each non-zero non-done state, joined with ` · `, using the pane's vocabulary.
  - Other not-done waves are `wN·`.
  - Tokens are separated by two spaces and windowed around the current wave with `…` at a cut end.
  - `waves → 2:Phases` is appended only when it fits.
  - The summary line above the strip is unchanged.
- **[inferred I-12] The stage block** is exactly two lines. Line A is a per-stage summary: `Discuss ✓  Research –  Plan 7  Execute 3/7  Verify –`, built from `derive_all_stage_statuses` plus counts. Line B is `Checks ✓Patterns ✓Plan-Check … +N not run`, built from the SAME (label, flag) table `build_substage_lines` uses today, refactored into one list so the set stays single-sourced. Both lines are fitted with `fit_cells`. The external-job-waiting line stays when it applies. `build_stage_detail_lines`, `build_substage_lines`, `build_waves_lines`, `waves_manifest_from_derived`, `build_plan_token_lines` and `MAX_PLAN_TOKEN_ROWS` are deleted, or reduced to what the new code calls, so that no dead code trips `cargo clippy -- -D warnings`. `fmt_tokens` and its tests stay.
- **[inferred I-13] waves.json size cap.** A `waves.json` over 1 MiB is skipped in the scan (it becomes None). It is read only when the directory walk sees the file, so no extra syscall is made when it is absent.
- **[inferred I-14] DetailRegions representation.** It drops `Copy`, keeping `Clone, Default, PartialEq`, and is stored in a `RefCell`. `regions()` returns a clone. It gains `waves_pane: Option<Rect>` (whenever the pane is drawn) and `waves_rows: Vec<WavesRowRegion { rect, target: WavesCursor }>` (one per visible row: plan, header or merged). `pane` is set to the waves pane rect only while it is FOCUSED, keeping 4a's "focused pane" meaning.
