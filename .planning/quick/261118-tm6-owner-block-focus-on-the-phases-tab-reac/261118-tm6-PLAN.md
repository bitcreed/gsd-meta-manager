# Quick 261118-tm6: Owner block focus on the Phases tab

Owner report: "From phases I can't go into the owner block by pressing down, and
where there's no phases found I don't see that that's the highlighted block, so
it's really awkward when I then press up that the owner block is finally selected."

## Root cause

1. The tab bar's `↓`/`j`/`Enter`/`Space` always descend to `DetailFocus::Content`
   (the phase list), so the Owner block drawn between the tab bar and the list is
   skipped; only `↑` from phase row 0 enters it.
2. With an empty phase list, `Content` focus has nothing to draw: the keyboard sits
   on an invisible list until `↑` jumps into the block (on its LAST stop).
3. While the block has focus, the phase list still draws its `> ` marker, so two
   identical cursors are on screen.

## Model (inferred, I-1)

Vertical reading order: tab bar -> Owner block -> phase list, both directions.
Landing on the tab via digits stays on the phase list when it has rows (its cursor
is visible, the footer already names `[↑]owner`; keeps Enter -> Waves muscle memory
and the inbox `g` jump unchanged). Rejected: landing on the block on every arrival,
because it moves every phase-list key one keypress away and needs arrival tracking
the render cannot mutate.

## Tasks

1. Test-first: failing tests for (a) tab bar `↓` on Phases enters the block on its
   first stop and walking down past its last stop reaches phase row 0; (b) with no
   phases the block's first row is drawn focused (`> `) on arrival, the footer names
   the block's keys, the first `j` moves inside the block, `↓` past the last stop
   stays, `Esc` goes to the tab bar; (c) the phase list drops its `> ` marker while
   the block has focus.
2. Fix in detail.rs (+ `owner_block::enter_first`): tab-bar descent enters the block;
   empty-list landing drawn by the render and materialized by the next key/mouse
   event; PastLast/Esc never land on an empty list; phase-list marker only when it
   holds focus; footer `[Esc]` names its real target.
3. `cargo test --no-fail-fast`, `cargo clippy --all-targets -- -D warnings`; README/
   help text only where now wrong.
