# Quick 260926-06g: agent-process cwd as a Linux-only liveness signal for the running-agents view

<objective>
Give Phase 25's running-agents observer (`src/agents/`) one extra, Linux-only, read-only signal taken
from the process table, reusing the /proc reading `src/session_detector.rs` already does:

1. **Orphan detection.** Claude Code locks each agent worktree with the reason
   `claude agent agent-<id> (pid N start T)`. Per D-A05 that pid is the top-level session every
   agent shares, so a LIVE pid says nothing per-agent. A DEAD pid does say something: every
   agent of that session is over. A locked worktree whose owner pid is gone reads
   `AgentLiveness::Ended`, whatever its transcript mtime says. It counts as gone when the pid is
   absent, when the pid exists but its procfs start time differs from `T`, or, only when no
   comparable start exists, when the pid's cwd is outside the project and its worktrees. `Ended`
   is the existing state the model already defines as "an aborted or crashed run's leftover
   worktree, which is over whatever its lock says (CR-01)". No new state is invented [inferred].
2. **Codex executors.** A `codex` process whose cwd is inside an agent worktree makes that row
   `Live`. This is core-level only. The Codex adapter stays deferred (D-A08).
3. **Linux only, a single swap point.** The procfs backend is `#[cfg(target_os = "linux")]`. On
   every other target, `session_detector::process_probe()` returns `NoProcessProbe`, which answers
   "unknown" to everything. The result is exactly today's mtime-only behaviour, so the "works
   without /proc" clause of D-B03 still holds. A later cross-platform backend (e.g. the `sysinfo`
   crate) replaces only the cfg-selected constructor body. It is NOT added now, and no dependency
   changes.

Purpose: today a crashed session's held-lock worktree reads `Live`/`Idle` for up to 10 minutes, and
then `N stalled` for up to 24 h (25-REVIEW.md "residual behaviour"). Also, a Codex executor
with no adapter reads `Unknown`. Both make the dashboard's live view lie.

**Measured facts this plan relies on (planner-verified, 2026-09-26):**
- The lock format comes from Claude Code 2.1.283's binary (the version the Claude adapter is
  measured against). Its lock-reason builder is `claude ${s} ${r} (pid ${process.pid} start ${g})`,
  or with `start` omitted when `g` is undefined. `g` is `procStart`, which on Linux is read from
  `/proc/${pid}/stat` via the same starttime extractor Claude uses for its own pid-reuse checks. So
  `T` is procfs field 22 (clock ticks since boot), which is what `session_detector::read_start_time`
  already returns. On macOS the builder writes a `ps -o lstart=` date string. That is not all
  digits and must parse as "no comparable start".
- Live example on this machine: `/home/blk/projects/python/mailbot/.claude/worktrees/agent-ab566f94e8a09dc6f`
  is locked `(pid 29572 start 32844)`, written 2026-09-23, before the 2026-09-25 boot. Pid 29572 is
  absent, a real orphan this change classifies `Ended`.
- `rustup target list --installed` lists only `x86_64-unknown-linux-gnu`. See Task 3 for the
  non-Linux type-check consequence.
