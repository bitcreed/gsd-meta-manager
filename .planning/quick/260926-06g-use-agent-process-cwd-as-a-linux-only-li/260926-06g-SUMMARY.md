# Quick 260926-06g: agent-process cwd as a Linux-only liveness signal Summary

On Linux, the running-agents view now reads a worktree `Ended` when the session that holds its lock is dead. That covers a missing pid, a pid reused with a different procfs start time, and (only when no start can be compared) an owner working outside the project. A `codex` process working inside an agent worktree reads it `Live`. Both facts come from a read-only, per-poll `ProcessProbe` that `session_detector` builds and injects. `src/agents` still reads no process table itself.

## How the signal maps to liveness states

`classify_observed` applies these rules in order:

1. `RuntimeInside` → **Live**. A `codex` cwd equals the worktree or lies inside it, and the worktree is not prunable. This holds with or without adapter facts, and even when the facts say `ended`, stale or released+SUMMARY.
2. `ended` (adapter fact) → **Ended**.
3. `OwnerGone` → **Ended**, with or without facts, whatever the transcript mtime, SUMMARY or lock-release says.
4. No facts or no `last_activity` → **Unknown**.
5. Age over MAX_AGENT_AGE_SECS → **Ended** (CR-01).
6. Released lock plus SUMMARY, or released lock plus staleness → **Finished**.
7. Otherwise **Live / Idle / Stalled** by age.

`Unknown` and `OwnerAlive` never change the result. A unit grid proves this: 7 ages × 3 lock states × 2 summary × ended/not, plus both no-facts shapes, all identical to `classify_liveness`. D-A05 holds because a live owner never upgrades a row.

`owner_verdict` works from the probe's observation of the lock pid:
- The probe could not say → Unknown.
- The pid is absent → OwnerGone.
- Both start times are numeric: equal → OwnerAlive, different → OwnerGone (pid reuse).
- Otherwise the cwd decides, compared component-wise: inside the project root, its canonical form, the main worktree or any worktree → OwnerAlive; outside all of them → OwnerGone; unreadable → Unknown.

## Residual false-orphan cases (T-06g-05, accepted)

In these setups a live agent can read `Ended`. The effect is display-only; the row stays listed and no action is taken:
- the TUI and Claude run in different pid namespaces (a container);
- they run on different hosts over a shared filesystem;
- `hidepid` hides a same-repo owner that belongs to another user.

The mitigations:
- procfs not mounted → Unknown;
- exact start-time identity when both sides are numeric;
- EACCES on the cwd → Unknown.
