# Phase quick-261023-05i Plan 01: Agent and worktree details for workstream phases Summary

The agents scan is now scoped by (workstream, phase number), so a workstream's Phase N gets its own worktree badge, worktree-held plan counts, Waves-pane plans, unmerged status, ghost rows and agent cross-jumps, and the project's Phase N data never lands on a same-numbered workstream phase or the reverse.

## What was built

- **Task 1 (tracer), 91b19ff.** New names-only module `src/agents/workstream_scope.rs` (`names`, `scope_planning`). `unmerged::detect_in` takes the planning dir relative to the root, and `detect` delegates with `.planning`. `ProjectAgents.workstreams: Vec<WorkstreamAgents>`. `AgentView` gained `workstream` and `workstreams: BTreeMap<String, AgentView>`. `derive` became `derive_scope` plus a per-workstream loop. `agent_view_of` returns the scope's own view. The Roadmap agent-view post-pass is scoped (the key splits at the first `/`). The `AgentsScanned` emptiness check also requires `agents.workstreams.is_empty()`.
- **Task 2, d6b497a.** `worktree_plans::detect_in` and `worktree_phases::detect_in`. The scan fills each workstream's lists. The badge and counts of project and workstream nodes go through one helper (`phase_badge_and_counts`), so escaping and counting cannot diverge. Workstream ghost rows sit in their workstream's band and are marked Unmerged by scoped key. `worktree_counted` holds scoped keys.
- **Task 3, e83c0d6.** `workstream_scope::resolve` (naming, then path evidence, then uniqueness, else the project). `AgentRow.workstream`. `summary_in_worktree` is checked in the resolved scope, with the `phase_dirs` cache keyed by `(scope, phase)`. In `derive`, the project's view counts only `workstream == None` rows but lists all rows. A workstream row never switches the project's executor ladder. `focus_agent_of_plan` and `focus_plan_in_phases` take the workstream. `agents_enter` passes the row's workstream through.
- **Fix, cd0e92e.** `names_token` delegates to `crate::text::is_identity_char`. The repo's single-spelling guard in `text.rs` rejected my duplicate `[A-Za-z0-9._-]` clause (Rule 1, caught by the full suite).

## Inferred decisions [INFERRED — audit]

The plan's I-1..I-6 were implemented as written:

- I-1 per-workstream views nested as `AgentView.workstreams` (no new `AppContext` map).
- I-2 resolution order naming / path evidence / uniqueness / project.
- I-3 the project view lists every row and counts only its own.
- I-4 a workstream with no attributed row falls back to its state's `active_phase_number()`.
- I-5 the dashboard reads the project's view only.
- I-6 workstream names are the `read_dir` subdirectory names.

Additional inferences made during execution:

- I-7 [INFERRED — audit] The `AgentsScanned` emptiness check uses `agents.workstreams.is_empty()`, not the plan's literal `all(unmerged.is_empty() && worktree_plans.is_empty())`. A `WorkstreamAgents` entry exists only when some list is non-empty, and the broader rule also keeps a workstream whose only data is worktree-only phases (otherwise its ghost rows would never render). The dashboard cell is unaffected either way (I-5, pinned by the test).
- I-8 [INFERRED — audit] `workstream_scope::resolve` returns `None` immediately, reading nothing, when the project has no workstreams, so flat projects pay no extra I/O and keep today's attribution.
- I-9 [INFERRED — audit] The nested workstream view is created when the workstream has scan lists or attributed rows. A `WorkstreamState` with neither gets no nested view, and `agent_view_of` returns `None` for it, same as before.
- I-10 [INFERRED — audit] Workstream detection covers only workstreams whose directory exists in main (`names` reads main's `.planning/workstreams`). A workstream created only inside a worktree is not detected.
- I-11 [INFERRED — audit] Workstream quick-task unmerged keys (`<ws>/quick/...`) fall out of `detect_in` for free. They are not rendered anywhere workstream-specific.
