<objective>
Draw a parallel workstream whose roadmap lists no phases on the Detail screen, instead of
leaving it out. Today the Roadmap layout skips any non-shipped band with no members, so such a
workstream draws nothing there (roadmap_graph.rs row_sequence). It also gets no row on the Phases
tab, which lists only phases. After this change both tabs show it. The Roadmap gets a band header
`ws vX.Y — Name` and one dim `no phases on roadmap yet · <status>` placeholder row, and the band
folds like any other. The Phases tab gets one dim placeholder line. Neither one changes what the
cursor or the selection index can address.

Purpose: this closes the `unresolved:` item "A workstream whose roadmap lists no phases is not drawn
on the Roadmap" from .planning/debug/resolved/workstreams-not-surfaced.md. A newly created
workstream should not be invisible on the Detail screen.

Output: changes to roadmap_graph.rs (the model), roadmap_view.rs (the widget) and detail.rs (the
adapter, the Phases tab, and tests), plus regression tests in all three.

Scope note: the dashboard already draws a no-phase workstream as `ws vX.Y Name`
(app.rs format_workstream_display, the `None` arm), so normal.rs and app.rs are not touched.
The Roadmap header line belongs to sibling item 261023-05g and is not touched here. The shared
fixture writer `state_reader::workstreams::write_sentriq_workstreams_fixture` is NOT modified,
because sibling items count its bands and phases. The tests add the empty workstream in a local
fixture variant instead.
</objective>

<inferred_decisions>
Human unavailable. Each of these is decided from the code, the debug session and UI-SPEC conventions:

- [INFERRED — audit] I-1: The placeholder is a non-target row, like a connector. The band header is
  the cursor stop and the fold handle. So j/k, g/G, PgUp/PgDn and mouse row mapping
  (`target_of` / `target_at`) skip the placeholder, and the "cursor targets are keys, never row
  indices" rule (RESEARCH Pitfall 7) holds without any change to the cursor code.
- [INFERRED — audit] I-2: Only a workstream (scoped) band gets the placeholder. A non-shipped band of
  the project's own roadmap with no phases keeps drawing nothing. For example, ttbook-style future
  milestone headings would otherwise turn into rows of empty bands, and that rule (D-A07) is not in
  this item's scope.
- [INFERRED — audit] I-3: The empty workstream's band header leaves out the `{done}/{total}` count.
  The item specifies the header as `ws vX.Y — Name`, and `0/0` carries no information. Every other
  band header, including a shipped band with zero listed phases, keeps its count.
- [INFERRED — audit] I-4: "Its status" means the workstream's own STATE.md `status` (`ws.state.status`).
  It is trimmed and escaped, and drawn dim as part of the placeholder text, not in a status colour,
  because the item says "a dim placeholder line". When the status is empty it is left out together
  with its `·` separator. The band's detail pane, shown when the cursor is on the header, reads the
  same text in place of `0/0 phases done`.
- [INFERRED — audit] I-5: Emptiness has one rule on both tabs: the workstream's roadmap entries are
  empty (`ws.state.roadmap_entries().is_empty()`, which equals "the scoped band has no members").
  This implies `ws.state.phases.is_empty()`, so an empty workstream never contributes a Phases row.
- [INFERRED — audit] I-6: On the Phases tab, the placeholder lines are drawn AFTER the selectable
  phase rows, one per empty workstream in workstream order. They never enter `scoped_phases`, the
  List widget or the recorded `ListRegion`, so the `pipeline_selected` index arithmetic, the
  j/k/PageDown arms, `share_pipeline_selection` and the mouse mapping all stay as they are. The
  cost: an empty workstream that sorts between two populated ones is listed after all phase rows,
  not between them. Interleaving would need a selection-index-to-visual-row map in the List and the
  mouse handler. That is the riskier change, and the item asks us not to break indexing. The
  placeholder lines take at most `inner.height - 1` rows, so the list always keeps a row. When no
  workstream is empty, the left pane is drawn exactly as today: same widget calls, same recorded
  ListRegion rect.
- [INFERRED — audit] I-7: Fixture. A local helper in detail.rs tests writes the shared sentriq
  fixture, then adds `.planning/workstreams/v0-13-store-listing/`. Its STATE.md has milestone
  `v0.13.1`, milestone_name `Store Listing` and status `planning`. Its ROADMAP.md has the
  `## v0.13.1 — Store Listing` heading and a `## Phases` heading with no phases under it. There is
  no `phases/` directory. Workstreams sort by name, so this one lands BETWEEN v0-13-public-beta and
  v0-14-voice-assistant. That puts the empty band between two populated bands, the hardest spot
  for the cursor, folds and lanes.
</inferred_decisions>
