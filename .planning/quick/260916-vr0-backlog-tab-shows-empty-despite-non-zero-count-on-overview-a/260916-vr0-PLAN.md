empty for every project that has any backlog at all.

and a regression test that fails if the two numbers ever disagree again.

<confirmed_root_cause>
**The todo's hypothesis had two branches. Branch 2 is CONFIRMED; branch 1 is MEASURED ABSENT.**
This was established at plan time against real on-disk data, so the fix tasks below do not
re-litigate it. The executor should verify the fixture matches this shape and proceed.

Measured across every registered project in `~/.config/gsd-meta-manager/config.json`
(`find /home/blk/projects -maxdepth 5 -type d -name '999.*'`, then counting `.md` files in each):

| project | backlog dirs | well-formed `999.N-slug` | dirs containing a `.md` |
|---|---|---|---|
| gsd-meta-manager | 4 | 4 | **0** |
| shopify-orderly-rescue | 3 | 3 | **0** |
| picsync | 2 | 2 | **0** |
| hitchmatch | 1 | 1 | **0** |
| hm-relverify | 1 | 1 | **0** |
| cdr-configurator | 1 | 1 | **0** |
| **total** | **12** | **12** | **0** |

Every single directory holds exactly one entry: `.gitkeep`. Examples from this repo:
`999.1-milestone-archive-browser-tab`, `999.4-coverage-sub-stage-may-need-frontmatter-status-not-a-presenc`.

**Branch 1 (naming) is NOT the cause.** All 12 names parse cleanly through
`parse_backlog_dir_name` — every one has the literal dot after `999` and the dash after the
number. No `999-something` directory exists anywhere. Do not loosen `parse_backlog_dir_name`.

**Branch 2 (the `.md` requirement) IS the cause, and it is total, not partial.** The `?` on
`find_first_md_file` at `backlog.rs:70` sits inside a `filter_map`, so it discards the item.
Because zero backlog directories anywhere contain a `.md` file, it discards 100% of them. The
overview's loose `starts_with("999")` count therefore reports 4 while the tab renders 0 —
exactly the reported symptom, and reproducible in every project that has a backlog.

**GSD stores a backlog item entirely in the DIRECTORY NAME.** The slug is the payload. A
`.md` body is an optional enrichment that, in practice, never exists. The comment at
`backlog.rs:69` calls md-less directories "empty backlog placeholders" — that premise is the
defect: they are not placeholders, they are the normal and only form.

**The downstream was already built for this.** Nothing outside `backlog.rs` needs to change:
- `BacklogItem.path` is already `Option<PathBuf>` and `content` already `Option<Untrusted>`.
- `description` already falls back to `humanize_slug(&slug)` when no heading is found.
- `detail.rs:3564-3578` already renders a dark-gray fallback string when `content` is `None`.
- `detail.rs:2985-2992` already guards `SuspendAndEdit` behind `if let Some(ref path)` and
  already emits a status message when the path is absent.
- `detail.rs:3002` enqueues from `dir_name`, never from `path`.

That is why this plan touches no UI file — see D-INF-04.
</confirmed_root_cause>

<inferred_decisions>
The human operator was unavailable. These four decisions were taken from the measured evidence
above and are flagged for later audit.

- **D-INF-01 — Fix the `.md` requirement, not the name grammar.** Branch 2 confirmed, branch 1
  measured absent (0 of 12 names malformed). Loosening `parse_backlog_dir_name` would be a
  change with no input that exercises it, and would weaken a parser that also guards against
  the `{`/newline malformed-JSON slugs it explicitly rejects.

- **D-INF-02 — Reconcile toward the STRICT rule: the count follows the parser.** The count's
  only job is to advertise how many rows the tab will draw, so the tab's rule is the correct
  one. The alternative (teach the parser the loose `starts_with("999")` rule) would make the
  parser accept names it cannot extract a number or slug from, and there is no such directory
  on disk to justify it. Consequence to accept: a hypothetical `999-nodot` directory would stop
  being counted. That is correct — it could never have been displayed.

- **D-INF-03 — The shared matcher lives in `backlog.rs`, so `mod.rs` gets a body-only edit.**
  `tests/spawn_seam_guard.rs::no_production_item_follows_a_test_module_marker` fails on any
  column-zero production item appearing after a file's `mod tests {` marker, and it names
  `src/state_reader/mod.rs`'s historical `count_backlog_items` as the live case that motivated
  it. Markers sit at `mod.rs:617` and `backlog.rs:226`. Adding a new helper to `mod.rs` risks
  re-tripping that guard; rewriting only `count_backlog_items`'s body cannot.

- **D-INF-04 — Touch no UI file.** Every consumer already handles `path: None` and
  `content: None` correctly (enumerated above). This also keeps the merge clean: sibling batch
  items 260916-vqz, 260916-vqx and 260916-vqy all touch `src/ui/screens/detail.rs` and
  `src/ui/screens/normal.rs`. `depends_on` is empty — this item is the upstream data fix and
  needs nothing from them.
