# Quick 260828-15f: Disambiguate round-13 finding ids in 21-REVIEW.md Summary

Round-scoped round 13's twelve finding ids in `21-REVIEW.md` with an `R13-` prefix and
added an `## Identifier scheme` section, so no bare id in that document silently collides
with a different, historical phase-21 finding of the same name.

## What Was Built

`.planning/phases/21-llm-goal-layer-prompt-injection-hardening/21-REVIEW.md` numbered its
own findings CR-01, CR-02, WR-01..WR-06, IN-01..IN-04. Every one of those bare ids also
names a *different* phase-21 finding cited by other committed artifacts in the same phase
directory — historical `WR-04` is `LegacyRegistryKey`'s derived `Debug` (closed by
c9345a1) while round 13's is the unbounded per-NUL `Vec` allocation; historical `CR-01` is
the shell command injection at `detail.rs:1692-1707` while round 13's is the
`--resume`/`-r` successor-arity defect. `21-VERIFICATION.md` (pass 14) had already felt
this and improvised the ad-hoc name `WR-05-new` at its line 109.

Three groups of edits, all inside the one file:

- **Twelve headings** prefixed: `### CR-01:` → `### R13-CR-01:` and so on for CR-02,
  WR-01..WR-06, IN-01..IN-04. No heading title text changed.
- **Five in-document self-references** rewritten to the `R13-` form: the two Summary
  parenthetical citations (`(R13-CR-01)`, `(R13-CR-02)`), the R13-WR-03 body reference to
  R13-CR-02, the R13-WR-05 body reference to R13-CR-01, and the closing probe-provenance
  line (`_CLI probes in R13-CR-01/R13-WR-05 …`).
- **Two historical WR-05 mentions** (both about the `detail.rs:7809-7811` comment block
  carrying a deleted test's truncated name) kept BARE and qualified with
  `` (not `R13-WR-05`) ``, so neither can be misread as round 13's `--` end-of-options
  finding.

A new `## Identifier scheme` section sits between the Status line and `## Summary`,
covering the prefix and its rationale (including why a higher-numbered `WR-07+` range was
rejected), a twelve-row `| Was | Now |` mapping table, the note that `21-VERIFICATION.md`
is deliberately unedited and cites the old bare ids, and the corollary rule that a bare id
in this document means the phase's historical finding.

The bare `IN-07` reference in R13-CR-01's fix list was left untouched — it names another
round's finding — and is now the single grandfathered bare id, which is what makes any
future undisambiguated id a detectable regression.
