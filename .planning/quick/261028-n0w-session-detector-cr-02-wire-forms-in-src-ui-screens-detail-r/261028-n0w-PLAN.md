<objective>
Close CR-02 (todo `.planning/todos/pending/2026-10-25-session-detector-wire-forms-omit-session-id.md`, from 21-VERIFICATION). `session_id_in_cmdline` reads six id-bearing spellings: `--resume=<id>`, `--resume <id>`, `-r<id>`, `-r <id>`, `--session-id=<id>` and `--session-id <id>`. But the generated round-trip certificate in src/ui/screens/detail.rs (`wire_forms()`) registers only the first four. So no whitespace-padded, ill-formed, option-shaped or empty value is ever driven through either `--session-id` spelling. And nothing ties the parser's spelling set to the size of the register.

This item does three things, matching the three `missing:` lines that 21-VERIFICATION records for CR-02:
1. It adds the two `--session-id` rows. They use a per-option oracle, because `--session-id` binds a REQUIRED value while `-r/--resume` binds an OPTIONAL one (fixed by 261028-n0v).
2. It adds a control that couples the register to the parser. It checks count equality and that each spelling has exactly one row, and the census itself is checked against the parser in both directions.
3. It corrects the parser doc so the contract's stated scope matches the register.

Purpose: before this, a spelling taught to the parser without a matching row silently narrowed the certificate while every gate stayed green. This is the "closed claim over an open set" failure that the 21-37 correction block says it had fixed.

Ordering: this item depends on 261028-n0v. Both items edit the same two files, and the per-option oracle for `split`/`short-split` is n0v's deliverable, so the CR-01 and CR-02 todos ask to land together. It also depends on 261028-n10, because that item edits the same file (detail.rs) and leaves the tree clean under `cargo fmt --check`, which Task 3 gates on.
