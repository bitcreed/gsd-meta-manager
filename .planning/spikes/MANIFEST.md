# Spike Manifest

## Ideas

### queue-driven-master-agent
Replace the v2.0 autonomy machinery (Phase 19 bash-parsing guard, Phase 21 LLM goal layer, Phase 22
containers, tmux/stdin injection) with a queue-driven master Claude session. A human writes direction
and work items into a file. The master dispatches one GSD step at a time to a worker subagent, records
a 15-line-or-shorter report, and decides against each item's done-when and budget. Steering means
editing the file, and gsd-mm is the editor, launcher, observer and pusher. Isolation comes from bwrap
plus `systemd-run --user --scope`.

**Requirements:**

- Never depend on tmux, stdin injection or AskUserQuestion. The only human channel is the files.
- The subagent's suggested next command is advisory. The driver decides from done-when, budget and
  evidence it has checked itself.
- Driver files are keyed by a gsd-mm-chosen run id, not by the Claude session id.
- Files have a single owner: DIRECTION.md is human-owned and LOG.md is driver-owned and append-only.
  Both live under `.planning/meta-manager/drivers/<run-id>/` (gitignored) in the main checkout.
- Pass `isolation: "worktree"` to nested GSD dispatches when the workflow's isolation config requires it.
- At most 2 gap-closure rounds per phase.
- (spike 002, from the user) The run's status frontmatter is tool-written, never LLM-generated. It is
  a derived view of tool-owned state, regenerated by a single writer (driverctl) on every event, and
  it sits at the top of DIRECTION.md. The tool replaces only its own `---` block, so the human body
  is preserved byte-for-byte. This supersedes "LOG.md is driver-owned": the driver records events
  only through `driverctl`, and the run dir is read-only inside the sandbox.
- (spike 002) Hard caps (dispatches, wall clock, gap rounds) are enforced by the launcher outside the
  sandbox. They are counted from tool-observed state (hooks and VERIFICATION.md on disk), never
  from the driver's account. Prompt rules stay the first line of defence.
- (spike 002) The sandbox never receives a refresh token. The host `~/.claude` is read-only and its
  secrets are masked.
- (spike 003, verdict INCONCLUSIVE) Prompt v0.3's round-numbering (D1), finding-granularity (D3), divergence-precedence (D1c),
  needs-human-on-park (D2) and OQ-R1 wording is Phase 29's stop-rule-precedence input; D1 and D2 behaved as written in a real
  Opus run, D1c, D3 and OQ-R1 were not exercised.
- (spike 003, observation) One verifier re-write of `VERIFICATION.md` made the launcher count a third gap after a single gap round
  (gap count 3, two verifier runs); a divergence signal must not depend on the raw file-hash count. The headless driver also ended
  its session with a worker unreported in one of two Opus launches. Both need a seed/instrument redesign before Phase 27.
- (spike 003, 26.1) The gap round count is coalesced: a `gaps_found` VERIFICATION write counts as a new round only when more than 45 s
  after the previous one for the phase (`tools/gapcount.py`, `COALESCE_S = 45`). Phase 28 ports this rule; the dispatch-epoch rule and
  writer-agent keying are the recorded alternatives. Live on Opus (`r261a`): two verifier re-writes were coalesced and the launcher count
  matched the verifier runs (A9 PASS).
- (spike 003, 26.1) The driver status enum Phase 27 writes needs a `stalled` value (clean exit with a dispatched worker unreported and no
  tripped cap), distinct from `crashed`.
- (spike 003, 26.1) Phase 29 inherits prompt v0.4's worker-brief and Loop step 4 early-worker wording with the D1, D3, D1c, D2 and OQ-R1
  clauses. On `r261a` a real Opus driver dispatched rounds 0, 1, 2 and parked `rule=divergence` at the third `gaps_found` with no launcher deny;
  OQ-R1 was not exercised.
- (spike 003, 26.1, verdict INCONCLUSIVE) The launcher's organic deny at L+1 and kill at L+2 under a prompt-rule-disabled Opus driver are unobserved
  (Run 2 converged: the feed advance was absorbed before the first verification); Phase 28 keeps the cap and the L7 cases as acceptance cases.
- (spike 003, 26.1) Stop guard (`tools/stop_guard.py`, at most 3 blocks per run) kept an early-ending Haiku worker's driver alive (L8); it never
  fired in the two paid Opus runs. GSD's stall-watch path was off (`planner.stall_detection_enabled: false`) and is a Phase 28/29 carry.
- (spike 003, 26.1 gap closure, verdict ADJUST) J1: on the gap-closure Run 2 (`r261-run2b`, seed v2) an Opus driver with the gap-round rules removed
  parked `needs-human` at the second `gaps_found`, before any round-3 dispatch, so the launcher's organic deny at L+1 and kill at L+2 stayed unobserved.
  Phase 28 keeps the cap and the L7 cases (`results/r261-l7`) as acceptance cases; Phase 29 records prompt-independent self-limiting: the prompt rules are
  not the only stop, and the launcher cap is a backstop never organically exercised.
- (spike 003, 26.1 gap closure) Seed v2 for the Phase 28/29 test harness: the moving target must advance after the executor ends; the verifier spawn is
  the earliest host-visible point (the feed advanced under 1 s after each `gsd-verifier` spawn and before its first read). Advancing on the executor's
  SUMMARY commit lets the executor absorb the change before verification (`r261-run2` converged).
- (spike 003, 26.1 gap closure) The Phase 27 driver status enum needs `stalled`, and Phase 28 ports the coalescing gap count (`COALESCE_S = 45`); both
  carry unchanged. `planner.stall_detection_enabled: false` was set in every paid run, so the stall-watch path stays a Phase 28/29 carry.
