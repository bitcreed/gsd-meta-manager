## Problem

`src/terminal_switch.rs` hardcodes tmux: `in_tmux()` reads `$TMUX`; `switch_to_session` joins on
tty via `tmux list-panes -a` then `select-window`/`select-pane`; `plan_launch` returns
`LaunchPlan { try_tmux: bool, gui }`; `open_new_window` runs `tmux new-window`. Call sites:
`src/ui/screens/normal.rs:840`, `src/ui/screens/detail.rs:2407`, `:4938`, `:5448`, `:5485`.
Inside a herdr pane `$TMUX` is unset (`HERDR_ENV=1`, `HERDR_SOCKET_PATH`, `HERDR_PANE_ID` are set)
and the herdr server runs under systemd, so focusing a session fails and launching falls back to a
GUI terminal.

## Ecosystem scan (2026-11-10, quick)

The seam must accommodate these; only tmux and herdr are implemented this milestone.

| Tool | Detect (env) | Enumerate / join key | Focus | Open in cwd with argv |
|---|---|---|---|---|
| tmux | `$TMUX` | `list-panes -a` (tty) | `select-window` + `select-pane` | `new-window -c <cwd> <argv...>` (direct exec when ≥2 args) |
| herdr TUI (`herdr`, 0.9.5) | `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, `HERDR_PANE_ID` | `herdr pane list` JSON: `agent_session.value` = Claude session id, plus pane/tab/workspace id, cwd | `herdr workspace focus`, `tab focus <id>`, pane focus | `herdr tab create --cwd --focus`, then `herdr pane run <pane> <COMMAND>...` (whether `pane run` bypasses a shell is unverified) |
| herdr-core / Herdr app (`hc`) | TBD | TBD | TBD | `hc run` — server behind the new native Herdr app; separate from the herdr TUI server, does not share agents with it |
| Rex (Superlogical, M. Hashimoto; public beta 2026) | TBD | scriptable CLI with JSON output; local Unix socket on macOS/Linux | sessions/windows/blocks | create sessions/windows/splits |
| zellij | `$ZELLIJ`, `$ZELLIJ_SESSION_NAME` | `zellij action list-clients` / dump-layout | `zellij action go-to-tab-name` / focus pane | `zellij action new-tab --cwd` / `zellij run --cwd -- <argv>` |
| WezTerm mux | `$WEZTERM_PANE` | `wezterm cli list --format json` (tty, cwd) | `wezterm cli activate-pane --pane-id` | `wezterm cli spawn --cwd <cwd> -- <argv>` |
| kitty remote control | `$KITTY_WINDOW_ID`, `$KITTY_LISTEN_ON` | `kitten @ ls` JSON (pid, cwd) | `kitten @ focus-window --match` | `kitten @ launch --type=tab --cwd -- <argv>`; needs `allow_remote_control` |
| GNU screen | `$STY` | `screen -Q windows` (weak) | `screen -X select <n>` | `screen -X chdir` + `screen -X screen <argv>` |

Seam implications **[inferred]**: join keys differ (tty, pid, Claude session id), so a backend
reports which identity it matched on; focus can need more than one step (workspace, tab, pane);
some backends only exist behind a socket or an opt-in setting, so detection distinguishes "inside"
from "reachable"; the argv sink must refuse a single-string program on every backend that would
hand it to a shell.

## v2.3.0 Requirements

### Multiplexer seam (MUX)

- [x] **MUX-01**: A `MultiplexerBackend` trait (name per planning) covers: detect whether the TUI is inside this backend, focus an existing Claude session, and open a new session in a cwd with an argv. It is designed against every tool in the ecosystem scan, and the design records how each would satisfy it.
- [x] **MUX-02**: Detection picks the innermost multiplexer when nested (e.g. herdr inside tmux, tmux inside herdr). The precedence rule is deterministic and unit-tested from env-var fixtures, with no live multiplexer.
- [x] **MUX-03**: tmux runs on the trait with unchanged behaviour. The fail-closed direct-exec boundary in `open_new_window` (refuse <2-element argv, refuse a `-`-leading head, cwd as the `-c` argv element; D-03, T-W0D-01, T-W0D-03, T-W0D-04) stays enforced on the shared sink, so every backend passes through it, and its tests still pass.
- [x] **MUX-04**: Inside herdr, a user can press the existing focus key on a Claude session and land in the herdr pane running it. The join is on `agent_session.value` from `herdr pane list`, with cwd/tty as fallback.
- [x] **MUX-05**: Inside herdr, a user can launch or resume a Claude session from the TUI. It opens in a new herdr tab in the project cwd without an interpreter parsing the program vector. If herdr cannot guarantee that, the backend refuses and falls back, with the reason recorded.
- [x] **MUX-06**: With no supported multiplexer detected, or when a backend's focus or launch fails, the existing GUI-terminal fallback chain (`$TERMINAL`, `xdg-terminal-exec`, candidates) runs as it does today, and the failure reason reaches the user.
- [x] **MUX-07**: All five current call sites go through the seam. No tmux-specific call remains outside the tmux backend.

## Out of Scope

- Controlling a multiplexer the TUI is not running inside (remote, or a different server) — local, enclosing-session only **[inferred]**.
- Windows-specific backends — Linux/macOS first, in line with the existing session detection.
- Replacing the GUI-terminal fallback chain.
