1. In `src/ui/screens/detail.rs`, implement the Backlog tab rendering. Add a helper function:

   `fn render_backlog_tab(frame: &mut Frame, area: Rect, alias: &str, ctx: &AppContext)`

   This function:
   a. Gets the `ProjectViewCache` for the alias from `ctx.view_cache`. If none, show "Press 3 to load backlog".
   b. If `cache.loading_backlog` is true, render dim "Loading backlog items..." Paragraph in the area.
   c. If `cache.backlog_items` is empty and not loading, render "No backlog items found" Paragraph.
   d. If items exist and `cache.backlog_expanded` is false:
      - Render a ratatui `List` widget filling the entire `area`
      - Each item rendered as: `"  999.N  description_text"` where description comes from BacklogItem.description
      - Highlight the selected item (index = `cache.backlog_selected`) with bold + cyan foreground
      - Use `List::new(items).highlight_style(Style::default().fg(Color::Cyan).add_modifier(Modifier::BOLD))`
      - Render with `frame.render_stateful_widget(list, area, &mut list_state)` where list_state has `select(Some(cache.backlog_selected))`
   e. If items exist and `cache.backlog_expanded` is true (per D-03 split pane):
      - Split area vertically: top 50% for list, bottom 50% for content
      - Top half: same List widget as above
      - Bottom half: render a Block with title " Content: {item.dir_name} " and borders ALL
      - Inside block: Paragraph with the selected item's `content` field. If content is None, show dim "No content available". If content is Some, render the raw markdown text with scroll support (use self.scroll_offset for content scroll -- or a separate content_scroll field).
      - Use `Paragraph::new(content_text).block(content_block).scroll((0, 0))` -- for now no separate scroll state, just show beginning of content

2. Wire the render_backlog_tab call into the main `render` method's Backlog match arm (replacing the placeholder from Plan 01).

3. In the `handle_key` method, add Backlog-tab-specific key handling:
   a. When on Backlog tab and `KeyCode::Char('j')` or `KeyCode::Down`: increment `backlog_selected` (clamped to items.len()-1)
   b. When on Backlog tab and `KeyCode::Char('k')` or `KeyCode::Up`: decrement `backlog_selected` (saturating_sub)
   c. `KeyCode::Enter` on Backlog tab: toggle `backlog_expanded`. When expanding, if selected item's `content` is None, load it synchronously via `backlog::load_backlog_content()` and store in the item. (Content is small -- single markdown file, sync is fine.)
   d. `KeyCode::Char('e')` on Backlog tab (per D-04): pre-fill input_buffer with `/gsd:review-backlog {item.dir_name}` where item is the currently selected backlog item, then push EnqueueScreen. Example command: `/gsd:review-backlog 999.3-queue-editor-and-reorder`

4. On first switch to Backlog tab (in handle_key tab-switch logic from Plan 01): if cache has no items and is not loading, synchronously load items via `backlog::parse_backlog_items(planning_dir)` and store in cache. Get planning_dir from `ctx.config.projects.get(&self.alias).map(|p| p.path.join(".planning"))`.

5. Also update `render_main_only` to include the backlog tab rendering (so EnqueueScreen overlay works when on backlog tab).
