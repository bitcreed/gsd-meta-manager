# Phase 1 — UI Design Contract

> Visual and interaction contract for the Phase 1 functional stub TUI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Important context:** This is a Rust terminal UI (ratatui + crossterm), not a web application. All visual specs use terminal cells, ANSI attributes, and character-based layout — not pixels, hex colors, or CSS units. Phase 1 is explicitly a "functional stub" (D-07): usable but unstyled. Phase 2 adds color-coding and polish.

| Property | Value |

## Spacing Scale

In a terminal UI, spacing is measured in character cells (columns and rows), not pixels. All values below are in **cells**.

| Token | Columns | Rows | Usage |
|-------|---------|------|-------|
| none | 0 | 0 | Tight packing within a widget line |
| xs | 1 | 0 | Inline padding (e.g., space between icon and label) |
| sm | 2 | 0 | Compact horizontal padding inside bordered blocks |
| md | 1 | 1 | Vertical gap between list items (1 empty row), horizontal inner margin |
| lg | 2 | 1 | Section padding inside bordered panels (2 cols horizontal, 1 row vertical) |

**Ratatui Margin/Padding convention:**
- `Block` borders consume 1 cell on each side (top, bottom, left, right)
- Inner content padding: 1 column left, 1 column right (via `Padding::horizontal(1)`)
- No vertical padding beyond what the border provides (content starts on the row after the top border)

Exceptions: none for Phase 1.

## Typography

Terminal UI has no font size control. "Typography" means text attributes applied via ratatui's `Style` struct.

| Role | Modifier | Weight Equivalent | Usage |
|------|----------|-------------------|-------|
| Body | `Style::default()` | Regular | List item text, status values, paths |
| Label | `Style::default().add_modifier(Modifier::DIM)` | Light | Secondary info, hints, column headers |
| Emphasis | `Style::default().add_modifier(Modifier::BOLD)` | Bold | Selected item highlight, section titles |
| Input | `Style::default().add_modifier(Modifier::UNDERLINED)` | Regular | Active text input field content |

**Constraint:** Phase 1 uses exactly 2 text weights: regular (no modifier) and bold (`Modifier::BOLD`). Dim is used only for de-emphasized labels. No italic. No strikethrough.

**Source:** CONTEXT.md D-07 (usable but unstyled), RESEARCH.md TEA pattern (stateless rendering)

## Color

Phase 1 uses the terminal's default foreground and background colors only. Color-coding by workflow state is explicitly deferred to Phase 2 (CONTEXT.md Deferred Ideas).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (background) | Terminal default background | All surfaces |
| Text (foreground) | Terminal default foreground | All body text |
| Selected row | `Style::default().add_modifier(Modifier::REVERSED)` | Currently highlighted row in project list |
| Destructive hint | `Color::Red` (ANSI red) | Remove confirmation prompt text only |
| Success feedback | `Color::Green` (ANSI green) | "Project added" transient status message only |

**Accent reserved for:** Nothing in Phase 1. The only non-default colors are ANSI red for destructive confirmation and ANSI green for success feedback. All other UI uses terminal defaults with bold/dim/reversed modifiers.

**Rationale:** Using terminal defaults respects the user's color scheme (dark, light, solarized, etc.). Phase 2 introduces explicit ANSI color-coding per workflow state (idle, active, blocked, complete) as specified in DASH-02.

**Source:** CONTEXT.md Deferred Ideas ("Color-coding and styling — Phase 2")

## Layout Contract

### Screen Structure (Phase 1 Stub)

```
+--[ GSD Manager ]-------------------------------------------+
| Alias        | Phase        | Status       | Path          |
|--------------|--------------|--------------|---------------|
| myapp        | 2 of 4       | planning     | /home/u/myapp |
| website      | 1 of 3       | active       | /home/u/web   |
|              |              |              |               |
|              |              |              |               |
+-------------------------------------------------------------+
 [a]dd  [d]elete  [q]uit                    2 projects tracked
```

### Layout Rules

| Element | Constraint |
|---------|-----------|
| Outer frame | `Block::bordered()` with title "GSD Manager" top-left |
| Column layout | 4 columns: Alias (20%), Phase (15%), Status (15%), Path (50%) |
| Column sizing | Use `Constraint::Percentage` for responsive terminal widths |
| Minimum terminal width | 60 columns — below this, truncate Path column with ellipsis |
| Minimum terminal height | 10 rows — below this, hide the footer keybind hint line |
| Project list | `ratatui::widgets::Table` with `Row` per project |
| Header row | Bold text, separated by `Table::header()` with bottom border |
| Selected row | `highlight_style` set to `Style::default().add_modifier(Modifier::REVERSED)` |
| Footer | Single line below the table, left-aligned keybind hints, right-aligned project count |
| Scrolling | Built-in `Table` scrolling via `TableState::select()` — no custom scroll logic |

### Adaptive Behavior

| Terminal Width | Behavior |
|----------------|----------|
| >= 100 cols | Full layout, all columns visible with comfortable widths |
| 60-99 cols | All columns visible, Path truncated with "..." |
| < 60 cols | Hide Path column entirely; show Alias + Phase + Status only |

## Interaction Contract

### Keyboard Bindings (Phase 1)

| Key | Context | Action |
|-----|---------|--------|
| `j` or Down | Project list | Move selection down |
| `k` or Up | Project list | Move selection up |
| `a` | Project list | Enter "add project" mode (inline prompt) |
| `d` | Project list (item selected) | Prompt to confirm removal of selected project |
| `q` | Any | Quit application |
| `Ctrl+C` | Any | Quit application (force) |
| `Enter` | Add mode: alias prompt | Accept alias, move to path prompt |
| `Enter` | Add mode: path prompt | Validate path and add project |
| `Esc` | Add/delete mode | Cancel and return to project list |
| `y` | Delete confirmation | Confirm removal |
| `n` | Delete confirmation | Cancel removal |

**No mouse interaction.** REQUIREMENTS.md Out of Scope: "Mouse-first interaction."

### State Transitions

```
ProjectList ──[a]──> AddAlias ──[Enter]──> AddPath ──[Enter]──> ProjectList
     │                   │                    │
     │                  [Esc]                [Esc]
     │                   │                    │
     │                   v                    v
     │              ProjectList          ProjectList
     │
     ├──[d]──> DeleteConfirm ──[y]──> ProjectList
     │              │
     │             [n/Esc]
     │              │
     │              v
     └─────── ProjectList
```

### Input Fields

| Field | Prompt Text | Validation | Error Copy |
|-------|-------------|------------|------------|
| Alias | `Alias: ` | Non-empty, no whitespace, unique among registered projects | `Alias already exists` or `Alias cannot be empty` |
| Path | `Path: ` | Non-empty, path exists on disk, contains `.planning/` directory | `Path does not exist` or `No .planning/ directory found at this path` |

Input fields render at the bottom of the screen (above the footer line), replacing the keybind hints during input mode.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Window title | `GSD Manager` |
| Primary CTA | `[a]dd project` (shown in footer) |
| Empty state heading | `No projects registered` |
| Empty state body | `Press [a] to add your first GSD project` |
| Error: alias exists | `Alias "{name}" already exists. Choose a different alias.` |
| Error: alias empty | `Alias cannot be empty.` |
| Error: path missing | `Path does not exist: {path}` |
| Error: no planning dir | `No .planning/ directory found at: {path}` |
| Delete confirmation | `Remove "{alias}"? This only unregisters it — project files are not deleted. [y/n]` |
| Success: added | `Added "{alias}"` (shown in footer for 3 seconds, then reverts to keybind hints) |
| Success: removed | `Removed "{alias}"` (shown in footer for 3 seconds) |
| Loading state | `Loading projects...` (shown while async state reads are in flight) |
| Column: Alias | `Alias` |
| Column: Phase | `Phase` |
| Column: Status | `Status` |
| Column: Path | `Path` |
| Phase cell format | `{completed} of {total}` (e.g., "2 of 4") |
| Status unknown | `unknown` (when STATE.md is missing or unparseable per D-06) |
| Footer project count | `{N} project(s) tracked` |
| Footer keybinds | `[a]dd  [d]elete  [q]uit` |

**Source:** REQUIREMENTS.md REG-01/02, CONTEXT.md D-03 (alias-based), D-06 (graceful degradation)

## Widget Inventory (Phase 1)

| Widget | ratatui Type | Purpose |
|--------|-------------|---------|
| Project table | `Table` | Main project list with header and selectable rows |
| Outer frame | `Block` | Bordered container with title |
| Footer bar | `Paragraph` (2 spans in a `Line`) | Left: keybinds, Right: project count |
| Input prompt | `Paragraph` | Alias/path text input at bottom of screen |
| Confirmation prompt | `Paragraph` | Delete confirmation "[y/n]" at bottom of screen |
| Empty state | `Paragraph` (centered) | Shown when project list is empty |
| Transient status | `Paragraph` | Success/error messages in footer area |

**No custom widgets in Phase 1.** All rendering uses ratatui built-in widgets only.
