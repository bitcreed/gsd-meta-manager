### SAFE-04 judgement: satisfied, with a documented limitation `[inferred — cleanup 2026-10-28]`

SAFE-04 asks that credentials be redacted "when captured into the run log, not when rendered". That
holds now on the only capture path. Every byte the master writes to stdout or stderr passes
`pump_redacted` before it reaches the file. JSON events, which make up the stream-json stdout, are
redacted per string leaf, so a PEM block inside a JSON string is caught whole. The multi-line PEM gap
(28 WR-13) applies only to a key printed as plain text across lines, on stderr or on a line that lost
its JSON framing. The sandbox withholds key material (LNCH-04/12), and the one live token
(`CLAUDE_CODE_OAUTH_TOKEN`) is single-line and pattern-covered. WR-11 (pipe interleave) and WR-12
(escapes on a non-JSON line) are likewise narrow, unreproduced edge cases. The previous "partial"
meant a whole unredacted path. These are completeness limits of pattern redaction on a covered path,
so they are tracked as security warnings rather than as a requirement gap. On a strict reading
SAFE-04 would be partial for the plain-text PEM case alone. The fix is small (stateful BEGIN..END
suppression in `pump_redacted`), and it is the first item to take into the next milestone.
