**fixers.rs (D-C12).** Module doc: an estimate, never a count of record. It reads one REVIEW.md frontmatter through the existing nested reader (no second YAML reader, D-C11) and commit subjects through `git_ops::log_subjects` only. It runs only while an active fixer exists. It writes nothing. Keep all test code in one trailing `#[cfg(test)] mod tests`. Regexes use the `OnceLock<Regex>` accessor idiom:
- `finding_ids` collects `\b(?:CR|WR|IN)-\d+\b` from subjects matching `^fix\((\d+(?:\.\d+)?)(?:-[^)]*)?\):` whose captured phase is `same_phase` as the target.
- `fixer_phase` takes `(?i)\bphase (\d+(?:\.\d+)?)\b` from the description, else the first `fix(NN…)` scope phase in the fixer's own subjects.
- `estimate`:
  1. The active fixers are rows whose raw `agent_type` is `gsd-code-fixer`, whose `plan` is `None` and whose liveness is Live, Idle or Finished; if there are none, return `None`.
  2. For each fixer, `log_subjects(&row.path, &format!("{base}..HEAD"), 200)`, when `base_sha` is `Some`.
  3. The phase is the one most fixers yield, ties to the higher `PhaseNum`; no phase → `Some(FixerEstimate { fixers, ..Default::default() })`.
  4. `find_phase_dir(&project_root.join(".planning"), &phase.padded())`. If any `*-REVIEW-FIX.md` exists there, leave `fixed` and `total` `None` (the run is over).
  5. Otherwise read the phase's `*-REVIEW.md` (not `-REVIEW-FIX`) with a 256 KiB `Read::take` cap: `total = leading_frontmatter_nested_value(content, "findings", "total")` parsed as `u32`.
  6. `fixed` = the size of the union of `finding_ids` over every fixer's subjects plus `log_subjects(main_worktree, "HEAD", 300)`.
  7. `fixed` and `total` are `Some` only when the total parsed.
