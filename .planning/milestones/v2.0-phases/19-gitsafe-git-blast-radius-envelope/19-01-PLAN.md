<objective>
Prove the whole GITSAFE architecture end to end on one path: a driven `git push` that resolves
outside the reserved namespace `refs/heads/gsd-auto/<alias>/` is refused by a mechanism that runs
with the model removed from the equation entirely (SAFE-01, D-05, D-31), while a push *inside*
that namespace succeeds.

This is the tracer for Phase 19. It is production-quality, not a prototype: it creates the real
`src/envelope/` module tree (D-01), the real out-of-repository artifact directory (D-02), the real
hidden `envelope` subcommand re-entry (D-04), the real env-injected `core.hooksPath` delivery
(D-09) and the real hook-provenance refusal (D-10). Every later plan in this phase expands
outward from this proven slice rather than re-deciding its shape.

Purpose: the hardest architectural risk in this phase is that the enforcement path does not
actually reach git. Proving it once, on the executor's best early-context tokens, converts that
risk into a committed fact before six more plans are stacked on top of it.

Output: a working refusal and a working allow, both asserted against a real `file://` bare
repository, plus the module tree the rest of the phase fills in.

Reversibility note: every decision this plan implements is already locked in `19-CONTEXT.md`
(autonomous mode; D-05 and the honesty posture are `[USER-HARD-REQUIREMENT]`). Ratings are
recorded on the tasks for the record; no `checkpoint:decision` is inserted, because gating a
decision the developer has already made is re-asking a settled question.
</objective>

<assumption_delta_decision>
The advisory assumption-delta detector fired `pluralization` on this phase. The genuine delta it
points at is not the PR count in the snippet it matched — it is that `<alias>` stops being only a
registry key and becomes a **path component**, joining `<run_id>` as the second value the codebase
interpolates into a filesystem path.

- **Noun that is now primary:** a plain path component (one `Component::Normal` whose text equals
  the whole string), of which a run id and a registry alias are both instances.
- **Decision:** `promote`. `journal::is_plain_run_id` is renamed to
  `journal::is_plain_path_component` and both callers use the one predicate (D-03). Adding a
  second, alias-specific validator alongside the still-run-id-named original is explicitly
  declined: two predicates is how the next caller escapes validation, which is the exact failure
  `journal::run_paths`' `Option` signature was introduced to foreclose (WR-02).
- **Companion invariant test:** Task 3's hostile-alias test is the invariant. It goes red the
  instant a future phase reintroduces an unvalidated path join.
</assumption_delta_decision>

**`src/lib.rs`** — add `pub mod envelope;` in alphabetical position (between `driver` and `error`).

**`src/envelope/mod.rs`** (new) — the module root, per D-01. It declares `pub mod policy;`,
`pub mod hooks;`, `pub mod cred;` and exposes the artifact-directory resolver.
Public surface: `pub fn envelope_root() -> Option<PathBuf>` resolving
`dirs::data_local_dir()/gsd-meta-manager/envelope`, and
`pub fn envelope_dir(alias: &str) -> Option<PathBuf>` which returns `None` for an alias that
fails the plain-path-component check rather than joining it (D-02, D-03). Note in a `//` comment
that `src/main.rs`'s log-directory fallback to `/tmp` is deliberately NOT copied here: a fallback
that could land inside a repository would defeat D-02, so an unresolvable data-local directory
yields `None` and the caller refuses. The module doc states the D-02 rationale in the
three-failures-it-prevents form CONTEXT.md records.

**`src/envelope/policy.rs`** (new) — pure decision functions, no I/O, no processes, in the shape of
`journal::is_plain_run_id` (a pure token-level validator with the declined alternative recorded in
its doc). This task creates only what the single path needs:
  - `pub const DEFAULT_NAMESPACE_ROOT: &str = "refs/heads/gsd-auto/"` — the D-05 reserved prefix.
  - `pub fn default_namespace(alias: &str) -> String` returning `refs/heads/gsd-auto/<alias>/`.
  - `pub fn validate_namespace(candidate: &str) -> Option<String>` implementing D-05's shape rules:
    non-empty; begins with `refs/heads/`; at least two `/`-separated segments below `refs/heads/`;
    the first segment below `refs/heads/` is none of `main`, `master`, `HEAD`; and it ends in `/`
    so it is a prefix rather than a single branch. Returns `None` on any violation, so a user
    cannot configure `refs/heads/` and silently disable the control.
  - `pub enum PushVerdict { Allow, Refuse { reason: &'static str, ref_name: String } }` and
    `pub fn classify_push_ref(dest_ref: &str, namespace: &str) -> PushVerdict`, allowing exactly
    the refs that start with `namespace` and refusing everything else with the reason string
    `push_outside_namespace` (the first member of D-24's taxonomy).

**`src/envelope/hooks.rs`** (new) — stub generation and provenance, per D-04 and D-10.
  - `pub fn install(alias: &str) -> anyhow::Result<PathBuf>` creates
    `<envelope_dir>/hooks/` and writes `<envelope_dir>/hooks/pre-push` with mode `0o755`,
    using the `NamedTempFile::new_in` + `persist` atomic-write idiom from `config.rs:234-249`
    and `anyhow::Context` naming the path on every I/O failure. It returns the hooks directory.
  - The generated file is a three-line `sh` stub and carries **no policy logic** (D-04): a
    shebang, and an `exec` of the absolute binary path captured from `std::env::current_exe()`
    at generation time with the envelope pre-push action and the alias, forwarding stdin. Policy
    lives in Rust where it is unit-testable, and one binary means the TUI, the driver and the
    hook can never disagree about what the policy is.
  - `pub fn pre_push(alias: &str, stdin: impl BufRead) -> anyhow::Result<i32>` is the hook body.
    It parses git's `<local-ref> <local-sha> <remote-ref> <remote-sha>` lines from stdin, asks
    `policy::classify_push_ref` about each `<remote-ref>` against `policy::default_namespace(alias)`,
    prints a legible refusal naming the offending ref and the reason to stderr, and returns a
    non-zero code if any line is refused. A deletion line (all-zero local sha) is still classified
    by its destination ref. An unparseable line is refused, never skipped — a hook that cannot
    read its input must not allow.

**`src/envelope/cred.rs`** (new) — this task creates only the git-config-injection half of D-09.
  - `pub fn hooks_path_env(hooks_dir: &Path) -> Vec<(OsString, OsString)>` returns the
    `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_0` / `GIT_CONFIG_VALUE_0` triplet setting
    `core.hooksPath` to `hooks_dir`. Its doc comment records the four things this buys over
    installing into `.git/hooks/` (the user's own git commands are unaffected; nothing is left
    behind on a crash; the agent cannot uninstall it by editing a file in the repo; repo-local
    config cannot override env-injected config), and states honestly that an agent which unsets
    `GIT_CONFIG_COUNT` in a subshell escapes this layer — the limit D-27 exists to tell the truth
    about. Note that `git -c core.hooksPath=…` is the one form that outranks it, and that plan
    19-02 denies that form by name.
