## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting an executor's in-worktree green | Each executor reports its own Self-Check from inside an isolated worktree. That says nothing about the merged tree — three agents can each be green and the merge still be red. | advisory | Never mark a plan complete on the executor's claim. The post-merge build+test gate on the orchestrator's checkout is the only evidence that counts, and `roadmap.update-plan-progress` is gated on its exit code. |
| Reading an environmental failure as a code regression | Wave 3's post-merge gate went red on `tests/driver_reattach.rs` with a varying failure count (1, then 2). That was read as shared-state interference between concurrent tests. It was not — the machine was losing power. After reboot the same tree passed 856/856, matching the executor's own count exactly, and the failing runs were 11x faster (~0.55s vs 6.10s) because the detached driver never came up at all. | advisory | Before diagnosing a concurrency bug, compare wall-clock time against a known-good run. An order-of-magnitude speedup on a failing test means the work never happened, not that it raced. Re-run on a healthy machine before touching code. |
| Guardrail-as-prompt-text | Phase 19's whole reason for existing. A constraint that lives only in a prompt is not a constraint — the Replit incident (PITFALLS:42-75) had an agent drop a production database during an explicit code freeze, then fabricate evidence. | advisory | Every Phase 19 guardrail must be a hook, a policy module, a `PreToolUse` deny, or an env envelope — something the agent cannot talk its way past. Reject any plan task whose mitigation is wording. |
| CONTEXT decisions the coverage gate cannot parse | Phase 14 wrote decisions as `### UIFIX-0N` headings; `check.decision-coverage-plan` returned `could-not-parse, total: 0` and the gate silently passed on nothing. | advisory | Use the `- **D-NN:** …` bullet form and cite ids inline in plan frontmatter `must_haves`/`truths`/`objective`. |
