<objective>
Make the user's ambient git identity **unreachable** to a driven run rather than merely unused, and
give the run a scoped credential that never becomes readable anywhere but the askpass responder's
stdout (SAFE-05, D-16, D-17, D-18).

Purpose: SAFE-05 is the one control in this phase whose failure mode is silent. An envelope that
merely declines to *use* the user's keychain still leaves it one `git config --global` away, and an
envelope that has no configured credential and quietly falls back to the ambient one satisfies
every test while violating the requirement outright. Both are closed by construction here.

Output: a pure, unit-assertable child-environment builder; an askpass responder scoped to the
configured remote's host; and a `file://` push that succeeds with `HOME` pointed at an empty
directory — because environment assertions alone would pass against an envelope that also broke
pushing.

Reversibility note: D-16, D-17 and D-18 are locked decisions in `19-CONTEXT.md`, and D-16 is a
`[USER-HARD-REQUIREMENT]`. Ratings are recorded on the tasks; no `checkpoint:decision` is inserted.
</objective>

to `src/envelope/cred.rs`. For the environment-variable form it reads the named variable from the
**parent** process environment; for the command form it runs the named command and takes trimmed

**The responder (D-17).** Add `EnvelopeAction::Askpass { alias: String, prompt: String }` in
`src/cli.rs` and its arm in `src/main.rs`, plus
`pub fn askpass(alias: &str, prompt: &str, configured_remote_host: &str) -> anyhow::Result<i32>` in
`src/envelope/cred.rs`. Git invokes the askpass program with a human-readable prompt that names the
host it is authenticating to. The responder:
  - parses the host out of the prompt;
  - emits a credential to **stdout only** when that host equals the host of the configured remote,
    and emits nothing with a non-zero exit for any other host, so an agent that adds a second remote
    gets an authentication failure rather than the user's token;

    credential is configured or resolution yielded nothing;

    the envelope directory, and not to stderr.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user's ambient identity → driven child | The parent process holds keychain access, an ssh agent socket and a global git config the child must not reach |
| configured credential → git | A token crosses from a secret store into a child process that an untrusted agent controls |
| git → askpass responder | Git supplies an attacker-influenceable prompt naming a host |
| driven agent → remotes | The agent can add a remote pointing anywhere |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-23 | Information Disclosure | ambient credential reachability | high | mitigate | `SSH_AUTH_SOCK`/`SSH_AGENT_PID` removed; `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` redirected to a helper-free generated config; `GH_CONFIG_DIR` redirected (D-16), each asserted individually |
| T-19-24 | Information Disclosure | token placement | high | mitigate | Token exists only on the askpass responder's stdout; no argv element, no URL userinfo, no envelope file — asserted by a directory-content behavior test and by negative source greps (D-17) |
| T-19-25 | Spoofing | agent adds a second remote to harvest the token | high | mitigate | The responder emits only for the configured remote's host and exits non-zero for any other, so the attack yields an authentication failure (D-17) |
| T-19-26 | Elevation of Privilege | silent ambient fallback when unconfigured | high | mitigate | `resolve_credential` has no ambient branch by construction; the unconfigured path fails closed with `credential_unavailable` (D-18) |
| T-19-27 | Denial of Service | authentication prompt into null stdio | high | mitigate | `GIT_TERMINAL_PROMPT=0` plus `BatchMode=yes`; a bounded-time test asserts termination rather than a block (D-16) |

| T-19-SC | Tampering | package-manager installs | high | mitigate | Not applicable — no new crate is added by this plan. No Package Legitimacy Audit table exists for this phase, so any proposed dependency blocks |
