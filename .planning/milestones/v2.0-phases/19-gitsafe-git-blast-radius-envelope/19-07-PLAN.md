<objective>
Attach the envelope to the spawn seam and make every refusal observable from disk rather than from
prose: the tool denylist and the settings path on argv (D-06 layer 1, D-07), the envelope
environment in the one place the child's environment is built (D-09, D-16), envelope establishment
at the single `ExecutionOptions` construction site, a positioned refusal in the ordered chain, and
`JournalEvent::Parked`'s first emission from **every** refusal path the phase produces — the
drive-time assertion and the three re-entry points that actually see a force push, a hooks-path
rewrite, a detected secret and an exceeded PR cap (D-24, D-25).

Purpose: everything the previous six plans built is inert until it reaches the child. This is the
plan where the envelope stops being a module and starts being a boundary — and it is also where
the phase's carried-in constraints (D-28) are most easily broken, because it touches four of the
five files those constraints name.

Output: a driven run that cannot be started without an envelope, cannot reach the user's ambient
git identity, and leaves a park reason on disk when the envelope refuses.

Reversibility note: D-06, D-24, D-25 and D-28 are locked decisions in `19-CONTEXT.md`, and D-25 is
a `[USER-HARD-REQUIREMENT]`. Ratings are recorded on the tasks; no `checkpoint:decision` is
inserted.
</objective>

Write the `<behavior>` rows as failing assertions first and watch them fail, then implement. The
four end-to-end rows are the ones ROADMAP success criteria 2, 3 and 5 rest on: those criteria say
the attempt **parks the run**, and until a `Parked` event with the right reason is readable on disk
the criterion is unmet no matter how correctly the operation was refused.

**One appender (`src/envelope/mod.rs`).** Add:

  - `pub enum ParkOutcome { Appended { seq: u64 }, NoLocator, NoActiveRun, Unresolvable(String), Failed(String) }`
  - `pub fn park_at(project_root: &Path, reason: ParkReason, needs: &str) -> ParkOutcome` — the whole
    of the work, taking the root as an argument so it is a unit test with no process and no
    environment mutation.
  - `pub fn park(reason: ParkReason, needs: &str, detail: &str) -> ParkOutcome` — the thin wrapper
    the re-entry points call: read `GSD_MM_ENVELOPE_PROJECT_ROOT` once, return `NoLocator` when it is
    absent, otherwise delegate to `park_at`.

Splitting the two is the same factoring `build_env` and the spawn closure already use, and for the
same reason: the environment is process-global, so a function that reads it cannot be exercised by a
parallel test suite without a race. `park_at` carries the behavior and the unit tests; `park` carries
the one environment read and is exercised end-to-end through spawned processes.

`park_at` joins `.planning`, calls `journal::writer::read_active_run`, calls `journal::run_paths` and
**handles the `None`** rather than unwrapping (D-28; that signature exists to conscript the compiler
into enumerating callers), opens the journal with `JournalWriter::open` and appends
`JournalEvent::Parked { reason: reason.as_str().into(), needs: needs.into() }`. `park`'s `detail`
goes into the stderr line beside the call, not into the event, because `Parked`'s two fields are the
schema and widening them is a journal migration this phase has no reason to spend.

Carrying the locator on the environment rather than on the subcommand's arguments is deliberate and
the doc says why in the shape `redact.rs:14-49` uses: the alternative is resolving the project root
from `alias`, which goes through `DrivableProject::from_registry`, whose single production call site
`tests/spawn_seam_guard.rs` holds (D-28). A second call site to make a log line writable would trade
a real containment property for an evidence convenience. This is also why no `EnvelopeAction` variant
changes shape: the three re-entry points keep the arguments plans 19-01, 19-03 and 19-05 gave them.

State the honest limit in the same doc: an agent that unsets the locator loses its own park record
but gains nothing — the refusal is already decided by the time `park` is called — and the answer to
that residue is D-27's server-side recommendation, not a stronger client-side guess. Also state why
the `active` pointer is unambiguous here rather than racy: `src/driver/lock.rs` holds a per-project
advisory lock, so an alias has at most one live run, and a pointer cleared by `JournalRun::finish`
correctly yields `NoActiveRun` for a hook that outlived its run.

**Three re-entry points (`src/envelope/hooks.rs`).** In `pre_push`, `pre_commit` and `guard`, on
**every** refusal branch, call `park` with that branch's own `ParkReason` — `ForcePushBlocked`,
`HookBypassBlocked` and `PushOutsideNamespace` from `classify_git`'s verdict in `pre_push`;
`SecretDetected` in `pre_commit` and in `pre_push`'s backstop scan; `PrCapExceeded` in `guard`. Take
the reason from the verdict the classifier already returned; do not re-derive it, because two
derivations is how the journal starts disagreeing with the refusal.

**Order is the decision, and it goes in a `//` comment.** Decide the verdict, write the stderr line,
call `park`, then exit non-zero — and the exit code does not depend on what `park` returned. A
`ParkOutcome` other than `Appended` adds a second stderr line naming which outcome it was, so a
refusal that could not be recorded says so instead of looking like a refusal that was never
attempted. Silence is the one behavior forbidden here.

**`src/main.rs`.** The envelope dispatch arm needs no new argument for any of this — the locator
travels on the environment and `park` reads it. What the arm does gain is the print-and-exit posture
already at lines 114-119 applied to the park outcome, so the second stderr line reaches the same
place the first one does. Add no new `EnvelopeAction` variant and change no existing variant's
fields; the three actions keep the shapes plans 19-01, 19-03 and 19-05 gave them.

**The terminal record (`src/driver/run.rs`, D-25).** D-25 requires the run's terminal record to
carry the park reason, and `outcome_label` cannot know one. Add
`pub(crate) fn terminal_label(outcome: &RunOutcome, journal: &Path) -> String`: it reads the run's
journal once with `journal::reader::read_all`, and if a `Parked` event is present it returns
`parked:<reason>` from the **last** one, otherwise `outcome_label(outcome).to_string()`. Use it at
the two `journal.finish(outcome_label(&outcome))` call sites. This is a single end-of-run read, not
a hot path, and it must sit inside whatever blocking hand-off already covers `finish` at each site —
plan 19-08's guard scans for exactly this, so an unwrapped synchronous read added on an `async fn`
path here is a hit that plan then has to resolve.

**The tests (`tests/envelope_wiring.rs`).** Use Task 3's `start_run_with_envelope` and
`parked_events` helpers for all four end-to-end rows. Each test spawns the real operation as a child
process carrying the envelope environment — never by calling `pre_push` in-process, because the
thing being proved is that a *separate* process found the journal. Reuse the staged-secret fixture
shape from `tests/envelope_hook_refusals.rs` and the at-cap ledger fixture shape from
`tests/envelope_pr_cap.rs`; name the source file in a comment so a later reader can see the shapes
are shared rather than forked.

Each end-to-end test asserts all four evidence facts D-25 names, in one test rather than four:
non-zero exit, the `Parked` event with the expected reason in the on-disk journal, the terminal
record carrying the park reason, and — for the two push rows — the remote ref byte-identical to
what it was before.
