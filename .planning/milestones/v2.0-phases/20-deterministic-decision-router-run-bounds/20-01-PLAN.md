<objective>
Build the iteration loop this phase was mis-scoped to merely bound, and prove it end to end
on the thinnest honest path: one routed command, chosen by a rule, executed, observed, and a
second iteration that trips a bound and stops the run with the detector named on disk.

Research established with three source statements plus an enforcing test that `DriveArgs::command`
is a single `String` and that no command loop exists (`src/driver/mod.rs:34-36`, `:98-102`,
`src/cli.rs:51-55`, `src/driver/mod.rs:538-547`). This plan makes the loop real. The hoist boundary
is exact: `src/driver/run.rs:1401` (the `select!` racing `executor.start`) through `:1673`
(`handle.wait_outcome()`). Nothing above `:1401` and nothing below `:1673` moves — the SIGTERM
handler, the process group, `establish_envelope`, `lock::acquire` and `JournalRun::start` are all
per-run by contract, and `run.json` is written exactly twice (research Pitfall 4, D-20.2).

Purpose: this is the phase's architectural spine. If the per-run/per-iteration split is wrong,
every later plan is wrong, so it is proven on one path before any rule table is widened.
Output: a bounded, routed, journalled iteration loop; a pure router with one rule and a
fail-closed no-rule park; a pure bounds module with all four CTRL-06 detectors.
</objective>

| Boundary | Description |

| driven agent → `.planning/` → `state_reader` → router | The agent this run spawns writes into the same `.planning/` tree the next iteration routes from. Agent-authored content crosses into a routing decision. |
