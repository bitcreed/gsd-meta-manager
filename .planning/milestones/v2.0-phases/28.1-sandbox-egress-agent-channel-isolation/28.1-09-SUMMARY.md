# Phase 28.1 Plan 09: The planted-file guard inside the launch, protections_absent per launch, and the final live sweep Summary

**`.git` and `.claude` are self-bound and their config, hooks, settings, agents and commands ro-bound inside the sandbox (rename and write both fail live), every launch re-scans the checkout and records what the driver planted before the push can run, every launch records `protections_absent`, and a live sweep over the finished profile shows exactly the run's two sockets, a runtime dir holding only `gsdmm-driverctl`, and an untouched host `~/.claude/daemon/dispatch`.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's socket sweep (RESEARCH Pitfall 8's form) is vacuous for bind-mounted sockets**
- **Found during:** Task 3 (first live run: `sockets=` was empty)
- **Issue:** `find / (prune) -o -type s -print` printed nothing although `ls` and `stat` showed both sockets. GNU find 4.10 trusts the directory entry's `d_type`, and a socket bind-mounted by bwrap sits on a regular-file mount point whose `d_type` is `DT_REG` (`find -printf %y` printed `f`; measured). The non-vacuity assertion caught it.
- **Fix:** the sweep puts an always-true stat-needing test first: `-perm -000 -type s` (reverse order does not work; measured in a throwaway bwrap). It then lists exactly the two run sockets.
- **Files modified:** tests/launcher_live_isolation.rs (comment in the probe explains it)
- **Verification:** live run above. **Impact:** the 28.1-06 residual-risk doc and RESEARCH Pitfall 8 should carry the corrected form.
- **Commit:** febe207

**2. [Rule 1 - Bug] The LOG grammar test did not know the new `planted` event**
- **Found during:** full-suite run after Task 3
- **Fix:** one grammar line in `src/driver_templates/assets/LOG.md`
- **Files modified:** src/driver_templates/assets/LOG.md
- **Verification:** `driver_templates` tests (33) pass; full suite back to the known failure only
- **Commit:** b1f6920

**3. [Rule 1 - Bug] Two `launcher_push` tests assumed the launcher records no baseline**
- **Found during:** Task 1 verify
- **Issue:** `strict_mode_without_a_baseline_still_refuses` asserted the baseline is absent after a launch (the launcher now writes it), and `push_uses_the_pinned_remote_not_the_rewritten_checkout_config` had the driver rewrite `.git/config` and expected the end-of-run push to succeed (with a baseline, `changed .git/config` is a git-relevant finding by design, D-23).
- **Fix:** the first test removes the baseline after the launch (strict mode is what a lost one leaves); the second asserts the end-of-run push is refused with `planted_git_config` and nothing reached either repository, then `driver push --ack-planted` goes to the pinned remote and not the rewritten one, so the original property (pinned URL wins) is kept.
- **Files modified:** tests/launcher_push.rs
- **Commit:** 528d42f
