## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The `ifaces` probe source in the plan lists the host's interfaces**
- **Found during:** Task 1 (measured before writing the test)
- **Issue:** the plan reads `/sys/class/net`; the sandbox keeps the host's `/sys` (read-only bind of `/`), and a sysfs mount is tied to the netns it was mounted in, so inside a fresh netns it still listed 17 host interfaces (docker0, wlo1, veth...).
- **Fix:** `ifaces` reads `/proc/net/dev`, which the sandbox mounts fresh and which answers for its own netns (`lo` only). Documented in the PROBE doc comment.
- **Files modified:** tests/launcher_live_egress.rs
- **Commit:** f67abe7
- **Residual (not fixed, out of scope):** the host's interface names are readable inside through `/sys/class/net`; they carry no reach, only names.

**2. [Rule 1 - Bug] The Phase 28 live isolation test broke on the new egress re-bind**
- **Found during:** final live regression run of `launcher_live_isolation` (not in the plan's verify list)
- **Issue:** `bwrap_argv` now re-binds the egress socket and bwrap refuses a missing source; the test only created the driverctl socket ("literal only" in the plan was not enough).
- **Fix:** bind a dummy listener at the egress path. The test then passes with all its isolation assertions unchanged (also under `--unshare-net`: the in-sandbox `https` push now fails with "Could not resolve host").
- **Files modified:** tests/launcher_live_isolation.rs
- **Commit:** 48335b6

**3. [Plan precision] Stricter live assertions** — `loopback_rc`, `lan_rc`, `abstract_rc`, `x11_rc` are asserted `== 7` (curl "failed to connect"), stricter than the plan's "non-zero". `docker_sock` / `system_bus` presence on the host is printed as a control but not asserted (they are present here).
