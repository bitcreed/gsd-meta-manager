# Phase 28.1 Plan 08: The $HOME allowlist Summary

**The driver's `$HOME` is a 256 MiB tmpfs with only a host-derived read-only allowlist, a three-key per-run gitconfig and an overlay on the cargo registry re-bound over it, and only GSD/rtk hooks reach its settings; proved live with a planted `~/.gsdmm-probe-<pid>/env` and a `$HOME` symlink to a project `.env`, both unreadable, while claude, node, cargo, rtk, git commit and gsd-tools all work.**

## Performance

- **Duration:** about 25 min (2026-10-24T23:29:06Z to 23:54Z)
- **Tasks:** 3 (tracer, TDD, TDD), 4 code commits
- **Files:** 1 created, 9 modified

## Accomplishments

- `home.rs`: `home_allowlist(facts, overlay)` is a pure function of `HostFacts` (CARGO_HOME/RUSTUP_HOME, the `PATH` hit and resolved binary of each of `claude node npm npx rtk cargo rustc rustup git`, this binary, the set of existing candidates). `HomeSetup::for_host` adds the git identity (three `git config --get` through `process::run_bounded`) and writes the 0600 gitconfig atomically into the run's state dir.
- `bwrap_argv`: right after `--tmpfs /run`: `--size 268435456 --tmpfs <home>`, then `--ro-bind` / `--overlay-src ... --tmp-overlay ...` / `--size n --tmpfs` per entry, then the gitconfig at `~/.gitconfig`, then the null masks, all before the project, run-dir, config-dir and socket binds. `TMPFS_MASK_DIRS` is out of the argv and is the invariant of `no_allowlist_entry_overlaps_a_mask_dir`; `NULL_MASK_FILES` (and the stored run-token file) is emitted only for an existing file inside a read-only entry.
- `launch()` builds `HomeSetup::for_host` once (an error closes the session like a seed error), prints the D-18 line, and hands the setup to the seed (hook roots) and to `supervise`. `LaunchContext` carries `home_setup`.
- D-19: `hook_is_kept` + `filter_user_hooks`, applied in both postures before the gate's own hooks are inserted. On this host 19 of 27 settings hooks are kept (GSD hooks and `rtk-rewrite.sh`), the 8 claudear pipx hooks are dropped.

- **Commit:** c641769
