### WR-05: Allowlist binds that lie under the project path are covered by the later read-write project bind

**Files modified:** `src/launcher/config_dir.rs`, `src/launcher/run.rs`, `src/launcher/sandbox.rs`
**Commit:** 1ed17dc
**Status:** fixed: requires human verification
**Decision source:** user decision (authoritative, given in the task). Launches whose binary lives in the driven project are NOT refused; `cargo build` inside the project keeps working.
**Applied fix:**
- (a) `config_dir::snapshot_exe` (`src/launcher/config_dir.rs:291`) copies a binary that lies under the canonical project (directly, or through a symlink either way) to `<config-dir>/bin/gsd-meta-manager.exe` through a temp file and a rename. `run.rs:711` calls it once per `launch()` and hands the result down as `ctx.binary`, so the `driverctl` shim, the `next` shim (both baked into `seed`), the gate hooks (which call the shim) and the bridge command (`bridged_command(&ctx.binary, ...)`) all exec the snapshot. It is read-only inside through the existing `--ro-bind <cfg>/bin` bind. A binary outside the project is returned unchanged and nothing is copied. Nothing is bound read-only in place, so `target/debug/gsd-meta-manager` stays an ordinary read-write file inside the project bind and cargo can rename over it.
- (b) `bwrap_argv` (`src/launcher/sandbox.rs:555`, `:567`, helper `push_home_entries` at `:460`) now emits every `$HOME`-phase entry (ro, overlay, tmpfs, the per-run gitconfig, the `/dev/null` credential masks) whose path lies under the project AFTER `--bind project project`; the rest stay before it. Guard binds already followed the project bind. Unit test `home_entries_under_the_project_follow_the_project_bind` (`sandbox.rs:1088`) asserts the order for all entry kinds; `config_dir` tests cover the copy (including symlink, replacement and the outside-project no-copy case).
- Redundancy note `[inferred — audit]`: the snapshot is passed to `HomeSetup::for_host` as the binary, so on a host whose data dir is under `$HOME` the allowlist adds a ro bind of `<cfg>/bin` that the later explicit bind makes a no-op. Harmless; I did not add an opt-out parameter to `HostFacts`.
- **For the disposition:** a host-side later rebuild or run of agent-edited source (for example the operator running `cargo build` or `cargo run` on what the agent changed) is out of scope. It carries the same trust as reviewing any agent commit; the snapshot protects the binary the SANDBOX side and the launcher execute, not what the operator chooses to build later.

### WR-04: The directory of this binary is bound read-only whole, which can expose unrelated files

**Files modified:** `src/launcher/home.rs`
**Commit:** 870a027
**Status:** fixed: requires human verification
**Applied fix:** `install_root` no longer falls back to the binary's parent; only a `bin` or `versions` parent yields a root (its grandparent, still subject to the refused-root rule). The launcher's own binary follows the same rule (`install_root(&facts.exe).unwrap_or(file)`), so `~/Downloads/node` and `~/tools/x/node` bind only the file. `[inferred — audit]` decision on "what a tool root is" (the open question in 28.1-12-PLAN): a tool root exists only for a `bin/` or `versions/` layout. A tool that needs siblings next to a binary in another layout will fail loudly inside the sandbox rather than expose a shared directory. The previously pinned `~/tools/x/launcher -> ~/tools/x` expectation was changed deliberately; golden allowlist unchanged.

### WR-10: The `egress.log` cap lets the driver switch the audit trail off

**Files modified:** `src/launcher/egress/log.rs`, `docs/DRIVER-SANDBOX.md`
**Commits:** 94514f4, c6e4765 (follow-up: the reopen after rotation goes through `spawn_blocking`, because `tests/async_blocking_guard` flags a lexical `OpenOptions::new(` in an async fn; the first commit alone failed that guard)
**Status:** fixed: requires human verification
**Applied fix:** at the cap the file is rotated once to `egress.log.1` (total bound 2 x 8 MiB) and a first line says so, so the log keeps the most recent records. Refusals (`denied`/`aborted` verdicts, written only by the launcher) take at most a quarter of each file; later ones are counted, one notice line is written, and the count is written before the next carried-out request, so junk requests cannot push out an allowed `CONNECT` or a forwarded inference call. A reopened full log rotates on its first record. A rotation failure stops logging (never traffic), as a write failure always did. Residual: a driver that makes more than 8 MiB of real allowed traffic still rotates earlier records into `.1` and, after a second rotation, out.

### WR-02: The egress server's work sits outside the sandbox cgroup and is unbounded in memory, connections and time

**Files modified:** `src/launcher/egress/mod.rs`, `docs/DRIVER-SANDBOX.md`
**Commit:** f5bab13
**Status:** fixed: requires human verification
**Applied fix (all limits `[inferred — audit]`):** a 512 MiB weighted body-memory budget (a body reserves 4 x its length, a chunked one the 32 MiB maximum, released once the request is on the wire; no share within 10 s is a `503`); `CONNECT` tunnels end after 5 min idle or 1 h in all (own `pump` replaces `copy_bidirectional`, same half-close behaviour); the response relay bounds upstream silence (10 min), each client write (60 s) and the whole response (2 h). The connection cap stays 64. Tests: `body_weight`, idle and lifetime tunnel limits. Residual host-side cost added to "residual risks". Not tested end to end: the 10 s budget wait and the relay timeouts (they would add 10 s to 10 min to the suite).

### IN-07: The duplicate-key refusal is exact-case, so a case-variant key is still judged and forwarded differently

*Also covers T-28.1-41 (28.1-SECURITY.md) — same code fix.*

**Commit:** 84a4053
**Status:** fixed: requires human verification
**Applied fix:** `inference_body_verdict` refuses a key that is not exactly, but case-folds (Unicode-aware, so the long s and the Kelvin sign meet ASCII) to, `tools`, `mcp_servers` or `container` at the top level, or `type` in a `tools[]` entry, whether or not the exact key is also present. Positions the walk reads deeper (`source`, content-block `type`) remain exact-case only. **For the security record:** T-28.1-41 is now partly mitigated rather than only accepted; `28.1-SECURITY.md` was not edited and should be updated by its owner.
