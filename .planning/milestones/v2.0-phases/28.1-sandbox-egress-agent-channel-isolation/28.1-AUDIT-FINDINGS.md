# Phase 28.1 — Sandbox reach audit (2026-10-24)

**Status:** canonical input for discuss / research / plan of Phase 28.1. Every item below must end
up closed with a test, verified as already closed, or documented as accepted residual risk.

**Question the operator asked:** can a driver confined by the Phase 28 sandbox
(`src/launcher/sandbox.rs` `bwrap_argv`, ~line 263) still reach agents outside it, and so bypass
its restrictions by delegating forbidden work to them?

**Short answer:** yes. The filesystem cage holds, but the sandbox shares the host network namespace
(no `--unshare-net`), and `$HOME` is masked by a denylist. Several outward channels remain open.

Sandbox as of the audit: `bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /tmp`, tmpfs over
each existing `TMPFS_MASK_DIRS` entry, `/dev/null` over each existing `NULL_MASK_FILES` entry,
project rw, drivers dir tmpfs + own run dir ro, per-run config dir rw (its `settings.json` and `bin/`
ro), `$XDG_RUNTIME_DIR` tmpfs with only the driverctl socket re-bound, `--unshare-pid
--new-session --die-with-parent`. No `--unshare-net`, `--unshare-ipc` or `--unshare-uts`.

## B. Open channels

1. **Localhost and LAN services.** With the host netns shared, any TCP/UDP service on localhost
   or the LAN is reachable. Concrete case: a local Claude remote-control bridge (claudear)
   listened on `0.0.0.0:8787`. Its secrets file `~/.claudear/env` (a symlink to a project `.env`)
   is not in `NULL_MASK_FILES`. It has since been rebound to `127.0.0.1`, which removes only the
   LAN exposure; the sandbox can still reach it on loopback. Any agent server on localhost/LAN is
   a delegation channel.
2. **`$HOME` masking is a denylist.** `TMPFS_MASK_DIRS` / `NULL_MASK_FILES` list known credential
   locations; any unlisted credential file is readable and, with the network open, usable or
   exfiltratable.
3. **Abstract unix sockets.** They belong to the network namespace, so filesystem masks (including
   the `/tmp` tmpfs) do not hide them. Xwayland's `@/tmp/.X11-unix/X0` is reachable. Today it is
   blocked only by X11 access control plus the cookie living in the masked runtime dir; if `xhost`
   ever allows `localuser`, keystroke injection into the operator's session becomes possible.
4. **Account-scoped cloud features reached with the run token.** Remote Control,
   routines / RemoteTrigger, claude.ai MCP connectors (e.g. Notion spawn-session). The belief that
   a `claude setup-token` token is inference-only is **UNVERIFIED**; Phase 28.1 must settle it
   with evidence (a probe from inside the sandbox, results recorded).
5. **Files read later outside the sandbox.** The project dir is rw, so the driver can plant files
   that the operator's next unsandboxed `claude` / `git` / shell / editor executes:
   - `.claude/settings.json` hooks; `.claude/` skills, agents, commands; `CLAUDE.md`;
   - `.git/hooks/*`; `.git/config` (`core.fsmonitor`, `core.hooksPath`, aliases, filters);
   - `.envrc` (direnv); `.vscode/tasks.json`.

   **Inherent, not closable:** planning docs read by an outside coordinator (DIRECTION.md,
   `.planning/`) are a steering channel. They must be treated as untrusted input and documented
   as accepted residual risk.

## C. Recommended mitigations (in order of payoff)

1. **`--unshare-net` + outside egress proxy.** The proxy runs outside the sandbox and is reached
   via a bound-in unix socket; it allows only a domain allowlist (`api.anthropic.com` and whatever
   Claude Code strictly needs — determine by evidence). Inside, Claude Code uses `HTTPS_PROXY`
   (likely via a small in-sandbox TCP→unix bridge, as sandbox-runtime does). Closes B1, B3 and
   most of B4. Prior art: Anthropic's sandbox-runtime (bwrap + net namespace + unix-socket proxy
   + allowlist). Also add `--unshare-ipc` / `--unshare-uts`.
   Must keep working: API access, the driverctl socket, cargo/git fetches the driver legitimately
   needs. **Open decision:** allowlist crates.io/github fetch hosts vs. offline vendoring
   `[inferred — audit]`.
2. **`$HOME` allowlist.** tmpfs over `$HOME`, ro re-bind only what the run needs (toolchains such
   as `~/.cargo`/`~/.rustup` minus credentials, the project, the per-run config dir). Closes B2.
3. **Planted-file guard.** ro-bind the B5 paths in the project inside the sandbox, or have the
   launcher detect and flag changes after the run (hash before/after), without breaking
   legitimate GSD writes to `.planning/`. Per-path choice is a discuss/plan decision
   `[inferred — audit]`. Note a ro-bind fails on paths that do not exist yet; creation of a new
   `.envrc`/`.vscode/tasks.json` needs either a placeholder bind or post-run detection.
4. **Deny agent-to-agent tools** in the gate's read-only `settings.json`: `SendMessage`,
   `ListAgents`, `RemoteTrigger`, `Cron*`, `mcp__claude_ai_*`; set
   `ENABLE_CLAUDEAI_MCP_SERVERS=false`. Defence in depth only; meaningful only after C1.
5. **Document** the planning-doc channel as accepted residual risk.

**Degraded / unsandboxed mode** (macOS, `--unsandboxed`) must surface which of these protections
are absent (recorded on the run with the existing `sandbox` posture keys, shown in the TUI).
