# Phase 28.1 Plan 11: Duplicate-key refusal, CONNECT host normalisation, egress.log cap Summary

**The egress body judge now refuses any inference body that repeats a JSON key (at any depth, on decoded key text) while still forwarding the exact bytes it judged, closing the T-28.1-02 server-tool bypass; CONNECT normalises the host before its IP-literal test; `egress.log` is capped at 8 MiB with one truncation marker.**

## Accomplishments

- `policy::judge_body` parses through `UniqueKeys` (a `Deserialize` newtype whose visitor builds the same `serde_json::Value` serde_json would, and errors on a repeated key) followed by `Deserializer::end`. A repeat gives `Deny("body repeats a JSON key")`; every other parse error keeps `"body is not valid JSON"`. The reason never names a key or value.
- `connect_verdict` runs `normalize_host` before `looks_like_ip_literal`, so `1.2.3.4.`, `127.1.` and `0x7f.0.0.1.` are refused as IP literals even when their dotless form is allowlisted; `Crates.IO.` still passes against `crates.io`.
- `EgressLog` holds a `Sink { file, written, full }` under the one `tokio::sync::Mutex`; `open_capped(path, cap)` starts `written` from the file length and `full` from `written >= cap`; `open` delegates with `LOG_MAX_BYTES`.
