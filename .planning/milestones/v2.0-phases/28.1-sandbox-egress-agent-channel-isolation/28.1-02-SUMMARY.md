# Phase 28.1 Plan 02: Gate in the managed tier Summary

**The gate's hooks and the agent/cloud-tool deny list now ship as Claude Code managed settings bound read-only at `/etc/claude-code` (tmpfs `/etc` re-bind, works on bwrap 0.9), so a nested `claude` that swaps its config dir, setting sources and disables hooks still reports every tool use to the gate.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fake bwrap/systemd-run argv logging forked per argument and starved timing-based tests**
- **Found during:** Task 2 (full-suite regression run)
- **Issue:** the bwrap argv now carries the host's whole `/etc` (about 250 entries, roughly 800 words). The fakes in `tests/prompt_acceptance.rs` and `tests/launcher_support/mod.rs` forked `head`/`tr` per argument (about 2,600 execs per launch), so each fake call took seconds. The scripted rehearsals h1/h2/h3 (8 s dispatch wait) and `launcher_caps` start waits then failed deterministically (and flakily under full-suite load). Baseline at `bdffe80` was green for these.
- **Fix:** log each argument with a plain `printf`; only an argument holding a newline (the master prompt) uses a subshell. Output format is unchanged.
- **Files modified:** `tests/prompt_acceptance.rs`, `tests/launcher_support/mod.rs`
- **Verification:** `prompt_acceptance` 20 passed twice in a row; full suite back to only the known witness failure.
- **Committed in:** `2572999`

**2. [Rule 2 - Missing critical] `etc_entries_in` made public**
- **Found during:** Task 2
- **Issue:** the plan's test `the_etc_block_precedes_remount_and_skips_host_claude_code` must show the host `claude-code` is skipped, but `from_host` reads the real `/etc`, which has no `claude-code` on this host (vacuous).
- **Fix:** the `/etc` reader is `pub fn etc_entries_in(&Path)` and `from_host` calls it with `/etc`; the test feeds it a fixture dir with a `claude-code` entry.
- **Files modified:** `src/launcher/sandbox.rs`, `tests/launcher_sandbox.rs`
- **Committed in:** `828d5c2`

**3. [Rule 3 - Blocking] Ignored smoke fixture needed a `managed` dir**
- **Found during:** Task 2 (`launcher_sandbox` live smoke)
- **Issue:** `bwrap_argv` now ro-binds `<cfg>/managed`; the fixture config dir had none.
- **Fix:** the fixture creates `config/managed`. Smoke test passes live.
- **Committed in:** `828d5c2`
