# Phase 28.1 Plan 03: Planted-file guard on the push Summary

**The push step now refuses, before any host git touches the driver-written checkout, when the driver planted git-relevant files (fsmonitor, hooks, filters, nested `.git`, worktree pointers), using a file-reader-only detector, an explicit `--ack-planted` override, and `-c`-hardened launcher git.**

## Performance

- **Duration:** about 50 min
- **Completed:** 2026-10-24
- **Tasks:** 3 (tracer, two TDD)
- **Files modified:** 6 (1 created)

## Accomplishments

- `planted.rs` snapshots TRACKED_FILES and TRACKED_DIRS by sha256, records the root `.git` kind, `.git/worktrees/*/{commondir,gitdir,config.worktree}`, every nested `.git` (bounded, non-following walk, skip list, `MAX_WALK_ENTRIES` truncation finding) and include targets. `findings` works with a baseline (diffs plus keys of new or changed configs) or in strict mode (all configs scanned, outward pointers flagged).
- `push_run_with` runs the gate after the destination check and before `refspec`/`fetch`; a git-relevant finding prints bounded findings to stderr, parks `push-refused:planted_git_config`, logs one `push-refused` line (`reason=planted_git_config findings=N`) and returns `Refused`.
- `driver push --ack-planted` logs one `push-ack-planted findings=N` line and proceeds. Every launcher `git` starts with `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.pager=cat` through the single `git()` chokepoint.

## Decisions Made

Exact reason string: `planted_git_config` (`push::REASON_PLANTED_GIT`), park status reason `push-refused:planted_git_config`.

`[inferred - audit]` choices:

- `planted` module nested under `push/` so wave 1 never touches `launcher/mod.rs`.
- Ack shape: per-invocation flag, no config key.
- Skip-dir list: `target`, `node_modules`, `.venv`, `venv`, `__pycache__` (a plant inside is an accepted residual for 28.1-06's doc).
- Strict mode without a baseline: scans every git config and flags outward gitfile/commondir pointers. A root `.git` gitfile shaped like `<repo>/.git/worktrees/<name>` (an ordinary linked worktree) is not flagged in strict mode, so projects that are themselves linked worktrees are not refused by default.
- Git `-c` override list: the three keys in `GIT_HARDENING`.
- Known harness worktrees (nested gitfile into the checkout's own `.git/worktrees/`, a commondir that resolves to its own `.git`, a created or removed `gitdir`/`commondir`) are not findings, so `git worktree add/remove` during a run does not park it. Any other pointer change is.
- Include targets recorded as `include:<path>` entries and reported as `git-config-key:included-file-changed`.
