## Accomplishments

- **WR-01** `exitclass.outstanding_dispatch(events) -> (item, event index) | None`. Open dispatches are kept per item; `report`, `recovered` and terminal `status` close all of an item's entries; a `RUN | dispatch-denied` pops exactly the most recent open entry, and only if no item-level event sits between it and the denial. `outstanding_item` now delegates (API unchanged), so `launcher_s003.py` H4 and the Stop guard share the corrected rule; the fork file is not modified. Selftest cases (a)-(f) plus the item-event-between case pin it.
- **WR-02 / IN-01** `stop_guard.py`: `stop-guard.count` is JSON `{"key": "<item>@<index>", "n": k}`. A changed outstanding dispatch appends `reset from=<old|-> to=<new>` and counts from 1; clearing appends `reset from=<old> to=-` before `allow reason=no-outstanding`. Decision lines `block item=<id> attempt=<n>` are unchanged. Unreadable, non-JSON, legacy integer, missing-key, negative, boolean or non-integer counters read as `("", 0)`. `n` is capped at GUARD_LIMIT+1. The docstring documents the trust boundary and the 90-minute wall-clock backstop.
- **IN-03** `make_variant.py` opens with `encoding="utf-8"` on read and write; `--check` prints `make_variant: check OK` in the default and the C locale.
- **Operator item 5** `26-SECURITY.md` approval line now ends `T-26-11 closed 2026-10-18 by f909f93 (26.1-02); no operator decision is pending.` (1 insertion, 1 deletion). `results/run1/rescore-26.1.txt` holds the acceptance output (rc=1: A1/A3/A9 FAIL, SEED VALID, RESULT FAIL) and the gapcount replay (NEW counts=[1, 2], GATE round-2 dispatch ALLOWED, CAP tripped=no, rc=0), labelled informational and not verdict input. `results/run1/acceptance.txt` is byte-unchanged.
