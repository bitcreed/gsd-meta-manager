## Inferred decisions (audit)

1. **Docstring ahead of code in Task 1.** The plan's Task 1 acceptance requires the docstring to name `l8` and `--block 26.1`; those features land in Task 2. The docstring was written complete in Task 1 (commit `f909f93`) and became true in `3b53276`; the usage line was updated in Task 2.
2. **SEED STALLED placement.** The stalled/crashed precondition sits after RECOGNISED and CONVERGED and immediately before the VALID test, so a parked or converged run is never reclassified; "parked or done" is read from I-01 `status state=parked|done` lines.
3. **WR-04 matching is exact-span, not substring.** A title or slug counts only when it equals the stripped content of a backticked, double-quoted (including YAML-escaped `\"`) or single-quoted span (apostrophes inside words do not open a span). Substring-in-span would re-admit prose, because the YAML-quoted `reason:` value is itself a long double-quoted span. Consequence: the committed run1 A8 reads `3/5 cases` instead of `3/7/7`; PASS is unchanged. `line N` references and the generic (non-drift) mode are untouched.
4. **L8-4 with no `launch-end` line is FAIL.** The plan says "last launch-end status is neither crashed nor stalled"; with no launch-end at all there is no observed exit status, so "not crashed" is not established. Flagged for 26.1-04's pre-registration text.
5. **L8-3 counts `dispatched` lines with an item other than RUN** (`ctx.dispatches()`, the same set A6 uses); L8-1 matches `block item=I-01` as a word-bounded token on any line of `stop-guard.log`; L8-2/L8-3 read the `dup_check:` line fields by name, so a field reorder does not matter.
6. **`--block` accepts only known names** (`26.1`); an unknown name or a missing value prints a usage message and exits 2, never an UNCHANGED.
7. **Unknown mode exit code.** `run_mode` returns rc 2 for an unknown mode (it used to return `ok=False`, exit 1), consistent with "nothing was decided".
8. **drift.py `start()` with a git failure** begins at generation 0 (`count_summaries(...) or 0`); only `poll()` treats None as "no change". The initial `w.poll()` in `cmd_watch` stays unwrapped so a startup fault is loud (run.sh's `WATCHER_ALIVE` from 26.1-03 observes it); only the repeating loop is shielded.
9. **Generation monotonicity uses `max(self.gen, min(n, MAX_GEN))`** on every count change, so even a real decrease in the summary count (not just a git failure) cannot rewind the feed; log lines and their format are unchanged.
10. **Two commits for Task 3** (dup_check and drift) so each WR fix has its own sha for the disposition record.
11. **Single commit per task for the `tdd="true"` tasks** (the tests are in-module `selftest`s in the same file as the code); `TDD_MODE` was not passed.
12. **VALID-02 precision edge (explicit).** Grouping uses drift.log's whole-second UTC while the launcher coalesces on float mtime; the 44 s / 45 s boundary is pinned on the acceptance side (`burst44`, `burst45`), and a disagreement with the launcher's count surfaces as A9 FAIL (ADJUST J2), never a silent pass.
