<objective>
The tracer: prove the whole duplex transport architecture end-to-end on one thin path before
any layer is built out, then make the NDJSON model tolerant enough to survive the CLI's patch
cadence (D-09).

Purpose: This phase touches six layers that have zero precedent in this codebase — grep
confirms no `tokio::select!`, no bounded channel, no internally-tagged serde enum, no piped
stdio, no long-lived child. Proving one command end-to-end first means an architectural
dead-end costs one commit instead of ten. Everything after this plan expands outward from
the slice this plan proves.

Output: `src/executor/` with its full type surface, a tolerant NDJSON model verified against
all eight golden transcripts, a transcript-replaying stand-in for `claude`, and one runnable
end-to-end test.
</objective>

      carried, a torn line is a real diagnostic (D-09).
    - `TurnOutcome`, `RunOutcome`, `RunState`, `InterruptAck`. `RunOutcome` gets the D-12

    - Spawn via process-wrap's `CommandWrap` with the process-group leader wrapper and the

      task awaiting process exit is a fourth and owns no pipe. Framing is

      emits a `LineTruncated` event and the run continues rather than failing. Reader tasks
      clone the sender and follow the established convention of breaking out when the send
      fails because the receiver was dropped.

      into `src/executor/gate.rs` to check that the observed `capabilities` array contains the

      tear the process group down and return a typed capability error. Because the prompt
      travels over stdin rather than as a positional argument, no turn ever begins before
      validation — that is what makes the refusal cost zero tokens. Plan 15-03 owns

      process exits. Do not break the reader loop on the first result envelope — that would
      truncate every run that ever uses `send` while reporting success.
    - Capture a `RunSnapshot` of the project immediately before spawn and again after the
      process exits, both from `spawn_blocking` because the fingerprint does full-tree file I/O

      (D-10, D-11, D-12). Fixing this four-argument signature now is what lets plan 15-05 fill
