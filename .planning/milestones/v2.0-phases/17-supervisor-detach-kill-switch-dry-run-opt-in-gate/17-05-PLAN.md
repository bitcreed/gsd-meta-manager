<objective>
CTRL-04: an autonomous run survives the TUI being closed, and the TUI reconciles live runs on
restart. This is ROADMAP success criterion #2 — *"Closing the TUI mid-run leaves the run going;
reopening the TUI shows that run still live with its current step."*

Three pieces, and the honesty of the third is as load-bearing as the mechanics of the first two:

1. **The detached spawn** (D-01, D-02). `tokio::process::Command` with `process_group(0)` applied
   through `as_std_mut()`, all three stdio handles null, `kill_on_drop(false)` written out
   explicitly because the default is load-bearing here — a clean TUI shutdown drops the `Child`,
   and an accidental `kill_on_drop(true)` would silently destroy the entire point of the phase —
   and a detached reaping task so a multi-hour run does not accumulate a zombie while the TUI is
   still its parent.
2. **The reconciliation** (D-10, D-12, D-13). A pid-plus-cmdline liveness probe reusing the `/proc`
   technique `session_detector.rs` already proves, a scan that performs **zero disk writes**, and
   attachment to the two existing scan points rather than a second timer.
3. **The wording** (D-11). Once the TUI exits, the child's stdout pipe is gone. Live re-streaming
   after a restart is impossible by construction and REQUIREMENTS lists it as out of scope for
   exactly that reason. The adopted state is **observed** — journal tail for history and current
   step, plus a kill handle — and it is not "reattached" and not "streaming". Code, docs and status
   text must not promise otherwise. Do not promise what physics forbids.

Also here, because this is where the enumeration already exists: D-18's concurrency cap. The scan
enumerates every live run across every registered project, so counting them at the spawn seam costs
almost nothing and hands Phase 20 a working cap instead of one to build.

Output: `src/driver/{liveness,reconcile,spawn}.rs`, the `observed_runs` sibling map, the two scan
attachment points, and the criterion-#2 proof.
</objective>

**`src/driver/liveness.rs`** — a new module with **no `cfg` guard**, declared in
`src/driver/mod.rs` outside the `#[cfg(unix)]` block. D-10 is explicit about the posture: match
`session_detector.rs`, which has no `cfg` guards at all — the `/proc` reads simply fail and yield
`None` off Linux — so the behaviour matches the module it copies rather than diverging. Say so in
the module doc, and document it as Linux-specific rather than `cfg`-gating it.

`fn cmdline_args(pid: u32) -> Option<Vec<Vec<u8>>>` — read `/proc/<pid>/cmdline`, split on NUL,
collect. This is `session_detector.rs:83-90` generalised by one step.

`pub fn is_run_alive(pid: u32, run_id: &str) -> bool` — the D-10 double-check, and **both halves
are required**:
- the process exists at all — `cmdline_args` returning `Some` with a non-empty first element is
  sufficient and needs no separate signal probe;
- `argv[0]`'s lossy string contains `gsd-meta-manager`;
- and a `windows(2)` scan over the argument list finds `--run-id` immediately followed by a value
  equal to `run_id`.
The doc must state why the cmdline half is not optional: pid reuse is real, the kernel recycles
pids, and a bare existence check against a recorded pid will eventually signal an unrelated process
— which in this phase means sending SIGTERM to a stranger's process group. This is the standard
defence and it is the same shape `read_session_id` already uses for `--resume`.

`pub fn process_state(pid: u32) -> Option<char>` — read `/proc/<pid>/stat` and return the state
character. Parse it the way `session_detector.rs:100-109` does: find the **last** `)` (the `comm`
field is parenthesised and may itself contain spaces and parentheses), skip two characters, then
`split_whitespace`, and take the first token's first character. Write the comm-field hazard in the
doc — a naive `split_whitespace` on the whole line is the classic bug here.

`pub fn is_zombie(pid: u32) -> bool` — `process_state(pid) == Some('Z')`. Its doc must state
exactly why it exists: `tests/executor_lifecycle.rs:92`'s `alive()` helper uses the zero signal,
which reports a **zombie as alive**, so ROADMAP success criterion #1's *"no zombie behind"* half
cannot be tested with it. Plan 17-06's kill test is the consumer. Do not extend or reuse `alive()`
for this.

Three unit tests, named in the artifact list. `a_live_pid_whose_cmdline_lacks_the_run_id_is_reported_dead`
spawns a real `sleep` child, asserts `is_run_alive(child_pid, "some-run-id")` is `false`, and
reaps it — that single assertion is the pid-reuse defence, and without it every other test here
passes on a version that only checks existence.

**`src/driver/reconcile.rs`** — a new module, no `cfg` guard, declared in `src/driver/mod.rs`.

Module doc: state D-12 as the module's governing rule, first line, in bold — **this module
performs zero disk writes**. Then the three things it must never do and why each is destructive:
it must not repair `run.json` (a third write breaks the exactly-twice contract the
`debug_assert_eq!` at `src/journal/mod.rs:636-639` enforces, and it destroys the evidence of how
the run died); it must not clear a stale `active` pointer (the pointer plus a missing `ended_at`
plus a dead pid *is* the crash record, and `read_active_run` already treats an inconsistent pointer
as ignorable at read time); and it must not prune (retention runs at run start, by design, because
an exit-time prune is skipped by exactly the crash this is reading). Add D-11's paragraph: the
verdict lives in memory and is surfaced; the disk stays as the driver left it; and the adopted
state is **observed**, not reattached and not streaming.

`RunVerdict { Live, CrashedWithoutEnding, Ended }` and
`ObservedRun { alias: String, run_id: String, pid: u32, pgid: u32, started_at: String, goal: String, gsd_command: String, live: bool }`

`fn read_run_facts(run_dir: &Path) -> Option<RunFacts>` — read `run.json` as a
`serde_json::Value`, **not** through `RunRecord`. Copy `has_end_timestamp`'s reasoning verbatim in
substance: a record written by a later schema must still be readable, and the only fields this
question needs are `ended_at`, `pid`, `pgid`, `started_at`, `goal` and `gsd_command`. A missing,
unreadable or unparseable record yields `None`, which the caller treats as "no observable run" —
never as "crashed", because an unreadable file is not evidence of a death.

`pub fn reconcile_one(alias: &str, project_root: &Path) -> Option<ObservedRun>`:
`writer::read_active_run(&project_root.join(".planning"))` for the run id; `read_run_facts` on that
run's directory; if `ended_at` is `Some`, the verdict is `Ended` and the function returns `None`
(there is no live run to observe); otherwise `live = liveness::is_run_alive(pid, run_id)` and the
verdict is `Live` or `CrashedWithoutEnding`. Return the `ObservedRun` in both of those cases — a
crashed run is exactly as worth surfacing as a live one.

`pub fn reconcile_all(projects: &HashMap<String, RegisteredProject>) -> Vec<ObservedRun>` — map

`pub fn spawn_detached(project_root: &Path, argv: &[OsString]) -> std::io::Result<u32>` — the

so one build and one version, and so the opt-in gate runs **in the child** where D-16 put it.
Then, and the comment on each of these is as load-bearing as the call:
- `.current_dir(project_root)` — the project root itself, never a worktree. D-21 resolved OQ4
  empirically and declined `--worktree` for five recorded reasons; cite the decision here because

- `.stdin(Stdio::null()).stdout(Stdio::null()).stderr(Stdio::null())` — all three. A detached child

- `.kill_on_drop(false)` — **written out explicitly**, with a comment saying the default is

- `cmd.as_std_mut().process_group(0)` via `std::os::unix::process::CommandExt` — the child becomes
  its own group leader, which is what makes `RunRecord.pgid == RunRecord.pid` true and what gives
  the kill switch a group to signal (D-01, D-04).

and reaped there, so both arms are covered.

Do **not** scrub `CLAUDE*` environment variables here: the child is this binary, not `claude`, and

the count itself.
