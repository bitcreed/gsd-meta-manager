<objective>
CTRL-02: a dry-run reports the GSD commands it would issue **plus** the diffstat and push refspecs
those commands would produce, and performs zero git writes.

This is one of the two deliverables the user personally made a hard requirement when they chose
full autonomy including `git push`, and PITFALLS is unusually blunt about the failure mode:
*"A dry-run that prints 'would run: /gsd:execute-phase' tells the user nothing about blast
radius"*, with *"the dry-run output does not include a refspec list"* listed as the warning sign.
A command log is not a dry-run. Three sections or it has not shipped.

Two honesty constraints shape what each section can actually say:

- **The command sequence is one command, and the output says so.** The decision router is Phase 20.
  In Phase 17 the sequence is the single `--command` argument, and that is the *complete and
  honest* sequence for this phase rather than a shortfall to paper over (D-22.1).
- **The diffstat is of the working tree, not of the run.** You cannot know the diff of a command
  you have not run. What is computable — and what the user actually wants to know — is the state
  the run would inherit and could commit: `git diff --stat HEAD` plus the untracked-file list,
  which answers *"if this run does `git add -A && git commit`, what goes in?"* (D-22.2).

Purpose: this section is the only place in v2.0 where a user sees blast radius **before** an
autonomous agent with push rights starts. Phase 19 enforces a policy over pushes; Phase 17 makes
the push visible. A refspec section that silently disappears is invisible to a smoke test, so its
shape is pinned by a test.

Output: `src/driver/dry_run.rs`, three new read-only helpers in `src/state_reader/git_ops.rs`, the
`--dry-run` branch in `drive()`, and the mechanical zero-write / zero-spawn proofs.
</objective>

Extend `src/state_reader/git_ops.rs` — do **not** start a second git wrapper. Follow the module's

`pub fn current_branch(project_root: &Path) -> Option<String>` — `git -C <root> symbolic-ref
--quiet --short HEAD`. `None` on a detached HEAD, an empty repository, or a non-repository. The
doc must say that `None` is a real answer here and not a failure: a detached HEAD genuinely has no
branch to push, and reporting it as "no refspec" is the honest preview.

`pub struct WorkingTreeStat { pub stat_lines: Vec<String>, pub untracked: Vec<String> }` and
`pub fn working_tree_stat(project_root: &Path) -> WorkingTreeStat`. Two reads:
`git -C <root> diff --stat HEAD` for the tracked delta, and
`git -C <root> ls-files --others --exclude-standard` for untracked files that are not gitignored.
Both are read-only. Keep them separate rather than merged, because `git diff --stat` does not list
untracked files at all and a preview that silently omitted them would under-report exactly the
files a fresh agent is most likely to have created. Both empty on a non-repository or an empty
repository — return an empty struct, never an error. Note in the doc why this is not folded into
the existing `GitDiffStat`: that type models a *parsed* numeric summary of a commit range for the
dashboard, while this one carries git's own rendered stat lines verbatim for a human-readable
preview; parsing and re-rendering them would only add a way to be wrong.

`pub struct PushPreview { pub remote: Option<String>, pub url: Option<String>, pub refspecs: Vec<String>, pub note: Option<String> }`
and `pub fn push_refspecs(project_root: &Path) -> PushPreview`. **Computed entirely from local git
config. Never invoke `git push` in any form, including `--dry-run`** — it contacts the network,
needs credentials, and makes the preview non-deterministic and untestable in CI. State that
prohibition in the function's doc as the first line, because it is the single most likely thing a
later reader will "improve".

The computation, in this order:
1. `current_branch`. `None` → `refspecs` empty, `note` set to a sentence naming detached HEAD as
   the reason. Return.
2. Remote: `git -C <root> config --get branch.<b>.remote`, falling back to
   `git -C <root> config --get remote.pushDefault`, falling back to `origin` **only if**
   `git -C <root> remote` lists it. If no remote can be resolved, `remote` is `None`, `refspecs`
   is empty, and `note` says no remote is configured and a push from this state would fail —
   which is the honest answer, not a gap.
3. URL: `git -C <root> remote get-url <r>`, carried verbatim into `url`. Do not normalise or
   rewrite it; the user needs to recognise their own remote.
4. Explicit refspecs: `git -C <root> config --get-all remote.<r>.push`. If any exist they are
   **authoritative** and are rendered as configured, one per entry; set `note` to say they came
   from `remote.<r>.push` and that `push.default` is therefore not consulted. Return.
5. Otherwise consult `git -C <root> config --get push.default`, defaulting to `simple` when unset
   (git's own default since 2.0 — say so in a comment so the default is not read as a guess), and
   branch:
   - `simple` — the upstream from `branch.<b>.merge` when it exists **and** its short name equals
     the local branch name, rendering `refs/heads/<b>:<merge-ref>`; when `branch.<b>.merge` is
     absent, render `refs/heads/<b>:refs/heads/<b>` and note that this is the central-workflow arm
     (same name on the remote); when an upstream exists but its short name **differs**, render no
     refspec and note that `simple` refuses this case, which is exactly the safety property the
     mode exists for.
   - `upstream` (and its `tracking` alias) — `refs/heads/<b>:<branch.<b>.merge>`, or no refspec
     plus a note when no upstream is configured.
   - `current` — `refs/heads/<b>:refs/heads/<b>`.
   - `matching` — enumerate `git -C <root> for-each-ref --format=%(refname:short) refs/heads` and
     emit `refs/heads/<x>:refs/heads/<x>` for each local branch that also exists under
     `refs/remotes/<r>/`; note that this mode pushes every matching branch, not only the current
     one, because that is the blast radius the user is being shown.
   - `nothing` — no refspecs, with a note.
   - anything else — no refspecs, with a note carrying the observed value verbatim, following the
     repository's forward-compatibility posture of carrying an unknown value rather than failing.

Every rendered refspec is a full `refs/heads/<src>:refs/heads/<dst>` line (or `<src>:<merge-ref>`
where the upstream ref is already fully qualified). Never a bare branch name — the whole point is
that the user can see the destination.

Five unit tests in this module's `#[cfg(test)] mod tests`, named in the artifact list, each
building a real temporary repository with `git init`, one commit, and the specific config keys
under test. Set config with `git -C <root> config <key> <value>` rather than writing `.git/config`
by hand. The `matching` and detached-HEAD cases each get their own repository shape.

occur" line. Every section prints *something* — that invariant is what makes the pinned-header test
meaningful.
