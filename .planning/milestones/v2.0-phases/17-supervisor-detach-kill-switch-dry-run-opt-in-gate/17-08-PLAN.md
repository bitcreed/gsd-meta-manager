## Decision surface

This is a gap-closure plan. Its decision source is `17-REVIEW.md`'s six CRITICAL findings, not a
fresh `17-CONTEXT.md` pass — but nothing here may contradict `17-CONTEXT.md`, and the decisions it
leans on hardest are D-04 (`pgid == pid` established, not assumed), D-05 (the platform limit is
named, never silent), D-06 (two process groups, two layers, reuse the existing teardown), D-08
(signals through `rustix`, never a hand-written negative pid), D-10 (pid **and** cmdline
double-check), D-12 (reconciliation writes nothing), D-16 (one gate, in the child), D-20 (the lock
is held for the run's duration) and D-27 (the sibling maps are cleaned on removal).

Three judgement calls this plan makes rather than asks about, because this run is unattended:

1. **`ObservedRun.live: bool` becomes `ObservedRun.liveness: Liveness`** (plus `is_live()`).
   A `bool` cannot carry the third state, and CR-05's requirement — *reconcile must not report
   `CrashedWithoutEnding` on `Unknown`* — is unreachable while the field is a `bool`. Rated
   **costly, not one-way**: it is a mechanical sweep of six call sites and is reversible by
   re-deriving the `bool`, but it does churn `src/app.rs` and `tests/driver_reattach.rs`.
2. **The startup stop performs its own explicit group teardown rather than trusting the
   Coordinator's cancellation path.** Dropping the `start` future does fire `cancel_tx` and the
   Coordinator does tear the agent group down — but that teardown is unobservable to `execute_run`
   and dies with the runtime the moment the driver process exits. Rated **reversible**.
3. **The startup teardown's SIGTERM→SIGKILL grace is 5s, not the 10s the drain-loop path uses.**
   During startup the agent is parked at its first `system/init`: there is no turn to abort, no
   Bash tree mid-command, and no `SessionEnd` chain worth ten seconds. Five seconds plus a two
   second reap plus two seconds of journal slack is nine, which fits inside the twelve-second
   `DRIVER_TEARDOWN_GRACE` the TUI gives the driver before it escalates. A unit test asserts the
   budget rather than a comment claiming it. Rated **reversible**.

No `checkpoint:` gate is emitted anywhere in this plan and no question is asked: this runs
unattended.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driven agent → `run.json` / `active` pointer | The record lives inside the project the autonomous agent is running in, with ordinary write access. Every field the TUI reads back from it crosses this boundary. |
| driven agent → its own process tree | The agent spawns Bash grandchildren in a process group of its own; the driver's group and the agent's group are different, and a signal to one does not reach the other. |
| user's TUI → detached driver process | The argv is the whole of the contract; the child's stdio is `/dev/null`, so anything omitted from the argv fails silently. |
| kernel `/proc` → liveness and kill decisions | The only source in this system the driven agent cannot write. Every safety decision that currently reads the record must read this instead. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-08-01 | Tampering | `kill::stop_run` signalling `run.json`'s `pgid` | critical | mitigate | Task 2: `resolve_signal_target` requires the recorded group to agree with `liveness::process_group(pid)` and signals the kernel-derived value; a disagreement or an unreadable group sends **no signal** and returns `SignalFailed` |
| T-17-08-02 | Denial of Service | `execute_run` swallowing SIGTERM during `Executor::start` | critical | mitigate | Task 4: `biased` `select!` with the terminate arm first over `start` and `close_input`, plus an explicit agent-group teardown budgeted inside `DRIVER_TEARDOWN_GRACE`; Task 5 proves it against three real processes |
| T-17-08-03 | Elevation of Privilege | `drive_argv` omitting `--config`, so the child resolves the alias from a different registry | high | mitigate | Task 6: the TUI's `ctx.config_path` is emitted before the subcommand, and the argv is parsed back through clap to prove the position is accepted |
| T-17-08-04 | Spoofing | A run whose `--run-id` is absent from argv, or written inline, is invisible to `liveness` — a stop answers already-gone while the agent runs on | high | mitigate | Task 1 matches the inline spelling; Task 3 refuses a real run with no `run_id` before anything is created |
| T-17-08-05 | Repudiation | A stop during startup leaving no `ended_at`, so a deliberate stop is permanently recorded as a crash | medium | mitigate | Task 4 journals the `terminate_signal_shutdown` diagnostic and finishes with the `killed` outcome on the startup path; Task 5 asserts both on disk |
| T-17-08-06 | Tampering | Unregistering a project abandons a live agent with git and push rights and no stop path | high | mitigate | Task 7: `do_remove_project` refuses unless the observed run's liveness is `Dead`, naming the `x` key |
| T-17-08-07 | Information Disclosure | An undeterminable liveness rendered to the user as "already finished; nothing was signalled" | medium | mitigate | Tasks 1–2: `Liveness::Unknown` propagates into `SignalFailed` and `RunVerdict::LivenessUnknown`; Task 3 refuses to start a real run there at all |
| T-17-08-08 | Tampering | A truncated or zero `pid`/`pgid` reaching `signal_group` — group 0 is the caller's own group, i.e. the user's terminal session | high | mitigate | Task 2 clamps `read_run_facts` to reject absent, zero and out-of-range values, yielding no observable run; `signal_group`'s existing group-zero refusal remains the backstop |
| T-17-08-SC | Tampering | npm/pip/cargo installs | high | accept | **This plan performs no package-manager install and adds no dependency.** `Cargo.toml` and `Cargo.lock` are outside `files_modified`, and Task 8 asserts their diff is empty. No `[ASSUMED]`/`[SUS]` package exists to gate on |
