<objective>
Close the phase: give the dashboard the minimum surface that makes this phase's capability
reachable by a human, fold in the two Phase 16 carry-forwards whose natural home is this phase's
retention and reattach work, and run the phase gate.

**The UI surface is deliberately tiny and the fence is explicit.** Phase 18 owns the Driver tab and
every rendered driver surface — the live stream widget, the dashboard badges, the injection UI, the
rich opt-in disclosure flow — and the ROADMAP says so twice. What Phase 17 needs to reach its own
success criteria from the TUI is three keys and one confirmation, reusing the existing
status-message and confirmation idioms rather than introducing a widget (D-25, D-26). A plan that
grows a screen here has taken Phase 18's work.

**The carry-forwards are retention and reattach bugs, which is this phase's territory.**
`journal_cursors` is keyed `(alias, run_id)`, inserted in one place and removed in none — it grows
unbounded for the process lifetime, and `registry::remove_project` touches neither it nor
`run_states` (D-27). And `seq_gaps` only compares within one batch while `ReadDiagnostics.last_seq`
is returned and never stored, so a gap straddling two tail reads is invisible — during a
multi-hour run, which is when it matters (D-28).

**The gate.** Five ROADMAP success criteria, five requirement ids, the clippy delta, and a sweep
for the debt markers Phase 16's verification checked for.

Output: `src/ui/screens/driver_confirm.rs`, three key bindings, the pruning, the widened cursor, and
a traceability table naming the test that evidences each criterion.

`impl Screen`:
- `handle_key` — `y` performs the action and pops; `n` or `Esc` sets `needs_redraw` and pops;

**D-28 first**, because it changes a type `app.rs` depends on.

**`src/journal/reader.rs`** — add
`pub struct JournalCursor { pub cursor: TailCursor, pub last_seq: u64 }` deriving
`Debug, Default, Clone, Copy, PartialEq, Eq`. **`Copy` is load-bearing**: `src/app.rs:287` calls
`.copied()` on the map lookup, and a non-`Copy` value changes that call site. Put that sentence in
the type's doc, citing PATTERNS note 4, so nobody adds a `String` field later without noticing.

Add `pub fn seq_gaps_from(prev_last_seq: u64, records: &[JournalRecord]) -> Vec<(u64, u64)>` — when
`prev_last_seq` is non-zero and the first record's `seq` is not `prev_last_seq + 1`, that boundary
pair is the first gap; then the existing within-batch `windows(2)` comparison supplies the rest.
Implement `seq_gaps` in terms of it (`seq_gaps(records) == seq_gaps_from(0, records)`) rather than
keeping two copies of the filter — one function, one behaviour. The doc states the bug this closes:
`seq_gaps` only ever compared within one batch and `ReadDiagnostics.last_seq` was returned but never
stored, so a gap straddling two tail reads was invisible — which is precisely the situation a
multi-hour run produces, and precisely when a lost event matters.

Add the three unit tests named in the artifact list. `the_journal_cursor_is_copy` is a one-line
compile-time assertion (bind the value twice) whose only job is to fail loudly if `Copy` is dropped.

**`src/app.rs`** — three changes.

(a) Retype `AppContext.journal_cursors` to
`HashMap<(String, String), crate::journal::reader::JournalCursor>` (the field lives in
`src/ui/screens/mod.rs`; edit it there and update its doc's bullet list to mention the seq the value
now carries and why). In `schedule_journal_tail`, keep the `.copied()` — the new type is `Copy` —
carry `last_seq` into the blocking task alongside the byte cursor, and on the way back build the
new `JournalCursor` from `read.cursor` and the last record's `seq` (retaining the previous

  otherwise reach for `run.json` timestamps.
Its doc states the leak it closes: the map is keyed `(alias, run_id)`, inserted in exactly one
place and removed in none, so it grows for the process lifetime; and retention aligns to
`RETAIN_RUNS` so the in-memory bound matches the on-disk one rather than being a second unrelated
number.
