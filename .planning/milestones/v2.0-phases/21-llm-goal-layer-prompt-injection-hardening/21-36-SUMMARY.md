# Phase 21 Plan 36: The Round-Trip Claim Made Total Summary

**The 28-fixture round-trip corpus is replaced by a total two-branch property over a seeded 4096-case byte-string generator with a committed non-vacuity floor, and the parser is changed narrowly so the property is true: wire bytes returned untrimmed, ill-formed UTF-8 refused instead of fabricated.**

## Accomplishments

- **The claim became falsifiable.** Round 12's headline — *what this build emits, this build can read back, byte-identically* — was false as shipped and its corpus was structurally incapable of saying so. It is now a disjunction with exactly two NAMED branches: byte-identical round trip, **or** `None` with the input in R1 (`std::str::from_utf8` fails) or R2 (valid UTF-8, empty after `trim`). Both directions fail loudly. There is no third outcome.
- **The certifying input space is generated, not enumerated.** `generated_session_id_bytes(GENERATOR_SEED, GENERATOR_CASES)` produces 4096 `Vec<u8>` from a fixed-seed xorshift64* over a five-arm mixture (`uniform` / `padded` / `prefixed` / `seed` / `ascii`). The 28 fixtures are RETAINED and consumed by the `seed` arm; everything that read them before still does.
- **The generator's reach is a committed floor that has been observed RED.** Six class minima plus three branch counters, each its own `assert!` so the first failure names the class.
- **The harness is byte-typed.** `nul_join_cmdline` takes `&[&[u8]]`. G3 was never a missing fixture — it was a class a `&str` harness could not construct, while `session_id_in_cmdline` has taken `&[u8]` all along.
- **The parser stopped rewriting and stopped fabricating.** Two expressions in one candidate branch. Signature unchanged, no value rule added.
- **Zero new dependencies.** `Cargo.toml` / `Cargo.lock` diff is empty.

**3. [Rule 1 - Bug] U+2028 is three UTF-8 bytes, not two**

- **Found during:** Task 1(b)
- **Issue:** The plan's generator spec says the `padded` arm draws from *"the two-byte UTF-8 encodings of U+00A0 and U+2028"*. U+00A0 is indeed two bytes (`C2 A0`); **U+2028 LINE SEPARATOR is three** (`E2 80 A8`). Spelling it as two bytes would have emitted a truncated, ill-formed sequence — which would have silently reclassified those cases from the G1 (padded) class into the R1 (ill-formed) class, weakening exactly the floor this round exists to establish.
- **Fix:** Both are spelled with their correct byte sequences in `GENERATED_WHITESPACE_UNITS`, as `b"\xc2\xa0"` and `b"\xe2\x80\xa8"`, with the arity difference called out in the constant's doc. Both carry Unicode `White_Space=yes`, which is the property `char::is_whitespace` and therefore `str::trim` are defined over, so both genuinely belong to the class the G1 floor counts.
- **Files modified:** `src/ui/screens/detail.rs`
- **Verification:** the padded floor measures 507 (floor 20); the whitespace-only floor measures 30 (floor 5)
- **Committed in:** `8c68c0a`
