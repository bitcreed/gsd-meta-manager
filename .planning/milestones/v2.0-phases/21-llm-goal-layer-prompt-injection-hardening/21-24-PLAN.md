<objective>
**Round 9, wave 2. The error and lookup layers, closed by the SAME carrier wave 1 built —
so CR-01 and CR-02 arrive as consequences rather than as two more patches.**

Round 8's central insight is written at `src/registry.rs:65-71` and it is correct: *"One
producer beats three consumers, and beats a list of three consumers that will be four next
round."* Round 8 applied it to `impl Display for AliasRefusal` and stopped. This plan applies
it to the two sibling error types that carry the same values on the same commands, and to the
lookup key whose SUCCESS echo `LegacyRegistryKey` was built for while its FAILURE echo, one
line above, was never asked about.

**The mechanism is not a new mechanism.** It is `crate::text::Untrusted` from 21-23, applied to
seven error fields and one function signature:

| What changes type | Where | What falls out |
|---|---|---|
| `OptInError::{UnknownAlias, NotOptedIn, RootUnusable, PromptInputsDrifted}.alias` | `src/error.rs:283-323` | `impl Display for OptInError` stops compiling until every interpolation is `shown()`, so `main.rs:256`, `:263`, `:310`, `:334` become correct without appearing in the diff — **CR-02** |
| `DriveError::AliasNotVisible.alias`, `RunIdInvalid.run_id`, `TargetPhaseInvalid.target_phase` | `src/error.rs:501-563` | the `{x:?}` route stops depending on `core::char::is_printable`, the unpinned std table `registry.rs:88-96` already condemned as a second spelling |
| `remove_project(config, alias: &str)` → `(config, key: &LegacyRegistryKey)` | `src/registry.rs:618` | `bail!("Project not found: {}", alias)` becomes unwritable — **CR-01** |

**Two corrections to the source artifacts, made by measuring rather than by reading.**

1. **The type the round-8 review calls `DriverError` does not exist in this tree.**
   `rtk proxy grep -rn "DriverError" src/ tests/` returns nothing. The four alias-carrying
   variants CR-02 quotes belong to **`OptInError`** (`src/error.rs:283-350`). The finding is
   real and reproduces exactly as described; only the name is wrong, and a plan that
   propagated the wrong name would send an executor looking for a type that is not there.

2. **The review's proposed WR-01 one-liner is wrong as written.**
   `display_identity(&crate::ui::screens::sanitize_render_line(value))` truncates to
   `DRIVER_OUTPUT_LINE_CELLS = 512` and appends `…`, because `sanitize_render_line` is a
   *display-capped* helper for agent prose. Hoisting it into a general escaping helper would
   silently cap every CLI echo and every error message. 21-23 separated the class from the cap;
   this plan uses `text::render_for_terminal`, which is the class without the cap, and that is
   why WR-01's fix lands here rather than in the review's shape.

**What does NOT fall out, named rather than smuggled in.** `registry::record_opt_in` and
`registry::clear_opt_in` carry the same `bail!` sentence and cannot be retyped in this wave:
they have 13 callers across four plans' files, three of which this plan is forbidden to touch.
They reach the same escape through the **one producer** (`registry::project_not_found`) by
constructing the carrier locally at the `bail!` site. That is a smaller lever than a signature
and it is stated as one: it protects the message, not the parameter, so a future caller that
formats the alias itself is not caught. **Direction: under-protection, silent. What bounds it:
the alias reaching those two functions has already passed `Alias::new` at every production
path except the legacy rows, and the legacy rows are what the escape is for.**

## Assumption delta — this plan IMPLEMENTS the promote

The full decision is recorded in `21-23-PLAN.md`. Restated here in one line because this is the
plan that executes its second half:

- **Noun now primary:** `crate::text::Untrusted` — a string this build did not author.
- **Decision:** `promote`. `registry::LegacyRegistryKey` is demoted to *the argv-lookup variant
  of `Untrusted`*: a thin wrapper whose two purpose-named accessors delegate, so `main.rs`'s
  call sites and D-17-3's accept/echo split read exactly as they do today while the carrier's
  certified absent conversions are inherited rather than re-asserted.
- **Rationale:** adding a second carrier alongside a general one silently contradicts the
  generalisation, and that is the round-8 failure mode this round exists to end.
- **Not accepted debt:** the promote is completed here, so there is nothing to force later.
  What remains as accepted debt is the SIX carrier types 21-23's objective table names as
  uncovered, and that debt is 21-25's and 21-26's to state, not this plan's to widen.
</assumption_delta_decision>
