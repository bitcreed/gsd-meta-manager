# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: `rtk` filters cargo/grep output — a presence/count check through the rtk-rewritten path can read `0` (symbol deleted) when the real answer is `1` (present). This has produced a false negative three times in this phase. Every count- or presence-bearing check MUST use `rtk proxy <cmd>`, never the hook-rewritten form.
- [ ] CONSTRAINT: Independent code review and `gsd-verifier` MUST run as separate agents from the executor, never the same agent or a shared context. That separation has caught a real defect in every one of the six previous gap-closure cycles in this phase; collapsing it is how six of seven verification passes went `gaps_found`.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Enumeration moved down a level instead of being closed | Six rounds running: an invisible/injection-character defect gets fixed by hand-enumerating the *next* level down (arms → fields → character class) while the fixture sampling never moves off what the implementation already covers. Pass 6 declared criterion 1 verified this way; pass 7 showed it was never true — a character outside the 22-point hand list (U+202E, U+00AD, U+E0041, U+FE0F) passed every seam. | blocking | Round 7 is designed to end this by deriving the class from `icu_properties` with no literal range surviving, and oracling the exhaustive fixture from an *independent* crate (`unicode-properties`) so implementation and falsifier share no source. Any future round that "fixes" this domain by adding literals to a list rather than proving non-enumerability is repeating the exact failure this handoff exists to stop. |
| Certifying a claim with prose instead of a planted-defect control | Guard docs and limits blocks have repeatedly claimed a bound (e.g. "tree-wide coverage") that no committed control actually goes red for. This is named explicitly as "the fifth consecutive round's defect" in 21-20-PLAN.md's own prohibitions. | blocking | Every claim about what a scan/guard reports must be certified by a planted-defect control committed red-first against the unfixed scanner, exercising the same extracted fn the live assertion consumes. Where a scan cannot deliver a bound, the residual must be named in prose WITH its failure direction — not silently claimed as covered. |
| Zero-width/bidi characters as an editing hazard | An agent was killed mid-session fighting a literal invisible/bidi character pasted into an Edit call. | advisory | Keep all escapes as literal `\u{...}` text in source and prompts; never paste a raw invisible or bidi character into a file. |
| Batched commits under quota risk | Three executor agents were killed mid-run by API quota limits in this phase. The one that batched all task commits to the end lost everything; the ones that committed incrementally lost almost nothing. | advisory | Executors must commit each task the moment it goes green, not batch to end-of-plan. |
| `REQUIREMENTS.md` flipped to Complete by an executor | Happened twice in this phase, both reverted (`828d7cc`, `0c4f712`). Clean for four rounds since. | advisory | Executors in this phase do not own `REQUIREMENTS.md` completion state; leave it for the phase-close step. |

<context>

LLM goal layer lets a user state a goal once and have GSD commands driven to completion
without further input, with the model confined to two narrow seams. Phase 21 is the
security-hardening half of that — refusing prompt injection from untrusted `.planning:`/
`CLAUDE.md` content, capping model escalations, and refusing any command outside a fixed
enum.

round-8 proposal that looks like "add these code points to the list" as a signal the
