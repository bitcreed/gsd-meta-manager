back to disk while reading a string that is not what it appears to be.

**This is not an unescaped render. It is an escape that exists and is laundered by a round
trip through an untyped buffer.** Escaping only at the second render would fix this field and
leave the mechanism intact for the next one. So the buffer gets a type: `EditBuffer`,
wrapping `crate::text::Untrusted`, with the operations an edit surface needs and nothing that
re-opens the raw path. `Span::styled(buffer.clone(), ..)` stops compiling.

**And the one thing this fix could make worse, closed in the same commit.** The escape is for
READING. What the operator types must be what gets PERSISTED — a `U+XXXX` spelling reaching
`.planning/config.json` would silently rewrite the user's config with a rendering of itself,
which is worse than the defect and would pass every escaping assertion in the tree.
`EditBuffer` has exactly one raw take, deliberately named, and a round-trip test asserts
byte-identity.

**Then the two mechanism defects that cannot fall out of a carrier.** WR-02: the sealed doc
claims the macro is the only in-crate route and that this keeps the vocabulary to two
constants. A hand-written in-crate impl can skip the macro, so the vocabulary claim is false.
It is made TRUE by a crate-private two-variant enum — a third value stops being expressible —

refuted panic claim, WR-04 recorded as already closed by a commit that landed after the
