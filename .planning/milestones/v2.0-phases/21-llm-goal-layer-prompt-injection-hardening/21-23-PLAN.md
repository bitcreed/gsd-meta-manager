**Round 9, wave 1. The tracer, and the whole round's premise: make an unescaped untrusted
string UNRENDERABLE, so the render defects fall out as consequences instead of as a ninth
list of sites.**

Eight rounds show that site-sweeping does not converge and that type-level inversion does.
Identities were closed permanently in round 7 when the plan stopped enumerating bad
characters and made a bad identity *unconstructable*. The display surface is still being
fixed the old way: round 8 escaped the sites it could see, and the round-8 review found four
more classes of site it could not.

**What is being inverted, stated with the constraint that shapes it.** `Span::raw` takes
`Into<Cow<'_, str>>` and `String: Into<Cow<'_, str>>` is a standard-library impl this project
cannot un-implement. There is therefore no way to forbid the raw sink globally, and any plan
that claims to have done so is lying. The inversion has to live in the **carriers** — the
types that hold text this build did not author — and in their accessors:

- `crate::text::Untrusted` holds the string and implements **no** `Display`, `AsRef<str>`,
  `Deref`, `Borrow<str>` or `Into<Cow<'_, str>>`. It cannot be interpolated, coerced, or
  passed to any ratatui sink. It has two accessors, named after the two questions:
  `as_raw_for_logic_only()` and `shown() -> Rendered`.
- `crate::text::Rendered` is the escaped result, and it is the **only** string type in this
  tree that is both escaped and `Into<Cow<'static, str>>`. So at a render site the escaped
  path is the short one and the raw path is a deliberate choice a reviewer sees in a diff.

**The measured reach of this lever, and what it does NOT cover.** Re-measured at HEAD
`dfa11c6` under `rtk proxy`: there are **129** `Span::raw` and **198** `Span::styled` calls in
`src/`, and **502** sink calls of all spellings under `src/ui/`. **The lever gates none of
them** — it cannot, for the reason above. What it gates is the *carriers*, and the round-9
set is **21 fields across 9 of the 15 carrier types this tree has** (wave 1 takes

## Assumption delta — the noun changed, and the response is PROMOTE

**Signal:** `pluralization` — the deterministic scan fired on this phase's scope, and it is
load-bearing rather than incidental.

**The noun that is now primary:** `crate::text::Untrusted` — *a string this build did not
author*, wherever it came from: a third-party git repository's commit subject, a
`.planning/` file's contents, a `config.json` registry key an older build accepted, an argv
value echoed back in a refusal.

**The noun it generalises:** `registry::LegacyRegistryKey` — *a registry key an older build
accepted, on its way to being removed*. Round 8 built exactly the right shape (no `Display`,
two accessors named after the questions they answer) and then applied it to **one call site**.

**Decision: `promote`.** `Untrusted` becomes the primary representation and
`LegacyRegistryKey` is demoted to *the argv-lookup variant of it* — plan 21-24 makes it a thin
wrapper whose accessors delegate, keeping its two purpose-named methods and its doc so
`main.rs`'s call sites and D-17-3's accept/echo split read exactly as they do today. Nothing
about removal's raw acceptance changes.

**Rationale (one line):** adding a second carrier alongside a general one silently contradicts
the generalisation, and that *is* the round-8 failure mode — a correct mechanism applied to the
one instance the round happened to be looking at, while its siblings kept the old shape.

**What is explicitly NOT promoted, so this is a decision rather than a drift:** the six carrier
types in the objective's table keep bare `String` fields for the measured reasons given there.
That is accepted debt with a named direction (under-protection, silent) and the thing that
would force a later promote is a verification pass finding a raw render through any of them
that the census + probe did not catch — because that would prove the sampling control
insufficient, which is the only argument left for paying `ProjectState`'s 135-mention cost.
</assumption_delta_decision>
