<objective>
Give the model seam a budget that can actually bind, a refusal vocabulary that a later reader can
grep, and a cap whose boundary is checked against the number the run is really running under.

Purpose: DRIVE-04 requires a per-run cap on model escalations. A cap is only a control if it can
be exceeded, if exceeding it changes what the run does, and if the unit it counts is pinned.
Phase 20's code review found a Critical hiding behind a guard that compared two constants instead
of the resolved value — this plan is where that hazard recurs, and it is written to be caught.

Output: `src/driver/escalate.rs` as the fifth sibling taxonomy, the fifth row of the journal's
park-reason table in the same commit, `--max-escalations` on argv refused at the seam, and a
named outcome arm for the CLI's structured-output retry exhaustion.
</objective>

Create `src/driver/escalate.rs` and declare it from `src/driver/mod.rs`.

Write the module doc in `rate_limit.rs`'s register. It must state that the module performs no I/O
and reads no clock — the caller retains what it retains and hands in what it judges against — and
it must declare itself a **fifth sibling taxonomy**, naming all four existing siblings
(the envelope's park reasons, the router's reasons, the bounds' reasons, the quota reason) and
the axis that makes it a sibling rather than a fifth arm of any of them: the four bounds are
facts about whether the run is making progress, while an escalation count is a fact about how
much the model was consulted. A run can burn its whole escalation budget while making excellent
progress, and a stalled run can burn none. They answer different questions and want different
prefixes. Also state that the payload it classifies is untrusted input, arriving from a process
that itself consumed untrusted repository content — so tolerant parsing throughout, no strict
unknown-field rejection, no panicking accessor, no `unwrap` on a wire field.

Declare `EscalationReason` in the shape all four siblings use: one `pub const REASON_*: &str` per
arm with the `escalation_` prefix, a `#[derive(Debug, Clone, Copy, PartialEq, Eq)]` enum, and an
`as_str` with one arm per variant and **no wildcard**, so a new condition is a compile error here
rather than a park that borrows somebody else's reason string. Three arms:

- the per-run cap was reached, so the run parks rather than continuing rules-only;
- the model named an action outside `router::SAFE_COMMAND_ALPHABET`;
- the seam produced no usable output — absent structured payload, malformed payload, or the CLI's
  own structured-output retry exhaustion.

The named-but-refused action is carried on the reason's detail. Follow the `QuotaWindow::Unknown`
distinction: "the wire named something we do not recognise" and "there was nothing to name" are
different states and must not collapse into one. The type carries the observed string whole; only
the rendering into a journal line is bounded and control-character-stripped, through
`untrusted::MAX_UNTRUSTED_FIELD_CHARS`. Never construct a command line, a shell string or a
pasteable preview from it — `router::command_for` is private and its doc records WR-09 as the
reason.

Declare the budget type and its resolution, mirroring `bounds::resolve` exactly: a pure function
taking the caller-supplied cap as an `Option<u32>` and the **resolved** step cap as a plain `u32`,
returning either the budget or a refusal enum, one variant per refused shape, each mapping to one
typed `DriveError` variant at the seam. Refuse a cap of zero — a seam that can never fire while
still looking configured, the same failure `bounds::resolve` refuses for a zero step cap. Refuse a
cap greater than or equal to the resolved step cap, with the refusal naming **both** numbers and
saying what to do about it, because an error a caller cannot act on is a bug report rather than an
error message. Copy the `MAX_WALL_CLOCK_CAP_SECS` justification for why the ceiling belongs in the
parser: it is what makes "there is no disablement" a property of the parser rather than of the
caller's restraint. Default the cap to 3 — goal decomposition plus two genuine ambiguities — and
say so in the constant's doc.

Declare the counter as part of the budget: a `u32` that increments per consultation and saturates
rather than wrapping, plus a permission check the caller consults **before** a consultation, never
after. Write the tie-breaking contract in the doc as a sentence a test can be written from: a run
with cap N performs at most N consultations, and the consultation that would be number N+1 does
not happen. Checking after the fact would make the cap describe a consultation that already
occurred.

Then edit `src/journal/mod.rs`'s `JournalEvent::Parked` reason doc **in this same task and this
same commit**. Three things change together: the word "Four" becomes "Five"; a new table row names

taxonomy rather than a fifth bounds arm, for the axis reason above); and "All four reach a
terminal record" becomes "All five". The table's own text says naming only some of them would be
the same quiet lie the record exists to prevent, so shipping the taxonomy without the row is a
documented lie rather than an oversight.
