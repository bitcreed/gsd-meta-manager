<objective>
Close CR-01 and verification pass 8's two render warnings by **deriving** the render surface
instead of naming it an eighth time.

Seven rounds each closed one enumeration level while the sampling stayed inside the
implementation's own coverage. Round 7 broke that twice — the character class was derived from
`icu_properties`, and identity was inverted to an allow-list. The reviewer's verdict is that it
is **not** broken for the render/display surface: the escaping mechanism (`display_identity`,
`src/text.rs:259`) is correct, but *where to apply it* was hand-named, and one of the three
named sites is in a file the module tree does not contain.

**This plan's whole content is the answer to one question: what performs the enumeration?**
Three mechanisms, each with its reach measured rather than assumed:

- **The compiler**, for values carrying the identity type. Withdrawing `impl Display for Alias`
  (`src/registry.rs:168`) turns every interpolation into a compile error that must be resolved
  deliberately to escaped-render or to an unattractively-named raw accessor. **Measured by
  planting the withdrawal and reverting it: exactly FOUR sites** — `src/registry.rs:640`,
  `src/main.rs:103`, `:111`, `:371`. That is the whole reach, and it is small, and saying so is
  the point: it does **not** catch `Removed project '{}'` (`src/main.rs:128`, whose arm binds the
  raw argv `String` and never an `Alias`) nor the two `eprintln!` refusal echoes.
- **The one producer**, for refusals. `AliasRefusal`'s own `Display` embeds the raw alias; making
  it escape there closes `src/main.rs:91` and `:359` *and every future refusal echo* without
  naming any of them. Verification pass 8 predicted this would fall out of the derivation; it
  does, and this plan proves it rather than patching the two by hand.
- **A source-derived, deny-by-default census over the `Screen` trait**, for the TUI, where no
  identity type reaches at all (`AppContext::filtered_aliases` is `Vec<String>`;
  `DeleteConfirmScreen::alias` is `String`). A recursive `read_dir` walk of `src/` collects every
  `impl Screen for` — eleven at HEAD — and asserts that derived set equal, both ways, to a
  disposition table. **A twelfth screen added tomorrow in a file this plan never touches is an
  unadjudicated implementor and goes red with nobody editing a list.** For every implementor
  adjudicated as rendering identity, a probe renders it through the real `Screen::render` and
  inspects the resulting `Buffer` — behavioural, so blind to no sink spelling.

**Why not a type-level derivation for the TUI, stated with its measurement.** Propagating the
identity type into `AppContext::filtered_aliases` was measured, by planting a no-`Display`
newtype and reverting: **25 direct compile errors** across `app.rs`, `screens/mod.rs`,
`normal.rs` and `add_project.rs`, plus an unbounded cascade through `selected_alias` (19
mentions) and every screen's `alias` field. It is the right long-term shape and it is named as
such in the SUMMARY's deferred list — but it is a mechanical retype of the whole UI layer, and
this round must be tight. The `Screen` census reaches the same sites at a granularity of
**eleven** rather than **seven hundred and sixty-two**, behaviourally, and it catches the
non-alias identities (workspace names, phase names, file names, entry names — all read from
`.planning/`, all untrusted under SAFE-07) that a type on `Alias` alone would never have reached.

**And one inherited claim that turns out to be wrong, measured with a scratch probe.** ratatui
0.30's `Buffer` **drops zero-width graphemes**: rendering `gsd-\u{202e}nur` yields buffer text
`gsd-nur`, with U+202E, U+200B and U+00AD absent — while **U+E0041 survives intact**. The TUI
therefore does not reorder; it silently *deletes*, so a legacy key renders as a different string
that can collide with a real project of that name, and the tag block is the one class reaching
the terminal whole. Both are closed by the same escaping. But a probe asserting the raw bidi
character is present in the buffer would be **false**, and a probe asserting a reorder would be
**vacuous** — which is why this plan's probe asserts the **escaped** form with the clean twin
proving arrival. Neither round 7's review nor verification pass 8 made this measurement.
</objective>
