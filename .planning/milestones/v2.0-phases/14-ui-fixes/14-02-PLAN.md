## Claude's Discretion (auto) — decisions taken without asking

**CD-01 — viewport metrics live on `DetailScreen` in a `Cell`, not on `ProjectViewCache`.**
The UI-SPEC's mechanism note assumes the render pass can write `total_lines` and `visible_height`
into `ProjectViewCache`. It cannot as written: `Screen::render` takes `&self` and `&AppContext`
(both immutable), so no render path can mutate the cache. The three options were (a) change the
`Screen::render` trait signature to `&mut AppContext`, which rewrites all eight screen impls and
their sub-renderers; (b) recompute both metrics in the key handler, which is impossible for
`visible_height` because the handler has no `Rect`; (c) interior mutability. Option (c) is chosen:
two `Cell<ViewportMetrics>` fields on `DetailScreen`, set by the two file-view render arms and read
by the four scroll arms. This is safe here because `App` already holds `Vec<Box<dyn Screen>>`, so it
is already neither `Send` nor `Sync` — a `Cell` changes no auto-trait bound. It also confines the
change to one file. Viewport height is a property of the terminal, not of a project, so
`DetailScreen` (one per open detail view) is the more accurate owner than the per-project cache.

**CD-02 — no `test_ctx()` AppContext helper is built.** PATTERNS.md offered copying the 18-field
`AppContext` construction from `src/app.rs:126-147` into a test helper, with a pure-function
extraction as an escape hatch. The escape hatch is taken as the primary approach: `browse_edit_target`,
`footer_spans` and `clamp_scroll` are all pure and cover every UI-SPEC row for both requirements
with zero `AppContext` construction and zero new test patterns. The key-routing wiring itself is
covered by a source assertion in the acceptance criteria.

**CD-03 — the generic `_ =>` scroll fallback is NOT clamped.** The UI-SPEC marks it "optional and
encouraged" but adds "must not expand the phase if the viewport plumbing for those tabs proves
invasive". It is invasive: each non-file tab computes its content differently, so a correct
`total_lines` would need per-tab plumbing across seven render arms. The four file-view sites named
in the UI-SPEC root-cause table are fixed; the fallback is left for a follow-up. Recorded so the
omission is a decision, not a miss.

**CD-04 — the root fence reuses shipped copy.** Prohibition enforcement (a path outside the browse
root is not editable) reports the existing `Select a markdown file to edit` message rather than
inventing a third guard string, honoring the UI-SPEC Copywriting Contract's "no new user-facing
strings except two" rule.
