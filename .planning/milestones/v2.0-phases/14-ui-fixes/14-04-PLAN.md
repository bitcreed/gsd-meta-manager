## Decisions taken by this plan (autonomous run — no human was available)

**GD-01 — CD-03 / IN-07 is CLOSED in this plan, not deferred again.** The gap-closure brief asked
whether the generic `_ =>` scroll fallback is the same defect class as gap 2. It is, and CD-03's
original rationale was factually wrong about its cost. CD-03 stated the fallback covers "seven
non-file tabs" needing "per-tab plumbing across seven render arms". Direct source reading at plan
time shows the `_ =>` arm is reached by exactly **two** sub-views — `PhaseList` and `RoadmapViz`; the
other eight sub-views all have explicit match arms. Those two tabs have exactly **two** render sites
(`render_phase_list` and `render_roadmap`), and **both already compute a content height and a
viewport height for their existing display-only clamp**. So the fix is the same shape as gap 2 — one
more `Cell<ViewportMetrics>`, two recording lines, four handler clamps — not a seven-arm refactor.
Closing it here is cheaper than carrying it, and it removes the dead-key symptom from the two tabs a
user lands on first. Recorded as a correction of CD-03, not a reversal of a sound decision.

**GD-02 — the `<60` width tier is deliberately NOT given a floor.** Measured: it already holds all
five stages from width 44 up. Adding `Constraint::Min(13)` there would fix widths 17-43 but starve
the Alias column to 2-3 characters, trading a clipped status for a clipped project name. Terminals
narrower than 44 columns are outside any realistic use of this dashboard, and the gap brief scopes
the fix to the `>=80` and `>=60` tiers. Recorded so the sub-44 behavior is a known, decided fact
rather than an unexamined hole. Follow-up material, not this plan's work.

**GD-03 — `REQUIREMENTS.md` is NOT touched by this plan.** UIFIX-02 and UIFIX-04 are currently marked
`Gaps Found` in the traceability table. Flipping them belongs to the re-verification pass that runs
after this plan executes and independently confirms the gaps closed — a plan marking its own
requirements complete is precisely how the previous round produced a false green.

**GD-04 — the fix is a layout floor, not a cell rewrite.** `compact_pipeline` is correct as shipped
(13 cells, no leading blank, verified passing). Do not touch it. The defect lives entirely in the
column that holds it.

stored offset is stale-high. Subtract-then-clamp lands the offset exactly on `max_scroll`, which the
renderer was already displaying — so the viewport would not visibly move on the first press and the
gap would reproduce through the "fix". That ordering is now an authored truth and a named test.

breadcrumb: no OWASP / traversal / injection / privacy candidate surfaced — this plan's diff adds no
