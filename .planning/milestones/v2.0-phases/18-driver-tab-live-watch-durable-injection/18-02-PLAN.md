<objective>
Make the driver an honest reporter of what happened to a steering message, and put every blocking
call in `src/driver/` behind the boundary this repository has already been bitten by not using.

Purpose: **`isReplay: true` arrives at DEQUEUE, roughly 55 seconds late — it is a "started
processing" ack, not a receipt** (D-07, measured: a message written at t=12s was echoed at t=68s,
45 ms after the *previous* turn's `result`). That timing is exactly what makes the three-state
semantics STEER-02 needs real rather than cosmetic: **queued** (durably on disk) → **delivered**
(written to the agent's stdin without error) → **acted-on** (the agent dequeued it and is running it
as its own turn), plus an honest fourth, **missed**. Only the driver has parsed envelopes, so only
the driver can perform the correlation (D-08) — the TUI reads a rendered projection, and
reconstructing protocol semantics from a rendered string is screen-scraping in another guise.

The blocking half is D-28 / WR-10, and it is not theoretical here: `tests/driver_lock.rs:201-215`
records an **observed** deadlock in which a blocking `flock` inside an `async fn` defeated
`tokio::time::timeout` on a current-thread runtime. Phase 18 is the TUI-side caller the review
predicted, and there the failure mode is a frozen frame rather than an error.

Output: the replay-echo correlator, the `missed` classifier, four `spawn_blocking` boundaries, and
the tests that keep them.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent stdout envelopes → driver correlator | `is_replay` and the echoed text are agent-controlled; a hostile agent can echo arbitrary text. |
| `inbox.jsonl` → `Executor::send` | Human text crosses into a process with git and push rights. |
| driver async runtime → blocking syscalls | A parked runtime thread is a liveness boundary: the stop path shares it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-08 | Spoofing | replay-echo correlation | medium | mitigate | Correlation removes the FIFO-front entry on exact text equality only; a forged echo can at worst ack a message the user really sent, and can never invent an id that was not delivered, because ids come from `PendingAcks`, never from the envelope. |
| T-18-09 | Repudiation | an injected message with no terminal record | high | mitigate | The `missed` classifier guarantees every id reaches `interjected`, `interjection_acted_on` or `interjection_missed` on disk (D-10). |
| T-18-10 | Denial of service | blocking `flock` inside `async fn` parking the runtime | high | mitigate | `spawn_blocking` on all four sections plus a named multi-thread regression test; the deadlock was previously observed, not theorised (D-28). |
| T-18-11 | Elevation of privilege | `RunLock` released early, admitting a second concurrent driver | high | mitigate | The lock is moved back out of the blocking task and held for the run's duration; asserted structurally at the call site and by the existing lock tests. |
| T-18-12 | Information disclosure | new log lines carrying echoed agent text | medium | mitigate | Error kind and counts only; never a message body (`PATTERNS` §S3, T-17-05 carried forward). |
| T-18-13 | Tampering | package-manager installs | low | accept | Zero Cargo dependencies added by this plan; no package-legitimacy surface exists. |

ASVS level 1; blocking threshold `high`. T-18-09, T-18-10 and T-18-11 are the `high` rows and all
three are `mitigate` with a named test.
