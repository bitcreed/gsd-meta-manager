# Phase 18 — UI Design Contract

> Visual and interaction contract for the Driver tab, the live output pane, the four-state
> injection display, the start flow, the dashboard driver badges, and the needs-a-human
> sort/filter. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Binding sources of truth, in precedence order:**

1. `18-CONTEXT.md` — every `D-NN` is binding. Where this document names a `D-NN`, that decision
   is the authority and this document is only its rendering.
2. The shipped code named inline (`detail.rs`, `normal.rs`, `enqueue.rs`, `driver_confirm.rs`,
   `help.rs`). This contract **extends** those conventions; it replaces none of them.
3. `.planning/research/FEATURES.md` Anti-Features — three of them are load-bearing here and are
   restated as fences in `## Non-Goals`.

## THE MEDIUM — read this before any other section

**This is a terminal UI.** There is no CSS, no DOM, no browser, no component library, no font
stack, no hex colour, no pixel, no rem, no breakpoint-in-pixels, no hover, no focus ring, no
transition, no animation, and no mouse.

| Web concept | What it is here |
|---|---|
| Colour palette | The 16 ANSI named colours via `ratatui::style::Color` |
| Font weight / size | Nothing. One monospace cell grid. Hierarchy = `Modifier::{BOLD, DIM, REVERSED}` + colour + indentation + `Block` borders |
| Spacing units | **Integer terminal cells** (horizontal) and **rows** (vertical), allocated by `ratatui::layout::{Layout, Constraint}` |
| Responsive breakpoints | **Terminal width tiers in columns** and **height tiers in rows** |
| Icons | Single Unicode glyphs, fixed `&'static str`, never derived from file content |
| Hover / focus / active | Does not exist. State = which pane holds the selection, which tab is active, the scroll offset, the follow bit |
| Accessibility | Glyph + text label + colour (never colour alone); keyboard-only operation; graceful under `NO_COLOR` |

Any token expressed in px/rem/Tailwind/hex/font-family in this phase is wrong and must be
rejected at review.

## Spacing Scale

All spacing is whole terminal cells. There is no sub-cell unit and no base-4 pixel constraint —
the grid's quantum is 1 cell. Inherited verbatim from the Phase 11 / Phase 14 scale.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 1 cell | Badge glyph → alias gap; glyph → label gap in a state cell |
| sm | 2 cells | Left indent inside a pane (`  goal: …`); footer hint separator; run-list `highlight_symbol` `"> "` |
| md | 3 cells | Tab-bar row height (`Constraint::Length(3)`) |
| lg | 4 cells | Continuation indent for an injected message's text line |

### Measured layout constants — the `STATUS_COLUMN_MIN_CELLS` discipline

`normal.rs:117` establishes the rule this phase obeys: **when a line has a known minimum rendered
width, name that width as a `pub const` derived from the render and give the layout a
`Constraint::Min` floor, never a bare percentage.** A percentage-only constraint is exactly what
clipped the trailing `V` of the D-R-P-E-V cell (UIFIX-02 / CR-01). Three new constants:

| Constant | Value | Derivation | Why it must be a floor |
|---|---|---|---|
| `PIPELINE_LINE_MAX_CELLS` | `37` | `build_pipeline_line` worst case: `2 + [D]3 + ---3 + [R]3 + ---3 + [P]3 + ---3 + [E 123/456]11 + ---3 + [V]3` | The reused D-R-P-E-V line (D-17) must never lose its trailing `[V]`. That is the CR-01 bug, verbatim |
| `DRIVER_DETAIL_MIN_CELLS` | `39` | `PIPELINE_LINE_MAX_CELLS + 2` (the pane's own **sm** left indent) | The run-detail pane's floor |
| `TAB_BAR_FULL_CELLS` / `TAB_BAR_COMPACT_CELLS` | `107` / `77` | See `## Tab Bar` | An 11th tab appended to a bar that already overflows at 80 columns is an invisible tab |

Exceptions to the scale: none. Every measurement in this document is an integer cell or row.

## Typography

There is none. One monospace cell grid, one size, one family, chosen by the user's terminal.
"Typography" here is the modifier + colour + indentation vocabulary that stands in for it.

| Role | Style | Usage in this phase |
|------|-------|---------------------|
| Body | `Style::default()` | Agent output lines, injected message text, run-list labels, goal text |
| Label | `Style::default().fg(Color::DarkGray)` | Timestamps, `cost`/`started`/`elapsed` field names, the run directory path, section rules |
| Muted / inert | `Style::default().fg(Color::DarkGray).add_modifier(Modifier::DIM)` | The honest one-command note; the "N earlier lines dropped" notice; `(none given)` |
| Emphasis | `Style::default().add_modifier(Modifier::BOLD)` | Footer key hints (`[i]`, `[s]`); the `Inject>` / `Command>` / `Goal>` prompt words |
| Heading | `Style::default().fg(Color::Cyan).add_modifier(Modifier::BOLD)` | Active tab label (existing `highlight_style`); selected run-list row (existing `> ` + Cyan BOLD idiom) |
| State | `Style::default().fg(<state colour>)` | Injection state cells, run terminal-state words, run-list glyphs |

**`Modifier::REVERSED` is not used anywhere in this phase.** It is unreadable on a meaningful
fraction of terminal colour schemes and the repo does not use it today.

**No section uses `Wrap` except the run-detail header goal field** (max 3 rows, then `…`). Every
scrolling pane renders `Paragraph::new(lines).scroll((offset, 0))` with wrapping **off**, because
`Wrap` breaks the `total_lines` ↔ scroll-offset correspondence the clamp invariant depends on —
the same reason the Browse viewer (`detail.rs:3054-3090`) does not wrap.

## Colour

ANSI named colours only. The project has **no theme module**; this table is the established
convention, documented so it can be reused rather than replaced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Terminal default fg on terminal default bg | All body text, all pane interiors, all borders drawn by `Block` |
| Secondary (30%) | `Color::DarkGray` | Borders, section rules, timestamps, field labels, inert/not-started states, gutters, the dropped-lines notice |
| Accent (10%) | `Color::Cyan` | See the exhaustive reserved list below |
| Destructive | `Color::Red` | Failed / denied / stalled / timed-out / crashed run states; `missed` injections; the stop confirmation prompt |

### The established semantic vocabulary (reused, not redefined)

| Colour | Meaning | Pre-existing sites |
|--------|---------|--------------------|
| `Color::Green` | active / complete / verified / landed | reached D-R-P-E-V stage, `▶` session badge, active project rows |
| `Color::Yellow` | idle / current / waiting / in-between | current D-R-P-E-V stage, `⏳` external-job badge, idle project rows |
| `Color::Red` | blocked / failed / destructive | blocked project rows, `delete_confirm` and `driver_confirm` stop prompts |
| `Color::DarkGray` | inert / not started / secondary chrome | not-started stages, borders, `Loading...`, line-number gutter |
| `Color::Magenta` | not one of the ordinary states | skipped pipeline stage (+ `DIM`), unknown-status rows, workstream cue |
| `Color::Cyan` | selection / active tab / heading | active tab, selected list item, `⏸` pause badge, `# H1` |
| `Color::Blue` | directory | `[DIR] ` prefix in the Browse listing |

### Accent (Cyan) — exhaustive reserved list for this phase

Cyan is **never** used for generic interactive affordance. Footer key hints are BOLD on default
foreground, not Cyan.

- Active tab label in the detail tab bar (existing `highlight_style`, Cyan + BOLD)
- Selected run row in the Driver tab's run list (existing `> ` + Cyan + BOLD idiom)
- The `»` marker that identifies a human-injected message in the output pane
- The `sort: attention` indicator on the dashboard when the non-default sort mode is active
- (pre-existing) `⏸` pause badge, pause context line, `# H1` in the file viewer, summary "done" count

### Magenta gains one new meaning, deliberately

`Color::Magenta` becomes the **driven-and-live** colour, on top of its existing
skipped/unknown/workstream duty. The reasoning, recorded so it can be overturned knowingly:
Cyan, Yellow and Green are already spoken for by the three shipped badges; DarkGray means inert;
Blue means directory; Red is taken by parked/needs-human below. Magenta is the codebase's
"this is not one of the ordinary states" colour, and an autonomous agent driving the user's repo
is precisely that. It is also the lowest-traffic colour in the alias column today (its existing
uses are the Pipeline tab's stage line and whole-row status colouring, neither of which paints a
badge cell).

### The never-colour-alone rule

**No meaning in this phase is carried by colour alone.** Every state is a triple
`(glyph, text label, colour)`, and the glyph shapes alone are mutually distinguishable:

| State family | Glyphs (shape-distinct without colour) |
|---|---|
| Run state | `◆` live · `◇` liveness unknown · `●` succeeded · `○` succeeded, nothing changed · `✗` failed · `■` killed |
| Injection state | `○` queued · `◐` delivered · `●` acted-on · `✗` missed |
| Dashboard badge | `◆` driven-and-live · `⚑` parked/needs-human · `⏸` paused · `⏳` external job · `▶` session |

Under `NO_COLOR` or a monochrome terminal every one of these remains readable, because the shape
differs in every pair and a text label accompanies it wherever the pane is ≥ 26 cells wide.

## Tab Bar — the 11th tab, and the overflow it inherits

`DetailSubView::Driver` is **index 10**, label `"D:Drive"`, reached by `Left`/`Right` and by
`Shift+D` (D-15). All ten digits `1`–`0` are taken.

### The inherited defect this phase must not walk into

Measured against the shipped code (`Tabs` renders `1 pad + label + 1 pad` per tab plus a 1-cell
`"|"` divider; `Block::inner` reserves row 0 for the `" Project: {alias} "` title, so the bar
gets the full area width on row 1):

- The **ten** shipped tabs already occupy **96 cells**. At an 80-column terminal, `9:Cfg` and
  `0:Docs` are **already silently dropped off the right edge** — this is the unresolved
  "Tab bar overflow at 80 columns" blocker carried in `STATE.md` since Phase 12.
- Appending `D:Drive ` takes the bar to **107 cells**. The Driver tab is the **last** entry, so
  at every common terminal width it would be the tab that never renders — invisible label,
  invisible Cyan+BOLD active cue.

A tab the user cannot see is not a shipped surface. Two rules, both **REQUIRED**:

### Rule 1 — measured width tiers with a compact label set

The title vector is built by one function, `tab_titles(compact: bool, driver_live: bool) -> Vec<Line>`,
so both the tiering and the live marker are assertable at the logic level (the repo's
`#[cfg(test)] mod tests` convention).

| Tier | Condition | Label set | Measured width |
|---|---|---|---|
| Full | tab-bar area width `>= TAB_BAR_FULL_CELLS` (107) | `1:Phases 2:Roadmap 3:Backlog 4:Git 5:Pipe 6:Queue 7:Sess 8:Arch 9:Cfg 0:Docs D:Drive_` | 107 cells |
| Compact | width `>= TAB_BAR_COMPACT_CELLS` (77) | `1:Ph 2:Rd 3:Bk 4:Gt 5:Pp 6:Qu 7:Ss 8:Ar 9:Cf 0:Dc D:Dr_` | 77 cells |
| Windowed | width `< 77` | Compact labels, windowed — see Rule 2 | fits by construction |

`_` in the Driver label is the reserved live-marker cell (Rule 3). The compact labels are
mutually unambiguous and the digit is the real handle in every case.

### Rule 2 — the active tab is always rendered

Below the compact width the bar renders a **contiguous window of compact labels that always
contains the active tab**, with `‹` (U+2039) / `›` (U+203A) DarkGray overflow markers on
whichever side is truncated. Example at 40 columns with `D:Drive` active:

```
‹|8:Ar|9:Cf|0:Dc|D:Dr◆
```

This is the general fix and it also retires the shipped ≥80-column defect. **A tab bar that
silently drops the active tab is a defect, not a tier.**

### Rule 3 — the Driver tab carries a live marker, at constant width

When the selected project has a live observed run, the Driver label's reserved final cell holds
`◆` (Magenta); otherwise it holds a space. The cell is **always** present so the bar's width never
changes when a run starts or ends.

| Run state for this alias | Full label | Compact label |
|---|---|---|
| live | `D:Drive◆` | `D:Dr◆` |
| anything else | `D:Drive ` | `D:Dr ` |

Rationale: inside a project's detail view the dashboard is not visible, and *"the user must never
be unsure whether something is driving their repo"* (FEATURES.md) has to hold on this screen too.

### Six sites (D-15) — none may be missed

`TAB_TITLES` (`:41-52`, literal-length array), `tab_index` (`:82-95`), `sub_view_from_index`
(`:97-112`), `switch_to_tab` (`:215-341`), render dispatch (`:1897-1908`) **and its duplicate**
(`:3199-3210`, used by `EnqueueScreen` to paint the body behind its footer), `footer_spans`
(`:3772-3855`).

## Surface 1 — The Driver tab

### Horizontal layout

```rust
Layout::horizontal([Constraint::Percentage(40), Constraint::Min(DRIVER_DETAIL_MIN_CELLS)])
```

`Min(39)` rather than `Percentage(60)` is the `STATUS_COLUMN_MIN_CELLS` discipline applied to a
new surface: it guarantees the reused D-R-P-E-V line never loses its trailing `[V]` at any width
where two panes render at all.

| Width tier | Layout | Run-list row | Rationale |
|---|---|---|---|
| `>= 80` | two panes; left 32, right 48 | glyph + timestamp + suffix + **state word** | Left inner (31) ≥ 26, so the word fits |
| `>= 60` | two panes; at 60 → left 21, right 39 | glyph + timestamp + suffix, **no word** | Left inner (20) is exactly the glyph row + `> ` |
| `< 60` | **single pane** — run detail only; the run list collapses | n/a — identity moves to the pane title | `0.4 × 59 = 23` for the list leaves < 39 for the detail, and a clipped `[V]` is the CR-01 bug |

At `< 60` the run detail's `Block` title carries the selection: `` ` 07-29 21:40 3f2a  (2/7) ` ``.
`j`/`k` still change the selection; only the list's *rendering* is dropped.

### Vertical layout of the run-detail pane

Top to bottom, per D-16. `content_height` is the detail content area
(`terminal rows − 3 tab bar − 1 footer`).

| Height tier | Sections | Constraints |
|---|---|---|
| `content_height >= 14` | header · pipeline · steps · output | `Length(3 + goal_rows)`, `Length(2)`, `Length(3 + n_steps)`, `Min(3)` |
| `8 ..= 13` | header (2 rows) · pipeline (1) · steps (1) · output | `Length(2)`, `Length(1)`, `Length(1)`, `Min(3)` |
| `< 8` | output only, with a 1-row identity header | `Length(1)`, `Min(1)` |

`goal_rows ∈ 1..=3`. **No section is ever allocated 0 rows** — a section that cannot fit is
dropped by the tier, never squeezed to nothing.

### Header (rows 1..n)

```
  goal: ship the driver tab and make injection honest
  cmd:  /gsd:execute-phase 18    started 21:40    elapsed +04:12
  cost  $1.83 cumulative

Wrapped with `Wrap { trim: false }` to **at most 3 rows**, then `…`. Empty goal renders `(none given)` DarkGray + DIM — never a fabricated summary |
| `cmd:` | `RunRecord.gsd_command` | label DarkGray, text default | Sanitised; truncated with `…` |
| `started` | `RunRecord.started_at` (RFC3339) rendered `HH:MM` local | label DarkGray, value default | — |
| `elapsed` | `now − started_at`, `+MM:SS` (or `+H:MM:SS` past an hour) | label DarkGray, value default | Redraws on the existing 250 ms tick **only** when the Driver tab is the active sub-view of the top `DetailScreen` and the selected project has a live observed run (D-21). Never a second timer |
| `cost` | `JournalEvent::Cost.cumulative_usd` | label DarkGray, value default | **The word `cumulative` is mandatory** (D-12): `total_cost_usd` accumulates across turns while `num_turns`/`duration_ms` reset. Any per-turn figure elsewhere must be labelled `this turn` |

For a **finished** run, `elapsed` becomes `ran MM:SS` and a fourth field appears on the `cmd:`

### Pipeline row — reused, never re-invented (D-17)

One blank row, then `build_pipeline_line(inf, &derive_all_stage_statuses(inf))` verbatim from

**Nothing about this widget is modified, wrapped, restyled, or duplicated.** A second progress
display is a named anti-feature (FEATURES.md) and D-17 makes reuse mandatory. `ARCHITECTURE` M5's
proposal to lift these functions into `state_reader/` is explicitly declined for this phase.

## Surface 2 — The live output pane

A bounded ring buffer (D-18) on `AppContext`, keyed by alias, **pruned in `prune_driver_maps`**
alongside the existing per-alias maps. View state (scroll offset, follow bit, selected run index)
lives on `ProjectViewCache` (`#[derive(Default)]`, additive).

### Named constants (the `main_loop.rs:41-49` idiom — doc-comment the untuned-ness)

| Constant | Value | Doc must say |
|---|---|---|
| `DRIVER_OUTPUT_RING_LINES` | `2_000` | Untuned starting point. Bounds one alias's buffer to roughly 400 KB |
| `DRIVER_OUTPUT_LINE_CELLS` | `512` | Per-line hard truncation at append time, by **character** count, `…`-suffixed |
| `DRIVER_OUTPUT_RECORD_MAX_LINES` | `64` | One journal record that expands past this is cut, so a single giant record cannot flush the whole ring |

### Header rule and the follow indicator

The follow bit does not exist anywhere in the codebase today and is the one behaviour a
`Paragraph::scroll` viewer does not give for free (D-19).

```
── output ────────────────────────────────── [following] ──
```

| Run / view state | Right-aligned indicator | Style |
|---|---|---|
| Live, following the tail | `[following]` | Green |
| Live, user has scrolled up | `[scrolled +N]` — `N` = buffered lines below the viewport, displayed `+999` above 999 | Yellow |
| Ended | `[ended 21:52]` | DarkGray |
| Ended, adopted (started before this TUI session) | `[journal only]` | DarkGray |

**`[scrolled +N]` deliberately does not say "paused".** `paused` already means "a non-empty
HANDOFF is present" (`⏸`) everywhere else in this tool, and reusing the word for a scroll state
would make the vocabulary lie.

### Follow behaviour

| Event | Effect |
|---|---|
| New records appended while following | Offset tracks the tail; `needs_redraw` set in the `Action::DriverJournalAppended` handler (D-20 — `app.rs:705-739` currently drops `records`; this is the seam, not a bug) |
| Any upward scroll (`PageUp`) | Follow bit → `false`, automatically |
| `f` | Toggles the follow bit. Turning it on jumps to the tail |
| `G` | Jumps to the tail **and** sets follow → `true` |
| `PageDown` reaching the tail | Follow bit → `true`, automatically. Reaching the bottom *is* the request to follow |
| Selecting a different run (`j`/`k`) | Offset resets to the tail; follow → `true` |

### The clamp-ordering invariant — UIFIX-04, non-negotiable

Repeated in four source comments (`detail.rs:889, 946, 975, 992`) and guarded by
`detail.rs:5046-5204`:

- **`PageDown`: add `PAGE_SCROLL_LINES` (20) THEN clamp** to `max_scroll`.
- **`PageUp` / `Up` / `k`: clamp to `max_scroll` FIRST, THEN subtract.**
- `max_scroll = total_lines.saturating_sub(visible_height)` — **the same formula the renderer
  uses**, never a parallel calculation.
- The clamp happens in the **key handler**, against a `Cell<ViewportMetrics>` recorded by the
  render pass (the `browser_viewport` / `archive_viewport` / `generic_viewport` idiom,
  `detail.rs:3054-3090`). Before the first render the recorded height is 0 → `max_scroll = 0`, a
  safe floor.

`total_lines` is computed **after** the `Vec<Line>` is fully built (including two-row expansion of
injected messages), so the offset always clamps against what is actually rendered.

### Event-kind rendering — the four visual classes

Each buffered entry carries its journal kind. The left marker column is 2 cells; the marker
glyphs are fixed `&'static str`.

| Journal source | Marker | Marker style | Text style | Notes |
|---|---|---|---|---|
| `ExecEvent { stream: "assistant" \| "user" \| "turn_completed" \| "unknown" \| "unparseable" }` | `  ` (two spaces) | — | default fg | The common case gets no marker, so injections and diagnostics stand out |
| `ExecEvent { stream: "stderr" }` | `· ` | DarkGray | DarkGray | Present but secondary |
| `Interjected` / acted-on | `» ` | **Cyan + BOLD** | see Surface 3 | The one Cyan use in this pane |
| `Diagnostic`, `EventsDropped`, `JournalTruncated` | `! ` | Yellow | Yellow | Never silently swallowed |
| `RunEnded`, `ExecFinished` (the terminal record) | `= ` | terminal-state colour + BOLD | same colour | Renders **last**; the visual full stop |

**`ExecEvent.text` is a readable text projection, not `format!("{m:?}")`.** Today
`journal::from_exec_event` (`mod.rs:822-825, 846-849`) stores a Rust `Debug` rendering of
`TurnMessage`, whose body `stream_json.rs:105-107` explicitly defers to *"Phase 18's rendering
concern"*. A pane full of `TurnMessage { session_id: Some(..), is_replay: false, .. }` satisfies
"watch its output" only in the letter (18-CONTEXT, *Things that will look done but are not*).

### Overflow and truncation affordances

| Condition | Affordance | Style |
|---|---|---|
| The ring dropped older lines | **First** rendered line: `… {N} earlier lines dropped (buffer holds {DRIVER_OUTPUT_RING_LINES})` | DarkGray + DIM |
| One record exceeded `DRIVER_OUTPUT_RECORD_MAX_LINES` | A trailing `    … record truncated` line | DarkGray + DIM |
| One line exceeded `DRIVER_OUTPUT_LINE_CELLS` | Character-truncated with a trailing `…` at append time | inherits |
| Line wider than the pane | Clipped at the right edge (no `Wrap` — see `## Typography`). The run directory path in the header is the escape hatch for reading the raw journal | inherits |
| `EventsDropped { count }` in the journal | Rendered as a `! ` diagnostic: `{count} stream events were dropped` | Yellow |
| `JournalTruncated` | Rendered as a `! ` diagnostic naming the byte cap | Yellow |
| Journal sequence gap (`reader::seq_gaps_from`) | Rendered as a `! ` diagnostic: `journal gap: {n} record(s) not read` | Yellow |

**These four are not cosmetic.** A pane that silently loses lines is exactly the "looks done but
isn't" failure the phase context enumerates.

## Surface 3 — The four-state injection display (STEER-02)

Three states plus the honest fourth (D-07, D-10). **The word "sent" is forbidden**, and so are
"received", "read" and "acknowledged" — `isReplay: true` arrives at **DEQUEUE**, measured
~55 seconds after the write, so any word implying receipt is a lie about the protocol.

| State | Glyph | Label (exact) | Colour | What it means | Authoritative observer |
|---|---|---|---|---|---|
| queued | `○` U+25CB | `queued` | DarkGray | Durably on disk in `inbox.jsonl`; nothing has read it | the TUI, from its own `sync_data()`-confirmed write |
| delivered | `◐` U+25D0 | `delivered` | Yellow | Written to the agent's stdin without error (`Executor::send` returned `Ok`) | the **driver** |
| acted-on | `●` U+25CF | `acted-on` | Green | The agent **dequeued** it and is running it as its own turn | the **driver**, from the `is_replay == true` echo |
| missed | `✗` U+2717 | `missed` | Red | Appended after the driver closed stdin — undeliverable, never retried | the **driver** |

The `○ → ◐ → ●` progression is a filling shape, and that is the whole point: it reads correctly
across a minute-long gap with **no animation, no spinner, and no implied imminence.** A spinner
idiom is wrong here and must be rejected at review.

### Rendering — always two rows, at every width

```
» ◐ delivered  21:40:02  (+0:47)
    skip the UI review
```

| Row | Content | Style |
|---|---|---|
| 1 | `» ` marker · glyph · space · label · **sm** gap · queue timestamp `HH:MM:SS` | `»` Cyan+BOLD; glyph+label in the state colour; timestamp DarkGray |
| 2 | **lg** (4-cell) indent + the verbatim message text, sanitised | default fg |
| 1, extra | `(+M:SS)` — time since the `delivered` transition | DarkGray. Rendered **only** in the `delivered` state |
| 2, extra (`missed` only) | A second lg-indented row: `(the run closed its input before this was delivered)` | DarkGray + DIM |

Always two rows means no width branch, a perfectly aligned state column, and no right-alignment
arithmetic that could clip at 39 cells. The `(+M:SS)` counter is the honest answer to the 55-second
gap: it shows time passing without predicting an arrival.

### State derivation is a pure function of disk

Per 18-CONTEXT `## Specific Ideas`: the TUI's state for a message id is a pure function of two
sets — ids present in `inbox.jsonl`, and ids present in each journal kind. Nothing is held in
memory that a restart would lose, which is exactly what makes STEER-03 hold with no extra
persistence.

**The `queued` state is not shown until the `sync_data()`-backed append returns `Ok`** (D-06). A
buffered write that dies with the process satisfies the UI and fails the criterion.

### New priority order (D-24)

| Rank | Condition | Badge | Colour + modifier | New? |
|---|---|---|---|---|
| 1 | driven **and** live (`ObservedRun::is_live()`) | `◆ ` U+25C6 + space | Magenta + **BOLD** | **new** |
| 2 | parked / needs a human (`needs_human(..)`, D-14) | `⚑ ` U+2691 + space | Red + **BOLD** | **new** |
| 3 | `state.paused` (non-empty HANDOFF) | `⏸ ` U+23F8 + space | Cyan | existing |

### Glyph selection rationale

- `◆` (filled diamond) and `⚑` (flag) are shape-distinct from `⏸` (two bars), `⏳` (hourglass) and
  `▶` (right triangle) at a glance. `▲` was rejected: it is `▶` rotated and fails the
  at-a-glance test.
- Both are covered by DejaVu Sans Mono and Noto, the same coverage the shipped `⏳` already
  requires.
- Both are narrow (East-Asian-Width Ambiguous), matching the shipped `▶` (U+25B6), so the
  glyph + space badge stays 2 cells and the Alias column stays aligned at all three dashboard
  width tiers (`>=80`, `>=60`, `<60`).
- Colours: Magenta and Red are the only two remaining unclaimed badge colours (Cyan, Yellow and
  Green are taken by ranks 3–5; DarkGray means inert; Blue means directory). Red for
  parked/needs-human matches the established "blocked" semantics exactly.

### `needs_human` is a predicate over evidence that exists today (D-14)

Fed by: `state.paused`, `state.external_job_waiting`, a finished run whose outcome is
`PermissionDenied` / `Failed` / `Stalled` / `TimedOut`, and — forward-compatibly — a
`JournalEvent::Parked` record if one is ever present.

**Do not wire this badge to `JournalEvent::Parked` alone.** Nothing emits it until Phase 20; the
badge would never light, no test would catch it (the test would emit the event by hand), and a
badge that can never light is worse than no badge because it teaches the user to ignore it.

### `STATUS_COLUMN_MIN_CELLS` is untouched

`13`. The badge lives in the Alias cell, not the Status cell. Nothing in this phase may reduce
that floor — the trailing `V` clip is UIFIX-02 / CR-01.

## Surface 7 — Dashboard sort and filter (OBS-07)

No new screen (D-25).

`parse_filter` (`app.rs:30-56`) gains `FilterColumn::NeedsHuman` on the suffix **`/h`** ("human").
`n`, `p`, `s` are taken; `h` is free and mnemonic.

| Typed | Meaning |
|---|---|
| `/term/h` | Rows matching `term` in any column **and** satisfying `needs_human` |

| Mode | Order | Default? |

## Untrusted Input Boundary

**Every string this phase renders that originated on disk is untrusted.** The threat model is
D-13's, and it is not hypothetical: an agent hid a production-database deletion, fabricated ~4000
fake users and fake test results, and falsely claimed rollback was impossible. That agent's prose
lands in `ExecEvent.text`, `Diagnostic.detail`, `RunRecord.goal` (on re-read from disk) and
`gsd_command`.

### One shared sanitiser, applied at buffer-append time and at every header interpolation

| Rule | Why |
|---|---|
| Split on `\n` into separate buffered lines **first** | Assistant output is genuinely multi-line and is more readable split than collapsed |
| Replace every C0 control character (`0x00`–`0x1F`) and `DEL` (`0x7F`) with `·` (U+00B7); `\t` → 4 spaces | — |
| **Strip `ESC` (`0x1B`) unconditionally** | Otherwise agent prose can emit ANSI/OSC sequences that repaint the screen, forge a status line, move the cursor, or set the window title. This is the single highest-value rule in this section |
| Truncate by **character** count to `DRIVER_OUTPUT_LINE_CELLS`, `…`-suffixed | Byte slicing panics on a multibyte boundary |
| Cap one record's expansion at `DRIVER_OUTPUT_RECORD_MAX_LINES` | One giant record must not flush the ring |

### The Replit rule, rendered (D-13)

| Never | Always |
|---|---|
| A badge, colour, status word, sort key, or run-list glyph derived from `ResultMessage.result` or any agent prose | Derived from `RunRecord.outcome` / `RunEnded.outcome` / `ExecFinished.exit` |
| Any string comparison against agent prose to decide "did it succeed" | The four-source derivation Phase 15 already computes |
| A badge glyph built from file content | Fixed `&'static str` constants, as `alias_badge` already guarantees |

Agent prose **may** be displayed as content in the output pane, and nowhere else with any
authority. **State this in the doc comment on the rendering function**, so the next reader cannot
undo it by accident (D-13).

## Non-Goals — explicit fences

Recorded so the checker does not flag omissions and the executor does not expand scope.

- **No second progress display.** The D-R-P-E-V widget is reused verbatim (D-17). Named
  anti-feature.
- **No chat-first framing.** The run view is CI-run vocabulary (goal / steps / status / cost).
  Chat is the injection affordance and a drill-down. Named anti-feature.
- **No full raw trace tree as the landing view.** The step timeline lands; the bounded ring buffer
  is the drill-down. Named anti-feature.
- **No per-step notification or toast spam.** Four transition messages only. Named anti-feature.
- **No promise of live output after a TUI restart**, in code, copy, status text, footer hint or
  doc comment. Physically impossible (Phase 17 D-11).
- **No status, badge, colour, sort key or glyph derived from agent prose** (D-13).
- **No badge stacking.** At most one badge per dashboard row.
- **No spinner, no animation, no transition** anywhere. The medium has none and the 55-second
  dequeue gap makes a fast-spinner idiom actively dishonest.
- **No `Modifier::REVERSED`.**
- **No mouse support.**
- **No theme module, no collapsing the three duplicate `status_color` implementations** — a
  separate quick task (18-CONTEXT deferred list).
- **No `tui-textarea` and no movable cursor** for any input this phase adds (D-22).
- **No changes to `src/ui/project_list.rs`** — it is dead code (`src/ui/mod.rs` does not declare
  it). `ARCHITECTURE` M6 points a future planner at it; do not follow. The live dashboard is
  `normal.rs`.
- **No interrupt affordance.** Deferred to Phase 20 (18-CONTEXT deferred list): its true state can
  only be known one turn later, which would be a second three-state UI.
- **No new Cargo dependency.** `VecDeque` is std.
- **No reduction of `STATUS_COLUMN_MIN_CELLS` (13)** and no growth in the 5 pre-existing
  `--all-targets` clippy lints.
